## 2. 운영 (DB/인프라) 협조 필요

### 2.1 DB schema 마이그레이션 [P1, 사전 존재 known issue]
- **배경**: PR #20에서 career_stage v2 도입했으나 DB schema는 여전히 INT (1~4) 제약.
- **요청**:
  - `artist_profiles.career_stage` INT CHECK (1..4) → FLOAT (0..8) 마이그레이션
  - 기존 row 변환 로직 (예: int 1 → 1.0, int 4 → 6.0 등) 합의
  - `artist_profiles`에 `career_age` 컬럼 추가 (현재 미존재)
  - 컬럼 추가는 다운타임 없이 가능하지만 read-write 동기화 검토 필요
- **참고 코드**:
  - `scripts/init_visionai_db.sql:46` (현재 schema)
  - `src/visionai/price_engine/api/primary_predictor.py` career_stage_v2_score
- **예상 효과**: career_stage v2 의미 정합. 현재는 학습/서빙 contract에 잔존 드리프트 있음.

### 2.2 artists.training_count 동기화 [P2]
- **배경**: PR #20에서 warm artist set을 JSON으로 우회 처리했으나, DB의 `training_count`는 여전히 raw count.
- **요청**:
  - 학습 파이프라인 산출물 (`integrated_v3_filtered_tuned_warm_artists.json`)을 DB에 sync하는 로직 추가
  - 또는 DB `training_count` 컬럼에 filtered count (입체 985건 제외 후) 저장하는 로직
- **참고 코드**:
  - `src/visionai/price_engine/api/artist_matcher.py` docstring (KNOWN ISSUES 1)
- **예상 효과**: 32명 작가 미스라우팅 위험 제거. 현재는 warm_artist JSON으로 우회.

### 2.3 PredictRequest에 gallery_name 필드 추가 [P2]
- **배경**: artist_matcher가 gallery_name을 'Gallery'/'Saatchi Art'로 하드코딩. 학습 vocab은 실제 갤러리명 59개.
- **요청**:
  - `PredictRequest`에 optional `gallery_name`, `gallery_type` 필드 추가
  - 사용자가 명시적으로 갤러리 정보 전달
  - 미입력 시 현재 fallback 유지 (sentinel encoding)
- **참고 코드**:
  - `src/visionai/price_engine/api/primary_schemas.py` PredictRequest
  - `src/visionai/price_engine/api/artist_matcher.py` docstring (KNOWN ISSUES 2)
- **예상 효과**: gallery_name 신호 회복 (importance 작지만 train/serve 정합). API 호환성 영향 없음 (optional).

### 2.4 Cold-start 자동 수집 강화 [P1]
- **배경**: 외부 수집(Artsy/Saatchi/웹) 정확도 한계.
- **요청**:
  - 한국 갤러리 사이트 크롤링 추가 (작가 프로필 페이지)
  - 5단계 → 7단계 필터로 정확도 향상
  - 운영 안정성 검증 (rate limit, 봇 탐지 회피)
- **참고**: `docs/MdAPE_개선_액션플랜_20260427.md` P1-1 두 번째 부분

### 2.5 모델 재배포 시 Docker 빌드 (artifacts 정합) [P3, 절차]
- **배경**: PR #20+#21+#22 머지 후 모델 artifacts 5개가 모두 필요 (cb/xgb/warm_artists/label_maps/source_calibration).

## 3. 정책 결정 필요 사항 (우선순위 결정)

### 3.1 m 값 업데이트 결정 [PR #22 후속]
- **권장치 (production-time MdAPE 기반)**:
  - A: 0.20 → **0.286** (현재 coverage 71.5%)
  - B: 0.30 → **0.609** (현재 coverage 50.6%)
  - C: 0.50 → **0.896** (현재 coverage 60.2%)
  - D: 0.70 → **0.827** (현재 coverage 72.8%)
- **결정 사항**:
  - 80% coverage 달성 위해 권장치 적용 vs 현재 좁은 m 유지
  - C/D는 사실상 가격 범위 의미 없음 (m≈0.9) — 가격 범위 표시 정책 변경?
  - 가격 범위가 넓어지면 사용자 신뢰도 영향 가능
- **현재 보류 중** (사용자 요청)

### 3.2 Bootstrap CI 도입 검토 [P3]
- **배경**: 코덱스 리뷰 누차 지적 — single seed CV의 통계적 신뢰성 부족.
- **요청**: fold-level bootstrap CI를 메트릭 보고서에 추가
- **소요**: 1일 작업
- **결정**: 운영 신뢰성 vs 추가 작업 ROI
