1. 실험 목적

사용자 가설: 입체 작품(3D)과 평면 작품(2D)을 모델 분기로 따로 학습하면 depth feature 효과가 살아나서 정확도가 올라갈까?
추가: depth 정보를 depth_cm(실수)만 / has_depth(유무)만 / 둘 다 넣어보면 어떻게 다른가?

Track 3 모델은 현재 작가 상태로만 분기: 학습된 작가 → Warm (LightGBM), 신규 작가 → Cold (LAD Quantile). 여기에 작품 유형(2D/3D) 분기를 어디까지 적용할지를 4가지 variant로 비교.

2. 평가 protocol

  • train 내부 mini hold-out 사용 (release_split test는 최종 1회 확인용으로 보존)
    • cold-mini: 작가 100명 통째 hold-out (low/mid/high 50/30/20 stratified)
    • warm-mini: 나머지 작가에서 1건씩 hold-out
    • mini-train: 나머지로 학습
  • 5 seeds 반복 (42, 123, 7, 2024, 999)
  • 분기 모델 학습 시 artist_works_log_branch — branch별 작가 작품수로 재계산 (leakage 방지)
  • 2D branch에선 depth_cm 제거 (constant 0)
  • 분기 라우팅 fallback: global_seen but branch_unseen 작가는 branch Cold로 보냄
  • Paired metric: row-wise APE delta + win-rate + catastrophic regression (APE 2배 악화)
⚠️ 평가 프로토콜 신뢰도 한계 (Codex 지적): mini hold-out의 stratify 기준은 artist works count뿐. 가격대, 2D/3D 비율, medium 구성은 통제 안 함. 결과적으로 cold row 수가 seed별로 747~1509로 2배 변동, cold 2D는 155~274 변동. Cold std 0.23은 단순 sample size 이슈가 아니라 이 평가 프록시가 cold 성능 차이를 안정적으로 측정하지 못한다는 신호.
분기 모델의 has_depth degenerate 처리: V1/V2/V3에서 has_depth는 branch 내 constant (2D=0, 3D=1). → has_only는 사실상 "depth signal 없음", both는 cm_only와 동등. 12 cells 표시하되 unique 학습은 9개.

10. 운영 결정 (Codex 권고 반영)

운영 채택: V0_cm_only (현 운영 v1.2) 유지.
단 분기 가설 전체 기각이 아니라 full replacement 불가 + cold 2D 국소 신호 후속 검증 가치 있음.
판단근거
Full replacement 불가 warm 분기 (V1/V3) 명확 악화 (catastrophic 20%) + cold overall std 0.23 → 안정적 우위 없음
V0_has_only 채택 금지 cold 2D 작품에 4/5 seeds 큰 악화. PR15 재확인
V2_has_only / V3_has_only baseline 대비 WinRate 0.560이지만 V2_cm_only보다 absolute worse. branched 내부에선 의미 없음
Cold 2D 국소 신호 V2_cm_only/V3_cm_only가 5/5 seeds WinRate >0.5, Δmed 3/5 개선. 후속 검증 가치
Cold 평가 자체 한계 mini hold-out stratify 부족 → cold 차이 안정 측정 어려움. 평가 protocol 보강 필요

11. 후속 검증 권고 — Frozen Cold Benchmark

Codex 권고 closure 실험: 평가 프록시 안정화 + cold 2D 신호 closure.

설계

  1. Frozen cold benchmark 1회 fix
    • artist-group holdout (cold 작가 100명)
    • Stratify 기준: 2D/3D 비율, 가격대 (low/mid/high), medium 구성 — 모두 통제
    • seed-free (한 번 만들어 영구 사용)
  2. 비교 대상 3개: V0_cm_only vs V2_cm_only vs V2_no_depth (=has_only)
  3. 판단 기준 3개:
    1. cold 2D 이득 재현되는가
    2. cold 3D 손실 없는가
    3. overall cold에서 우위 남는가
  4. 셋 중 하나라도 무너지면 → branch 가설 종료, V0 영구 유지
