# Track6 모델과 평가 지표 이해 가이드

- 목적: 프로젝트에서 사용하는 가격 예측 모델과 평가 지표를 비전공자도 이해할 수 있게 정리
- 적용 범위: Track6 실험 중심, Track3/이전 트랙에서 사용한 후보 모델 포함
- 핵심 질문:
  - 모델이 무엇을 보고 가격을 예측하는가?
  - 모델 출력값은 어떻게 해석해야 하는가?
  - 어떤 지표를 보고 모델이 좋아졌다고 판단하는가?

## 1. 가격 예측 모델의 기본 구조

- 입력값:
  - 작가명, 호수, 크기, 재료, 지지체, 제작연도, 작가 메타 정보 같은 변수
  - 예: `artist_name_ko`, `ln_estimated_ho`, `nant_material_idx`, `nant_support`
- 정답값:
  - 실제 작품 가격
  - 프로젝트에서는 주로 `ln_price_krw`를 학습 목표로 사용
- 모델 출력:
  - 대부분의 실험 모델은 `로그 가격`을 먼저 예측
  - 예측 로그 가격을 다시 원화 가격으로 되돌려 해석
- 원화 복원:
  - `예측가격 = exp(예측 로그 가격)`

## 2. 왜 로그 가격을 쓰는가

- 미술품 가격은 낮은 가격대 작품은 많고, 매우 비싼 작품은 적음
- 가격 차이가 커서 원화 가격 그대로 학습하면 고가 작품이 모델에 과하게 영향을 줄 수 있음
- 로그 가격을 쓰면 100만 원과 1,000만 원의 차이를 더 안정적으로 다룰 수 있음
- 실험에서는 실제로 `호수 -> 가격`보다 `ln(호수) -> ln(가격)` 형태가 더 안정적인 결과를 보였음

## 3. Warm / Cold 모델 구분

| 구분 | 의미 | 사용 가능한 정보 | 해석 |
|---|---|---|---|
| Warm | 학습 데이터에 같은 작가가 있는 작품 예측 | 작가명, 작가 이력, 작품 정보 | 이미 본 작가의 새 작품 가격 예측 |
| Cold | 학습 데이터에 없는 신규 작가 작품 예측 | 작품 정보, 운영에서 수집 가능한 작가 메타 | 처음 보는 작가의 가격 예측 |

- Warm과 Cold는 난이도가 다름
- Warm은 작가명 효과가 크기 때문에 성능이 좋아질 수 있음
- Cold는 작가명을 학습한 적이 없으므로 작품 자체 정보와 작가 메타 정보가 중요함
- 따라서 Warm 성능과 Cold 성능은 합쳐서 한 숫자로 판단하지 않음

## 4. Track6 기본 비교 모델

| 코드 | 평가 구분 | 모델 | 쉬운 설명 | 주로 보는 이유 |
|---|---|---|---|---|
| A | Warm | Huber | 이상치에 덜 흔들리는 회귀 모델 | 비싼 작품이나 특이값이 있어도 안정적인지 확인 |
| B | Warm | Linear Regression | 가장 기본적인 직선형 회귀 모델 | 변수와 가격 관계를 가장 단순하게 확인 |
| C | Warm | Ridge | Linear Regression에 과적합 방지 장치를 넣은 모델 | 작가명처럼 변수가 많을 때 더 안정적인지 확인 |
| D | Cold | Huber | 이상치에 강한 회귀 모델 | Cold에서 큰 오차가 줄어드는지 확인 |

| F | Cold | LightGBM | 여러 조건을 나눠가며 학습하는 트리 모델 | 비선형 관계와 변수 조합을 잘 잡는지 확인 |

## 4-1. 모델 한눈에 비교

| 모델 | 모델 성격 | 쉽게 말하면 | 잘하는 것 | 약한 점 | Track6에서 보는 포인트 |
|---|---|---|---|---|---|
| 중앙값 기준 모델 | 기준선 모델 | 그냥 대표 가격 하나를 찍는 방식 | 최소 기준 만들기 | 작품별 차이를 거의 반영 못함 | 새 모델이 이보다 나은지 확인 |
| Linear Regression | 선형 회귀 | 변수별 효과를 더해서 가격을 예측 | 설명이 쉬움 | 복잡한 관계와 이상치에 약함 | 호수/재료/지지체가 가격에 영향을 주는지 1차 확인 |
| Hedonic Linear Regression | 설명형 선형 회귀 | 가격을 작가/크기/재료 같은 속성별 효과로 나눠 설명 | 보고와 해석에 좋음 | 변수 조합 효과는 약함 | “이 변수가 가격 설명에 도움이 되는가?” 확인 |
| Ridge | 안정화된 선형 회귀 | Linear Regression이 특정 변수에 과하게 기대지 않게 조절 | 작가명처럼 변수가 많을 때 안정적 | 여전히 직선형 관계 중심 | Warm에서 작가명 포함 시 안정성 확인 |
| Lasso | 변수 선택형 선형 회귀 | 영향이 약한 변수를 줄이는 방식 | 피처 축소에 도움 | 중요한 변수를 과하게 제거할 수 있음 | 후보 피처가 많을 때 보조 검토 |
| ElasticNet | Ridge + Lasso 절충 | 안정화와 변수 선택을 같이 시도 | 피처가 많을 때 균형적 | 설정값 영향 있음 | 피처 축소/정규화 후보 |
| Huber | 이상치 강건 회귀 | 보통 값은 믿고, 너무 튀는 값은 덜 믿는 방식 | 고가/특이 작품에 덜 흔들림 | 복잡한 패턴은 제한적 | Warm/Cold 기본 후보 |
| LAD / Quantile | 중앙값 중심 회귀 | 평균보다 대표적인 가격대를 맞추는 방식 | 가격이 튀는 데이터에 안정적 | 평균 예측과 목적이 다를 수 있음 | Cold 대표 가격 예측 후보 |
| LightGBM | 트리 부스팅 | 조건을 여러 번 나눠 가격을 예측 | 비선형/조합 효과에 강함 | 설명이 어렵고 과적합 주의 | Cold/Warm에서 복잡한 피처 조합 효과 확인 |
| XGBoost | 트리 부스팅 | LightGBM과 비슷한 고성능 트리 모델 | 다양한 데이터에서 강함 | 튜닝 부담 있음 | 최종 후보 모델 비교 |
| CatBoost | 범주형 특화 트리 | 작가명/재료명 같은 문자형 변수를 잘 다룸 | 범주형 변수가 많을 때 강함 | 실행/설치 부담, 통제 필요 | 작가명/재료 중심 후보 비교 |
| HistGradientBoosting | sklearn 트리 부스팅 | 기본 제공되는 빠른 트리 모델 | 외부 라이브러리 부담이 적음 | 범주형 특화는 약함 | 초기 baseline 후보 |

## 4-2. 모델을 고르는 기준 비교

| 상황 | 우선 볼 모델 | 이유 |
|---|---|---|
| 변수가 가격에 영향을 주는지 설명하고 싶을 때 | Linear Regression, Hedonic, Ridge | 계수와 방향성을 해석하기 쉬움 |
| 고가 작품이나 이상치가 많을 때 | Huber, LAD / Quantile | 튀는 가격에 덜 흔들림 |
| 작가명이 포함된 Warm 모델을 볼 때 | Ridge, Huber, CatBoost, LightGBM | 작가명 피처가 많고 영향이 크기 때문 |
| 신규 작가 Cold 모델을 볼 때 | Huber, Quantile-LAD, LightGBM | 작가명 없이 작품 정보만으로 안정성 확인 필요 |
| 피처 조합 효과를 보고 싶을 때 | LightGBM, XGBoost, CatBoost | 재료 x 크기 같은 조합 관계를 잘 잡을 수 있음 |
| 보고용으로 설명이 중요할 때 | Hedonic, Linear Regression, Ridge | “어떤 변수가 가격에 기여했는지” 설명하기 쉬움 |
| 최종 성능 후보를 넓게 비교할 때 | Ridge, Huber, Quantile, LightGBM, XGBoost, CatBoost | 선형/강건/트리 계열을 균형 있게 비교 가능 |

## 4-5. 모델 출력 해석 비교

| 모델 | 출력값 | 출력 해석 | 주의점 |
|---|---|---|---|
| Linear / Hedonic / Ridge | 예측 로그 가격 | 변수 효과를 더해 계산한 가격 | 실제 서비스에서는 원화로 복원해야 함 |
| Huber | 예측 로그 가격 | 이상치 영향을 줄인 가격 | 일반 회귀보다 극단값에 덜 반응 |
| Quantile-LAD | 예측 로그 가격 | 평균보다 중앙값에 가까운 대표 가격 | “평균 가격”이 아니라 “대표 가격대”로 이해 |
| LightGBM / XGBoost / CatBoost | 예측 로그 가격 | 여러 조건 조합을 반영한 가격 | 왜 그런 값이 나왔는지 설명이 더 어려움 |
| MultiQuantile 계열 | 하위/중앙/상위 가격 | 가격 범위 예측에 활용 가능 | 범위가 너무 넓으면 실무성이 낮음 |

## 5. 모델별 쉬운 설명

### 5.1 기준 모델

- 의미:
  - 복잡한 모델을 쓰기 전에 최소 비교 기준으로 쓰는 모델
- 예시:
  - 전체 가격 중앙값만 예측
  - 재료별 중앙값만 예측
  - 크기 구간별 중앙값만 예측
- 해석:
  - 새 모델이 기준 모델보다 못하면 그 모델은 쓸 이유가 약함
  - 기준 모델은 “아무 학습도 안 한 단순 예측보다 나은가?”를 확인하는 기준선

### 5.2 Linear Regression

- 쉬운 설명:
  - 입력 변수와 가격 사이의 관계를 직선처럼 단순하게 계산하는 모델
- 예:
  - 호수가 커질수록 가격이 오른다
  - 특정 재료가 있으면 가격이 조금 달라진다
- 장점:
  - 설명이 쉬움
  - 어떤 변수가 가격에 어떤 방향으로 영향을 주는지 보기 좋음
- 단점:
  - 복잡한 관계를 잘 못 잡을 수 있음
  - 이상치에 흔들릴 수 있음
- 출력 해석:
  - 예측값은 로그 가격 또는 가격
  - 계수를 보면 변수의 방향성을 볼 수 있음

### 5.3 Hedonic Linear Regression

- 쉬운 설명:
  - 작품 가격을 여러 속성의 합으로 설명하는 선형 모델
- 예:
  - 가격 = 작가 효과 + 크기 효과 + 재료 효과 + 지지체 효과
- “헤도닉”의 의미:
  - 가격을 하나의 덩어리로 보지 않고, 여러 속성이 가격에 기여한다고 보는 방식
- 장점:
  - 보고서에서 설명하기 좋음
  - 어떤 피처가 가격 설명에 도움이 되는지 확인하기 좋음
- 단점:
  - 변수 사이의 복잡한 조합 효과는 제한적으로만 반영
- 프로젝트 내 사용:
  - 작가명 + 호수
  - 호수 단독
  - 재료 단독
  - 지지체 단독 같은 피처 실험의 기준 모델로 적합

### 5.4 Ridge

- 쉬운 설명:
  - Linear Regression이 너무 특정 변수에 과하게 기대지 않도록 조절한 모델
- 왜 필요한가:
  - 작가명이 많으면 변수 수가 매우 많아짐
  - 일반 선형 회귀는 일부 작가명에 과하게 맞춰질 수 있음
  - Ridge는 이런 과적합을 줄임
- 장점:
  - 변수가 많아도 비교적 안정적
  - 작가명 one-hot 피처가 있을 때 유용
- 단점:
  - 여전히 직선형 관계 중심
- 출력 해석:
  - Linear Regression과 비슷하지만 계수 크기가 더 눌려 있음

### 5.5 Lasso / ElasticNet

- 쉬운 설명:
  - 중요하지 않은 변수를 줄이거나 제거하는 선형 모델 계열
- Lasso:
  - 영향이 약한 변수의 계수를 0에 가깝게 만듦
- ElasticNet:
  - Ridge와 Lasso의 중간 성격
- 장점:
  - 변수 선택에 도움이 됨
  - 피처가 너무 많을 때 후보 축소에 유용
- 단점:
  - 현재 Track6 기본 공통 실행기에는 기본 모델군으로 고정되어 있지는 않음
- 사용 위치:
  - 후보 모델 비교 또는 피처 축소 실험에서 보조 후보로 고려

### 5.6 Huber

- 쉬운 설명:
  - 보통 데이터는 선형 회귀처럼 학습하고, 너무 튀는 값은 덜 믿는 모델
- 왜 필요한가:
  - 미술품 가격에는 매우 비싼 작품, 특이한 작품이 있음
  - 이런 값이 전체 모델을 흔들 수 있음
- 장점:
  - 이상치에 강함
  - Warm과 Cold 모두에서 기본 후보로 쓰기 좋음
- 단점:
  - 복잡한 비선형 관계는 제한적
- 출력 해석:
  - 예측 가격 자체는 일반 회귀와 같음
  - 다만 큰 이상치에 덜 끌려간 결과로 보면 됨

### 5.7 LAD / Quantile Regression

- 쉬운 설명:
  - 평균 가격을 맞추기보다 중앙값에 가까운 대표 가격대를 맞추려는 모델
- LAD:
  - Least Absolute Deviation의 약자
  - 제곱 오차가 아니라 절대 오차를 줄이는 방식
- Quantile Regression:
  - 특정 분위수의 값을 예측
  - q=0.5는 중앙값 예측에 가까움
- 장점:
  - 가격 분포가 한쪽으로 치우친 데이터에 강함
  - Cold처럼 불확실성이 큰 상황에서 안정적인 후보가 될 수 있음
- 단점:
  - 평균 가격을 잘 맞추는 목적과는 다를 수 있음
- 출력 해석:
  - q=0.5 모델의 출력은 “대표적인 가격대”로 해석
  - q=0.1, q=0.9를 함께 쓰면 가격 범위 후보로도 활용 가능

### 5.8 LightGBM

- 쉬운 설명:
  - 데이터를 여러 조건으로 나누면서 가격을 예측하는 트리 기반 모델
- 예:
  - 호수가 큰 작품인가?
  - 재료가 유화인가?
  - 지지체가 캔버스인가?
  - 이런 조건을 여러 단계로 나눠 학습
- 장점:
  - 변수 조합 효과를 잘 잡음
  - 비선형 관계를 잘 처리
  - 성능이 빠르고 강한 편
- 단점:
  - 선형 모델보다 설명이 어려움
  - 데이터가 부족하거나 편향되면 과적합 가능
- 프로젝트 내 해석:
  - Warm에서는 작가명과 작품 피처의 복잡한 관계를 잡는 후보
  - Cold에서는 작품 구조 정보만으로도 복잡한 패턴이 있는지 확인하는 후보

### 5.9 XGBoost

- 쉬운 설명:
  - LightGBM과 비슷한 트리 기반 고성능 모델
- 장점:
  - 예측 성능이 강한 편
  - 다양한 데이터에서 검증된 모델
- 단점:
  - 학습 시간이 늘 수 있음
  - 설정값 영향을 많이 받을 수 있음
- 프로젝트 내 사용:
  - Track3/Track4 모델 후보 비교에서 사용 또는 후보로 검토
  - Track6 기본 고정 모델군에는 현재 포함하지 않음

### 5.10 CatBoost

- 쉬운 설명:
  - 작가명, 재료명 같은 문자형 범주 변수를 잘 다루는 트리 기반 모델
- 장점:
  - 범주형 변수가 많은 데이터에 강함
  - 작가명, 재료, 지지체 같은 변수에 적합할 수 있음
- 단점:
  - 환경에 따라 설치와 실행 시간이 부담될 수 있음
  - 실험 통제를 위해 Track6 기본 피처 실험에서는 고정 모델군에서 제외한 상태
- 프로젝트 내 사용:
  - 이전 트랙과 최종 모델 후보 비교에서 사용 또는 검토

### 5.11 HistGradientBoosting

- 쉬운 설명:
  - scikit-learn에서 제공하는 트리 기반 부스팅 모델
- 장점:
  - 별도 외부 라이브러리 없이 사용 가능
  - 기본 구조 피처 baseline으로 쓰기 좋음
- 단점:
  - LightGBM/CatBoost만큼 범주형 처리에 특화되지는 않음
- 프로젝트 내 사용:
  - Track6 초기 구조-only baseline에서 후보로 등장

## 6. 모델 출력값 해석 방법

| 출력 종류 | 의미 | 해석 방법 |
|---|---|---|
| `pred_log_price` | 모델이 예측한 로그 가격 | 모델 내부 계산값 |
| `pred_price_krw` | 로그 가격을 원화로 되돌린 예측 가격 | 서비스에서 보여줄 수 있는 예측 가격 |
| `actual_price_krw` | 실제 가격 | 평가용 정답 |
| `APE` | 작품별 비율 오차 | 실제 가격 대비 얼마나 틀렸는지 |

### 예시

- 실제 가격: 1,000,000원
- 예측 가격: 1,300,000원
- 오차:
  - `APE = |1,300,000 - 1,000,000| / 1,000,000`
  - `APE = 0.30`
  - 해석: 30% 틀림

## 7. 주요 평가 지표

| 지표 | 계산식 | 좋고 나쁨 | 쉬운 해석 | 주의점 |
|---|---|---|---|---|
| `R2` | 1 - 모델오차 / 평균모델오차 | 높을수록 좋음 | 평균만 예측하는 것보다 얼마나 잘 설명하는지 | 음수가 나올 수 있음 |
| `APE` | `|예측가격 - 실제가격| / 실제가격` | 낮을수록 좋음 | 작품 1건의 비율 오차 | 개별 작품 오차 |
| `MdAPE` | 작품별 APE의 중앙값 | 낮을수록 좋음 | 대표적으로 몇 % 틀리는지 | 최우선 판단 지표 |
| `p95 APE` | APE의 95번째 백분위 | 낮을수록 좋음 | 큰 오차 위험이 얼마나 큰지 | tail risk 확인용 |
| `MAPE` | 작품별 APE의 평균 | 낮을수록 좋음 | 평균적으로 몇 % 틀리는지 | 고가/이상치 영향 큼 |
| `Within-30` | APE가 0.30 이하인 비율 | 높을수록 좋음 | 실제 가격의 ±30% 안에 들어온 비율 | 실무 감각에 가까움 |
| `Within-50` | APE가 0.50 이하인 비율 | 높을수록 좋음 | 실제 가격의 ±50% 안에 들어온 비율 | 완화된 기준 |
| `RMSE(log)` | 로그 예측오차 제곱평균제곱근 | 낮을수록 좋음 | 로그 가격 공간에서 얼마나 안정적인지 | 원화 오차와 직접 같지는 않음 |

## 8. 지표 우선순위

- 1순위: `MdAPE`
  - 대표 오차를 가장 안정적으로 보여줌
  - 미술품처럼 가격 편차가 큰 데이터에서는 평균보다 중앙값이 더 안정적
- 2순위: `p95 APE`
  - 큰 오차가 얼마나 위험한지 보여줌
  - 서비스에서 신뢰도 경고를 만들 때 중요
- 3순위: `Within-30`, `Within-50`
  - 실무적으로 얼마나 자주 “쓸 만한 범위”에 들어오는지 확인
- 4순위: `R2`
  - 설명력 확인용
  - 특히 선형/헤도닉 모델에서 변수 설명력을 볼 때 유용
- 5순위: `MAPE`, `RMSE(log)`
  - 보조 지표
  - 모델 안정성과 평균 오차 확인에 사용

## 9. R2 해석 방법

| R2 값 | 쉬운 해석 |
|---|---|
| 1에 가까움 | 모델이 가격 차이를 매우 잘 설명 |
| 0 근처 | 평균 가격을 예측하는 것과 큰 차이가 없음 |
| 음수 | 평균만 예측하는 것보다 못함 |

- R2는 “가격을 몇 % 맞췄다”는 뜻이 아님
- R2는 모델이 가격 변동을 얼마나 설명하는지 보는 지표
- 가격 예측 서비스에서는 R2만 보고 모델을 고르면 안 됨
- MdAPE, p95 APE, Within-30과 함께 봐야 함

## 10. p95 APE와 tail risk

- `p95 APE`는 오차가 작은 순서로 정렬했을 때 95% 지점의 오차
- 쉽게 말하면:
  - 대부분의 작품은 이 정도 오차 안에 들어오지만
  - 상위 5% 정도는 더 크게 틀릴 수 있음
- tail risk:
  - 아주 크게 틀리는 위험
  - 단일 예측 가격을 서비스에 보여줄 때 특히 중요

### 예시

- `MdAPE = 0.25`
  - 대표적으로 25% 정도 틀림
- `p95 APE = 2.00`
  - 나쁜 경우에는 실제 가격의 200% 수준까지 틀릴 수 있음
- 해석:
  - 평소에는 괜찮아 보여도, 일부 작품에서 크게 틀리는 위험이 있음

## 11. 가격 범위, coverage, interval width

| 용어 | 의미 | 좋고 나쁨 |
|---|---|---|
| 가격 범위 | 예측 가격 하나가 아니라 하한~상한으로 보여주는 범위 | 너무 넓으면 실무성이 낮음 |
| coverage | 실제 가격이 예측 범위 안에 들어온 비율 | 목표 coverage에 가까울수록 좋음 |
| interval width | 예측 범위의 폭 | 같은 coverage라면 좁을수록 좋음 |

- 예:
  - 예측 가격: 100만 원
  - 예측 범위: 60만 원 ~ 180만 원
  - 실제 가격이 120만 원이면 coverage 성공
- 주의:
  - 범위를 무조건 넓히면 coverage는 좋아짐
  - 하지만 범위가 너무 넓으면 서비스에서 의미가 약해짐
  - 따라서 coverage와 interval width를 같이 봐야 함

## 12. 모델 선택 시 보는 기준

| 판단 항목 | 질문 | 판단 방식 |
|---|---|---|
| 대표 오차 | 보통 얼마나 틀리는가? | MdAPE가 낮은지 확인 |
| 큰 오차 위험 | 아주 크게 틀리는 경우가 줄었는가? | p95 APE 확인 |
| 실무 적중률 | ±30%, ±50% 안에 자주 들어오는가? | Within-30/50 확인 |
| 설명 가능성 | 왜 그런 예측이 나왔는지 설명 가능한가? | 선형/헤도닉, 피처 중요도 확인 |
| 운영 가능성 | 서비스에서 입력 가능한 변수인가? | 출처, 가격, 수집 불가 피처 제외 |
| 재현 가능성 | 같은 데이터/코드로 다시 같은 결과가 나오는가? | 동일 실험 재실행 비교 |

## 13. Warm 모델 해석 기준

- Warm 모델은 작가명을 사용할 수 있음
- 작가명만으로 성능이 좋아질 수 있음
- 따라서 Warm에서 작품 피처 효과를 보려면:
  - 작가명을 넣은 상태에서 작품 피처를 추가
  - 성능이 더 좋아지는지 확인
- 해석 예:
  - `artist_name_ko`만 사용했을 때 MdAPE가 낮음
  - 여기에 `ln_estimated_ho`를 추가했더니 더 낮아짐
  - 결론: 작가 효과 외에도 호수 정보가 추가 설명력을 가짐

## 14. Cold 모델 해석 기준

- Cold 모델은 학습 데이터에 없는 작가를 예측함
- 작가명은 사용할 수 없음
- 주로 사용하는 정보:
  - 호수
  - 크기
  - 재료
  - 지지체
  - 제작연도
  - 운영에서 수집 가능한 작가 메타
- 해석 예:
  - 작가명 없이 `ln_estimated_ho`만으로 어느 정도 예측 가능
  - 재료/지지체를 추가했을 때 MdAPE가 낮아지면 Cold에서도 작품 정보가 도움이 됨
  - p95 APE가 높으면 가격 범위 또는 신뢰도 경고가 필요

## 15. 모델별 장단점 요약

| 모델 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|
| 중앙값 기준 모델 | 단순하고 빠름 | 개인화/작품별 차이 반영 약함 | 최소 기준선 |
| Linear Regression | 설명 쉬움 | 이상치와 복잡한 관계에 약함 | 변수 효과 확인 |
| Hedonic Linear Regression | 가격을 속성별로 설명 가능 | 복잡한 조합 효과 제한 | 보고용, 피처 검증 |
| Ridge | 변수가 많아도 안정적 | 비선형 관계 제한 | 작가명 포함 Warm |
| Lasso | 변수 선택에 도움 | 과도하게 변수를 제거할 수 있음 | 피처 축소 |
| ElasticNet | Ridge와 Lasso 절충 | 설정값 영향 있음 | 피처가 많을 때 |
| Huber | 이상치에 강함 | 복잡한 패턴은 제한 | Warm/Cold 기본 후보 |
| LAD / Quantile | 중앙값 기준 안정성 좋음 | 평균 예측 목적과 다름 | Cold, tail risk 완화 |
| LightGBM | 비선형/조합 효과 강함 | 설명이 어려움, 과적합 주의 | 피처 조합, 최종 후보 |
| XGBoost | 강력한 트리 모델 | 학습/튜닝 부담 | 최종 후보 비교 |
| CatBoost | 범주형 변수에 강함 | 설치/실행 부담 | 작가명/재료 등 범주형 많을 때 |
| HistGradientBoosting | 외부 의존성 적음 | 범주형 특화는 약함 | 빠른 baseline |

## 16. 실험 결과표 읽는 순서

1. Warm과 Cold를 분리해서 본다.
2. 같은 피처셋 안에서 모델을 비교한다.
3. 먼저 `MdAPE`가 낮은 모델을 찾는다.
4. 그 다음 `p95 APE`가 너무 커지지 않았는지 확인한다.
5. `Within-30`, `Within-50`이 좋아졌는지 확인한다.
6. R2는 설명력 참고 지표로 본다.
7. 성능이 좋아도 운영에서 만들 수 없는 피처면 최종 후보에서 제외한다.

## 17. 자주 생기는 오해

| 오해 | 정확한 해석 |
|---|---|
| R2가 높으면 무조건 좋은 모델이다 | 가격 예측에서는 MdAPE와 p95 APE도 함께 봐야 함 |
| MdAPE가 낮으면 모든 작품을 잘 맞춘다 | 대표 오차가 낮다는 뜻이고, 일부 큰 오차는 p95로 확인해야 함 |
| Cold에서도 작가명을 쓰면 된다 | 학습에 없는 작가이므로 작가명 효과를 쓸 수 없음 |
| 가격 범위를 넓히면 좋은 모델이다 | coverage는 좋아지지만 범위가 너무 넓으면 서비스성이 낮음 |
| 피처를 많이 넣으면 무조건 좋아진다 | 중복 피처와 운영 불가 피처는 오히려 해석과 재현성을 해칠 수 있음 |
| LightGBM이 항상 선형 모델보다 좋다 | 데이터 크기, 피처 품질, Warm/Cold 상황에 따라 다름 |

## 18. 현재 프로젝트에서의 실무 판단 방식

- 피처 효과 실험:
  - 같은 모델군을 고정하고 피처만 바꿈
  - Warm: `Huber / Linear Regression / Ridge`
  - Cold: `Huber / Quantile-LAD / LightGBM`
- 모델 비교 실험:
  - 피처셋을 고정하고 모델만 바꿈
  - 모델 차이와 피처 차이를 섞지 않기 위함
- 최종 판단:
  - Warm 후보와 Cold 후보를 따로 고름
  - 운영 입력 가능한 피처만 남김
  - 큰 오차 위험이 큰 구간은 신뢰도 경고 또는 가격 범위 정책으로 보완

## 19. 한 줄 요약

- 선형/헤도닉 모델은 “왜 그런 가격이 나왔는지 설명하기 좋은 모델”
- Huber와 Quantile-LAD는 “가격 이상치에 덜 흔들리는 안정형 모델”
- LightGBM, XGBoost, CatBoost는 “복잡한 패턴을 잡는 성능형 모델”
- 평가는 `MdAPE`를 먼저 보고, `p95 APE`로 큰 오차 위험을 확인하고, `Within-30/50`으로 실무 적중률을 확인한다.
