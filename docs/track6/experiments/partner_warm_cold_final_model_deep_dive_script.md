- 대상 슬라이드: `partner_warm_cold_final_model_deep_dive_presentation.md`

- 권장 시간: 발표 280~340분 + 질의 30~45분
- 발표 원칙: 실험 ID보다 계산 흐름, 학습/사용 단계, 피처의 역할을 먼저 설명한다.

## 1. 리포트 검토 결과

- 예상 시간: 4분

먼저 이 발표 자료를 만들기 전에 기준 리포트의 핵심 수치가 재현 가능한지 확인했습니다. Warm의 fixed test 성능은 `warm_model_policy_wmin8.json`에 기록된 값과 일치합니다. Warm-lite 최신 채택 모델은 `PP-WLITE-Q3` 산출 CSV에서 직접 재계산해 1,947행 기준 MdAPE `0.107246`, MAPE `0.275773`, p95 `0.852026`, RMSE log `0.423003`이 확인됐습니다. Cold는 `cold_prediction_v0.3` 재현 파일에서 기록 지표와 재계산 지표의 최대 차이가 `1.110e-16`로 확인됐습니다.

다만 리포트에는 Warm-lite의 과거 저이력 경로 검증값과 최신 “Quantile 예측 + 잔차 보정” 채택값이 함께 있습니다. 과거 PP-WCUT4 RMSE log `0.447586`은 경로 분리 근거로는 유효하지만 현재 채택 모델의 성능값은 아닙니다. 그래서 이 발표 자료에서는 최신 채택 모델 성능표에는 `0.423003`만 사용하고, 과거 값은 경계 판단 근거에서만 다루겠습니다.

오늘 설명에서 가장 중요한 원칙은 API 버전과 내부 artifact 버전명을 분리해서 읽는 것입니다. 현재 서비스 라우팅은 `0.1v API` 기준입니다. `cold_prediction_v0.2_operational` 같은 이름은 Cold 내부 번들명이지 API v0.2라는 뜻이 아닙니다.

또 하나 구분해야 할 점이 있습니다. 성능표와 검증표의 숫자는 근거 artifact에서 확인한 값입니다. 뒤쪽의 계산 예시에 나오는 `18.300`, `17.800` 같은 숫자는 산식을 눈으로 따라가기 위한 가상 입력값입니다. 실제 평가 행의 결과나 채택 근거 수치로 읽으면 안 됩니다.

## 2. 오늘 설명할 질문

- 예상 시간: 4분

오늘 발표는 모델 이름을 암기하는 방식으로 진행하지 않겠습니다. 대신 실제 작품이 들어왔을 때 어떤 조건으로 어느 경로에 배정되고, 그 경로 안에서 어떤 피처와 산식으로 최종 가격이 만들어지는지를 설명하겠습니다.

첫 번째 질문은 라우팅입니다. 작가가 확실한가, 그리고 같은 작가의 가격 이력이 몇 건인가가 핵심입니다. 두 번째 질문은 학습과 사용 단계의 차이입니다. 학습 때는 실제 가격이 있으므로 모델과 보정값을 만들 수 있지만, 사용 때는 실제 가격이 없으므로 동결된 모델만 적용합니다.

세 번째 질문은 왜 Warm과 Warm-lite를 나누느냐입니다. 이 부분은 실험 근거가 있어야 설명력이 생깁니다. 1~4건을 Cold로 보내면 크게 나빠지고, 1~4건 전체를 Warm 계열 대체 후보로 통일해도 현재 근거로는 Warm-lite가 더 낫습니다. 반대로 5건 이상을 Warm-lite로 보내면 WMIN8 Warm이 더 낫습니다.

마지막 질문은 Cold입니다. Cold는 같은 작가 가격 기준을 만들 수 없기 때문에 작품 피처, 작가 메타, 검색 문맥, 불확실성 방어가 필요합니다.

## 3. 전체 라우팅 구조

- 예상 시간: 6분

작품이 들어오면 바로 하나의 모델에 넣지 않습니다. 먼저 라우팅을 합니다. 라우팅에서 보는 값은 두 가지입니다. 첫 번째는 작가매칭신뢰도점수입니다. 입력 작가가 학습 데이터의 특정 작가와 같은 사람인지 판단합니다. 두 번째는 같은작가_사용가능가격이력수입니다. 같은 작가로 확정됐고 가격이 있으며 예측에 사용할 수 있는 과거 작품 수입니다.

작가매칭신뢰도점수가 `0.80` 이상이고 가격 이력이 `5건 이상`이면 Warm입니다. 이 경우에는 같은 작가의 과거 가격을 기준으로 삼을 만큼 데이터가 충분합니다. 같은 점수가 `0.80` 이상이지만 가격 이력이 `1~4건`이면 Warm-lite입니다. 이 구간은 같은 작가 가격 신호가 있지만, Warm 본체처럼 정밀 비교군과 위험도 라우터를 안정적으로 운영하기에는 표본이 적습니다.

작가 이력이 `0건`이거나 작가 매칭이 불확실하거나 동명이인 위험이 있으면 Cold 또는 검수대기입니다. 이때는 같은 작가 가격을 기준으로 쓰는 것이 위험하므로, 작품 자체 정보와 작가 메타, 검색 문맥을 이용합니다.

## 3.1 작가매칭신뢰도점수 계산 흐름

- 예상 시간: 6분

라우팅에서 가장 먼저 보는 값이 `작가매칭신뢰도점수`입니다. 이 점수는 입력 작가가 학습 작가 사전의 특정 `artist_key`와 같은 사람인지 0에서 1 사이로 표현한 값입니다. 1에 가까울수록 같은 작가일 가능성이 높고, 0에 가까울수록 같은 작가로 볼 근거가 약합니다.

계산은 먼저 입력값을 정리하는 것에서 시작합니다. 사용자가 `artist_key`나 `selected_artist_key`를 직접 보냈으면 그 고유키를 학습 작가 사전에서 바로 찾습니다. 이 경우는 가장 강한 매칭 근거입니다. artist_key가 없으면 한글명과 영문명을 정규화합니다. 현재 0.1v 구현은 소문자 변환, 공백 제거, 문장부호 제거를 적용한 뒤, 정규화된 입력 이름을 학습 작가 alias 사전과 비교합니다.

그 다음 학습 작가 사전에서 후보를 찾습니다. 정규화 alias가 완전히 일치하는 후보가 있으면 고신뢰 후보가 됩니다. 완전 일치가 없으면 구현상 `alias_normalized LIKE` 조건으로 부분 이름 후보를 봅니다. 후보를 찾은 뒤에는 바로 Warm으로 보내지 않고 검증을 합니다. 후보가 한 명인지, 생년이 충돌하지 않는지, 같은 이름의 다른 artist_key가 있는지 확인합니다. 국적이나 외부 작가 식별자는 정책상 중요한 보조정보지만, 현재 0.1v 점수 보정에는 직접 쓰지 않습니다.

이 과정을 거쳐 `작가매칭신뢰도점수`와 `동명이인위험점수`가 함께 나옵니다. 중요한 점은 이름이 같다는 사실만으로 충분하지 않다는 것입니다. 이름이 같아도 생년이 다르거나 같은 이름 후보가 여러 명이면 잘못된 작가의 가격 이력을 쓸 수 있습니다. 그래서 동명이인 위험은 점수를 낮추거나 검수대기로 보내는 역할을 합니다.

## 3.2 작가매칭신뢰도점수 구현과 예시

- 예상 시간: 7분

여기서는 현재 0.1v API가 실제로 작가 매칭 점수를 어떻게 계산하는지 기준으로 설명합니다. 핵심은 하위점수 여러 개를 합산하는 방식이 아니라, `직접 key`, `alias 완전 일치`, `부분 이름 후보`, `생년 보정`, `동명이인 위험`을 순서대로 적용한다는 점입니다.

현재 0.1v 구현은 더 직접적인 상태 기반 계산입니다. 사용자가 `artist_key` 또는 `selected_artist_key`를 직접 보내고 그 값이 학습 작가 사전에 있으면 작가매칭신뢰도점수는 `1.00`이고 동명이인위험점수는 `0.00`입니다. 이 경우는 작가가 이미 고유키로 지정된 것이므로 이름 기반 매칭보다 강한 근거로 봅니다.

artist_key가 없으면 입력 이름을 정규화해서 `artist_aliases`에서 후보를 찾습니다. 정규화 alias가 완전히 일치하면 기본 점수는 `1.00`입니다. 입력 생년과 후보 생년이 모두 있고 서로 같으면 `+0.05` 보정을 하지만 최종 점수는 최대 `1.00`입니다. 생년이 서로 다르면 `-0.15`를 적용합니다.

완전 일치 후보가 없고 부분 이름 후보만 있으면 기본 점수는 `0.78`입니다. 여기에 생년이 일치하면 `+0.05`가 붙어서 `0.83`이 됩니다. 그래서 부분 이름 후보라도 생년이 맞으면 0.80 기준을 넘을 수 있습니다. 반대로 생년 정보가 없으면 `0.78` 그대로라서 0.80 미만이고, Warm/Warm-lite가 아니라 Cold 또는 검수대기입니다.

동명이인위험점수는 별도로 계산합니다. 후보 artist_key가 여러 명이면 후보 수에 따라 위험도가 올라가고, 사전에서 `is_homonym`으로 표시된 작가도 위험도가 올라갑니다. 산식은 `clip((후보 수 - 1)*0.35 + is_homonym*0.25, 0, 1)`입니다. 이 값이 `0.60` 이상이면 점수와 별개로 검수대기입니다.

마지막으로 라우팅 기준을 다시 연결합니다. `작가매칭신뢰도점수 >= 0.80`만으로 Warm이 되는 것이 아닙니다. 점수 통과 후 동명이인위험점수가 낮아야 하고, 같은 작가의 사용 가능한 가격 이력이 5건 이상이면 Warm, 1~4건이면 Warm-lite, 0건이면 Cold 또는 검수대기입니다. 향후에는 API 응답에 `이름이 완전 일치했는지`, `생년 보정이 적용됐는지`, `후보 수가 몇 명이었는지` 같은 분해 근거를 같이 노출하면 설명력이 더 좋아집니다.

## 4. 성능 기준 요약

- 예상 시간: 6분

이 표는 세 경로의 성능 기준을 정리한 것입니다. Warm은 fixed test 607행 기준 MdAPE `0.104326`, MAPE `0.235814`, p95 `0.739416`입니다. Warm-lite는 최신 “Quantile 예측 + 잔차 보정” 모델 기준으로 1,947행에서 MdAPE `0.107246`, MAPE `0.275773`, p95 `0.852026`입니다. Cold는 fixed test 3,099행 기준 MdAPE `0.409820`, MAPE `0.849260`, p95 `2.346465`입니다.

여기서 중요한 점은 세 숫자를 단순히 모델 순위로 읽으면 안 된다는 것입니다. Warm과 Warm-lite는 같은 작가의 실제 가격 이력을 사용합니다. Cold는 그 신호를 직접 사용할 수 없습니다. 따라서 Cold가 더 어렵고 오차가 큰 것은 구조적으로 자연스럽습니다.

`n`도 학습 작품 수가 아닙니다. 성능 지표를 계산한 평가 행 수입니다. Warm과 Cold는 fixed test 행 수이고, Warm-lite는 실존 저이력 작가 leave-one-out 평가를 3회 반복한 행 수입니다.

## 5. 지표를 읽는 방법

- 예상 시간: 5분

MdAPE는 작품별 절대 비율 오차의 중앙값입니다. 일반적인 작품에서 어느 정도 틀리는지를 보여줍니다. MAPE는 평균 오차입니다. 전체 평균을 보여주지만 큰 오차 작품의 영향을 더 많이 받습니다. p95 APE는 상위 5% 큰 오차 경계입니다. 운영에서는 이 값이 중요합니다. 평균이 좋아도 p95가 크면 일부 작품에서 크게 빗나갈 수 있습니다.

모델 내부 계산은 로그가격에서 합니다. 가격은 수십만 원부터 수억 원까지 분포가 넓기 때문에 원화 가격을 그대로 모델링하면 고가 작품이 과도하게 영향을 줍니다. 로그가격으로 계산하면 비율 관점에서 더 안정적으로 학습하고 보정할 수 있습니다.

최종적으로는 `exp()`를 사용해 로그가격을 원화 가격으로 되돌립니다. 실제 성능 지표인 MdAPE, MAPE, p95는 원화 가격으로 환산한 뒤 실제 원화 가격과 비교해 계산합니다.

## 6. 학습 단계와 사용 단계

- 예상 시간: 7분

이 슬라이드는 오늘 발표에서 가장 중요한 개념 중 하나입니다. 학습 단계와 사용 단계가 섞이면 모델이 실제 가격을 사용해서 예측하는 것처럼 오해할 수 있습니다. 그렇지 않습니다.

학습 단계에서는 실제 가격이 있습니다. 그래서 실제 로그가격을 target으로 모델을 학습하고, 예측값과 실제값의 차이인 잔차를 계산할 수 있습니다. Huber 잔차 보정, CatBoost 잔차 보정, Cold 구간별 보정값 같은 것들은 모두 학습 또는 검증 단계에서 실제 가격을 사용해 만들어집니다.

사용 단계에서는 새 작품의 실제 가격을 모릅니다. 따라서 실제 가격은 입력으로 들어가지 않습니다. 사용 단계에서는 동결된 모델, 동결된 보정표, 동결된 조회표, 동결된 임계값만 사용합니다. 입력 작품의 크기, 매체, 지지체, 작가 매칭, 이력 통계, 검색 문맥 같은 피처만으로 최종 로그가격을 계산합니다.

## 7. 공통 피처 그룹

- 예상 시간: 6분

세 경로가 모두 같은 피처를 같은 방식으로 쓰는 것은 아닙니다. Warm에서는 같은 작가 가격 이력이 핵심입니다. Warm-lite도 작가 가격 이력을 핵심으로 쓰지만 표본이 1~4건뿐이기 때문에 q25/q75/IQR 같은 가격 분포 통계와 면적단가 통계를 조심스럽게 씁니다. Cold는 같은 작가 가격 이력을 직접 쓰지 못하므로 작품 피처와 작가 메타, 검색 문맥을 더 많이 사용합니다.

작품 크기는 세 경로 모두 중요합니다. 가로, 세로, 깊이, 면적, 로그면적, 비율 같은 값이 가격대에 직접 영향을 줍니다. 매체와 지지체도 중요합니다. oil/canvas와 acrylic/paper는 같은 크기라도 가격 구조가 다를 수 있습니다.

검색 문맥은 Cold에서 특히 중요합니다. 같은 작가 가격 이력이 없을 때 작가가 미술 문맥에서 어떻게 등장하는지, 갤러리나 미술관 문맥이 있는지, 시장 문맥이 있는지가 가격 추정의 보조 신호가 됩니다.

---

## 8. Warm/Warm-lite 분리 근거

- 예상 시간: 10분

Warm과 Warm-lite를 왜 나누는지는 이 모델 설명의 핵심입니다. 먼저 1~4건 이력을 Cold로 보내면 안 됩니다. PP-WCUT4에서 같은 저이력 작품을 Warm-lite로 처리하면 MdAPE `0.1092`이고, Cold로 보내면 `0.5429`입니다. 중앙 오차 기준으로 약 4.97배 차이가 납니다.

그 다음 질문은 1~4건을 Warm으로 통일할 수 있느냐입니다. PP-WMIN9C와 PP-WMIN9E에서 WMIN8 계열 대체 후보와 비교했습니다. 전체 1~4건 기준 Warm-lite는 `0.1092/0.2866/0.8765`이고 Warm 계열 대체 후보는 `0.1291/0.2932/0.9163`입니다. 전 지표에서 Warm-lite가 낫습니다.

물론 WMIN8 전체 구조를 저이력 hold-out마다 완전히 재학습한 것은 아닙니다. PP-WMIN11에서는 이미 학습된 WMIN8/PPV8을 그대로 쓰지 않고 재학습 가능한 축만 다시 만들어 비교했습니다. 그 결과 부분 재학습 라우팅 후보는 `0.1480/0.2931/0.8716`입니다. p95는 조금 낮지만 MdAPE와 MAPE가 나빠서 Warm-lite 대체 근거는 부족합니다.

마지막으로 5건 이상에는 Warm-lite를 쓰면 안 됩니다. PP-WMIN9D에서 5건 이상 fixed test에 Warm-lite를 강제 적용하면 WMIN8보다 전 지표가 나쁩니다. 그래서 현재 경계는 `1~4건 Warm-lite`, `5건 이상 Warm`입니다.

## 9. Warm 모델 목적

- 예상 시간: 5분

Warm은 작가 매칭이 확실하고 같은 작가 가격 이력이 5건 이상일 때 적용됩니다. 이 구간에서는 작가 본인의 과거 가격대가 가장 강한 가격 신호입니다.

Warm의 목적은 가격을 완전히 새로 맞히는 것이 아닙니다. 먼저 같은 작가 유사작품 기준가격을 만듭니다. 그리고 기준가격이 반복적으로 조금 높거나 낮게 잡히는 패턴을 Huber 잔차 보정으로 보정합니다. 마지막으로 작품단위위험도가 임계값 이상이고 보수 후보가 기본 후보보다 최소 `0.005 log` 낮은 경우에만 보수 대안으로 바꿉니다.

즉 Warm은 “작가 가격 이력을 중심으로 기준가격을 만들고, 작은 보정과 조건부 방어를 더하는 경로”입니다. 기준가격이 핵심이고, 보정은 기준가격을 뒤집는 것이 아니라 안정화하는 역할입니다.

## 10. Warm 학습 단계 순서

- 예상 시간: 10분

Warm 학습 단계에서는 실제 가격이 있는 과거 Warm 데이터를 사용합니다. 먼저 같은 작가 유사작품 찾기 단계를 검증합니다. 가장 좁은 비교군부터 넓은 비교군까지 어떤 조건이 안정적인지 확인합니다.

다음으로 보조 Warm 예측축을 만듭니다. 여기서 중요한 점은 보조축이 하나가 아니라 두 개라는 것입니다. 첫 번째는 큰오차방어 Warm 예측값이고, 두 번째는 버킷순차보정 Warm 예측값입니다. 두 축은 역할이 다릅니다.

큰오차방어 축은 여러 Warm 후보 예측값을 다시 입력으로 쓰는 meta-model입니다. 학습 단계에서는 같은 작품에 대해 여러 후보 로그가격을 모읍니다. 예를 들어 기본 Huber 계열 후보, 순차 보정 후보, 블렌드 후보, 유사작품 fallback 후보처럼 서로 다른 방식으로 만든 Warm 후보들이 있습니다. 이 후보들의 평균, 표준편차, 최댓값과 최솟값의 범위, 기준 후보와 다른 후보의 차이, 불확실성 폭을 피처로 만듭니다. 그 다음 Huber meta-model이 실제 로그가격을 target으로 방어형 중심 로그가격을 학습합니다. Huber를 쓰는 이유는 일부 후보가 크게 빗나가도 중심선이 그 후보에 과도하게 끌려가지 않게 하기 위해서입니다. 마지막으로 이 값이 하위 후보들의 합리적인 범위를 너무 벗어나지 않도록 clip을 적용합니다.

버킷순차보정 축은 작품 조건을 더 구조적으로 반영하는 보조축입니다. 먼저 작품 크기, 면적, 로그면적, 비율, 형태, 매체, 지지체, 작가 식별 피처를 만듭니다. 그 다음 이 값들을 size_bucket, shape_bucket, support_size_bucket, medium_shape_bucket 같은 구간 피처로 바꿉니다. bucket은 작품을 비슷한 크기와 형태, 재료 조건끼리 묶기 위한 장치입니다. 이후 CatBoost Quantile 모델이 낮은값(q10), 중앙값(q50), 높은값(q90)을 만들고, 높은값에서 낮은값을 빼서 Quantile 예측의 불확실성 폭을 만듭니다. 이 값은 “이 조건의 작품 가격 범위가 얼마나 넓게 예상되는가”를 보여줍니다. 다음으로 Huber 중심선이 중심 로그가격을 학습하고, 마지막으로 CatBoost 잔차 모델이 그 중심선에서 남은 오차를 학습합니다. 그래서 버킷순차보정의 출력은 `Huber 중심선 + CatBoost 잔차보정`입니다.

이 두 축을 만든 뒤에는 보조안정 가중식을 동결합니다. 현재 구조에서는 큰오차방어 축을 75%, 버킷순차보정 축을 25% 반영합니다. 이 보조안정 값은 최종 가격을 직접 결정하는 값이 아니라, 뒤에서 기본 후보와 대안 후보를 만들 때 같은 작가 유사작품 기준가격 옆에 섞는 안정화 기준입니다.

그 다음 Huber 잔차 보정을 학습합니다. 이때 target은 실제 로그가격에서 후보 기준 로그가격을 뺀 잔차입니다. 마지막으로 위험도 조건부 라우터를 검증하고 `위험도임계값`과 `대안교체최소차이`를 동결합니다.

여기서 `위험도임계값`과 `대안교체최소차이`는 임의 상수가 아닙니다. PP-WMIN8에서 validation 데이터로 라우팅 후보를 비교해 선택한 값입니다. `위험도임계값 = 0.2534165869`는 validation에서 계산한 `risk_score`의 q50, 즉 중앙값입니다. `risk_score`는 Quantile 예측의 불확실성 폭, 후보 예측값 간 분산, 현재 기준가와 안정 기준가의 차이, low confidence 여부, very high price 여부를 합쳐 만든 작품단위 위험도입니다. `대안교체최소차이 = 0.005 log`는 대안 후보가 기본 후보보다 최소 `0.005 log` 낮을 때만 대안으로 바꾸는 조건입니다.

최종 선택된 후보명은 `min1_route_w850_risk_q50_altlower_gap005`입니다. 이름 자체가 의미를 담고 있습니다. `w850`은 대안 후보가 유사작품 기준가격을 85% 반영한다는 뜻이고, `risk_q50`은 위험도 중앙값 이상에서만 검토한다는 뜻이며, `altlower_gap005`는 대안 후보가 더 낮고 그 차이가 최소 0.005 log 이상이어야 한다는 뜻입니다.

발표할 때는 학습 단계의 이유를 아래처럼 짚으면 됩니다.

* 이유: Warm 학습 데이터를 5건 이상 이력 조건으로 제한하는 것은, 같은 작가 가격 이력이 충분할 때만 Warm의 정밀 비교군과 위험도 라우터가 안정적으로 작동하기 때문입니다.
* 이유: 유사작품 찾기 단계를 검증하는 것은, 최종 가격의 출발점이 “같은 작가의 어떤 과거 작품을 기준으로 삼느냐”에서 결정되기 때문입니다.
* 이유: 좁은 비교군에서 넓은 비교군으로 fallback하는 것은, 가장 비슷한 작품을 우선 쓰되 표본이 없어서 계산이 끊기는 상황을 막기 위해서입니다.
* 이유: 큰오차방어 Warm 예측값을 따로 학습하는 것은, 여러 Warm 후보 중 일부가 크게 빗나가도 후보들의 중심을 방어적으로 잡기 위해서입니다.
* 이유: 버킷순차보정 Warm 예측값을 따로 학습하는 것은, 같은 작가 이력만으로 놓칠 수 있는 크기, 형태, 매체, 지지체 조합의 가격 패턴을 보조축으로 반영하기 위해서입니다.
* 이유: 보조안정 가중식을 동결하는 것은, 큰오차방어 축과 버킷순차보정 축을 매번 새로 판단하지 않고 검증에서 선택된 비율로 일관되게 섞기 위해서입니다.
* 이유: Huber 잔차 보정을 학습하는 것은, 기준가격이 반복적으로 조금 높거나 낮게 잡히는 패턴만 작은 폭으로 보정하기 위해서입니다.
* 이유: 위험도 라우터를 검증하는 것은, 모든 작품을 보수적으로 낮추지 않고 위험도가 높은 작품에서만 대안 후보를 검토하기 위해서입니다.
* 이유: 위험도임계값과 대안교체최소차이를 동결하는 것은, 운영 시점에 임의 판단을 하지 않고 validation에서 검증된 조건으로만 기본 후보와 대안 후보를 선택하기 위해서입니다.

## 11. Warm 사용 단계 순서

- 예상 시간: 10분

사용 단계에서는 새 작품의 실제 가격을 모릅니다. 입력으로 들어오는 것은 작가키, 작가 이력, 작품 크기, 매체, 지지체입니다. 여기서 새로 학습하는 것은 없습니다. 학습 단계에서 동결해 둔 비교군 규칙, 보조 예측축, Huber 잔차 모델, 라우터 조건을 순서대로 적용합니다.

첫 번째 단계는 같은 작가 유사작품 기준가격 생성입니다. 같은 작가 안에서 대상 작품과 가장 비슷한 과거 작품을 먼저 찾습니다. 1순위는 같은 작가 + 같은 재료/지지체 + 같은 크기입니다. 없으면 같은 작가 + 같은 크기를 봅니다. 그래도 없으면 같은 작가 전체 이력을 봅니다. 검증 때는 자기 작품을 비교군에서 제외하고, 제외 후 0건이면 다음 단계로 내려갑니다.

두 번째 단계는 보조안정 Warm 예측값 계산입니다. 이 값은 새로 학습하는 것이 아닙니다. 이미 동결된 큰오차방어 Warm 예측축과 버킷순차보정 Warm 예측축을 새 작품 피처에 적용합니다. 그 다음 큰오차방어 75%, 버킷순차보정 25%로 섞습니다. 이 값은 유사작품 기준가격이 소표본 때문에 흔들릴 때 완충하는 보조 기준입니다.

세 번째 단계는 기본 후보와 대안 후보 생성입니다. 기본 후보는 유사작품 기준가격 70%, 보조안정 30%입니다. 이 70대 30 구조는 WMIN4 기본 후보로 채택된 기준입니다. 대안 후보는 유사작품 기준가격 85%, 보조안정 15%입니다. 85% 후보는 WMIN7에서 여러 가중치를 비교한 뒤 WMIN8 라우터에서 선택된 대안입니다. 대안 후보는 같은 작가 유사작품 신호를 더 강하게 반영하는 후보입니다.

네 번째 단계는 각 후보에 Huber 잔차 보정을 적용하는 것입니다. 여기서 실제 잔차를 계산하는 것이 아닙니다. 새 작품의 실제 가격은 모르기 때문입니다. 동결된 Huber 잔차 모델이 후보별 예상 잔차를 계산하고, 그 보정값은 `0.50 * clip(잔차예측, -0.05, +0.05)`로 계산됩니다. 즉 잔차예측을 먼저 ±0.05 log로 제한하고 그 절반만 반영하므로, 실제 후보별 로그가격 보정폭은 최대 ±0.025입니다. 이 설정은 HCOEF3 반복 검증에서 통과한 `hcoef2_size_reliability_cap005_s050` 설정입니다.

다섯 번째 단계는 작품단위 위험도 계산입니다. Quantile 예측의 불확실성 폭, 후보 예측값 간 분산, 기준가격과 보조안정값의 차이, 신뢰도 tier, 가격대 같은 피처를 사용합니다. 이 값이 높을수록 해당 작품은 기본 후보만 믿기에는 흔들릴 위험이 크다고 봅니다.

마지막 단계는 위험도 조건부 라우터입니다. 작품단위위험도가 `위험도임계값(0.2534165869)` 이상이고, 대안 후보가 기본 후보보다 `대안교체최소차이(0.005 log)` 이상 낮으면 대안 후보를 선택합니다. 두 조건 중 하나라도 실패하면 기본 후보를 유지합니다. 이렇게 선택된 최종 Warm 로그가격에 `exp()`를 적용해 원화 가격으로 변환합니다.

## 12. Warm 피처와 사용처

- 예상 시간: 9분

이 슬라이드는 Warm에서 피처가 어디에 쓰이는지 한 번에 정리하는 장입니다. 중요한 점은 Warm이 단순히 “작가 이력 하나를 넣으면 가격이 나오는 모델”이 아니라는 것입니다. 먼저 원천 입력이 있고, 그 입력으로 비교군 통계와 보조 예측축을 만들고, 그 다음 기본 후보와 대안 후보를 만든 뒤, 잔차 보정과 위험도 라우터를 거쳐 최종 가격이 나옵니다.

라우팅 단계에서는 작가매칭신뢰도점수와 같은작가_사용가능가격이력수가 필요합니다. 이 두 값은 Warm으로 들어갈 수 있는지 판단합니다. 현재 0.1v 기준에서는 작가매칭신뢰도점수가 `0.80` 이상이고, 같은 작가의 사용 가능한 가격 이력이 `5건 이상`이어야 Warm입니다.

Warm 안으로 들어온 뒤에는 artist_key, 재료/지지체, 크기 구간으로 같은 작가 유사작품 비교군을 찾습니다. 여기서 만든 비교군 로그가격 중앙값, q25, q75, IQR, 표본 수가 기준가격의 핵심 피처가 됩니다.

Warm은 네 가지 기준으로 설명하면 이해가 쉽습니다. 첫째, 유사작품을 묶는 기준입니다. 같은 작가 안에서 재료/지지체와 크기 구간이 가까운 과거 작품부터 찾습니다. 둘째, 기준가 생성 기준입니다. 선택된 비교군의 로그가격 중앙값과 분산 통계에 보조안정 예측값을 섞어 기본 후보와 대안 후보를 만듭니다. 셋째, 보정 기준입니다. Huber 잔차 모델이 후보별 남은 오차를 예측하지만 최대 ±0.025 log만 반영합니다. 넷째, 최종 선택 기준입니다. 작품단위위험도가 위험도임계값 이상이고 대안 후보가 기본 후보보다 대안교체최소차이 이상 낮을 때만 보수 후보로 바꿉니다.

그 다음 보조안정 단계에서는 큰오차방어 Warm 예측값과 버킷순차보정 Warm 예측값을 씁니다. 이 값은 비교군 기준가격이 표본 수 때문에 흔들릴 때 완충 역할을 합니다. 잔차 보정 단계에서는 후보 기준가, 로그면적, 비교군 표본 수, 후보 간 차이, 수축 prior 같은 값이 들어갑니다.

마지막으로 위험도 라우터에는 Quantile 예측의 불확실성 폭, 후보 예측값 간 분산, 기준가격과 보조안정값의 차이, 신뢰도 tier, 가격대가 들어갑니다. 이 피처들은 가격을 직접 새로 맞히는 것보다, 기본 후보를 유지할지 보수 후보로 바꿀지 판단하는 데 쓰입니다. 사용 단계에서는 실제 가격이 입력되지 않는다는 점도 여기서 강조해야 합니다.

## 13. Warm 유사작품 비교군

- 예상 시간: 9분

Warm의 기준가격은 같은 작가 유사작품 비교군에서 출발합니다. 여기서 먼저 강조할 것은 Warm 대상 자체입니다. 작가 매칭 신뢰도가 충분하고 같은 작가 이력이 5건 이상이어야 이 단계에 들어옵니다.

유사작품 찾기는 세 단계입니다. 1순위는 같은 작가, 같은 재료/지지체, 같은 크기 구간입니다. 이 조건에서 비교군이 있으면 가장 가까운 비교군이므로 바로 사용합니다. 없으면 2순위로 내려가서 같은 작가와 같은 크기 구간을 봅니다. 그래도 없으면 3순위로 작가 전체 이력을 봅니다.

비교군 선택은 섞는 방식이 아닙니다. 1순위에 1건 이상 있으면 1순위를 사용하고, 2순위와 3순위까지 섞어 평균내지 않습니다. 1순위가 없을 때만 2순위로 내려가고, 2순위도 없을 때 3순위로 내려갑니다. 이 기준 때문에 “가까운 비교군의 직접성”과 “비교군이 없을 때의 fallback”이 동시에 유지됩니다.

여기서 `min1`은 오해하기 쉽습니다. `min1`은 Warm 진입 조건을 1건으로 낮춘다는 뜻이 아닙니다. Warm 진입은 여전히 5건 이상입니다. `min1`은 Warm으로 들어온 작가 안에서 더 좁은 비교군, 예를 들어 같은 작가 + 같은 재료 + 같은 크기 조건이 1건만 있어도 그 비교군을 인정한다는 뜻입니다.

왜 이렇게 하느냐면, 가까운 조건의 1건은 때로 넓은 작가 전체 통계보다 더 직접적인 가격 신호일 수 있기 때문입니다. 단, 학습과 검증에서는 자기 가격 누수를 막아야 합니다. 평가 대상 작품이 자기 비교군에 들어가면 성능이 실제보다 좋게 보입니다. 그래서 자기 fold를 제외하고 비교군을 만들고, 제외 후 0건이면 다음 단계로 fallback합니다.

예시로 작가 전체 이력이 18건이고, 같은 재료/지지체와 같은 크기 구간에서 3건이 발견되었다고 하겠습니다. 그러면 1순위 비교군을 사용하고, 그 3건의 로그가격 중앙값이 `18.300`이면 같은작가_유사작품기준로그가격은 `18.300`이 됩니다.

## 14. Warm 보조안정 예측값

- 예상 시간: 10분

보조안정 Warm 예측값은 비교군 기준가격 옆에 붙는 안정화 축입니다. 왜 필요하냐면, 비교군 기준가격은 같은 작가의 직접 가격 신호라서 강하지만, 가까운 비교군 표본이 1건이나 2건이면 특정 작품 가격에 크게 흔들릴 수 있습니다. 그래서 Warm은 비교군 기준가격만 보지 않고, 별도로 만든 보조 예측값을 일부 섞습니다.

보조안정값은 두 축의 가중 평균입니다. 큰오차방어 Warm 예측값을 75%, 버킷순차보정 Warm 예측값을 25% 반영합니다. 큰오차방어 축은 여러 Warm 후보 예측값을 다시 입력으로 쓰는 Huber meta-model입니다. 후보 평균, 후보 표준편차, 후보 범위, 기준 후보와의 차이, 불확실성 폭 같은 값이 들어갑니다. 목적은 특정 하위 후보 하나가 크게 빗나갈 때 중심을 안정화하는 것입니다.

버킷순차보정 축은 작품 조건을 더 구조적으로 반영합니다. 작품 크기, 형태, 매체, 지지체를 bucket으로 만들고, CatBoost Quantile, Huber 중심선, CatBoost 잔차 보정을 순서대로 적용합니다.

중요한 점은 보조안정값이 최종 가격을 혼자 결정하지 않는다는 것입니다. 이 값은 뒤에서 기본 후보와 대안 후보를 만들 때 비교군 기준가격 옆에 일부 섞입니다. 기본 후보는 유사작품 기준가격 70%, 보조안정 30%이고, 대안 후보는 유사작품 기준가격 85%, 보조안정 15%입니다. 즉 Warm의 중심은 여전히 같은 작가 유사작품 기준가격입니다.

## 15. 버킷순차보정 Warm 예측값

- 예상 시간: 10분

버킷순차보정은 단순한 고정 산식 하나가 아닙니다. 먼저 작품의 크기, 면적, 로그면적, 비율, 깊이 여부, 매체, 지지체, 작가 식별 피처를 만듭니다. 그 다음 네 가지 bucket 피처를 만듭니다. size_bucket, shape_bucket, support_size_bucket, medium_shape_bucket입니다.

여기서 bucket이 4개이고 처리 단계가 3개라는 점을 구분해야 합니다. 네 가지 bucket은 생성되는 피처의 종류입니다. 처리 단계 3개는 이 bucket 피처를 사용하는 모델 흐름입니다.

첫 번째 처리 단계는 CatBoost Quantile입니다. 작품 피처와 네 가지 bucket 피처를 넣어 낮은값(q10), 중앙값(q50), 높은값(q90)을 얻고, 높은값(q90)에서 낮은값(q10)을 빼 Quantile 예측의 불확실성 폭을 만듭니다. 이 값은 해당 작품 조건에서 가격 불확실성이 얼마나 큰지 나타냅니다.

두 번째 처리 단계는 Huber 중심선입니다. 원본 작품 피처, bucket 피처, Quantile 피처를 함께 넣어 중심 로그가격을 계산합니다. 세 번째 처리 단계는 CatBoost 잔차 보정입니다. 원본 피처, bucket 피처, Quantile 피처, 그리고 Huber 중심선을 넣어 중심선에서 남은 오차를 예측합니다.

최종 버킷순차보정 Warm 예측값은 Huber 중심 로그가격과 CatBoost 잔차보정값을 더한 값입니다. 운영 예측 때는 이 모델들을 새로 학습하지 않습니다. 학습 단계에서 동결된 bucket 규칙과 모델을 적용만 합니다.

## 16. Warm Huber 잔차 보정

- 예상 시간: 8분

Warm 잔차 보정은 후보 기준가격을 완전히 다시 만드는 단계가 아니라, 작은 폭으로 보완하는 단계입니다. 학습 단계에서는 실제 로그가격에서 후보 기준 로그가격을 뺀 값을 잔차 target으로 사용합니다. 예를 들어 후보 기준가격이 실제보다 반복적으로 조금 낮게 나오는 패턴이 있으면, Huber 잔차 모델이 그 패턴을 배우게 됩니다.

사용 단계에서는 실제 가격을 모르기 때문에 실제 잔차를 계산하지 않습니다. 대신 학습 때 동결해 둔 Huber 잔차 모델에 후보 기준가, 로그면적, 비교군 표본 수, 후보 차이, 수축 prior 같은 피처를 넣어 예상 잔차를 계산합니다.

적용식은 `0.50 * clip(잔차예측, -0.05, +0.05)`입니다. 이 말은 잔차예측을 먼저 ±0.05 log로 제한하고, 그 절반만 최종 후보가격에 반영한다는 뜻입니다. 그래서 최종 적용 보정폭은 최대 ±0.025 log입니다.

이 설정은 PP-HCOEF3에서 반복 검증을 통과한 `hcoef2_size_reliability_cap005_s050`입니다. Huber 자체는 큰 오차에 덜 끌리는 강건 회귀 방식이고, 여기서 말하는 Huber 모델은 과거 데이터로 계수와 절편을 산출해 둔 예측기라고 설명하면 됩니다.

## 17. Warm 위험도 조건부 라우터

- 예상 시간: 9분

Warm에는 기본 후보와 대안 후보가 있습니다. 기본 후보는 같은작가 유사작품 기준가격 70%, 보조안정 값 30%입니다. 대안 후보는 같은작가 유사작품 기준가격 85%, 보조안정 값 15%입니다. 대안 후보는 같은 작가 유사작품 신호를 더 강하게 반영하는 후보입니다.

하지만 대안 후보를 항상 쓰지는 않습니다. 먼저 작품단위위험도를 계산합니다. 위험도에는 Quantile 예측의 불확실성 폭, 후보 예측값 간 분산, 현재 기준가격과 안정 기준가격의 차이, low confidence 여부, very high price 여부가 들어갑니다.

`위험도임계값 = 0.2534165869`는 임의로 적은 숫자가 아닙니다. PP-WMIN8 validation 데이터에서 계산한 risk_score의 q50, 즉 중앙값입니다. 다시 말해 validation에서 위험도가 중간 이상인 행만 대안 검토 대상으로 삼는다는 뜻입니다.

두 번째 조건은 `대안교체최소차이 = 0.005 log`입니다. 이것도 PP-WMIN8에서 `altlower_gap005` 후보 비교로 선택된 조건입니다. 따라서 최종 규칙은 간단합니다. 작품단위위험도가 위험도임계값 이상이고, 보수적인 w850 후보가 기본 후보보다 대안교체최소차이 이상 낮으면 대안을 씁니다. 위험도가 낮거나 차이가 `0.005 log` 미만이면 기본 후보를 유지합니다.

## 18. Warm 계산 예시

- 예상 시간: 7분

이 슬라이드는 가상 계산 예시입니다. 여기 나오는 `18.300`, `18.360` 같은 숫자는 산식 이해를 위한 예시값이고, 평가 성능 수치가 아닙니다.

예시 작품은 작가 매칭 신뢰도 `0.92`이고 같은 작가 이력이 18건입니다. 따라서 Warm 조건을 만족합니다. 작품은 acrylic/canvas, 100cm x 80cm라고 가정합니다.

같은 작가 유사작품 비교군을 찾았고, 같은 작가 + acrylic/canvas + 대형 비교군이 3건 있다고 하겠습니다. 이 비교군의 로그가격이 `18.10`, `18.30`, `18.55`라면 중앙값은 `18.300`입니다. 따라서 같은작가 유사작품 기준 로그가격이 `18.300`이 됩니다.

보조안정 값은 큰오차방어 `18.360`, 버킷순차보정 `18.420`을 섞어 계산합니다. `0.75*18.360 + 0.25*18.420 = 18.375`입니다.

여기까지는 최종 가격을 고른 것이 아닙니다. 기준가격과 보조안정값을 만들었을 뿐입니다. 다음 슬라이드에서 이 두 값을 이용해 기본 후보와 대안 후보를 동시에 만듭니다.

## 19. Warm 계산 예시: 후보와 보정

- 예상 시간: 8분

이제 기본 후보와 대안 후보를 만듭니다. 기본 후보는 유사작품 기준 `18.300`을 70%, 보조안정 `18.375`를 30% 반영합니다. 계산하면 `18.323`입니다.

대안 후보는 유사작품 기준을 85% 반영하고 보조안정을 15%만 반영합니다. 계산하면 `18.311`입니다. 여기서는 유사작품 기준이 보조안정보다 낮기 때문에 대안 후보가 더 낮습니다.

각 후보에 잔차 보정을 합니다. 기본 후보의 잔차 예측이 `+0.020`이면 `clip` 범위 안에 있으므로 그대로 두고, 그 절반인 `+0.010`을 더합니다. 대안 후보의 잔차 예측이 `+0.016`이면 `+0.008`을 더합니다. 그 결과 기본 후보 보정 로그가격은 `18.333`, 대안 후보 보정 로그가격은 `18.319`가 됩니다.

이 단계에서도 아직 최종 선택은 끝나지 않았습니다. 기본 후보는 보조안정을 더 많이 섞은 안정 후보이고, 대안 후보는 같은 작가 유사작품 기준을 더 강하게 반영한 보수 후보입니다. 둘 중 어느 것을 쓸지는 다음 단계의 위험도 라우터가 결정합니다.

## 20. Warm 계산 예시: 위험도 라우팅

- 예상 시간: 8분

마지막으로 위험도 라우터를 봅니다. 예시에서는 Quantile 예측의 불확실성 폭이 `1.65`, 후보예측분산이 `0.08`, 현재-안정기준차이가 `0.03`이라고 하겠습니다. 신뢰도구간은 보통이고 가격대도 일반이라고 가정합니다.

이 값을 위험도 산식에 넣으면 불확실성 폭 기여가 `0.180`, 후보 분산 기여가 `0.098`, 기준 차이 기여가 `0.070`입니다. 저신뢰와 초고가 기여는 0입니다. 합치면 작품단위위험도는 `0.348`입니다.

임계값은 `0.2534165869`이므로 위험도 조건은 통과합니다.

두 번째 조건은 대안 후보가 기본 후보보다 최소 `0.005 log` 낮은지입니다. 기본 후보 `18.333`에서 대안 후보 `18.319`를 빼면 `0.014`입니다. 이것은 `0.005`보다 큽니다. 따라서 두 조건이 모두 통과합니다.

이 경우 최종 Warm 로그가격은 대안 후보인 `18.319`입니다. 만약 위험도가 낮거나, 대안 후보가 기본 후보보다 낮아도 차이가 `0.005` 미만이었다면 기본 후보 `18.333`을 유지했을 것입니다. 이 구조 때문에 보수 대안은 항상 쓰이는 값이 아니라 조건부 방어 장치라고 설명해야 합니다.

## 21. Warm 성능과 재현

- 예상 시간: 6분

Warm 최종 후보는 fixed test 607행에서 MdAPE `0.104326`, MAPE `0.235814`, p95 `0.739416`, RMSE log `0.377190`입니다. 여기서 n은 학습 데이터 수가 아니라 성능을 계산한 평가 행 수입니다.

WMIN8 최종 후보가 왜 의미가 있는지 보려면 WMIN4 기본 후보와 비교하면 됩니다. WMIN4 기본 후보는 fixed test에서 MdAPE `0.106598`, MAPE `0.239302`, p95 `0.779196`입니다. WMIN8 최종 후보는 `0.104326`, `0.235814`, `0.739416`입니다. 즉 위험도 조건부 w850 라우터를 추가하면서 세 지표가 모두 좋아졌습니다.

재현 관점에서는 `warm_model_policy_wmin8.json`에 성능과 정책이 기록되어 있고, 선택 실험은 `PP-WMIN8_warm_min1_weight_router`입니다. `PP-WMIN10` API parity에서는 607행 모두 성공했고, 최대 로그가격 차이는 `5.33e-15`입니다. 사실상 동결 번들과 API 출력이 같은 값이라고 볼 수 있습니다.

Warm의 해석은 명확합니다. 같은 작가 가격 이력을 중심으로 기준가격을 만들고, 기준가격을 크게 흔들지 않으면서, 위험한 작품만 조건부로 방어하는 구조입니다.

## 22. Warm-lite 모델 목적

- 예상 시간: 8분

Warm-lite는 같은 작가 이력이 1~4건뿐인 작품을 위한 경로입니다. 이 구간은 Cold로 보내기에는 같은 작가 가격 신호가 있고, Warm 본체를 쓰기에는 표본이 적습니다.

현재 채택된 Warm-lite는 먼저 작가 이력 1~4건에서 가격 통계를 만들고, 작품 크기와 매체/지지체 피처를 붙입니다. 그 다음 두 가지 LightGBM 중앙값 예측을 만듭니다. 하나는 전체 피처 기반 LightGBM Quantile 예측이고, 다른 하나는 저표본 안정화 LightGBM Quantile 예측입니다. 두 중앙값 예측을 평균한 뒤, 마지막으로 LightGBM Huber 잔차 보정을 정해진 범위 안에서만 더합니다.

Warm-lite도 기준을 네 가지로 나눠 설명합니다. 첫째, 이력을 묶는 기준입니다. 같은 작가 이력 1~4건 안에서 매체/지지체와 크기가 가까운 과거 작품부터 씁니다. 둘째, 기준가 생성 기준입니다. 이력 로그가격 통계, 면적단가 통계, 대상 작품 크기에 맞춰 환산한 작가 기준가격, 작품 피처를 모델에 넣어 두 중앙값 예측을 만들고 평균합니다. 셋째, 보정 기준입니다. LightGBM Huber 잔차 예측값을 `clip(0.50*잔차예측, -0.10, +0.10)` 범위에서만 더합니다. 넷째, 표시 기준입니다. 이력 1건은 넓은 범위와 검수 플래그, 2~4건은 표준 Warm-lite 표시를 씁니다.

왜 별도 경로가 필요한지도 같이 설명해야 합니다. PP-WCUT4에서는 1~4건 구간을 Cold로 보냈을 때 MdAPE가 `0.5429`였고, Warm-lite는 `0.1092`였습니다. 즉 이력이 1건이라도 있으면 같은 작가 가격 신호를 버리면 손실이 큽니다. 반대로 5건 이상에서는 WMIN8 Warm이 강제 Warm-lite보다 전 지표 우세였습니다. 그래서 현재 경계는 1~4건 Warm-lite, 5건 이상 Warm입니다.

한 문장으로 말하면, Warm-lite는 “적은 작가 이력으로 기준가격을 만들고, 두 중앙값 예측과 제한된 잔차 보정으로 저표본 흔들림을 관리하는 검증된 전용 경로”입니다.

## 23. Warm-lite 학습 단계 순서

- 예상 시간: 9분

Warm-lite 학습은 저이력 상황을 일부러 재현하는 것에서 시작합니다. 과거 데이터에는 실제 가격이 있지만, 학습/검증에서는 같은 작가 이력을 1~4건만 볼 수 있게 구성합니다. 그리고 fold 또는 leave-one-out으로 자기 가격이 자기 통계에 들어가지 않게 합니다.

그 다음 작가 이력 통계 피처를 만듭니다. 여기서 `median`은 중앙값입니다. 같은 작가 이력 가격을 정렬했을 때 가운데 값입니다. `q25`와 `q75`는 각각 하위 25% 지점과 상위 75% 지점이고, `IQR`은 `q75 - q25`입니다. 즉 이 세 값은 같은 작가 이력 가격이 얼마나 퍼져 있는지 보여주는 통계값입니다.

중요한 구분이 있습니다. 여기서 말하는 `q25`, `q75`, `IQR`은 LightGBM이 새 작품에 대해 예측한 값이 아닙니다. 과거 같은 작가 이력 그룹에서 먼저 계산한 통계 피처입니다. 반대로 뒤에서 나오는 LightGBM `q10`, `q50`, `q90`은 모델이 새 작품에 대해 예측한 낮은값, 중앙값, 높은값입니다.

면적단가 median에 대상 작품의 `log_area`를 더해 “대상 작품 크기에 맞춰 환산한 작가 기준 로그가격”도 만듭니다. 과거 이력 작품의 면적단가를 기준으로 이번 대상 작품 크기에 맞춰 환산한 값입니다. 내부 필드명은 `grp_price_proxy`이지만, 발표에서는 내부명보다 “대상 작품 크기에 맞춰 환산한 작가 기준가격”이라고 설명하는 편이 더 이해하기 쉽습니다.

이 피처로 LightGBM Quantile 예측 모델을 학습합니다. 전체 피처 기반 LightGBM Quantile 예측은 낮은값, 중앙값, 높은값을 만들고, 저표본 안정화 LightGBM Quantile 예측은 중앙값을 만듭니다. 이후 검증 대상 작품을 제외한 모델과 통계로 두 중앙값 예측의 평균 기준가격을 만들고, 실제 로그가격에서 이 기준가격을 뺀 값을 잔차 보정 학습의 목표값으로 사용합니다.

마지막으로 LightGBM Huber 잔차 보정 모델을 학습합니다. 현재 선택된 내부 후보명은 `qavg_lgbres_s05_cap010`입니다. 발표에서는 이름을 외우게 하기보다, “잔차 예측값의 50%만 반영하고 보정폭을 ±0.10 log 안으로 제한한 후보”라고 설명하면 됩니다. 이후 bundle replay와 API parity를 통과한 bundle을 동결합니다.

여기서 실제 가격은 학습 단계에서만 쓰입니다. 사용 단계에서는 실제 가격이 없으므로 동결된 Quantile 예측 모델과 잔차 보정 모델만 적용합니다.

발표할 때는 학습 단계의 이유를 아래처럼 짚으면 됩니다.

* 이유: 저이력 상황을 일부러 재현하는 것은, 운영에서 Warm-lite가 실제로 맡는 1~4건 이력 조건과 같은 난이도로 검증하기 위해서입니다.
* 이유: fold 또는 leave-one-out을 쓰는 것은, 평가 대상 작품의 자기 가격이 자기 통계에 들어가 성능이 과하게 좋아 보이는 label leakage를 막기 위해서입니다.
* 이유: 작가 이력 통계 피처를 만드는 것은, 1~4건뿐인 과거 가격을 median, q25/q75/IQR, 표본 수 같은 모델 입력 신호로 바꾸기 위해서입니다.
* 이유: 면적단가 기준가격을 만드는 것은, 과거 작품과 대상 작품의 크기가 다를 때 가격을 같은 크기 기준으로 비교하기 위해서입니다.
* 이유: 전체 피처 기반 LightGBM Quantile 예측을 학습하는 것은, 적은 이력에서도 사용할 수 있는 작가 이력 통계와 작품 피처를 최대한 반영하고 낮은값, 중앙값, 높은값을 함께 만들어 가격 분포와 불확실성을 보려는 목적입니다.
* 이유: 저표본 안정화 LightGBM Quantile 예측을 별도로 학습하는 것은, q25/q75/IQR 같은 저표본 분포 피처가 흔들릴 때 더 안정적인 중앙값 축을 확보하기 위해서입니다.
* 이유: 두 중앙값 예측을 평균하는 것은, 정보량이 많은 예측과 안정적인 예측 중 하나만 고르지 않고 둘의 장점을 절충하기 위해서입니다.
* 이유: 잔차 target을 `실제 로그가격 - 두 중앙값 예측의 평균 기준가격`으로 만드는 것은, 기준가격 자체를 다시 만들기보다 기준가격이 남긴 반복 오차만 학습하기 위해서입니다.
* 이유: LightGBM Huber 잔차 보정과 clip을 쓰는 것은, 남은 오차를 보정하되 저이력 구간에서 보정값이 과도하게 커지는 것을 막기 위해서입니다.
* 이유: bundle replay와 API parity를 확인하는 것은, 실험에서 선택한 Warm-lite 계산과 0.1v API 계산이 같은 입력에서 같은 결과를 내는지 보장하기 위해서입니다.

## 24. Warm-lite 사용 단계 순서

- 예상 시간: 9분

사용 단계에서는 먼저 같은 작가 가격 이력 1~4건에서 통계를 만듭니다. 이 통계와 작품 크기, 매체, 지지체 피처를 두 가지 LightGBM Quantile 예측 모델에 넣습니다.

첫 번째 모델은 전체 피처 기반 LightGBM Quantile 예측입니다. 이 모델은 낮은값, 중앙값, 높은값과 Quantile 예측의 불확실성 폭을 만듭니다. 두 번째 모델은 저표본 안정화 LightGBM Quantile 예측입니다. 이 모델은 저표본에서 흔들릴 수 있는 피처를 줄여 중앙값을 만듭니다. 두 중앙값을 50:50으로 평균해 Warm-lite 기준 로그가격을 만듭니다.

그 다음 Huber 잔차 보정 모델이 남은 오차를 예측합니다. 보정값은 `clip(0.50*잔차예측, -0.10, +0.10)`으로 제한됩니다. 최종 Warm-lite 로그가격은 두 중앙값 예측의 평균 기준가격에 이 제한된 보정값을 더한 값입니다.

출력에는 최종 로그가격과 원화 가격뿐 아니라, 전체 피처 기반 예측의 낮은값/중앙값/높은값, 저표본 안정화 중앙값, Quantile 예측의 불확실성 폭, 적용된 잔차 보정값, 신뢰도 표시값도 포함됩니다. 이 출력값들은 운영 화면에서 가격 범위와 신뢰도를 설명할 때 사용됩니다.

이력 1건이면 같은 산식으로 점 예측은 만들지만 `wide_range_with_review_flag`를 붙입니다. 이력 2~4건이면 표준 Warm-lite 표시 정책을 씁니다. 즉 신뢰도 표시 정책은 계산식이 아니라 출력 해석 정책입니다.

## 25. Warm-lite 피처와 사용처

- 예상 시간: 9분

Warm-lite의 핵심 피처는 작가 이력 통계입니다. 1~4건의 로그가격 median은 작가의 직접 가격 수준을 반영합니다. IQR은 가격 분산을 반영합니다. 면적단가 median은 이력 작품과 대상 작품의 크기 차이를 보정하는 데 쓰입니다.

여기서 내부 필드명보다 의미를 먼저 설명하는 것이 좋습니다. 핵심은 과거 이력 작품이 작거나 크더라도 대상 작품 크기에 맞춰 작가 가격 기준을 다시 환산한다는 점입니다. 산식은 `같은 작가 이력의 면적단가 중앙값 + 대상작품 log_area`입니다.

작품 피처도 중요합니다. 면적, 로그면적, 가로세로비, 입체 여부, 매체, 지지체, 크기 구간이 들어갑니다. 같은 작가의 가격 이력이 있어도 대상 작품이 훨씬 크거나 다른 매체이면 가격이 달라질 수 있기 때문입니다.

이력을 찾은 단계도 중요합니다. 같은 2건의 이력이라도 대상 작품과 매체/크기까지 비슷한 2건인지, 아니면 작가 전체에서 가져온 2건인지에 따라 신뢰도가 다릅니다. 내부 필드명은 `grp_match_level`입니다.

마지막으로 모델이 만든 예측값도 잔차 보정 피처로 다시 들어갑니다. 전체 피처 기반 예측의 낮은값/중앙값/높은값, Quantile 예측의 불확실성 폭, 두 중앙값 예측의 평균은 잔차 보정 모델이 “기준가격이 얼마나 불확실하고 어느 방향으로 보정될 가능성이 있는지” 판단하는 데 사용됩니다.

## 26. Warm-lite 이력 찾기 단계

- 예상 시간: 7분

Warm-lite는 같은 작가 이력 안에서 가장 가까운 비교군부터 찾습니다. 1순위는 같은 작가 + 같은 매체/지지체 + 같은 크기 구간입니다. 없으면 같은 작가 + 같은 크기 구간을 봅니다. 그래도 없으면 같은 작가 전체 1~4건을 사용합니다.

Warm-lite도 1순위가 있으면 그 이력 묶음을 사용하고, 2순위나 3순위와 섞지 않습니다. 어떤 단계에서 이력을 찾았는지는 별도 입력값으로 남깁니다. 이 값은 모델이 “매체와 크기까지 가까운 이력인지, 아니면 작가 전체 이력인지”를 구분하도록 돕습니다.

이 단계에서 중요한 점은 Warm-lite가 작가 이력 없이 동작하는 경로가 아니라는 것입니다. Warm-lite 라우팅은 같은 작가 이력 1~4건이 있을 때만 들어옵니다. 대체 통계는 입력 결측이나 통계 생성 실패를 막기 위한 방어 장치입니다.

따라서 Warm-lite의 가격 신호 중심은 여전히 같은 작가의 실제 가격 이력입니다.

대체 통계를 설명할 때는 “작가 이력이 없어도 Warm-lite를 쓴다”가 아니라는 점을 분명히 해야 합니다. 라우팅 단계에서 이미 1~4건 이력이 확인되어야 들어오고, 대체 통계는 세부 통계 피처가 비었을 때 전체/동결 통계로 계산 중단을 막는 장치입니다.

## 27. Warm-lite 기준가격: 두 중앙값 예측의 평균

- 예상 시간: 8분

Warm-lite는 두 가지 중앙값 예측을 함께 씁니다. 첫 번째는 전체 피처 기반 LightGBM Quantile 예측입니다. 이 예측은 작가 가격 q25, q75, IQR, 면적단가 IQR까지 사용합니다. 이 피처들이 유효할 때는 같은 작가의 가격 분포를 더 풍부하게 설명할 수 있습니다.

하지만 이력 1~4건은 표본이 적습니다. q25와 q75 같은 Quantile 통계는 표본이 작을 때 흔들릴 수 있습니다. 그래서 두 번째 예측은 일부 흔들릴 수 있는 피처 의존도를 줄여 중앙값을 더 안정적으로 만듭니다.

최종 기준값은 두 중앙값 예측의 50:50 평균입니다. 이 평균은 전체 피처 기반 축과 저표본 안정성을 중시하는 축을 동시에 반영합니다.

전체 피처 기반 예측의 낮은값과 높은값은 최종 평균에 직접 들어가지는 않지만 중요합니다. 높은값(q90)에서 낮은값(q10)을 뺀 Quantile 예측의 불확실성 폭은 불확실성 피처가 되고, 잔차 보정 모델이 보정 방향과 크기를 판단할 때 사용됩니다. 그래서 첫 번째 예측은 중앙값만 만드는 것이 아니라 낮은값/중앙값/높은값을 함께 만듭니다.

## 28. Warm-lite Huber 잔차 제한 보정

- 예상 시간: 8분

두 중앙값 예측의 평균이 기준 로그가격을 만들면, 잔차 보정 모델이 그 기준값에서 남은 반복 오차를 보정합니다. 잔차 보정 모델은 Warm-lite 기본 피처와 전체 피처 기반 예측의 낮은값/중앙값/높은값, Quantile 예측의 불확실성 폭, 두 중앙값 예측의 평균 기준가격을 입력으로 받습니다.

여기서 Huber objective를 쓰는 이유는 저이력 구간에서 일부 큰 오차가 보정층 전체를 과하게 흔들지 않게 하기 위해서입니다. 보정값은 잔차 예측값의 절반만 반영하고, 로그 기준 ±0.10으로 제한합니다.

현재 채택 후보의 내부명은 `qavg_lgbres_s05_cap010`입니다. 발표에서는 공식보다 의미를 먼저 말하면 됩니다. “두 중앙값 예측의 평균 기준가격에, Huber 잔차 예측값의 절반만 더하고, 그 보정폭은 ±0.10 log로 제한한다”입니다.

이 보정은 기준가격을 새로 만드는 단계가 아닙니다. 두 중앙값 예측의 평균이 이미 만든 기준 로그가격 위에, 잔차 보정 모델이 예측한 남은 오차의 절반만 제한적으로 더합니다. 그래서 저이력 표본의 불안정성을 관리하면서도 보정층이 가격을 과하게 뒤집지 못하게 합니다.

## 29. Warm-lite 신뢰도 표시 정책

- 예상 시간: 5분

Warm-lite는 이력 1건과 2~4건의 점 예측 산식은 같습니다. 차이는 출력 표시 정책입니다. 이력이 1건이면 `warm_lite_low`와 `wide_range_with_review_flag`를 붙입니다. 즉 점 예측은 내지만 넓은 범위와 검수 플래그로 보여줍니다.

이력이 2~4건이면 `warm_lite_standard`와 표준 범위 표시를 사용합니다. 이 정책은 가격을 바꾸는 보정이 아닙니다. 같은 점 예측을 운영에서 얼마나 조심스럽게 보여줄지 정하는 정책입니다.

이 구분은 사용자에게 “이 가격은 작가 이력 신호가 있지만 표본이 작다”는 점을 명확히 전달하기 위한 장치입니다. 특히 이력 1건은 같은 작가 신호가 있지만 분산을 충분히 알 수 없으므로, 가격 자체는 계산하되 해석은 더 넓은 범위와 검수 플래그로 안내합니다.

## 31. Warm-lite 계산 예시: 통계와 예측

## 33. Cold 모델 목적

- 예상 시간: 8분

Cold는 같은 작가 가격 이력이 없거나 작가 매칭이 불확실할 때 적용됩니다. 이 상황에서는 Warm이나 Warm-lite처럼 같은 작가의 과거 가격대를 기준가격으로 만들 수 없습니다.

그래서 Cold는 작품 피처, 작가 메타, 검색 문맥을 함께 사용합니다. 작품 크기와 매체, 지지체는 가격 기준선을 만들고, 작가 메타는 작가의 시장 위치를 보조하며, 검색 문맥은 작가가 미술 시장에서 어떤 맥락으로 등장하는지를 반영합니다.

Cold에는 불확실성 방어가 필요합니다. 같은 작가 가격 이력이 없어서 Quantile 예측의 불확실성 폭이 넓고 대표가격이 높은 경우 과대예측 위험이 커집니다. 그래서 guard가 있습니다.

Cold를 설명할 때는 “정보가 적으니 약한 모델”이라고 말하기보다, “같은 작가 기준가격을 만들 수 없는 상황을 처리하는 전용 경로”라고 설명하는 편이 정확합니다. Cold는 LightGBM Quantile 모델, Quantile 예측의 불확실성 폭별 잔차 안정화, 과대예측 guard, 검색 보정 조회표가 결합된 구조입니다.

Cold는 Warm/Warm-lite처럼 같은 작가 유사작품 묶음을 직접 만들 수 없습니다. 그래서 Cold의 묶는 방식은 다른 의미입니다. 작품 크기, 매체, 지지체, 작가 메타, 검색 문맥이 비슷한 패턴을 LightGBM tree가 나누고, Quantile 예측의 불확실성 폭이 비슷한 작품끼리는 잔차 안정화표에서 같은 구간으로 묶입니다. 정규화 작가명이나 artist_key는 검색 보정 조회표에서 값을 찾는 기준으로 사용됩니다.

따라서 Cold의 기준가는 “같은 작가 과거 가격의 중앙값”이 아닙니다. 작품/작가/검색 피처를 Quantile 모델에 넣어 만든 q50 계열 대표 로그가격입니다. 그 다음 Quantile 예측의 불확실성 폭별 잔차 중앙값, guard, 검색 보정 조회표를 순서대로 적용합니다.

## 34. Cold 학습 단계 순서

- 예상 시간: 9분

Cold 학습 단계에서는 작품 피처, 작가 메타, 검색 피처를 사용해 LightGBM Quantile 모델을 학습합니다. 이 모델은 낮은값(q10), q40, 중앙값(q50), 높은값(q90) 후보 로그가격과 Quantile 예측의 불확실성 폭을 만듭니다. q50은 대표 후보의 중심이고, q40은 과대예측 방어에서 낮은쪽 기준으로 사용됩니다.

그 다음 검증 잔차를 사용해 Quantile 예측의 불확실성 폭 구간별 안정화 보정값을 만듭니다. Quantile 예측의 불확실성 폭이 비슷한 작품들이 반복적으로 높게 또는 낮게 예측된다면 그 편향을 보정하기 위한 값입니다.

guard 임계값도 검증 데이터에서 산출합니다. 현재 Quantile 예측의 불확실성 폭 임계값은 `1.4612207078910142`이고, 대표가격과 q40 후보 간 gap 임계값은 `0.07715547281151025`입니다. 마지막으로 검색 문맥에 따른 작가별 보정 조회표를 만듭니다.

이 모든 값은 학습/검증 단계에서 실제 가격을 보고 만들어 둔 뒤 동결합니다. 사용 단계에서는 실제 가격이 없으므로 Quantile 모델, 잔차 안정화표, guard 조건, 조회표를 순서대로 적용만 합니다.

Cold에서 말하는 묶음은 세 가지입니다. 첫째, 모델 내부 패턴 묶음입니다. tree가 작품 크기, 매체, 작가 메타, 검색 문맥이 비슷한 행을 나눠 q10, q40, q50, q90 후보를 만듭니다. 둘째, Quantile 예측의 불확실성 폭 묶음입니다. 높은값(q90)에서 낮은값(q10)을 뺀 폭이 비슷한 작품은 같은 불확실성 구간으로 보고 잔차 중앙값 보정을 받습니다. 셋째, 검색 보정 조회표 묶음입니다. 정규화 작가명 또는 artist_key 기준으로 검색 문맥 보정값을 조회합니다.

발표할 때는 학습 단계의 이유를 아래처럼 짚으면 됩니다.

* 이유: Cold 학습에서 작품 피처, 작가 메타, 검색 피처를 함께 쓰는 것은, 같은 작가 가격 이력이 없어서 작가 본인의 과거 가격 기준가를 만들 수 없기 때문입니다.
* 이유: LightGBM Quantile 모델을 학습하는 것은, 하나의 평균 가격만 내는 대신 낮은값, 중앙값, 높은값을 함께 만들어 예측 중심과 불확실성을 같이 보기 위해서입니다.
* 이유: q40 후보를 따로 만드는 것은, 대표가격이 과하게 높게 잡혔는지 비교할 낮은쪽 기준가격이 필요하기 때문입니다.
* 이유: Quantile 예측의 불확실성 폭을 계산하는 것은, 모델이 해당 작품 가격 범위를 넓게 보고 있는지 좁게 보고 있는지 판단하기 위해서입니다.
* 이유: Quantile 예측의 불확실성 폭 구간별 잔차 안정화표를 만드는 것은, 비슷한 불확실성 구간에서 반복적으로 생기는 예측 편향을 검증 잔차로 보정하기 위해서입니다.
* 이유: guard 임계값을 검증 데이터에서 산출하는 것은, 불확실성이 크고 대표가격이 q40보다 충분히 높을 때만 과대예측 방어를 작동시키기 위해서입니다.
* 이유: guard weight를 0.50으로 두는 것은, 대표가격을 q40으로 완전히 바꾸지 않고 과대예측 위험만 절반 정도 완화하기 위해서입니다.
* 이유: 작가 검색 보정 조회표를 만드는 것은, 검색 문맥이 검증 데이터에서 반복적으로 설명한 작가별 잔차를 최종 가격에 반영하기 위해서입니다.
* 이유: Quantile 모델, 잔차 안정화표, guard 조건, 조회표를 동결하는 것은, 운영 사용 단계에서 실제 가격 없이 같은 규칙을 일관되게 적용하기 위해서입니다.

## 35. Cold 사용 단계 순서

- 예상 시간: 8분

사용 단계에서는 입력 작품의 크기, 매체, 지지체, 작가 메타, 검색 문맥을 피처로 만듭니다. 이 피처를 LightGBM Quantile 모델에 넣어 기초 후보와 Quantile 예측의 불확실성 폭을 얻습니다.

그 다음 Quantile 예측의 불확실성 폭 구간별 잔차 보정값을 더해 대표 로그가격을 안정화합니다. 이후 guard 조건을 검사합니다. Quantile 예측의 불확실성 폭이 충분히 넓고 대표가격이 낮은쪽 기준보다 충분히 높으면 과대예측 방어를 작동시킵니다.

마지막으로 작가 검색 보정 조회표에서 해당 작가의 검색 문맥 보정값을 찾아 더합니다. 그 결과가 최종 Cold 로그가격입니다.

출력 흐름은 네 개의 중간값으로 설명하면 쉽습니다. 첫째, 검색포함 대표로그가격입니다. 둘째, guard 적용 후 과대예측방어 로그가격입니다. 셋째, 조회표에서 찾은 작가검색보정 로그값입니다. 넷째, 이 둘을 더한 최종 Cold 로그가격입니다.

## 36. Cold 피처와 사용처

- 예상 시간: 9분

Cold는 같은 작가 가격 이력을 직접 쓰지 못하므로 작품 자체 정보가 중요합니다. width, height, depth, area, log_area, aspect_ratio가 가격 기준선을 만듭니다.

매체와 지지체도 중요합니다. 같은 크기라도 canvas인지 paper인지, oil인지 acrylic인지에 따라 가격 구조가 달라질 수 있습니다. 제작연도나 edition 여부 같은 작품 메타도 작품의 시기와 희소성을 보조합니다.

작가 메타와 검색 문맥은 Cold에서 특히 중요합니다. 작가의 생년, 국적, 작품 수, 팔로워, 판매작 수는 작가의 시장 위치를 간접적으로 설명합니다. 검색 문맥은 갤러리, 미술관, 시장, 동명이인 위험을 구분합니다.

Quantile 산출값도 후속 단계의 피처가 됩니다. 낮은값(q10), q40, 중앙값(q50), 높은값(q90), Quantile 예측의 불확실성 폭은 대표 로그가격 안정화와 guard 판단에 사용됩니다. 특히 q40은 과대예측 방어에서 낮은쪽 기준가격 역할을 합니다.

Cold 피처는 크게 두 종류로 나눌 수 있습니다. 첫 번째는 가격을 예측하는 피처입니다. 작품 크기, 매체, 작가 메타, 검색 문맥이 여기에 속합니다. 두 번째는 예측을 방어하는 피처입니다. Quantile 예측의 불확실성 폭, q40과 대표가격의 gap, 동명이인 위험이 여기에 속합니다.

---

## 37. Cold 검색 피처

- 예상 시간: 8분

Cold에서 검색 피처는 작가 이력이 없는 상황을 보완하는 중요한 신호입니다. 검색 결과 수가 많고, 그 결과가 미술 문맥, 갤러리/미술관 문맥, 시장 문맥과 연결되어 있으면 작가의 활동성과 시장 노출을 간접적으로 볼 수 있습니다.

반대로 동명이인 의심 문맥이 높으면 작가 식별 위험이 있습니다. 이 경우 가격 예측보다 검수나 보수적 처리가 필요할 수 있습니다.

검색 품질 점수는 이런 검색 문맥 비율과 품질을 정규화한 값입니다. Cold는 이 값을 LightGBM Quantile과 검색 보정 조회표에서 활용합니다.

검색 피처의 흐름은 원천 검색 결과에서 시작합니다. title, snippet, url을 보고 미술 문맥, 갤러리/미술관 문맥, 시장/거래 문맥, 동명이인 의심 문맥으로 나눕니다. 그 결과가 `search_art_match_ratio`, `search_gallery_ratio`, `search_market_ratio`, `search_homonym_risk_ratio`, `search_quality_score` 같은 피처가 됩니다.

검색 보정 조회표는 이 검색 문맥이 검증 데이터에서 반복적으로 설명한 작가별 잔차를 반영합니다. 즉 검색 피처는 Quantile 모델에 한 번 들어가고, 조회표 보정에서도 한 번 더 사용됩니다.

## 38. Cold 대표 로그가격 안정화

- 예상 시간: 8분

Cold의 첫 번째 예측값은 검색피처포함 기초 Quantile 후보입니다. 이 값은 작품 피처, 작가 메타, 검색 피처를 입력으로 LightGBM Quantile 모델이 예측합니다.

그 다음 Quantile 예측의 불확실성 폭별 잔차 안정화를 적용합니다. Quantile 예측의 불확실성 폭이 비슷한 작품들이 검증 데이터에서 반복적으로 어떤 방향의 오차를 보였다면, 그 잔차 중앙값을 보정값으로 사용합니다. 보정값은 `clip`으로 제한합니다.

이 과정을 거친 값이 검색포함 대표로그가격입니다. 이후 guard와 검색 보정 조회표가 적용됩니다.

이 안정화는 새로운 모델이 아니라 검증 잔차 기반 보정표입니다. 예를 들어 Quantile 예측의 불확실성 폭이 큰 작품들이 검증 데이터에서 반복적으로 낮게 예측됐다면 해당 구간에는 양수 보정값이 생길 수 있습니다. 반대로 높게 예측됐다면 음수 보정값이 생길 수 있습니다. 단, 보정값은 ±0.25 log로 제한해 과도하게 움직이지 않게 합니다.

## 39. Cold 과대예측 방어 guard

- 예상 시간: 9분

Cold guard는 불확실성이 큰데 대표가격이 높은 경우를 방어하기 위한 고정 규칙입니다. 조건은 두 가지입니다. 첫째, Quantile 예측의 불확실성 폭이 `1.4612207078910142` 이상이어야 합니다. 둘째, 대표가격이 낮은쪽 40% 기준보다 `0.07715547281151025 log` 이상 높아야 합니다.

두 조건이 모두 맞으면 대표가격과 낮은쪽 기준가격을 50:50으로 섞습니다. 즉 바로 낮은쪽으로 완전히 보내는 것이 아니라, 과대예측 위험을 절반 정도 완화하는 방식입니다.

guard는 학습 모델이 아닙니다. 검증 데이터에서 산출된 임계값을 동결해 사용하는 조건부 후처리 규칙입니다.

여기서 `1.4612207078910142`는 Quantile 예측의 불확실성 폭의 q67입니다. 불확실성 폭이 상위 쪽에 있는 작품을 대상으로 한다는 뜻입니다. `0.07715547281151025`는 대표가격과 q40 후보 차이의 q50입니다. 즉 대표가격이 낮은쪽 후보보다 충분히 높을 때만 guard를 켭니다.

조건이 통과하지 않으면 guard는 아무것도 하지 않습니다. 이 점을 반드시 말해야 합니다. Cold가 항상 보수 가격을 쓰는 것이 아니라, 불확실성과 높은 대표가격 조건이 동시에 맞을 때만 방어합니다.

## 40. Cold 작가 검색 보정 조회표

- 예상 시간: 7분

조회표는 미리 만든 표에서 값을 찾는 방식입니다. Cold의 작가 검색 보정은 정규화 작가명 또는 작가키에 대해 검색 문맥 기반 보정값을 찾아 최종 로그가격에 더합니다.

이 보정값은 작가 검색 결과가 검증 데이터에서 반복적으로 어떤 방향의 가격 차이를 보였는지 반영합니다. 예를 들어 갤러리/미술관 문맥이 강하고 시장 문맥이 확인되는 작가는 보정값이 양수일 수 있습니다.

하지만 작가별 보정은 과하게 적용되면 위험하므로 clip 범위로 제한합니다. Cold의 최종 로그가격은 과대예측방어 로그가격에 작가검색보정 로그값을 더한 값입니다.

조회표는 사용 단계에서 새로 학습하지 않습니다. 이미 만들어 둔 작가 검색 보정 조회표에서 값을 찾습니다. 찾을 수 없으면 보정값은 0 또는 fallback 값이 됩니다. 이 구조 덕분에 검색 문맥이 있는 작가는 반복 잔차를 보정하고, 근거가 부족한 작가는 과한 보정을 피할 수 있습니다.

## 41. Cold 계산 예시

- 예상 시간: 6분

이 슬라이드도 가상 계산 예시입니다. 검색 비율과 로그가격 숫자는 Cold 산식을 따라가기 위한 예시값이지, 평가 결과 수치가 아닙니다.

예시 작품은 작가 매칭 신뢰도 `0.62`이고 같은 작가 가격 이력이 0건입니다. 따라서 Warm이나 Warm-lite가 아니라 Cold로 갑니다.

작품은 mixed media/panel, 65cm x 53cm라고 가정합니다. 면적은 3,445이고 로그면적은 8.145입니다. 검색 피처로는 미술 문맥 비율, 갤러리 비율, 시장 비율, 검색 품질 점수 등이 만들어집니다.

이 예시는 Cold가 작품 정보만 보는 것이 아니라 검색 문맥까지 같이 본다는 점을 보여주기 위한 예시입니다. 이 단계에서는 아직 가격 계산이 아니라 라우팅과 피처 생성이 끝난 상태입니다.

## 42. Cold 계산 예시: 최종값

- 예상 시간: 8분

LightGBM 기초 후보가 17.800이고, 낮은쪽 40% 기준이 17.550, Quantile 예측의 불확실성 폭이 1.700이라고 하겠습니다. 이 폭이 속한 구간의 보정값이 +0.040이면 대표로그가격은 17.840입니다.

낮은쪽 40% 기준이 17.550이면 대표가격과 낮은쪽 기준의 차이는 0.290입니다. Quantile 예측의 불확실성 폭 조건 `1.700 >= 1.4612`도 통과하고, gap 조건 `0.290 >= 0.0772`도 통과합니다. 따라서 guard가 작동합니다.

guard 후 가격은 대표가격과 낮은쪽 기준을 50:50으로 섞어 17.695가 됩니다. 여기에 검색 조회표 보정 +0.060을 더하면 최종 Cold 로그가격은 17.755입니다.

마지막에는 `exp(17.755)`로 원화 가격을 만듭니다. 이 예시에서 Cold 계산은 Quantile 후보, 구간별 잔차 안정화, guard, 조회표 보정의 네 단계를 모두 거친 것입니다.

## 43. Cold 성능과 재현

- 예상 시간: 7분

Cold 성능 기준은 단계별로 개선이 확인됩니다. 검색포함 대표 로그가격은 MdAPE `0.424663`, MAPE `0.991042`, p95 `3.305298`입니다. guard만 적용하면 p95가 `2.537708`로 크게 내려갑니다. guard와 검색 보정을 함께 쓰면 최종적으로 MdAPE `0.409820`, MAPE `0.849260`, p95 `2.346465`가 됩니다.

재현성도 확인되어 있습니다. fixed test는 3,099행이고, 검색 보정 조회표 작가 수는 372명입니다. test 검색 커버리지는 1.0입니다. 후처리기와 독립 계산식의 로그가격 차이는 0이고, 기록 지표와 재계산 지표의 최대 차이는 `1.110e-16`입니다.

재현 스크립트는 `scripts/track6/verify_cold_best_research_reproducibility.py`이고, 결과 파일은 `models/track6/cold_prediction_v0.3/reproduction/best_research_reproducibility_check.json`입니다. 따라서 Cold 성능 기준 모델은 산식과 후처리까지 재현 가능한 상태입니다.

## 44. 세 경로는 단일 모델인가

- 예상 시간: 8분

여기서 예상 질문이 하나 나올 수 있습니다. 이 세 경로를 각각 하나의 모델로 봐야 하느냐, 아니면 앙상블로 봐야 하느냐는 질문입니다. 답은 “단일 모델이라기보다 앙상블형 하이브리드 구조”입니다.

Warm은 특히 그렇습니다. Warm은 같은 작가 유사작품 기준가격 하나만 쓰는 것도 아니고, CatBoost 하나만 쓰는 것도 아닙니다. 같은 작가 유사작품 통계로 기준가격을 만들고, Huber 잔차 회귀와 큰오차방어 Huber meta-model, 버킷순차보정의 CatBoost/Huber 모델을 결합합니다. 여기에 70:30 기본 후보, 85:15 보수 후보, 75:25 보조안정, clip, 위험도임계값, 대안교체최소차이 같은 고정 규칙이 붙습니다.

Warm-lite도 단일 모델 하나는 아닙니다. 1~4건 작가 이력 통계를 만들고, 전체 피처 기반 LightGBM Quantile 예측과 저표본 안정화 LightGBM Quantile 예측을 함께 사용한 뒤, LightGBM Huber 잔차 보정 모델을 붙입니다. 그리고 두 중앙값 예측의 평균, 제한된 잔차 보정, 신뢰도 표시 정책 같은 고정 규칙을 같이 씁니다.

Cold도 마찬가지입니다. LightGBM Quantile 후보 모델이 중심이지만, 검색 피처 생성 규칙, 구간별 잔차 안정화표, 과대예측 guard, 검색 보정 조회표가 결합됩니다. 그래서 Cold도 모델 하나가 바로 최종 가격을 내는 구조가 아니라, 학습된 모델과 고정 후처리 규칙이 결합된 구조입니다.

Huber에 대한 질문도 이 슬라이드에서 정리하면 됩니다. Huber 자체는 모델 이름이라기보다 큰 오차에 덜 끌리는 손실 함수 또는 강건 회귀 방식입니다. 하지만 문서에서 `Huber 모델`이라고 부르는 것은 과거 데이터로 Huber 기준에 맞춰 계수와 절편을 산출해 둔 회귀 예측기입니다. 따라서 학습 단계에서는 실제 가격을 보고 계수와 절편을 맞추고, 사용 단계에서는 그 계수와 절편을 동결해서 새 작품 피처에 적용합니다.

CatBoost나 LightGBM도 같은 원리입니다. 학습 단계에서는 과거 데이터와 실제 가격을 보고 tree 구조를 학습합니다. 사용 단계에서는 tree를 새로 만들지 않고, 이미 저장된 tree에 입력 피처를 넣어 예측값을 받습니다.

따라서 발표에서는 이렇게 말하면 됩니다. “세 경로 모두 운영 시점에는 새로 학습하지 않습니다. 학습은 과거 데이터로 미리 끝나 있고, 운영에서는 동결된 모델, 계수, 보정표, 조회표, 임계값을 순서대로 적용합니다.”

## 45. 세 경로의 핵심 차이

- 예상 시간: 6분

세 경로의 가장 큰 차이는 어떤 기준가격을 쓸 수 있는가입니다. Warm은 같은 작가 유사작품 기준가격을 쓸 수 있습니다. Warm-lite는 같은 작가 이력이 있지만 1~4건뿐이므로 저이력 통계와 두 중앙값 예측, 제한된 잔차 보정을 씁니다. Cold는 같은 작가 가격 기준을 직접 만들 수 없으므로 작품, 작가 메타, 검색 문맥으로 추정합니다.

보정과 방어도 다릅니다. Warm은 Huber 잔차 보정과 위험도 조건부 보수 후보를 씁니다. Warm-lite는 Huber 잔차 제한 보정과 신뢰도 표시 정책을 씁니다. Cold는 구간별 잔차 안정화, 과대예측 guard, 검색 보정 조회표를 씁니다.

하지만 공통점도 있습니다. 세 경로 모두 로그가격에서 계산하고 마지막에 `exp()`로 원화 가격을 만듭니다. 또한 학습 단계와 사용 단계가 분리되어 있고, 사용 단계에서는 실제 가격을 입력으로 쓰지 않습니다.

## 46. 운영 모니터링 포인트

- 예상 시간: 5분

운영에서는 모델 성능만 보지 않고 라우팅과 데이터 조건을 모니터링해야 합니다. R1은 라우팅 규칙 위반입니다. 0.80 임계와 이력 조건이 지켜지는지 봅니다. R2는 경로별 트래픽 비중입니다. 특정 경로에 지나치게 쏠리면 데이터 유입 구조가 달라졌을 수 있습니다.

R3는 보조정보 없이 상위 경로로 통과한 비중입니다. 이름만으로 Warm이나 Warm-lite에 들어가면 동명이인 위험이 커질 수 있습니다. R4는 Warm-lite 실측 성능입니다. 확정 판매 라벨이 충분히 쌓여야 측정할 수 있습니다. R5는 동명이인율입니다.

이 모니터링은 모델을 바꾸기 위한 것이 아니라, 현재 라우팅이 의도대로 작동하는지 확인하기 위한 운영 안전장치입니다.

---

## 47. 최종 설명 문장

- 예상 시간: 4분

마지막으로 한 문장으로 정리하면 이렇습니다. 이 가격 예측 시스템은 하나의 모델이 모든 작품을 처리하는 구조가 아닙니다. 작가가 확실하고 이력이 5건 이상이면 Warm이 같은 작가 유사작품을 기준으로 계산합니다. 작가가 확실하지만 이력이 1~4건이면 Warm-lite가 저이력 통계, 두 중앙값 예측, 제한된 잔차 보정으로 계산합니다. 작가 이력이 없거나 매칭이 불확실하면 Cold가 작품 피처, 작가 메타, 검색 문맥과 과대예측 방어로 계산합니다.

세 경로는 모두 로그가격에서 계산하고 마지막에 원화 가격으로 변환합니다. 학습 때는 실제 가격으로 모델과 보정값을 만들지만, 운영 사용 때는 실제 가격 없이 동결 모델과 입력 피처만으로 계산합니다.

이 문장을 이해하면 전체 시스템의 핵심은 이해한 것입니다. 나머지 세부 구조는 이 문장을 각 경로별로 풀어낸 것입니다.

## 48. 재현 근거 요약

- 예상 시간: 4분

마지막으로 재현 근거를 정리합니다. Warm은 `warm_model_policy_wmin8.json`과 PP-WMIN10 API parity가 근거입니다. Warm-lite는 `warm_lite_quantile_residual_v0.1` bundle과 PP-WLITE-Q3/Q4/Q5가 근거입니다. Cold는 `cold_prediction_v0.3` 재현 패키지와 독립 재계산 결과가 근거입니다.

발표 후 질의가 나오면 답변 순서를 유지하는 것이 좋습니다. 먼저 해당 작품이 어느 라우팅 조건에 들어가는지 설명합니다. 그 다음 학습 단계와 사용 단계 중 어느 부분을 묻는지 구분합니다. 마지막으로 해당 경로의 보정과 방어 로직이 왜 필요한지 설명하면 됩니다.

이 방식으로 답하면 모델 이름이나 실험 ID에 의존하지 않고, 실제 가격 예측이 만들어지는 원리를 일관되게 설명할 수 있습니다.
