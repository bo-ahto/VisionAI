# Warm / Warm-lite / Cold 최종 가격 예측 모델 상세 설명

- 기준 리포트: `partner_warm_cold_best_model_report.html`
- 발표 목적: 최종 모델이 어떤 조건에서 선택되고, 학습/사용 단계에서 어떤 피처와 로직으로 가격을 계산하는지 설명
- 권장 시간: 발표 280~340분 + 질의 30~45분
- 기준 API 표기: `0.1v API`
- 핵심 메시지: 세 모델은 성능 순서가 아니라 입력 정보 조건별 전용 경로다

## 1. 리포트 검토 결과

| 점검 항목 | 결과 | 발표 자료 반영 방식 |
|---|---|---|
| 핵심 성능 수치 | Warm, Warm-lite, Cold 모두 근거 artifact에서 재확인 | 슬라이드 성능표에 최신 채택값만 사용 |

## 2. 오늘 설명할 질문

| 질문 | 답변 방식 |
|---|---|
| 작품이 어떤 모델로 라우팅되는가 | 작가 매칭 신뢰도와 같은 작가 가격 이력 수로 결정 |
| 학습 단계와 사용 단계는 어떻게 다른가 | 학습 때는 실제 가격으로 모델/보정값을 만들고, 사용 때는 동결 모델만 적용 |
| Warm은 왜 5건 이상인가 | 5건 이상 WMIN8이 강제 Warm-lite보다 전 지표 우세 |
| Warm-lite는 왜 따로 있는가 | 1~4건은 Cold보다 훨씬 낫고, Warm 계열 대체 후보보다도 전체 우세 |
| Cold는 왜 검색 피처와 guard가 필요한가 | 같은 작가 가격 기준이 없어서 작가 문맥과 불확실성 방어가 핵심 |

## 3. 전체 라우팅 구조

```text
[작품 입력]
  - 작가명 또는 artist_key
  - 작품 크기, 면적, 깊이
  - 매체, 지지체, 작품 카테고리
  - 작가 메타, 검색 문맥
        |
        v
[라우팅 판단]
  - 작가매칭신뢰도점수 >= 0.80 ?
  - 같은작가_사용가능가격이력수는 몇 건인가?
        |
        +-- 0.80 이상 AND 5건 이상  -> Warm
        +-- 0.80 이상 AND 1~4건     -> Warm-lite
        +-- 그 외                    -> Cold 또는 검수대기
```

| 경로 | 입력 조건 | 가격 판단의 중심 |
|---|---|---|
| Warm | 고신뢰 작가 매칭 + 이력 5건 이상 | 같은 작가 유사작품 기준가격 |
| Warm-lite | 고신뢰 작가 매칭 + 이력 1~4건 | 저이력 작가 통계 + 두 중앙값 예측 + 잔차 제한 보정 |
| Cold | 이력 0건, 매칭 불확실, 동명이인 위험 | 작품 피처 + 작가 메타 + 검색 문맥 |

## 3.1 작가매칭신뢰도점수 계산 흐름

`작가매칭신뢰도점수`는 입력 작가가 학습 작가 사전의 특정 `artist_key`와 같은 사람인지 0~1로 환산한 값이다.

```text
[입력 작가 정보]
  - artist_key 또는 selected_artist_key
  - 한글명, 영문명
  - 생년
  - 국적/외부 식별자는 후속 검증 보조정보
        |
        v
[작가명 정규화]
  - 소문자 변환, 공백/기호 정리
  - 정규화된 입력 이름을 alias 사전과 비교
        |
        v
[학습 작가 사전 후보 검색]
  - artist_key 직접 일치
  - 정규화 alias 완전 일치
  - 부분 이름 후보
        |
        v
[후보 검증]
  - 후보가 1명인가?
  - 생년이 충돌하지 않는가?
  - 같은 이름의 다른 artist_key가 있는가?
        |
        v
[작가매칭신뢰도점수 + 동명이인위험점수]
```

| 구성 요소 | 점수에 미치는 영향 | 해석 |
|---|---|---|
| `artist_key` 직접 일치 | `1.00` | 사용자가 이미 작가 고유키를 지정한 경우 |
| 이름 완전 일치 | 크게 상승 | 정규화된 한글명/영문 alias가 학습 사전에 있음 |
| 생년 일치 | 상승 | 같은 이름 후보 중 같은 사람임을 보강 |
| 생년 불일치 | 하락 | 같은 작가로 보기 어려운 반대 근거 |
| 후보 여러 명/동명이인 | 하락 또는 검수대기 | 잘못된 작가 이력을 쓰는 위험 차단 |

## 3.2 작가매칭신뢰도점수 구현과 예시

현재 0.1v API는 하위점수 5개를 그대로 합산하지 않는다. 실제 구현은 매칭 상태와 생년 보정, 동명이인 위험을 직접 계산한다.

```text
artist_key 직접 일치:
  작가매칭신뢰도점수 = 1.00
  동명이인위험점수 = 0.00

정규화 alias 완전 일치:
  기본 점수 = 1.00
  생년 일치 +0.05, 생년 불일치 -0.15
  최종 점수는 최대 1.00

부분 이름 후보:
  기본 점수 = 0.78
  생년 일치 +0.05, 생년 불일치 -0.15
  최종 점수는 최대 0.95

동명이인위험점수 =
  clip((후보 수 - 1)*0.35 + is_homonym*0.25, 0.00, 1.00)
```

따라서 작가 매칭은 현재 운영 구현 기준으로 `직접 key`, `alias 완전 일치`, `부분 이름 후보`, `생년 보정`, `동명이인 위험` 순서로 설명한다.

| 상황 | 계산/판단 | 점수 | 라우팅 해석 |
|---|---|---:|---|
| `artist_key` 직접 일치 | 고유키가 학습 작가 사전과 동일 | `1.00` | 이력 수만 확인 |
| 정규화 alias 완전 일치 | alias 기본 점수 | `1.00` | 동명이인 위험이 낮으면 이력 수 확인 |
| alias 완전 일치 + 생년 일치 | `1.00 + 0.05`, 최대 1.00 제한 | `1.00` | 동명이인 위험이 낮으면 이력 수 확인 |
| 부분 이름 후보 + 생년 일치 | `0.78 + 0.05` | `0.83` | 이력 수와 동명이인 위험 추가 확인 |
| 부분 이름 후보 + 생년 없음 | 기본 점수 | `0.78` | 0.80 미만이므로 Cold/검수대기 |
| 후보 여러 명/동명이인 위험 높음 | `동명이인위험점수 >= 0.60` | 점수와 별개 | 검수대기 |

라우팅은 점수만으로 끝나지 않는다. `작가매칭신뢰도점수 >= 0.80`을 통과한 뒤에도 같은 작가 가격 이력 수가 `5건 이상`이면 Warm, `1~4건`이면 Warm-lite, `0건`이면 Cold/검수대기다.

## 4. 성능 기준 요약

| 경로 | 평가 기준 | n | MdAPE | MAPE | p95 APE | 보조 RMSE log |
|---|---|---:|---:|---:|---:|---:|
| Warm | fixed test | 607 | 0.104326 | 0.235814 | 0.739416 | 0.377190 |
| Warm-lite | 실존 저이력 LOO x3 | 1,947 | 0.107246 | 0.275773 | 0.852026 | 0.423003 |
| Cold | fixed test | 3,099 | 0.409820 | 0.849260 | 2.346465 | 비교값 없음 |

- `n`은 학습 작품 수가 아니라 평가 행 수다.
- Cold는 같은 작가 가격 이력을 직접 쓰지 못하므로 Warm/Warm-lite와 절대 난이도가 다르다.
- 세 경로 비교의 주 지표는 MdAPE, MAPE, p95 APE이고, RMSE log는 경로 내부 보조 검증값이다.

## 5. 지표를 읽는 방법

| 지표 | 계산 단위 | 의미 | 발표에서의 해석 |
|---|---|---|---|
| MdAPE | 원화 가격 | 작품별 APE의 중앙값 | 일반적인 작품에서 체감되는 대표 오차 |
| MAPE | 원화 가격 | 작품별 APE의 평균 | 전체 평균 오차 |
| p95 APE | 원화 가격 | APE 상위 5% 경계 | 크게 틀리는 tail risk |
| RMSE log | 로그가격 | 로그 예측값과 실제 로그값 차이 | 모델 내부 로그 공간 흔들림 |

```text
예측가격_KRW = exp(최종_로그가격)
APE = abs(예측가격_KRW - 실제가격_KRW) / 실제가격_KRW
```

## 9. Warm 모델 목적

**적용 대상**

- `작가매칭신뢰도점수 >= 0.80`
- `같은작가_사용가능가격이력수 >= 5`

**핵심 아이디어**

```text
같은 작가 유사작품 기준가격
  + 제한된 잔차 보정
  + 위험도 조건부 보수 라우터
  -> 최종 Warm 로그가격
```

Warm은 가격을 처음부터 새로 맞히는 모델이 아니다. 같은 작가의 과거 가격대를 기준가격으로 만들고, 그 기준가격을 작게 보정하며, 위험한 경우에만 더 보수적인 후보로 바꾼다.

## 10. Warm 학습 단계 순서

```text
[Warm 학습 데이터]
  - 실제 가격이 있는 과거 Warm 작품
  - 작가 이력 5건 이상 조건
        |
        v
[유사작품 찾기 단계 학습/검증]
  - 작가+재료/지지체+크기
  - 작가+크기
  - 작가 전체
        |
        v
[보조 Warm 예측축 생성]
  [축 A: 큰오차방어 Warm 예측값 학습]
    - 여러 Warm 후보 로그가격을 같은 행 단위로 모음
    - 후보 평균/표준편차/범위/기준후보와의 차이/불확실성 폭 생성
    - Huber meta-model이 큰 오차에 덜 흔들리는 방어형 중심 로그가격을 학습
    - 하위 후보 범위에서 과도하게 벗어나지 않도록 clip

  [축 B: 버킷순차보정 Warm 예측값 학습]
    - 작품 크기/형태/매체/지지체/작가 식별 피처 생성
    - size_bucket, shape_bucket, support_size_bucket, medium_shape_bucket 생성
    - CatBoost Quantile로 낮은값(q10)/중앙값(q50)/높은값(q90)과 Quantile 예측의 불확실성 폭 생성
    - Huber 중심선이 중심 로그가격을 학습
    - CatBoost 잔차 모델이 중심선에서 남은 오차를 학습

  [보조안정 가중식 동결]
    - 0.75 * 큰오차방어 Warm 예측값
    - 0.25 * 버킷순차보정 Warm 예측값
        |
        v
[Huber 잔차 보정 학습]
  - target = 실제 로그가격 - 후보 기준 로그가격
        |
        v
[위험도 조건부 라우터 검증/동결]
  - 위험도임계값 = 0.2534165869
    * 근거: PP-WMIN8 validation risk_score q50, 즉 validation 위험도 중앙값
  - 대안교체최소차이 = 0.005 log
    * 근거: PP-WMIN8 후보 비교에서 선택된 altlower_gap005 조건
```

| 보조축 | 학습 때 만드는 것 | 사용 때 쓰는 것 |
|---|---|---|
| 큰오차방어 | 여러 Warm 후보를 입력으로 한 Huber meta-model | 후보들이 서로 흔들릴 때 방어형 중심값 |
| 버킷순차보정 | bucket + Quantile + Huber 중심선 + CatBoost 잔차 모델 | 크기/형태/매체 조건을 반영한 보조 예측값 |
| 보조안정 | 두 축의 75:25 가중식 | 기본/대안 후보를 만들 때 섞는 안정화 기준 |

## 11. Warm 사용 단계 순서

```text
[Warm 입력 작품]
  - 고신뢰 artist_key
  - 같은 작가 가격 이력 5건 이상
  - 크기/매체/지지체
        |
        v
[1. 같은 작가 유사작품 기준가격 생성]
  - 1순위: 작가 + 재료/지지체 + 크기
  - 2순위: 작가 + 크기
  - 3순위: 작가 전체
  - 검증 때는 자기 작품 제외, 0건이면 다음 단계로 fallback
        |
        v
[2. 보조안정 Warm 예측값 계산]
  - 큰오차방어 Warm 예측값 적용
  - 버킷순차보정 Warm 예측값 적용
  - 보조안정 = 0.75*큰오차방어 + 0.25*버킷순차보정
        |
        v
[3. 기본 후보와 대안 후보 생성]
  - 기본 후보 w700 = 0.70*유사작품기준 + 0.30*보조안정
  - 대안 후보 w850 = 0.85*유사작품기준 + 0.15*보조안정
  - 근거: w700은 WMIN4 기본 후보, w850은 WMIN7 가중 후보 중 WMIN8 라우터에서 선택된 대안
        |
        v
[4. 각 후보에 Huber 잔차 보정 적용]
  - 동결된 Huber 잔차 모델이 예상 잔차를 계산
  - 후보별 보정값 = 0.50*clip(잔차예측, -0.05, +0.05)
  - 근거: HCOEF3 안정 후보 hcoef2_size_reliability_cap005_s050
        |
        v
[5. 작품단위 위험도 계산]
  - Quantile 예측의 불확실성 폭, 후보 분산, 기준-안정 차이, 신뢰도, 가격대 사용
        |
        v
[6. 위험도 조건부 라우터]
  - 작품단위위험도 >= 위험도임계값(0.2534165869)
  - 기본후보_보정로그가격 - 대안후보_보정로그가격 >= 대안교체최소차이(0.005 log)
  - 두 조건이 모두 통과하면 대안 후보, 아니면 기본 후보
        |
        v
[7. 최종 Warm 로그가격 -> exp() -> 원화 가격]
```

> 사용 단계에서는 실제 가격을 모른다. 새로 학습하지 않고, 동결된 비교군 규칙·보조 예측축·Huber 잔차 모델·라우터 조건만 순서대로 적용한다.

## 12. Warm 피처와 사용처

```text
[원천 입력]
  artist_key, 작가매칭신뢰도점수, 같은작가_사용가능가격이력수
  width/height/depth/area/log_area/aspect_ratio
  medium_category, support_category, size_bucket
        |
        v
[Warm 내부 피처 생성]
  - 같은작가 유사작품 비교군 통계
  - 큰오차방어 Warm 예측값
  - 버킷순차보정 Warm 예측값
  - 후보 간 차이/분산/불확실성 피처
        |
        v
[계산에 사용]
  비교군 기준가격 -> 보조안정값 -> 기본/대안 후보
  -> Huber 잔차 보정 -> 위험도 라우터 -> 최종 Warm 가격
```

| 단계 | 사용하는 피처 | 계산 결과 | 역할 |
|---|---|---|---|
| 라우팅 | 작가매칭신뢰도점수, 같은작가_사용가능가격이력수 | Warm 진입 여부 | 0.80 이상 + 5건 이상만 Warm |
| 비교군 매칭 | `artist_key`, 재료/지지체, 크기 구간 | 비교군 행 집합 | 같은 작가 안에서 가장 가까운 과거 작품 선택 |
| 기준가격 | 비교군 로그가격 median/q25/q75/IQR, 표본 수 | 같은작가_유사작품기준로그가격 | Warm의 주 가격 신호 |
| 보조안정 | 큰오차방어 축, 버킷순차보정 축 | 보조안정_Warm예측로그가격 | 소표본 비교군의 흔들림 완충 |
| 후보 생성 | 기준가격, 보조안정값 | w700 기본 후보, w850 대안 후보 | 기본/보수 후보를 둘 다 준비 |
| 잔차 보정 | 후보 기준가, 로그면적, 표본 수, 후보 차이, 수축 prior | 후보별 보정로그가격 | 반복 오차를 작은 폭으로 보정 |
| 위험도 라우터 | Quantile 예측의 불확실성 폭, 후보 분산, 기준-안정 차이, 신뢰도 tier, 가격대 | 최종 후보 선택 | 위험 구간만 대안 후보로 교체 |

Warm을 설명할 때는 아래 네 기준을 분리해서 말한다.

| 기준 | Warm에서의 의미 | 최종 가격에 미치는 영향 |
|---|---|---|
| 유사작품을 묶는 기준 | 같은 작가 안에서 재료/지지체와 크기 구간이 가까운 과거 작품부터 선택 | 어떤 과거 가격을 기준가격의 원천으로 쓸지 결정 |
| 기준가 생성 기준 | 선택된 비교군의 로그가격 중앙값과 분산 통계, 보조안정 예측값을 결합 | `w700`, `w850` 후보의 출발점 결정 |
| 보정 기준 | Huber 잔차 모델이 후보별 남은 오차를 예측하되 최대 ±0.025 log만 반영 | 기준가가 반복적으로 높거나 낮게 잡히는 패턴을 제한적으로 보정 |
| 최종 선택 기준 | 작품단위위험도가 위험도임계값 이상이고 대안 후보가 기본 후보보다 대안교체최소차이 이상 낮을 때만 대안 선택 | 보통은 기본 후보 유지, 조건을 만족한 위험 구간만 보수 후보로 교체 |

> 사용 단계에서 실제 가격은 피처로 들어가지 않는다. 실제 가격은 학습 단계에서 target과 검증 지표를 만들 때만 사용한다.

## 13. Warm 유사작품 비교군

```text
[Warm 대상 작품]
  - 작가 매칭 신뢰도 >= 0.80
  - 같은 작가 사용 가능 가격 이력 >= 5건
        |
        v
[유사작품 찾기 단계]
  1순위: 같은 작가 + 같은 재료/지지체 + 같은 크기 구간
  2순위: 같은 작가 + 같은 크기 구간
  3순위: 같은 작가 전체
        |
        v
[비교군 통계]
  - 로그가격 중앙값
  - 로그가격 q25/q75/IQR
  - 표본 수, 표본 수 로그값
  - 비교군 단계
        |
        v
[같은작가_유사작품기준로그가격]
```

| 질문 | 답 |
|---|---|
| `min1`의 의미 | Warm 진입 조건을 1건으로 낮추는 것이 아니라, 이미 5건 이상인 Warm 작가 안에서 좁은 하위 비교군을 1건부터 인정한다는 뜻 |
| 왜 1건 비교군도 쓰는가 | 같은 작가 + 같은 재료/크기처럼 가까운 1건은 넓은 작가 전체 통계보다 더 직접적인 가격 신호일 수 있음 |
| 누수 차단 | 학습/검증 때는 자기 fold를 제외하고 비교군 통계를 만든다 |
| fallback | 자기 fold 제외 후 0건이면 2순위, 그래도 없으면 3순위로 내려간다 |

비교군 선택 기준:

| 기준 | 설명 |
|---|---|
| 작가 기준 | 정규화된 `artist_key`가 같은 과거 작품만 비교군 후보가 된다 |
| 재료/지지체 기준 | 매체와 지지체가 대상 작품과 같은 그룹이면 1순위 후보가 된다 |
| 크기 기준 | 동결된 크기 구간이 대상 작품과 같은 작품을 먼저 본다 |
| 표본 기준 | Warm 진입은 작가 전체 5건 이상이지만, 진입 후 좁은 비교군은 1건부터 인정한다 |
| 선택 방식 | 1순위에 1건 이상 있으면 1순위를 사용하고, 없을 때만 2순위/3순위로 내려간다 |

예시:

```text
작가 전체 이력 18건
같은 재료/지지체 + 같은 크기 구간 3건 발견
-> 1순위 비교군 사용
-> 3건 로그가격 중앙값이 18.300이면
   같은작가_유사작품기준로그가격 = 18.300
```

## 14. Warm 보조안정 예측값

```text
[비교군 기준가격만 사용하면 생길 수 있는 문제]
  - 가까운 비교군 표본이 적음
  - 특정 작품 1~2건 가격에 기준가격이 흔들림
  - 작가 전체 가격대와 작품 조건 신호가 덜 반영될 수 있음
        |
        v
보조안정_Warm예측로그가격 =
  0.75 * 큰오차방어_Warm예측로그가격
  + 0.25 * 버킷순차보정_Warm예측로그가격
```

| 축 | 입력 | 처리 | 출력 | 역할 |
|---|---|---|---|---|
| 큰오차방어 Warm 예측값 | 여러 Warm 후보 예측값, 후보 평균/표준편차/범위, 불확실성 폭 | Huber meta-model + 후보 범위 clip | 방어형 중심 로그가격 | 하위 후보 하나가 크게 빗나가는 위험 완화 |
| 버킷순차보정 Warm 예측값 | 작품 크기/형태/매체/지지체/작가 피처 | bucket -> CatBoost Quantile -> Huber 중심선 -> CatBoost 잔차 보정 | 조건 기반 보조 로그가격 | 작품 조건에 따른 가격 패턴 보완 |

사용 방식:

```text
기본후보_기준가 = 0.70*유사작품기준 + 0.30*보조안정
대안후보_기준가 = 0.85*유사작품기준 + 0.15*보조안정
```

> 보조안정값은 최종 가격을 혼자 결정하지 않는다. 같은 작가 유사작품 기준가격 옆에 섞여 기준가격의 흔들림을 줄이는 보조축이다.

## 15. 버킷순차보정 Warm 예측값

```text
[작품 피처]
  width, height, depth, area, log_area, aspect_ratio,
  medium, support, artist_key, has_depth
        |
        v
[4개 bucket 피처 생성]
  size_bucket, shape_bucket,
  support_size_bucket, medium_shape_bucket
        |
        v
[처리 단계 1: CatBoost Quantile]
  입력: 작품 피처 + 4개 bucket 피처
  낮은값(q10), 중앙값(q50), 높은값(q90)
  Quantile 예측의 불확실성 폭 = 높은값(q90) - 낮은값(q10)
        |
        v
[처리 단계 2: Huber 중심선]
  입력: 작품 피처 + 4개 bucket 피처 + Quantile 피처
  중심 로그가격
        |
        v
[처리 단계 3: CatBoost 잔차 보정]
  입력: 작품 피처 + 4개 bucket 피처 + Quantile 피처 + 중심 로그가격
  남은 오차 예측
        |
        v
버킷순차보정_Warm예측로그가격 =
  Huber 중심 로그가격 + CatBoost 잔차보정
```

정리:

- `4개 bucket 피처`는 생성되는 피처의 종류다.
- `처리 단계 3개`는 그 bucket 피처를 사용하는 모델 흐름이다.
- 따라서 "bucket은 4개인데 사용은 3번"이라는 표현은 모순이 아니다.
- 같은 100호라도 세로형/가로형, canvas/paper, 평면/입체 조건이 다르면 bucket 피처가 다른 가격 패턴을 전달한다.

## 16. Warm Huber 잔차 보정

```text
[학습 단계]
잔차 target =
  실제_로그가격 - 후보_기준로그가격
Huber잔차모델이 이 잔차를 예측하도록 계수/절편을 산출

[사용 단계]
잔차예측 =
  동결된 Huber잔차모델(후보 기준가, 로그면적, 표본 수, 후보 차이, 수축 prior 등)

보정후보_로그가격 =
  후보_기준로그가격
  + 0.50 * clip(잔차예측, -0.05, +0.05)
```

| 항목 | 설명 |
|---|---|
| Huber의 의미 | 큰 오차에 덜 끌려가는 강건 회귀 방식 |
| 학습 때 실제 가격 사용 | 실제 로그가격으로 잔차 target을 만들 때만 사용 |
| 사용 때 실제 가격 사용 | 사용하지 않음. 동결 모델이 입력 피처로 잔차예측만 계산 |
| `cap=0.05` | 잔차예측을 먼저 ±0.05 log로 제한 |
| `strength=0.50` | 제한된 잔차예측의 절반만 반영 |
| 최종 보정폭 | 최대 ±0.025 log |

> 근거 설정: PP-HCOEF3 반복 검증 통과 후보 `hcoef2_size_reliability_cap005_s050`.

## 17. Warm 위험도 조건부 라우터

```text
기본 후보:
  0.70 * 같은작가_유사작품기준로그가격
  + 0.30 * 보조안정_Warm예측로그가격

대안 후보:
  0.85 * 같은작가_유사작품기준로그가격
  + 0.15 * 보조안정_Warm예측로그가격

동결 라우터 기준:
  위험도임계값 = 0.2534165869
  대안교체최소차이 = 0.005 log

대안 선택 조건:
  작품단위위험도 >= 위험도임계값
  AND 기본후보_보정로그가격 - 대안후보_보정로그가격 >= 대안교체최소차이
```

작품단위위험도:

```text
risk_score =
  0.38 * clip((Quantile예측_불확실성폭 - 1.20) / 0.95, 0, 1)
  + 0.22 * clip(후보예측분산 / 0.18, 0, 1)
  + 0.14 * clip(현재-안정기준차이 / 0.06, 0, 1)
  + 0.16 * (신뢰도구간 == 저신뢰)
  + 0.10 * (안정기준가격대 == 초고가)
```

| 라우터 기준 | 값 | 의미 | 근거 |
|---|---|---|---|
| 위험도임계값 | `0.2534165869` | 이 값 이상이면 위험 구간으로 보고 대안 후보를 검토 | PP-WMIN8 validation `risk_score` q50 |
| 대안교체최소차이 | `0.005 log` | 대안 후보가 기본 후보보다 이 값 이상 낮을 때만 교체 | PP-WMIN8 `altlower_gap005` |
| 보수 대안 후보 | `w850` | 위험 구간에서 검토하는 보수 대안 | WMIN7 가중 후보 중 WMIN8에서 선택 |

보수 대안은 항상 쓰지 않는다. 작품단위위험도가 위험도임계값 이상이고, 대안 후보가 기본 후보보다 대안교체최소차이 이상 낮을 때만 쓴다.

> 근거: PP-WMIN8 `min1_route_w850_risk_q50_altlower_gap005` 후보가 validation-only gate 비교에서 선택됐다. `risk_q50`은 validation `risk_score` 중앙값이고, `altlower_gap005`는 대안 후보가 기본 후보보다 최소 `0.005 log` 낮아야 한다는 조건이다.

## 18. Warm 계산 예시

```text
가상 예시:
  아래 숫자는 산식 이해를 위한 예시값이며 평가 성능 수치가 아님

[1. 입력]
  작가 매칭 신뢰도 = 0.92
  같은 작가 이력 = 18건
  작품 = acrylic/canvas, 100cm x 80cm

[2. 라우팅]
  0.92 >= 0.80
  18건 >= 5건
  -> Warm

[3. 유사작품 찾기]
  같은 작가 + acrylic/canvas + 대형 비교군 3건
  -> 1순위 비교군 사용

[4. 비교군 통계]
  비교군 로그가격 = 18.10, 18.30, 18.55
  같은작가_유사작품기준로그가격 = 18.300
  비교군표본수로그 = log1p(3)

[5. 보조안정]
  큰오차방어 18.360
  버킷순차보정 18.420
  보조안정 = 0.75*18.360 + 0.25*18.420 = 18.375
```

이 시점에서 최종 가격은 아직 정해지지 않았다. 기준가격과 보조안정값을 만든 뒤 기본 후보와 대안 후보를 동시에 계산한다.

## 19. Warm 계산 예시: 후보와 보정

```text
[6. 기준 후보 2개 생성]
기본후보_기준로그가격 =
  0.70*18.300 + 0.30*18.375
  = 18.323

대안후보_기준로그가격 =
  0.85*18.300 + 0.15*18.375
  = 18.311

[7. 후보별 Huber 잔차 보정]
기본후보 잔차예측 = +0.020
기본후보 보정값 = 0.50*clip(+0.020, -0.05, +0.05) = +0.010
기본후보_보정로그가격 = 18.333

대안후보 잔차예측 = +0.016
대안후보 보정값 = 0.50*clip(+0.016, -0.05, +0.05) = +0.008
대안후보_보정로그가격 = 18.319
```

해석:

- 기본 후보는 보조안정값을 더 많이 섞어 기준가격을 완충한다.
- 대안 후보는 같은 작가 유사작품 기준가격을 더 강하게 반영한다.
- 두 후보 모두 Huber 잔차 보정을 같은 방식으로 받는다.
- 아직 최종 후보 선택 전이다. 다음 단계에서 위험도 라우터가 둘 중 하나를 고른다.

## 20. Warm 계산 예시: 위험도 라우팅

```text
[8. 작품단위위험도 계산]
Quantile 예측의 불확실성 폭 = 1.65
후보예측분산 = 0.08
현재-안정기준차이 = 0.03
신뢰도구간 = 보통
안정기준가격대 = 일반

불확실성 폭 기여 = 0.38*clip((1.65-1.20)/0.95, 0, 1) = 0.180
후보 분산 기여 = 0.22*clip(0.08/0.18, 0, 1) = 0.098
기준 차이 기여 = 0.14*clip(0.03/0.06, 0, 1) = 0.070
저신뢰 기여 = 0.000
초고가 기여 = 0.000

작품단위위험도 = 0.348
위험도임계값 = 0.2534165869
대안교체최소차이 = 0.005 log

[9. 라우팅 조건 A: 위험도]
  0.348 >= 위험도임계값(0.2534165869)  -> 통과

[10. 라우팅 조건 B: 대안교체최소차이]
  기본후보_보정로그가격 - 대안후보_보정로그가격
  = 18.333 - 18.319
  = 0.014 >= 대안교체최소차이(0.005 log)       -> 통과

[11. 최종 선택]
최종 Warm 로그가격 = 18.319
최종 Warm 가격 = exp(18.319)
```

조건 A와 B가 모두 통과했기 때문에 보수 대안 후보를 선택한다. 둘 중 하나라도 실패하면 기본 후보를 유지한다.

## 22. Warm-lite 모델 목적

**적용 대상**

- `작가매칭신뢰도점수 >= 0.80`
- `같은작가_사용가능가격이력수 = 1~4건`

```text
[왜 별도 경로인가]
  Cold로 보내기에는 같은 작가 실제 가격 이력이 있음
  Warm 5건 이상 본체를 쓰기에는 이력 표본이 작음
        |
        v
[Warm-lite 핵심 계산]
  작가 이력 1~4건 통계
  + 작품 크기/매체/지지체 피처
        |
        v
  두 가지 중앙값 예측을 평균
  - 전체 피처 기반 LightGBM Quantile 예측
  - 저표본 안정화 LightGBM Quantile 예측
        |
        v
  LightGBM Huber 잔차 제한 보정
        |
        v
  최종 Warm-lite 로그가격 -> exp() -> 원화 가격
```

경계 근거:

| 질문 | 검증 | 결론 |
|---|---|---|
| 1~4건을 Cold로 보내도 되는가 | PP-WCUT4 | Warm-lite MdAPE 0.1092 vs Cold 0.5429 |
| 1~4건을 Warm 계열로 통일해도 되는가 | PP-WMIN9E / PP-WMIN11 | 전체 기준 Warm-lite 유지 |
| 5건 이상도 Warm-lite로 보내도 되는가 | PP-WMIN9D | 5건 이상은 WMIN8 Warm 우세 |

> Warm-lite는 “간단한 fallback”이 아니라 1~4건 저이력 구간을 위해 별도로 검증된 최종 경로다.

Warm-lite도 Warm처럼 `이력 그룹 -> 기준가 -> 보정` 순서로 계산하지만, 기준이 더 보수적이다.

| 기준 | Warm-lite에서의 의미 | 최종 가격에 미치는 영향 |
|---|---|---|
| 이력 묶는 기준 | 같은 작가 이력 1~4건 안에서 매체/지지체와 크기가 가까운 과거 작품부터 선택 | 적은 이력 중 어떤 가격 통계를 쓸지 결정 |
| 기준가 생성 기준 | 이력 로그가격 통계, 면적단가 통계, 대상 작품 크기에 맞춰 환산한 작가 기준가격, 작품 피처를 모델에 입력 | 두 가지 중앙값 예측의 평균 기준가격 생성 |
| 보정 기준 | LightGBM Huber 잔차 예측값을 `clip(0.50*잔차예측, -0.10, +0.10)` 범위에서 더함 | 두 중앙값 예측의 평균이 남긴 반복 오차만 제한적으로 보정 |
| 표시 기준 | 이력 1건은 넓은 범위와 검수 플래그, 2~4건은 표준 Warm-lite 표시 | 점 예측 산식은 같고 운영 해석만 달라짐 |

## 23. Warm-lite 학습 단계 순서

```text
[저이력 상황 재현]
  - 실제 가격이 있는 과거 작품
  - 같은 작가 이력을 1~4건만 볼 수 있게 구성
  - fold/leave-one-out으로 자기 가격 누수 차단
        |
        v
[작가 이력 통계 피처 생성]
  - 로그가격 median(중앙값)
  - 로그가격 q25/q75/IQR(이력 가격 분포)
  - 면적단가 median/IQR
  - 대상 작품 크기에 맞춰 환산한 작가 기준 로그가격
      = 면적단가 median + 대상작품 log_area
  - 표본 수 로그값, 이력 찾기 단계
        |
        v
[LightGBM Quantile 예측 학습]
  - 전체 피처 기반 LightGBM Quantile 예측: 낮은값/중앙값/높은값
  - 저표본 안정화 LightGBM Quantile 예측: 중앙값
  - 두 중앙값 예측의 평균 기준가격 생성
        |
        v
[검증 대상 작품을 제외한 기준가격으로 잔차 생성]
  actual_log - 두 중앙값 예측의 평균 기준가격
        |
        v
[LightGBM Huber 잔차 보정 학습]
  - 두 중앙값 예측의 평균에서 남은 반복 오차를 예측
  - strength=0.50, cap=0.10 후보 검증
        |
        v
[bundle 동결과 parity]
  - 선택된 내부 후보명: qavg_lgbres_s05_cap010
  - replay/API parity 확인
```

학습 단계에서 실제 가격은 학습 목표값과 잔차를 만들기 위해 사용한다. 사용 단계에서는 실제 가격을 쓰지 않고, 동결된 Quantile 예측 모델과 잔차 보정 모델만 적용한다.

용어 구분:

| 용어 | 뜻 | 여기서의 출처 |
|---|---|---|
| `median` | 중앙값. 이력 가격을 정렬했을 때 가운데 값 | 같은 작가 이력 통계 |
| `q25`, `q75` | 하위 25%, 상위 75% 지점 값 | 같은 작가 이력 통계 |
| `IQR` | `q75 - q25`, 이력 가격이 퍼진 정도 | 같은 작가 이력 통계 |
| 대상 작품 크기에 맞춰 환산한 작가 기준 로그가격 | 이 작가의 면적단가를 대상 작품 크기에 맞춰 환산한 기준 로그가격 후보. 내부 필드명은 `grp_price_proxy` | 같은 작가 이력 + 대상 작품 `log_area` |

여기서 `q25/q75/IQR`은 LightGBM이 새 작품에 대해 예측한 값이 아니다. 과거 같은 작가 이력 그룹에서 먼저 계산한 통계값이다. LightGBM의 `q10/q50/q90`은 그 다음 단계에서 모델이 새 작품에 대해 예측하는 낮은값/중앙값/높은값이다.

| 설명할 이름 | 내부 필드/생성 방식 | 사용하는 단계 | 의미 |

| `medium_category`, `support_category`, `size_bucket` | 정규화/구간화 | 이력 찾기 단계, LightGBM | 재료/지지체/크기 조합 |
| 이력을 찾은 단계 | 내부 필드명 `grp_match_level` | 기준가격 예측/잔차 보정 | 비교 이력의 가까움 |

| 두 중앙값 예측의 평균 | 내부 필드명 `lgbq_full_lean_avg` | 잔차 보정/최종 기준 | Warm-lite 기준 로그가격 |

  -> 남은 오차 보정
```

        v
[선택된 이력 그룹 통계]
  이력 로그가격 중앙값/q25/q75/IQR
  면적단가 중앙값/IQR
  이력 수 로그값, 이력을 찾은 단계
```

| 단계 | 사용하는 이유 |
|---|---|
| 1순위 | 이력 수가 적어도 조건이 가까우면 가장 직접적인 가격 신호 |
| 2순위 | 재료/지지체까지는 다르지만 크기가 비슷한 작가 가격 신호 |
| 3순위 | 저이력 작가의 전체 가격대 |
| 4순위 | 결측 방어. 작가 이력 없이 Warm-lite를 쓰겠다는 의미가 아님 |

이력 그룹 선택 기준:

| 기준 | 설명 |
|---|---|
| 같은 작가 제한 | Warm-lite의 모든 이력 통계는 같은 작가 가격 이력 1~4건에서 출발한다 |
| 가까운 조건 우선 | 매체/지지체와 크기 구간이 모두 가까운 그룹을 먼저 쓴다 |
| 혼합 금지 | 1순위 그룹이 있으면 2순위/3순위와 섞어 평균내지 않는다 |
| 이력을 찾은 단계 | 어떤 단계에서 이력을 찾았는지 모델 입력으로 남겨 신뢰도 차이를 반영한다. 내부 필드명은 `grp_match_level` |
| 대체 통계 의미 | 통계 생성 실패 방어용이며, 작가 이력 0건을 Warm-lite로 보내는 정책이 아니다 |

> Warm-lite 라우팅 자체는 같은 작가 이력 1~4건이 있을 때만 들어온다. 대체 통계는 통계 생성 실패를 막는 안전장치다.

## 27. Warm-lite 기준가격: 두 중앙값 예측의 평균

```text
전체 피처 기반 중앙값 예측 =
  이력 가격 분포 피처까지 포함해 예측한 중앙 로그가격

저표본 안정화 중앙값 예측 =
  저표본 흔들림 피처를 줄인 중앙 로그가격

두 중앙값 예측의 평균 기준가격 =
  0.50 * 전체 피처 기반 중앙값 예측
  + 0.50 * 저표본 안정화 중앙값 예측
```

| 구성 | 포함 피처 | 출력 | 역할 |
|---|---|---|---|
| 전체 피처 기반 예측 | q25/q75, IQR, 면적단가 IQR까지 포함 | 낮은값/중앙값/높은값과 Quantile 예측의 불확실성 폭 | 사용 가능한 이력 통계를 최대한 반영 |
| 저표본 안정화 예측 | 흔들릴 수 있는 q25/q75/IQR 같은 분포 피처 일부 제외 | 안정 중앙값 | 1~4건 저표본의 과도한 흔들림 완화 |
| 50:50 평균 | 두 중앙값 예측 | Warm-lite 기준 로그가격 | 정보량과 안정성 절충 |

두 예측을 나누는 이유:

```text
전체 피처 기반 예측 = 정보량은 많지만 저표본 q25/q75/IQR 흔들림 가능
저표본 안정화 예측 = 안정적이지만 세부 분포 반영은 약함
평균 = 두 위험을 절충한 기준 로그가격
```

## 28. Warm-lite Huber 잔차 제한 보정

```text
LightGBM_Huber_잔차 =
  Huber 잔차 보정 model(
    기본 피처
    + 전체 피처 기반 예측의 낮은값/중앙값/높은값
    + Quantile 예측의 불확실성 폭
    + 두 중앙값 예측의 평균 기준가격
  )

최종_Warm-lite_로그가격 =
  두 중앙값 예측의 평균 기준가격
  + clip(0.50 * LightGBM_Huber_잔차, -0.10, +0.10)
```

| 항목 | 설명 |
|---|---|
| 잔차 보정 학습 목표 | 학습 때 `actual_log - 두 중앙값 예측의 평균 기준가격` |
| 잔차 보정 입력 | 원본 피처 + 작가 이력 통계 + Quantile 예측 출력값 |
| `0.50` | 잔차 예측값의 절반만 반영하는 비율 |
| `±0.10` | 최종 잔차 보정 상한 |
| 선택된 내부 후보명 | `qavg_lgbres_s05_cap010` |

잔차 보정은 두 중앙값 예측의 평균이 남긴 반복 오차만 보정한다. 기준가격을 완전히 다시 만드는 단계가 아니다.

## 33. Cold 모델 목적

**적용 대상**

- 같은 작가 가격 이력이 0건
- 작가 매칭이 불확실
- 입력 부족 또는 동명이인 위험

```text
[왜 Cold가 필요한가]
  같은 작가 가격 기준가격을 만들 수 없음
  작가 매칭이 불확실하면 Warm/Warm-lite 사용이 위험
        |
        v
[Cold 핵심 계산]
작품 피처 + 작가 메타 + 검색 문맥
  -> LightGBM Quantile 후보
  -> Quantile 예측의 불확실성 폭별 잔차 안정화
  -> 과대예측 방어 guard
  -> 작가 검색 보정 조회표
  -> 최종 Cold 로그가격
```

Cold의 역할:

| Warm/Warm-lite와 다른 점 | Cold에서 보완하는 방식 |
|---|---|
| 같은 작가 기준가격 없음 | 작품 피처, 작가 메타, 검색 문맥으로 추정 |
| 작가 매칭 불확실 가능 | 검색 피처와 검수/보수 조건 활용 |
| 예측 불확실성 큼 | Quantile 예측의 불확실성 폭, guard, 잔차 안정화 사용 |
| 과대예측 위험 큼 | 낮은쪽 q40 후보와 50:50 혼합 방어 |

> Cold는 “정보가 없어서 대충 예측하는 경로”가 아니라, 같은 작가 가격 기준이 없는 상황을 검색 문맥과 불확실성 방어로 처리하는 전용 경로다.

Cold는 Warm/Warm-lite처럼 같은 작가 유사작품 그룹을 만들 수 없다. 대신 `작품/작가/검색 문맥이 비슷한 패턴`을 모델과 보정표가 사용한다.

| 기준 | Cold에서의 의미 | 최종 가격에 미치는 영향 |
|---|---|---|
| 묶는 기준 | 같은 작가 가격 비교군이 아니라 작품 피처, 작가 메타, 검색 문맥, Quantile 예측의 불확실성 폭 구간으로 묶는다 | LightGBM 후보와 잔차 안정화 구간 결정 |
| 기준가 생성 기준 | 작품/작가/검색 피처를 LightGBM Quantile에 넣어 q10/q40/q50/q90 생성 | q50 계열 대표가격과 q40 보수 후보 생성 |
| 보정 기준 | Quantile 예측의 불확실성 폭 구간별 잔차 중앙값을 더하고, 작가 검색 보정 조회표의 값을 추가 | 반복 편향과 검색 문맥 효과를 반영 |
| 방어 기준 | Quantile 예측의 불확실성 폭이 높고 대표가격이 q40보다 충분히 높을 때만 50:50 guard 적용 | 불확실한 고가 예측의 과대평가를 낮춤 |

## 34. Cold 학습 단계 순서

```text
[Cold 학습 데이터]
  - 같은 작가 이력이 없거나 매칭이 불확실한 조건
  - 작품 피처, 작가 메타, 검색 피처
        |
        v
[LightGBM Quantile 학습]
  - q10/q40/q50/q90 후보 로그가격
  - Quantile 예측의 불확실성 폭 = 높은값(q90) - 낮은값(q10)
        |
        v
[검증 잔차 기반 안정화표 생성]
  - Quantile 예측의 불확실성 폭 구간별 잔차 중앙값
  - clip(구간별 보정값, -0.25, +0.25)
        |
        v
[guard 임계값 산출]
  - Quantile 예측의 불확실성 폭 q67 = 1.4612207078910142
  - gap_q50 = 0.07715547281151025
  - weight = 0.50
        |
        v
[작가 검색 보정 조회표 생성]
  - 정규화 작가명/artist_key별 search_delta
  - 과도한 보정 방지를 위한 cap
        |
        v
[동결 산출물]
  Quantile 모델, 잔차 안정화표, guard 조건, 작가 검색 보정 조회표
```

학습 단계에서 실제 가격은 Quantile 모델 학습, 잔차 중앙값, guard 임계값, 조회표 보정값을 만들 때 사용한다. 사용 단계에서는 실제 가격 없이 동결 산출물만 적용한다.

Cold의 “묶음”은 세 가지다.

| 묶음 | 생성 기준 | 사용하는 곳 |
|---|---|---|
| 모델 내부 패턴 묶음 | 작품 크기/매체/지지체, 작가 메타, 검색 문맥이 비슷한 행을 tree가 나눔 | q10/q40/q50/q90 후보 예측 |
| Quantile 예측의 불확실성 폭 묶음 | 높은값(q90) - 낮은값(q10)이 비슷한 작품을 같은 구간으로 묶음 | 구간별 잔차 중앙값 안정화 |
| 검색 보정 조회표 묶음 | 정규화 작가명 또는 artist_key와 검색 문맥 | 작가 검색 보정값 조회 |

따라서 Cold의 기준가는 “같은 작가 과거 가격의 중앙값”이 아니라, 동결된 Quantile 모델이 피처 패턴으로 만든 대표 로그가격이다.

[Cold 입력 작품]

## 36. Cold 피처와 사용처

| 피처 그룹 | 예시 | 사용 단계 | 계산에 미치는 역할 |
|---|---|---|---|
| 작품 크기 | width, height, depth, area, log_area, aspect_ratio | Quantile | 작품의 물리적 가격 기준선 |
| 매체/지지체 | medium_category, support_category, material bucket | Quantile | 재료별 가격 차이 |
| 작품 메타 | 제작연도, 작품 유형, edition 여부 | Quantile | 시기/희소성 보조 |
| 작가 메타 | 생년, 국적, 작품 수, 팔로워, 판매작 수 | Quantile | 작가 시장 위치 |
| 검색 문맥 | 검색 결과 수, 갤러리/미술관 비율, 시장 문맥 | Quantile, 조회표 보정 | 작가 활동성/시장 노출/검색 품질 |
| 동명이인 위험 | 이름 충돌, 무관 검색 결과 비율 | 라우팅/검수/Cold 피처 | 잘못된 작가 문맥 사용 방지 |
| Quantile 산출값 | 낮은값(q10), q40, 중앙값(q50), 높은값(q90), Quantile 예측의 불확실성 폭 | 안정화, guard | 불확실성 판단 |

피처 흐름:

```text
작품/작가/검색 피처
  -> LightGBM Quantile 후보
  -> Quantile 예측의 불확실성 폭으로 불확실성 판단
  -> q40과 대표가격 차이로 guard 판단
  -> 검색 보정 조회표로 최종 보정
```

## 37. Cold 검색 피처

```text
[검색 원천]
  작가명 검색 결과 title/snippet/url
        |
        v
[문맥 분류]
  - 미술 문맥 비율
  - 갤러리/미술관 문맥 비율
  - 시장/거래 문맥 비율
  - 동명이인 의심 문맥 비율
        |
        v
[검색 피처]
  검색 결과 수
  검색 품질 점수
  search_art_match_ratio
  search_gallery_ratio
  search_market_ratio
  search_homonym_risk_ratio
```

| 피처 | 의미 | 사용 |
|---|---|---|
| `search_art_match_ratio` | 검색 결과가 미술 문맥과 맞는 비율 | Quantile |
| `search_gallery_ratio` | 갤러리/미술관 문맥 비율 | Quantile, 조회표 보정 |
| `search_market_ratio` | 거래/시장 문맥 비율 | Quantile, 조회표 보정 |
| `search_homonym_risk_ratio` | 동명이인 또는 무관 결과 위험 | 라우팅/검수/Quantile |
| `search_quality_score` | 검색 결과 품질 요약 | Quantile |

검색 보정 조회표는 학습된 작가별 검색 문맥 효과를 최종 로그가격에 더하는 단계다.

## 38. Cold 대표 로그가격 안정화

```text
검색피처포함_기초Quantile후보_로그가격 =
  LightGBM Quantile(작품 피처 + 작가 메타 + 검색 피처)

구간별_보정값 =
  Quantile 예측의 불확실성 폭 구간의 검증 잔차 중앙값

검색포함_대표로그가격 =
  검색피처포함_기초Quantile후보_로그가격
  + clip(구간별_보정값, -0.25, +0.25)
```

작동 방식:

| 단계 | 설명 |
|---|---|
| Quantile 후보 | 검색 피처 포함 LightGBM이 대표 로그가격 후보를 만든다 |
| Quantile 예측의 불확실성 폭 구간화 | 높은값(q90)-낮은값(q10) 폭이 비슷한 작품끼리 묶는다 |
| 잔차 중앙값 | 검증 데이터에서 같은 폭 구간의 반복 편향을 계산한다 |
| clip | 구간별 보정이 과도하게 움직이지 않도록 ±0.25 log로 제한 |

Quantile 예측의 불확실성 폭이 넓은 작품은 불확실성이 큰 작품이다. 이 구간에서 반복적으로 생기는 편향을 검증 잔차로 안정화한다.

## 39. Cold 과대예측 방어 guard

```text
방어조건 =
  Quantile 예측의 불확실성 폭 >= 1.4612207078910142
  AND
  검색포함_대표로그가격 - 낮은쪽40퍼센트기준_로그가격
    >= 0.07715547281151025

방어조건 통과 시:
  과대예측방어_로그가격 =
    0.50 * 검색포함_대표로그가격
    + 0.50 * 낮은쪽40퍼센트기준_로그가격
```

| 값 | 의미 | 근거 |
|---|---|---|
| `1.4612207078910142` | Quantile 예측의 불확실성 폭 q67 | 검증 데이터에서 산출 |
| `0.07715547281151025` | 대표가격 - q40 gap q50 | 검증 데이터에서 산출 |
| `0.50` | 대표가격과 q40을 반반 섞는 guard weight | 동결 guard 설정 |

guard는 학습 모델이 아니라 고정 조건부 방어 규칙이다. 불확실성이 크고 대표가격이 낮은쪽 후보보다 충분히 높을 때만 하향한다. 조건이 통과하지 않으면 대표 로그가격을 그대로 유지한다.

## 40. Cold 작가 검색 보정 조회표

```text
작가검색보정_로그값 =
  작가검색보정조회표[정규화작가명]

최종_Cold_로그가격 =
  과대예측방어_로그가격
  + 작가검색보정_로그값
```

| 항목 | 의미 | 왜 필요한가 |
|---|---|---|
| 조회표 | 미리 만든 표에서 값을 찾는 방식 | 운영 사용 때 새로 학습하지 않고 고정 보정값 적용 |
| search_delta | 작가 검색 문맥이 검증 데이터에서 반복적으로 만든 로그가격 보정값 | 검색 문맥이 설명하는 작가별 잔차 반영 |
| clip/cap | 과도한 작가별 보정 방지 | 검색 결과 품질 변동에 따른 과보정 방어 |

작동 흐름:

```text
정규화작가명 또는 artist_key
  -> 작가 검색 보정 조회표에서 값 확인
  -> 보정값을 cap 범위 안에서 적용
  -> 과대예측방어_로그가격에 더함
```

## 44. 세 경로는 단일 모델인가

세 경로는 하나의 단일 모델이 아니라, `학습된 모델 + 고정 통계/규칙 + 후처리`를 결합한 앙상블형 하이브리드 구조다.

| 경로 | 학습된 모델/계수 | 고정 통계/규칙 | 사용 단계에서 하는 일 |
|---|---|---|---|
| Warm | Huber 잔차 회귀, 큰오차방어 Huber meta-model, 버킷순차보정의 CatBoost/Huber 모델 | 유사작품 찾기 단계, 70:30/85:15 후보 가중, 75:25 보조안정, clip, 위험도임계값, 대안교체최소차이 | 같은 작가 기준가격 위에 동결 모델과 규칙을 순서대로 적용 |
| Warm-lite | 전체 피처 기반 LightGBM Quantile 예측, 저표본 안정화 LightGBM Quantile 예측, LightGBM Huber 잔차 보정 | 1~4건 작가 이력 통계, 이력 찾기 단계, 두 중앙값 예측의 평균, 제한된 잔차 보정, 신뢰도 표시 | 저이력 통계와 작품 피처를 동결 모델에 넣어 로그가격 계산 |
| Cold | LightGBM Quantile 후보 모델 | 검색 피처 생성 규칙, 구간별 잔차 안정화표, guard, 검색 보정 조회표, clip/cap | 작품/작가/검색 피처로 후보를 만들고 고정 방어 규칙을 적용 |

**Huber 설명**

- Huber 자체는 “학습이 필요 없는 모델명”이 아니라 큰 오차에 덜 끌리는 손실/강건 회귀 방식이다.
- 문서에서 `Huber 모델`이라고 부르는 것은 과거 데이터로 Huber 기준 계수/절편을 산출해 동결한 회귀 예측기다.
- 운영 사용 단계에서는 Huber나 CatBoost를 새로 학습하지 않고, 이미 동결된 계수와 tree에 새 작품 피처를 넣어 결과만 계산한다.

## 47. 최종 설명 문장

```text
이 가격 예측 시스템은 하나의 모델이 모든 작품을 맞히는 구조가 아니다.

작가가 확실하고 이력이 5건 이상이면 Warm이 같은 작가 유사작품을 기준으로 계산한다.
작가가 확실하지만 이력이 1~4건이면 Warm-lite가 저이력 통계와 두 중앙값 예측, 제한된 잔차 보정으로 계산한다.
작가 이력이 없거나 매칭이 불확실하면 Cold가 작품 피처, 작가 메타, 검색 문맥과 과대예측 방어로 계산한다.

세 경로 모두 로그가격에서 계산하고, 마지막에 exp()로 원화 가격을 만든다.
학습 때는 실제 가격으로 모델과 보정값을 만들지만, 사용 때는 실제 가격 없이 동결 모델과 입력 피처만 사용한다.
```
