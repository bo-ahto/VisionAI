Track6 후처리 및 모델 고도화 검증 계획

  • 목적: 선정된 Warm / Cold 모델을 실제 가격 예측 서비스에 적용하기 전, 예측 정확도 개선 후보정, 예측값 표시 방식, 신뢰도 기준, 추가 데이터 수집 효과를 검증한다.
  • 기준 모델:
  • Warm: Huber
  • Cold 1순위: CatBoost
  • Cold 보조 비교 후보: LightGBM, Quantile-LAD, HistGradientBoosting
  • 기준 문서:
  • final_model_decision_and_enhancement_plan.md
  • followup_experiment_plan.md
  • 기준 데이터:
  • Track6 고정 split
  • validation: 보정 기준과 정책 결정용
  • test: 최종 확인용
  • 핵심 원칙:
  • 모델 후보는 이미 선정된 상태로 본다.
  • 단, 후처리 기준으로 사용할 피처/구간은 최종 모델 기준 group-drop ablation으로 먼저 검증한다.
  • 후속 실험의 1차 목적은 단일 예측 정확도 개선이다.
  • 후속 실험의 2차 목적은 가격 범위와 신뢰도 표시 안정화이다.
  • Warm / Cold는 합치지 않고 별도 판단한다.
  • test 결과를 보면서 보정 기준을 다시 만들지 않는다.

1. 왜 후처리와 고도화 검증이 필요한가

  • Warm 결과:
  • Test MdAPE 약 22.4%
  • Test p95_APE 약 2.02
  • 단일 가격 예측 서비스 가능성 높음
  • 단, 작가명 매칭 오류와 저이력 작가 위험 존재
  • Cold 결과:
  • CatBoost Test MdAPE 약 48.4%
  • CatBoost Test p95_APE 약 4.42
  • LightGBM Test MdAPE 약 48.0%
  • LightGBM Test p95_APE 약 5.06
  • 단일 가격만 제공하기에는 위험
  • 가격 범위, 신뢰도, 주의 문구 필수
  • 결론:
  • 후처리 전: 최종 피처셋 기준의 group-drop ablation으로 보정 segment 타당성을 먼저 확인
  • Warm: 단일 예측 정확도 유지 + 저이력 작가 보정 검증
  • Cold: 단일 예측 정확도 개선 후보정 우선
  • Cold: 가격 범위와 신뢰도 라우팅은 서비스 안전장치로 병행
  • 가격 범위 보정만으로는 예측 정확도가 올라가지 않음
  • 예측 정확도 개선은 PP1, PP2, PP3, PP4, PP5에서 먼저 검증

2. 예측 정확도를 올리는 후보정 실험 우선순위

  • 0순위: 모델별 피처 영향도 선행 검증
  • 목적: 후처리 기준으로 사용할 피처/구간이 실제 성능에 필요한지 확인
  • 기대 효과: 후처리 segment 선택의 설명력 확보
  • 예시: CatBoost depth/3D, medium_shape_bucket 제거 실험, LightGBM size_bucket, support_size_bucket 제거 실험
  • 1순위: validation 기반 편향 보정
  • 목적: 반복적으로 높게/낮게 예측하는 구간 보정
  • 기대 효과: MdAPE, RMSE_log 개선
  • 예시: Cold 대형 작품 과대예측 보정, 특정 재료 과소예측 보정
  • 2순위: 잔차 보정 모델
  • 목적: 1차 모델의 예측 오차를 별도 모델로 보정
  • 기대 효과: 단일 예측값 자체 개선
  • 예시: 실제 로그가격 - 예측 로그가격을 target으로 학습
  • 3순위: 모델 앙상블/블렌딩
  • 목적: 서로 다른 모델의 장점을 평균 또는 가중 평균으로 결합
  • 기대 효과: p95_APE, RMSE_log 안정화
  • 예시: Cold CatBoost + LightGBM + Quantile-LAD
  • 4순위: 저신뢰 구간 라우팅
  • 목적: 특정 조건에서 더 안정적인 모델 또는 보정식 사용
  • 기대 효과: 고위험 구간 p95_APE 감소
  • 예시: 저이력 Warm은 Cold 방식 또는 보수적 보정 사용
  • 5순위: 추가 데이터 수집 후 재학습
  • 목적: 모델이 모르는 외부 작가 정보를 추가
  • 기대 효과: Cold 성능 근본 개선
  • 예시: 전시 이력, 수상, 기관 전시, 갤러리 소속
  • 데이터 고도화 실험의 필수 연결:
  • 추가 데이터를 수집만 하면 채택하지 않음
  • 반드시 모델 피처로 변환해야 함
  • 기준 모델 대비 성능 개선을 확인해야 함
  • 개선이 없으면 수집 우선순위를 낮춤
  • 개선이 있어도 결측률/동명이인 오염률이 높으면 보류

4. PP1 구간별 편향 보정 검증

목적

  • 단일 예측값 자체의 정확도를 올린다.
  • 특정 구간에서 반복적으로 높게 또는 낮게 예측하는 문제를 줄인다.
  • 모델을 교체하지 않고 예측값을 후처리로 보정한다.

가설

  • 가격대, 크기 구간, 작가 이력 구간, 재료/지지체 구간별 반복 편향이 존재하면 validation 기준 보정으로 MdAPE와 RMSE_log를 줄일 수 있다.

보정 후보

  • 가격대별 보정
  • 크기 구간별 보정
  • Warm 작가 학습 작품 수 구간별 보정
  • Cold 작가 메타 정보량 구간별 보정
  • 재료/지지체 구간별 보정
  • Cold 활동량/인지도 구간별 보정
  • 작가명 매칭 신뢰도별 보정

실험 방법

  • validation 예측값에서 구간별 로그 오차 계산
  • 반복적으로 높게 예측하는 구간과 낮게 예측하는 구간 탐색
  • validation 기준 보정값 생성
  • 보정 공식 적용
  • residual_log = 실제 로그가격 - 예측 로그가격
  • 구간 보정값 = 해당 구간 residual_log의 median
  • 보정 예측 로그가격 = 기존 예측 로그가격 + 구간 보정값
  • 보정 예측 가격 = exp(보정 예측 로그가격)
  • 구간 sample 수가 부족하면 상위 구간 보정값 사용
  • 예: 세부 재료 구간 부족 시 재료 대분류 보정값 사용
  • 예: 작가 이력 구간 부족 시 전체 Warm 보정값 사용
  • test에 보정값을 한 번만 적용
  • 보정 전후 성능 비교

검증해야 하는 보정 단위

  • Warm 우선 보정 단위:
  • 작가 학습 작품 수 구간
  • 작가명 계수 안정성 구간
  • 가격대 구간
  • 크기 구간
  • 재료/지지체 구간
  • Cold 우선 보정 단위:
  • 가격대 구간
  • 호수/크기 구간
  • 재료/지지체 구간
  • 작가 메타 정보량 구간
  • 활동량/인지도 정보 구간

확인 지표

  • 보정 전후 MdAPE
  • 보정 전후 p95_APE
  • 보정 전후 RMSE_log
  • 보정 전후 Within_30
  • 보정 전후 Within_50
  • 구간별 오차 변화

판단 기준

  • 전체 MdAPE가 보정 전보다 낮아져야 함
  • RMSE_log가 보정 전보다 낮아지거나 최소한 유지되어야 함
  • p95_APE가 악화되면 보류
  • 특정 구간만 좋아지고 전체가 나빠지면 보류
  • 보정 규칙이 너무 복잡하면 보류
  • sample 수가 부족한 구간 보정은 보류
  • 보정값이 과도하게 커서 예측 가격을 크게 흔들면 보류

결과 활용

  • Warm 보정 정책
  • Cold 보정 정책
  • 가격대별 편향 보정 여부
  • 보정 전후 성능표
  • 운영 적용 가능한 보정 규칙 목록

5. PP2 잔차 보정 모델 검증

목적

  • 1차 모델이 남긴 오차를 별도 모델로 학습한다.
  • 단순 구간 보정보다 세밀한 예측값 보정이 가능한지 확인한다.
  • Cold 단일 예측 정확도 개선 가능성을 우선 검증한다.

가설

  • 기준 모델 예측값과 입력 피처를 함께 사용하면, 남은 오차 패턴을 학습해 단일 예측값의 MdAPE를 낮출 수 있다.

잔차 정의

  • 기준 예측값:
  • pred_log
  • 실제 로그가격:
  • actual_log
  • 잔차:
  • residual = actual_log - pred_log
  • 보정 후 예측값:
  • corrected_pred_log = pred_log + residual_model_prediction

실험 방법

  • validation을 내부 학습/검증으로 다시 나눈다.
  • 기준 모델 예측값을 생성한다.
  • 잔차를 target으로 둔다.
  • 잔차 보정 모델 후보를 비교한다.
  • Ridge
  • Huber
  • LightGBM
  • CatBoost
  • 최종 잔차 보정 모델을 test에 한 번 적용한다.

잔차 모델 입력 후보

  • 기준 모델 예측값
  • 기준 모델 예측 로그가격
  • 작품 크기
  • 재료/지지체
  • 작가 메타 정보량
  • 작가 활동량/인지도
  • 신뢰도 후보 피처

확인 지표

  • 보정 전후 MdAPE
  • 보정 전후 RMSE_log
  • 보정 전후 p95_APE
  • 보정 전후 Within_30
  • 잔차 모델 과적합 여부

판단 기준

  • validation과 test 모두에서 MdAPE 개선
  • RMSE_log 악화 없음
  • p95_APE 악화 없음
  • 잔차 모델이 너무 복잡하면 보류
  • test에서만 좋아지면 채택하지 않음

결과 활용

  • Cold 예측 정확도 개선 후보
  • Warm 저이력 작가 보정 후보
  • 최종 운영 모델의 2단계 보정 구조 검토

6. PP3 모델 앙상블/블렌딩 검증

목적

  • 한 모델의 약점을 다른 모델로 보완한다.
  • Cold에서 CatBoost 단독보다 안정적인 조합이 있는지 확인한다.
  • p95_APE와 RMSE_log 개선 가능성을 확인한다.

가설

  • CatBoost, LightGBM, Quantile-LAD처럼 성격이 다른 모델을 결합하면 큰 오차 위험을 줄일 수 있다.

실험 방법

  • 같은 피처셋으로 여러 모델 예측값 생성
  • validation에서 가중치 후보 탐색
  • 단순 평균
  • MdAPE 기준 가중 평균
  • RMSE_log 기준 가중 평균
  • p95_APE 방어형 가중 평균
  • 선택한 가중치를 test에 한 번 적용

후보 조합

  • Cold:
  • CatBoost + LightGBM
  • CatBoost + Quantile-LAD
  • CatBoost + HistGradientBoosting
  • CatBoost + Quantile-LAD + HistGradientBoosting
  • Warm:
  • Huber + Linear Regression
  • Huber + Ridge
  • Huber + 작가명 교차항 후보

확인 지표

  • MdAPE
  • RMSE_log
  • p95_APE
  • Within_30
  • 모델별 예측 분산

판단 기준

  • CatBoost 단독보다 Cold MdAPE 개선
  • p95_APE가 악화되지 않음
  • 가중치가 단순하고 재현 가능함
  • 특정 모델 하나가 압도적으로 좋으면 앙상블 보류

결과 활용

  • Cold 단일 예측 정확도 개선
  • 큰 오차 방어용 보조 모델 후보

7. PP4 예측값 캘리브레이션 검증

목적

  • 예측값의 가격대별 치우침을 줄인다.
  • 모델이 낮은 가격대와 높은 가격대에서 각각 과대/과소 예측하는지 보정한다.

가설

  • 로그가격 구간별로 예측값을 재보정하면 전체 MdAPE와 가격대별 오차 균형이 개선될 수 있다.

실험 방법

  • validation 예측값을 가격대 구간으로 나눈다.
  • 100만 원 미만
  • 100만~300만 원
  • 300만~1,000만 원
  • 1,000만 원 이상
  • 각 구간별 실제 로그가격과 예측 로그가격의 관계를 확인한다.
  • 보정 함수 후보를 비교한다.
  • 선형 캘리브레이션
  • isotonic regression
  • 구간별 median residual 보정
  • test에서 보정 전후 비교

확인 지표

  • 전체 MdAPE
  • 가격대별 MdAPE
  • 전체 RMSE_log
  • 가격대별 RMSE_log
  • p95_APE
  • 과대예측/과소예측 비율

판단 기준

  • 전체 MdAPE 개선
  • 특정 가격대 악화 제한
  • p95_APE 악화 없음
  • 보정 함수가 단순하고 설명 가능함

결과 활용

  • 가격대별 예측값 보정
  • 고가 작품 과대/과소 예측 완화
  • 서비스 가격대별 신뢰도 문구 개선

8. PP5 신뢰도 기반 모델 라우팅 검증

목적

  • 모든 작품에 같은 모델을 쓰지 않고 조건별로 더 안정적인 모델을 선택한다.
  • 특히 Cold 고위험 구간과 Warm 저이력 구간에서 예측 정확도를 개선한다.

가설

  • 저위험 구간과 고위험 구간을 나누면, 구간별 최적 모델 또는 보정식을 적용해 전체 MdAPE와 p95_APE를 개선할 수 있다.

라우팅 후보

  • Warm:
  • 고이력 작가: Warm Huber
  • 저이력 작가: Warm Huber 보정 또는 Cold CatBoost/LightGBM fallback
  • Cold:
  • 메타 충분: Cold CatBoost
  • 메타 부족: Quantile-LAD 또는 보수적 보정
  • 극단 크기: 크기 구간 보정 적용
  • NANT 분류 불명확: 신뢰도 낮음 처리

실험 방법

  • validation에서 라우팅 규칙 후보 생성
  • 규칙별 모델 선택 결과 계산
  • 단일 모델 대비 성능 비교
  • test에서 최종 라우팅 규칙 검증

확인 지표

  • 전체 MdAPE
  • 전체 p95_APE
  • 구간별 MdAPE
  • 구간별 p95_APE
  • 모델 선택 비율
  • 고위험 구간 sample 수

판단 기준

  • 전체 MdAPE 개선
  • 고위험 구간 p95_APE 개선
  • 라우팅 규칙이 설명 가능함
  • sample 수가 적은 규칙은 보류

결과 활용

  • 운영 라우팅 정책
  • 신뢰도별 모델 선택 기준
  • 저신뢰 결과 안내 문구

9. PP6 Warm 가격 범위 보정 검증

목적

  • Warm 예측값을 단일 가격으로만 보여도 되는지 확인
  • Warm에서도 참고 가격 범위를 함께 제공해야 하는지 판단
  • 예측 가격 주변의 실무적 허용 범위 설정

가설

  • Warm은 예측력이 비교적 높기 때문에, 좁은 가격 범위로도 충분한 coverage를 확보할 수 있다.

실험 방법

  • Warm validation에 Huber 모델 적용
  • 예측 가격과 실제 가격의 로그 오차 계산
  • coverage 후보별 가격 범위 계산
  • 70%
  • 80%
  • 90%
  • 각 coverage별 실제 포함률과 범위 폭 확인
  • Warm test에서 최종 후보 범위 한 번만 확인

확인 지표

  • coverage:
  • 예측 가격 범위 안에 실제 가격이 들어온 비율
  • interval width:
  • 가격 범위가 얼마나 넓은지
  • MdAPE:
  • 단일 예측값의 대표 오차
  • p95_APE:
  • 큰 오차 위험

판단 기준

  • 80% coverage 범위가 지나치게 넓지 않으면 채택 후보
  • 90% coverage 범위가 너무 넓으면 보수적 안내용으로만 사용
  • Warm 가격 범위가 실무적으로 이해 가능한 수준이면 서비스 화면 반영

결과 활용

  • Warm 표시 방식 결정
  • 예측가만 표시
  • 예측가 + 참고 범위 표시
  • 예측가 + 신뢰도 표시

10. PP7 Cold 가격 범위 보정 검증

목적

  • Cold 예측값을 단일 가격으로 제공할 수 있는지 확인
  • Cold 가격 범위가 실무적으로 의미 있는지 확인
  • Cold를 “정확한 예측”이 아니라 “참고 추정”으로 보여야 하는지 판단

가설

  • Cold는 단일 가격 오차가 크기 때문에, 가격 범위와 신뢰도 문구를 함께 제공해야 한다.

실험 방법

  • Cold validation에 CatBoost 모델 적용
  • 예측 가격과 실제 가격의 로그 오차 계산
  • coverage 후보별 가격 범위 계산
  • 70%
  • 80%
  • 90%
  • Cold 전체와 주요 slice를 별도 계산
  • 크기 구간
  • 재료 구간
  • 지지체 구간
  • 작가 메타 보유량 구간
  • 활동량/인지도 정보 있음/없음

확인 지표

  • coverage
  • interval width
  • MdAPE
  • p95_APE
  • Within_30
  • slice별 coverage
  • slice별 sample 수

판단 기준

  • Cold 80% coverage 범위가 지나치게 넓으면 단일 예측 서비스 보류
  • 특정 slice에서 범위가 크게 넓으면 고위험 조건으로 분리
  • 저위험 slice에서 범위가 충분히 좁으면 조건부 제공 가능

결과 활용

  • Cold 화면 정책 결정
  • 예측가 + 넓은 가격 범위
  • 참고용 추정 문구
  • 신뢰도 낮음 표시
  • 고위험 조건 경고

11. PP8 신뢰도 점수 및 라우팅 검증

목적

  • 예측 결과마다 신뢰도 등급을 붙일 수 있는지 확인
  • Cold 전체를 한 가지 방식으로 보여주는 문제 방지
  • Warm에서도 저이력 작가를 별도 처리할지 판단

가설

  • 작가 학습 작품 수, 작가 메타 정보량, 작품 극단값을 이용하면 예측 신뢰도를 구분할 수 있다.

후보 신뢰도 변수

  • Warm:
  • 작가 학습 작품 수
  • artist_works_log
  • 작가명 매칭 신뢰도
  • 작품 크기가 학습 분포 안에 있는지 여부
  • Cold:
  • 작가 메타 정보 보유 개수
  • 활동량/인지도 정보 존재 여부
  • NANT 재료/지지체 분류 성공 여부
  • 작품 크기 극단값 여부
  • 작가 외부 정보 출처 수

실험 방법

  • validation 예측 결과를 신뢰도 후보 기준으로 구간화
  • 각 구간별 성능 확인
  • 저위험 / 보통 / 고위험 후보 기준 생성
  • test에서 최종 기준 검증

확인 지표

  • 구간별 MdAPE
  • 구간별 p95_APE
  • 구간별 Within_30
  • 구간별 coverage
  • 구간별 sample 수

판단 기준

  • 고위험 구간:
  • 전체보다 p95_APE가 높음
  • coverage가 낮음
  • sample 수가 충분함
  • 저위험 구간:
  • 전체보다 MdAPE가 낮음
  • Within_30이 높음
  • 가격 범위가 좁음

결과 활용

  • 서비스 신뢰도 등급 정의
  • 높음
  • 보통
  • 낮음
  • 신뢰도별 문구 정의
  • Warm / Cold 라우팅 기준 보완

12. PP9 Warm 저이력 작가 fallback 검증

목적

  • 학습 데이터에 작가가 있어도 작품 수가 적으면 Warm 모델이 불안정한지 확인
  • Warm / Cold 라우팅 기준을 단순 작가 존재 여부에서 확장할지 판단

가설

  • 학습 작품 수가 적은 Warm 작가는 Warm 모델보다 Cold 방식 또는 보수적 범위 제공이 더 안정적일 수 있다.

실험 방법

  • Warm test를 작가 학습 작품 수 기준으로 구간화
  • 1~4개
  • 5~9개
  • 10~29개
  • 30개 이상
  • 같은 작품에 대해 Warm 후보와 Cold 후보를 모두 적용
  • 구간별 성능 비교

확인 지표

  • 구간별 MdAPE
  • 구간별 p95_APE
  • 구간별 Within_30
  • 구간별 sample 수
  • Warm 대비 Cold 성능 차이

판단 기준

  • 저이력 구간에서 Warm p95_APE가 높으면 저신뢰 Warm 처리
  • 특정 구간에서 Cold가 더 안정적이면 fallback 후보
  • sample 수가 부족하면 결론 보류

결과 활용

  • Warm / Cold 라우팅 정책 보완
  • 저이력 작가 안내 문구 정의
  • 작가 데이터 추가 수집 필요 기준 설정

13. PP10 외부 작가 DB 추가 수집 검증

목적

  • 추가 데이터 수집이 실제 성능 개선으로 이어지는지 확인
  • 작가 DB 구축 우선순위를 정한다.
  • 운영에서 자동 매칭 가능한 피처를 선별한다.

수집 우선순위

우선순위수집 항목기대 효과사용 가능 조건
1개인전 수작가 경력 반영작가 DB 자동 매칭
2단체전 수활동 이력 반영작가 DB 자동 매칭
3아트페어 참여 수시장 노출 반영작가 DB 자동 매칭
4주요 기관 전시 여부작가 위상 반영기관명 표준화 필요
5수상 이력외부 인정도 반영수상 등급 정리 필요
6레지던시 이력경력 단계 반영수집 가능률 확인
7언론/비평 기사 수인지도 반영중복 기사 제거 필요
8검색량대중 인지도 반영수집 주기 관리 필요
9갤러리 소속/전속 여부시장 신뢰도 반영운영 입력이 아닌 내부 DB 기준

실험 방법

  • 기존 Warm / Cold 최종 후보를 기준 모델로 둔다.
  • 외부 작가 DB 피처를 하나씩 추가한다.
  • 외부 작가 DB 피처 묶음도 별도로 비교한다.
  • 경력 묶음
  • 수상/기관 묶음
  • 인지도 묶음
  • 갤러리 관계 묶음
  • 전체 작가 DB 묶음
  • 결측이 많은 변수는 원값과 결측 여부를 분리한다.
  • 메타 정보가 있는 작품만 골라 학습하지 않는다.

정확도 개선 연결 방식

  • Step 1: 수집 데이터 표준화
  • 작가 단위 외부 DB 테이블 생성
  • 작가명/생년/국적 기준으로 기존 작가 ID와 매칭
  • 매칭 실패 작가는 별도 리스트업
  • Step 2: 피처 생성
  • 원값 피처 생성
  • 로그 변환 피처 생성
  • 결측 여부 flag 생성
  • 정보 완성도 점수 생성
  • Step 3: 기준 모델 재학습
  • 기존 최종 피처만 사용한 baseline 재학습
  • 같은 train/validation/test split 사용
  • 같은 모델군 사용
  • Step 4: 고도화 피처 추가 모델 학습
  • baseline 피처 + 외부 작가 DB 피처
  • baseline 피처 + 외부 작가 DB 묶음 피처
  • baseline 피처 + 외부 작가 DB 피처 + PP1/PP2 후보정

14. PP11 검색/소셜 인지도 지표 수집 검증

목적

  • 네이버/구글 검색 기반 지표가 작가 인지도와 시장 관심도를 설명하는지 확인
  • 검색/소셜 지표가 Warm 또는 Cold 예측 정확도를 개선하는지 검증
  • 외부 검색 지표를 실제 운영 피처로 쓸 수 있는지 판단

배경 근거

  • 검색량은 대중 관심도와 수요 변화를 반영하는 대리 지표로 연구에서 자주 사용됨
  • 검색 쿼리량은 소비자 행동, 금융 거래량, 경제 지표 예측에 활용된 사례가 있음
  • 검색/소셜 데이터는 노이즈가 크기 때문에 전처리와 검증이 필수
  • 구글 검색 결과 수는 공식 문서상 추정값이며 정확하지 않을 수 있음
  • Google Trends는 공식 API가 제한적이므로 운영 파이프라인에서는 수집 안정성을 별도 검증해야 함

구분후보 지표수집 방법주의점

구글 웹검색작가명 검색 결과 수Google Custom Search JSON APItotalResults는 추정값
구글 트렌드기간별 관심도Google Trends/서드파티/수동 수집 후보공식 API 안정성 검토 필요
SNS/소셜Instagram/YouTube/X 언급량 또는 팔로워공식 API 또는 수동 수집 후보플랫폼별 접근 제한과 정책 확인 필요

18. 참고 리서치 및 수집 기준

  • Google Custom Search JSON API:

  • Naver Search API:
  • 블로그/뉴스/웹문서 등 검색 결과를 JSON으로 수집 가능
  • API 요청에는 Client ID와 Client Secret 필요
  • 검색량 기반 예측 연구:

  • Google Trends 사용 주의:
  • 검색 관심도는 대중 관심도를 보는 데 유용
  • 낮은 검색량, 샘플링, 결측, 노이즈 문제 존재
  • 공식 운영 파이프라인 적용 전 재수집 변동성 검증 필요
