# 후처리 상세 실험 계획서 작성 가이드

- 작성일: `2026-05-29`
- 목적: PP-A1-W, PP-A1-CB 수준의 상세 실험 계획서를 일관된 기준으로 작성하기 위한 공통 작성 규칙을 정의한다.
- 적용 범위: Track6 후처리 실험군 `PP-A` ~ `PP-I`

## 1. 기본 작성 원칙

- 실험 계획서는 단순 아이디어 목록이 아니라, 실제 실행 기준 문서로 작성한다.
- 모든 실험은 기존 모델과 피처를 고정한 뒤, 변경되는 요소를 명확히 분리한다.
- 성능 개선 기대만 쓰지 말고, 왜 이 실험을 하는지 기존 결과와 연결한다.
- validation에서 결정할 것과 test에서 확인할 것을 반드시 분리한다.
- test 결과를 보고 보정값, 보정 강도, 구간 기준, fallback 기준을 바꾸지 않는다.
- 실험이 실패했을 때 baseline을 유지할지, 다른 실험군으로 넘길지까지 명시한다.

## 2. 실험 계획서 필수 구성

| 순서 | 섹션 | 필수 여부 | 작성 목적 |
|---:|---|---|---|
| 1 | 문서 헤더 | 필수 | 실험 ID, 실험명, 대상 모델, 대상 피처셋, 목적을 명시한다. |
| 2 | 실험 배경 | 필수 | 이 실험이 어떤 후처리 그룹에 속하는지 설명한다. |
| 3 | 이전 실험 근거 | 필수 | 기존 실험 결과에서 왜 이 실험이 필요한지 연결한다. |
| 4 | 기준 피처셋 정의 | 필수 | 실험에 사용하는 입력 피처를 고정한다. |
| 5 | 기대 산출값 | 필수 | 보정값, 세그먼트 보정값, calibration 계수 등 기대하는 값을 정의한다. |
| 6 | 실험 조건 통제 | 필수 | 고정값과 변경값을 분리한다. |
| 7 | 모델 입력 전처리 | 필수 | 결측 처리, 인코딩, 스케일링, 모델 설정을 명시한다. |
| 8 | 표준식과 적용식 | 필수 | 일반식과 현재 실험식의 차이를 설명한다. |
| 9 | 보정 강도/안정성 기준 | 조건부 필수 | alpha, 최소 표본 수, fallback이 있으면 반드시 작성한다. |
| 10 | 실험 절차 | 필수 | validation 선택 후 test 고정 적용 순서로 작성한다. |
| 11 | 데이터 누수 방지 기준 | 필수 | validation/test 역할 분리를 명시한다. |
| 12 | 평가 지표 | 필수 | 전체 지표와 실험 전용 지표를 구분한다. |
| 13 | 성공/보류/중단 기준 | 필수 | 채택 조건이 AND인지 OR인지 명확히 쓴다. |
| 14 | 현재 실행 결과 참고 | 조건부 필수 | 이미 실행 결과가 있으면 baseline과 보정 후 결과를 표로 넣는다. |
| 15 | 해석 시 주의점 | 필수 | 적용 범위, 한계, 다른 실험과의 경계를 쓴다. |
| 16 | 실패 시 판단 기준 | 필수 | 미채택 시 baseline 유지 또는 다른 실험군 이동 기준을 쓴다. |
| 17 | 결론 | 필수 | 실험의 핵심 판단과 다음 단계를 요약한다. |

## 3. 문서 헤더 작성 규칙

- 헤더에는 아래 항목을 반드시 포함한다.

```text
- 작성일:
- 실험 ID:
- 실험명:
- 대상 모델:
- 대상 피처셋:
- 실험 목적:
```

- 실험명은 방법과 대상을 같이 드러나게 작성한다.
- 예시는 아래와 같다.

```text
좋음: Cold CatBoost 전체 residual 보정 및 segment 확장 검증
나쁨: CatBoost 보정 실험
```

## 4. 이전 실험 근거 작성 규칙

- 이전 실험 근거는 최소 3가지를 포함한다.
- 어떤 후보가 선정됐는지 쓴다.
- 어떤 성능 문제가 남았는지 쓴다.
- 이번 실험이 기존 결과의 반복인지, 확장 검증인지 명확히 쓴다.

```text
- T6-E006에서 기준 후보를 선정했다.
- T6-E007에서 test baseline 성능을 확인했다.
- 기존 보정 사전 실행 결과에서 어떤 지표가 개선/악화됐는지 확인했다.
- 따라서 본 실험은 신규 피처 탐색이 아니라 후처리 기준 검증이다.
```

## 5. 피처셋 작성 규칙

- 피처셋 이름만 쓰지 않는다.
- 실제 입력 피처 목록을 표로 작성한다.
- 모델별로 추가되는 피처가 있으면 별도 행으로 명시한다.

| 구분 | 사용 피처 |
|---|---|
| 기본 수치 피처 | `width_cm`, `height_cm`, `depth_cm`, `area_cm2`, `log_area`, `aspect_ratio` |
| 기본 범주 피처 | `has_depth`, `is_3d_candidate`, `medium_category`, `support_category` |
| 모델 전용 피처 | 모델별 추가 피처 |

- 피처셋은 후처리 중 변경하지 않는다.
- 피처셋을 변경해야 한다면, 해당 실험은 후처리가 아니라 별도 피처 실험으로 분리한다.

## 6. 고정값과 변경값 작성 규칙

- 모든 계획서에는 아래 블록을 포함한다.

```text
고정: 대상 데이터
고정: train / validation / test split
고정: 모델
고정: 피처셋
고정: 모델 학습 설정
변경: 예측 후 적용하는 보정값 또는 보정 방식
```

- 변경값이 여러 개면 후보 목록을 표로 작성한다.
- 변경값을 늘릴수록 과적합 위험이 커지므로, 후보 수를 제한한다.

## 7. 표준식과 적용식 작성 규칙

- 보정식은 반드시 표준식과 적용식을 나눠 작성한다.

```text
residual = actual - prediction
correction = median(residual)
corrected_prediction = prediction + correction
```

- 로그 가격 예측이면 아래 변환식을 반드시 포함한다.

```text
residual_log = actual_log - pred_log
correction_log = median(residual_log)
corrected_pred_log = pred_log + correction_log
corrected_pred_price = exp(corrected_pred_log)
```

- `median(residual_log)`는 residual_log의 중앙값을 뜻한다. 함수처럼 보이는 추상 표현을 쓰지 말고, 실제 사용할 대표값을 식에 직접 쓴다.
- 실험별 적용식에는 실제 변수명을 사용한다.

```text
warm_global_correction = median(actual_log - pred_log)
corrected_pred_log = pred_log + alpha * warm_global_correction
```

- 세그먼트 보정은 아래 형태로 작성한다.

```text
segment_key = selected_segment(feature_values or leaf_pattern)
segment_correction[segment_key] = median(actual_log - pred_log | segment_key)
corrected_pred_log = pred_log + alpha * segment_correction[segment_key]
```

## 8. validation/test 역할 분리 규칙

- validation에서 결정하는 항목은 아래와 같다.

```text
보정값
보정 강도 alpha
세그먼트 후보
최소 표본 수
fallback 순서
채택 후보
```

- test에서 하는 일은 아래로 제한한다.

```text
validation에서 확정한 규칙을 고정 적용한다.
성능을 최종 확인한다.
unseen rate, fallback rate 같은 적용 안정성을 사후 진단한다.
```

- 금지 표현은 아래와 같다.

```text
test 성능을 보고 alpha를 조정한다.
test 결과에 따라 fallback 순서를 바꾼다.
test에서 잘 나온 세그먼트를 채택한다.
```

## 9. 보정 강도 alpha 작성 규칙

- 보정값을 그대로 적용하지 않고 alpha 후보를 둔다.

```text
alpha 후보 = {0.25, 0.5, 0.75, 1.0}
```

- alpha 선택은 validation 기준으로만 수행한다.
- test에는 validation에서 선택된 alpha를 고정 적용한다.
- 표본 수가 적은 세그먼트는 낮은 alpha만 허용한다.

| validation 표본 수 | 허용 alpha 후보 |
|---:|---|
| `n >= 100` | `0.5`, `0.75`, `1.0` |
| `50 <= n < 100` | `0.25`, `0.5` |
| `30 <= n < 50` | `0.25` |
| `n < 30` | 적용 안 함 |

## 10. 세그먼트/fallback 작성 규칙

- 세그먼트 보정은 최소 표본 수와 fallback 기준을 반드시 포함한다.
- 기본 수치 기준은 아래와 같다.

| 지표 | 기준 | 역할 |
|---|---:|---|
| `segment_coverage` | `>= 0.70` | validation 후보 선택 |
| `fallback_rate` | `<= 0.30` | validation 후보 선택 |
| `unseen_segment_rate` | `<= 0.20` | test 사후 진단 |
| `worsened_segment_count` | `<= improved_segment_count` | validation 후보 선택 |

- fallback 순서는 구체적으로 쓴다.

```text
세부 세그먼트
-> 상위 세그먼트
-> 전체 median residual
-> no_correction
```

- test unseen rate는 사후 진단 지표로만 사용한다.
- test unseen rate를 보고 규칙을 변경하지 않는다.

## 11. 평가 지표 작성 규칙

- 모든 실험은 공통 지표를 포함한다.

```text
MdAPE
p95_APE
RMSE_log
Within_30
Within_50
```

- 실험별 전용 지표가 있으면 별도 표로 작성한다.
- 세그먼트 보정이면 아래 지표를 포함한다.

```text
segment_coverage
fallback_rate
improved_segment_count
worsened_segment_count
unseen_segment_rate
```

- 가격 범위/신뢰도 실험이면 포함률과 범위 폭을 별도로 둔다.

## 12. 성공/보류/중단 기준 작성 규칙

- 채택 조건은 AND 조건인지 OR 조건인지 명시한다.

```text
채택 조건은 아래 채택 항목을 모두 만족하는 경우로 본다.
```

- 기본 채택 기준은 아래와 같다.

```text
채택: MdAPE 개선
채택: p95_APE 악화 없음
채택: RMSE_log 기존 수준 유지
```

- 세그먼트 보정은 아래 기준을 추가한다.

```text
채택: segment_coverage >= 0.70
채택: fallback_rate <= 0.30
채택: worsened_segment_count <= improved_segment_count
```

- 보류 기준도 명시한다.

```text
보류: MdAPE는 개선되지만 p95_APE가 악화되는 경우
보류: p95_APE는 개선되지만 MdAPE가 악화되는 경우
보류: 일부 세그먼트만 개선되고 악화 세그먼트가 많은 경우
```

- 중단 기준도 명시한다.

```text
중단: MdAPE와 p95_APE가 모두 baseline보다 악화되는 경우
미적용: 모든 후보가 baseline보다 안정적으로 낫지 않은 경우
```

## 13. 현재 실행 결과 작성 규칙

- 이미 실행된 결과가 있으면 표로 넣는다.
- baseline과 보정 후 결과를 같은 표에 둔다.
- 결과가 사전 실행인지, 최종 실행인지 구분한다.
- 사전 실행 결과가 좋지 않은 경우에도 숨기지 않고, 왜 추가 검증이 필요한지 쓴다.
- 결과 출처를 반드시 명시한다.
- 동일 실험 결과가 아니라 유사 방식의 결과라면 `사전 실행 결과` 또는 `참고 결과`라고 표시한다.
- 결과 출처에는 최소한 아래 항목을 포함한다.

```text
- 결과 출처:
- 실행 스크립트:
- 결과 파일:
- 보정 규칙 파일:
- 기준 모델:
- 기준 피처셋:
- 비교 방식:
```

| 구분 | method | MdAPE | p95_APE | RMSE_log |
|---|---|---:|---:|---:|
| 보정 전 | `baseline` | `-` | `-` | `-` |
| 보정 후 | `candidate_method` | `-` | `-` | `-` |

## 14. 해석 시 주의점 작성 규칙

- 적용 범위를 명시한다.
- 피처셋이나 모델이 바뀌면 보정값을 재계산해야 한다고 쓴다.
- 다른 실험군과의 경계를 명시한다.
- test 결과를 보고 규칙을 변경하지 않는다고 다시 명시한다.

## 15. 실패 시 판단 기준 작성 규칙

- 실패 시 기준을 반드시 쓴다.
- 기본 판단은 아래와 같다.

```text
채택 기준을 충족하지 못하면 baseline 예측을 유지한다.
특정 구간에서만 가능성이 있으면 해당 구간 실험 또는 조건별 모델 선택 실험으로 넘긴다.
운영 재현성이 낮으면 최종 후보에서 제외한다.
```

## 16. 실험군별 작성 차이

| 실험군 | 문서 작성 초점 |
|---|---|
| PP-A | residual 보정값, 구간 기준, 최소 표본 수, fallback |
| PP-B | OOF residual 생성, 2단계 모델 누수 방지 |
| PP-C | 예측값 calibration 식, 기울기/절편, 비선형 보정 과적합 방지 |
| PP-D | 앙상블 가중치 선택 기준, validation 고정, test 적용 |
| PP-E | 조건별 모델 선택 기준, 운영 시점에 알 수 있는 조건만 사용 |
| PP-F | 가격 범위 포함률, 범위 폭, 신뢰도 등급 |
| PP-G | 외부 데이터 결측률, 매칭률, 신규 피처 추가 여부 |
| PP-H | 검색/소셜 수집 가능성, 동명이인 위험, 재현성 |
| PP-I | 보정 강도, 설정값 민감도, 안정성 확인 |

## 18. 결론

- 앞으로 후처리 상세 실험 계획서는 이 가이드를 기준으로 작성한다.
- 실험 계획서의 핵심은 많이 쓰는 것이 아니라, 실행 기준과 판단 기준을 모호하지 않게 고정하는 것이다.
- PP-A1-W와 PP-A1-CB는 본 가이드의 기준 문서로 사용한다.
