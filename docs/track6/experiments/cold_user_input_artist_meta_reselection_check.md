# Cold 사용자 입력 작가 메타 기반 모델 재선정 점검

- 작성일: 2026-06-18
- 목적: 외부 live 검색을 보류할 경우, Cold 모델을 사용자 입력 작가 메타 + 작품 정보 기반으로 다시 정해야 하는지 확인한다.

## 1. 결론

Cold 모델은 다시 정해야 한다.

현재까지의 운영 방향이 “외부 live 검색 보류”이고, 사용자가 작품 입력 시 알고 있는 작가 정보를 직접 입력하게 하는 방식이라면, 공식 Cold 후보는 아래 조건을 만족해야 한다.

1. `artist_key`를 모델 피처로 쓰지 않는다.
2. 같은 작가 가격 이력이나 작가별 가격 통계를 쓰지 않는다.
3. `artist_key` 기반 lookup 후처리를 쓰지 않는다.
4. 외부 live 검색을 가격 예측 요청 중 직접 호출하지 않는다.
5. 승인된 외부 검색 cache가 없는 경우에도 작동해야 한다.
6. 사용자가 입력 가능한 작가 메타와 작품 정보만으로 feature frame을 만들 수 있어야 한다.

이 기준으로 보면 기존 `search_external_bucket` 계열과 v0.3 `search_delta_lookup` 후처리는 공식 Cold 기본 후보로 쓰기 어렵다. 사용자 입력 메타 기반 후보를 별도로 재선정해야 한다.

## 2. 기존 후보 판정

| 후보 | 판정 | 이유 |
|---|---|---|
| `search_external_bucket` | 보류 | 성능은 좋지만 외부 검색/전시 cache 피처에 의존한다. live 검색 운영 게이트가 통과되기 전에는 공식 후보로 쓰지 않는다. |
| `cmeta1_repro_full` | 보류 | 외부 검색/전시/갤러리 피처가 포함된다. |
| 기존 v0.3 guard+search 후처리 | 제외 필요 | 후처리 입력에 `artist_key` 기반 `search_delta_lookup`가 들어간다. unresolved Cold 원칙과 맞지 않는다. |
| `meta_bucket_raw` | 사용 가능 후보 | 작품 정보 + 작가 메타 + 메타 bucket만 사용한다. 외부 검색과 작가 키 lookup 없이 동작한다. |
| `meta_bucket_raw_lgb_residual_clip` | 사용 가능 후보 | `meta_bucket_raw` 기준가격 위에 모델 내부 residual 보정만 더한다. 외부 검색 피처 없이 쓸 수 있다. |
| `meta_bucket_raw_guard_only_q40` | 재검증 필요 | 이름은 메타 후보지만 현재 스크립트의 guard 조건이 `search_quality_score`를 참고한다. 외부 검색 보류 정책에서는 그대로 쓰면 안 된다. |

## 3. 현재 근거 수치

`PP-CMETA3` strict Cold test 기준이다.

| 후보 | MdAPE | MAPE | p95 APE | 해석 |
|---|---:|---:|---:|---|
| `cmeta1_repro_artwork_only` | 0.482312 | 1.242417 | 4.380572 | 작품 정보만 쓴 기준 |
| `meta_bucket_raw` | 0.468331 | 1.094027 | 3.003857 | 사용자 입력 가능 작가 메타 + 작품 정보 후보 |
| `meta_bucket_raw_lgb_residual_clip` | 0.464247 | 1.085605 | 3.023533 | 중앙/평균 오차는 조금 더 좋고 p95는 소폭 악화 |
| `search_external_bucket` | 0.440549 | 1.037633 | 3.394335 | 외부 검색 cache 의존 후보. 운영 보류 |

해석:

- 사용자 입력 작가 메타를 쓰면 작품 정보만 쓰는 것보다 MdAPE, MAPE, p95가 모두 개선된다.
- 외부 검색 후보가 중앙 오차는 더 좋지만, 운영 보류 조건에서는 공식 후보가 아니다.
- `meta_bucket_raw_lgb_residual_clip`은 `meta_bucket_raw`보다 MdAPE/MAPE가 소폭 좋지만 p95가 약간 나빠진다. 운영 기본 후보는 이 둘을 다시 비교해서 결정해야 한다.

## 4. 사용자 입력 메타 필드 근거

`PP-CDATA` 후속 검증 기준으로, Cold에서 작가 메타는 개수보다 어떤 필드가 채워지는지가 중요했다.

주요 결과:

- 메타 풍부 구간은 빈약 구간보다 관측 MdAPE가 낮다.
- 다만 이 차이는 선택편향이 섞여 있으므로, “메타만 채우면 30% 개선”으로 단정하면 안 된다.
- 수동 입력 개입 실험에서는 `팔로워 + 경력` 조합이 rich subset에서 효과가 컸다.
- 전체 64개 메타 부분집합 재학습에서는 full 메타를 유의하게 이기는 조합은 없었다.

따라서 운영 입력 필드는 아래처럼 설계하는 편이 맞다.

| 입력 권장도 | 필드 | 이유 |
|---|---|---|
| 필수에 가까움 | 작품 크기, 면적, 매체, 지지체 | Cold 기본 가격대를 만드는 핵심 작품 피처 |
| 권장 | 작가 활동량/작품수, 팔로워/인지도, 전시 이력 | 메타 후보에서 가장 설득력 있는 신호 |
| 권장 | 작가 경력 단계 | 단독으로 쓰면 불안정하지만 다른 필드와 함께 쓰면 유효 가능성 |
| 선택 | 국적/활동국가, 갤러리/기관 노출 | 보조 신호 |
| 주의 | 생년 단독, 경력 단독 | 일부 실험에서 노이즈 또는 역효과가 있어 단독 입력으로 강하게 믿으면 안 됨 |

## 5. 권장 재선정 방향

공식 Cold 모델은 다음 2단계로 다시 정한다.

1. 단기 official 후보
   - 외부 검색과 `artist_key` lookup을 모두 제거한다.
   - `meta_bucket_raw` 또는 `meta_bucket_raw_lgb_residual_clip`을 기준 후보로 둔다.
   - 입력 필드는 “사용자가 직접 입력 가능한 작가 메타 + 작품 정보”로 제한한다.

2. 추가 검증 후보
   - `meta_bucket_raw` 위에 search 없는 guard를 다시 실험한다.
   - guard 조건은 `Quantile 폭`, `q50-q40 차이`, `메타 완성도`, `작품 가격대/크기`만 사용한다.
   - `search_quality_score`나 외부 검색 품질 등급은 쓰지 않는다.

## 6. 다음 액션

1. `PP-CMETA3`를 기반으로 `PP-CMETA4_user_input_meta_only` 실험을 만든다.
2. 후보는 아래 네 가지로 제한한다.
   - 작품 only
   - 작품 + 사용자 입력 가능 작가 메타
   - 작품 + 사용자 입력 가능 작가 메타 + meta bucket
   - 위 후보 + search 없는 residual/guard
3. validation/test에서 같은 strict Cold 조건으로 비교한다.
4. official 0.1v Cold 설명에서는 외부 검색 후보와 `artist_key` lookup 후보를 제외한다.
5. 운영 입력 schema에는 사용자가 입력한 작가 메타와 각 필드의 입력 신뢰도를 포함한다.

## 7. 운영 문장 초안

Cold는 같은 작가의 가격 이력을 직접 쓰지 못하는 입력에 적용한다. 이때 official Cold는 외부 live 검색을 가격 예측 요청 중 호출하지 않고, 사용자가 입력한 작가 메타와 작품 정보를 사용한다. 모델은 학습 데이터에서 비슷한 작가 메타와 작품 조건이 어떤 가격 분포를 보였는지 학습한 뒤, 입력 작품의 Quantile 기준가격을 계산한다. 작가 메타가 부족하거나 신뢰도가 낮으면 예측 신뢰도를 낮게 표시하고, 외부 검색 피처는 승인된 cache로 승격된 경우가 아니면 사용하지 않는다.
