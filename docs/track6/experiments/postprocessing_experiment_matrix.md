# Track6 후처리 실험 매트릭스

- 목적: 모델 선정 이후 예측 정확도를 높이기 위한 후처리 실험을 기존 A~K 실험 방식처럼 표로 관리한다.
- 후처리 전 기본 예측 모델:
  - Warm 기본 예측 모델: `Huber(base_existing_combo)`
  - Warm 추가 검증 후보: `CatBoost(base_existing_combo / artist_key + size 계열)`
  - Cold 기본 예측 모델 1순위: `CatBoost(base_medium_shape)`
  - Cold 보조/비교 예측 모델: `LightGBM(base_support_size)`
- 기준 데이터:
  - Track6 고정 데이터 나누기 기준
  - 검증 데이터: 보정값, 조건별 모델 선택 기준, 설정값 조정 기준 결정
  - 최종 테스트 데이터: 확정된 기준을 마지막으로 한 번 확인
- 핵심 원칙:
  - 후처리 전 최종 모델 기준 피처 그룹 제거 실험을 먼저 수행한다.
  - 최종 테스트 결과를 보고 보정 기준을 다시 만들지 않는다.
  - Warm / Cold는 분리해서 판단한다.
  - 후처리 전 기준 모델 결과와 후처리 후 결과를 반드시 비교한다.
  - 운영에서 알 수 없는 값은 보정 기준으로 쓰지 않는다.
  - 실제 가격은 학습 target과 평가 라벨로만 사용한다.
  - 실험 결과는 `MdAPE`, `RMSE_log`, `p95_APE`, `Within_30` 기준으로 본다.

## 후처리 전 기본 예측 모델 정의

이 문서에서 `기준 모델`은 최종 확정 모델이라는 뜻이 아니라, 각 후처리 실험을 적용하기 전에 먼저 예측값을 생성하는 기본 모델을 의미한다.

```text
기본 모델 예측값(pred_log)
-> validation에서 residual_log = actual_log - pred_log 계산
-> 보정값 또는 조건별 정책 생성
-> test에 같은 보정 기준 적용
```

| 구분 | 후처리 전 기본 예측 모델 | 기준 피처셋 | 실제 사용 피처 | 이 모델을 기준으로 보는 이유 |
|---|---|---|---|---|
| Warm 기본 | `Huber` | `base_existing_combo` | `artist_key`, `width_cm`, `height_cm`, `area_cm2`, `log_area`, `depth_cm`, `has_depth`, `is_3d_candidate`, `aspect_ratio`, `is_extreme_aspect_ratio`, `medium_category`, `support_category`, `medium_support_bucket` | 작가 이력이 있는 Warm에서 작가 기준선과 크기 효과를 선형적으로 설명할 수 있음 |
| Warm 추가 검증 | `CatBoost` | `base_existing_combo`, `artist_key + size`, `artist_key + size + material/support` | Warm Huber 기준 피처를 기본으로 두고, 작가 x 크기 x 재료/지지체 조합을 CatBoost가 더 잘 나누는지 확인 | CatBoost 대칭 트리 구조가 작가별 작품 크기 구간을 더 잘 학습할 수 있는지 검증 |
| Cold 기본 | `CatBoost` | `base_medium_shape` | `width_cm`, `height_cm`, `depth_cm`, `area_cm2`, `log_area`, `aspect_ratio`, `has_depth`, `is_3d_candidate`, `medium_category`, `support_category`, `shape_bucket`, `medium_shape_bucket` | Cold는 작가 기준선이 약하므로 작품의 크기, 형태, 재료 조합을 조건별로 나누는 CatBoost가 주 후보 |
| Cold 보조/비교 | `LightGBM` | `base_support_size` | `width_cm`, `height_cm`, `depth_cm`, `area_cm2`, `log_area`, `aspect_ratio`, `has_depth`, `is_3d_candidate`, `medium_category`, `support_category`, `size_bucket`, `support_size_bucket` | LightGBM은 세밀한 구간 분리에 강하므로 Cold tail 위험과 보조 모델 가능성을 확인 |

## 중복/일관성 점검 결과

| 점검 대상 | 문제 | 조치 |
|---|---|---|
| 기존 우선순위 | 바로 PP-A/PP-B/PP-D/PP-E로 들어가면 후처리 segment의 피처 근거가 부족함 | `PRE-PP` 선행 검증 단계를 추가 |
| CatBoost 추가 가설 | Warm/Cold 모두에서 CatBoost 구조가 조건 조합 학습에 유리할 수 있으나 기존 후처리 표에는 별도 검증 단계가 없음 | `PRE-MODEL`을 추가해 Warm/Cold CatBoost 적합성을 먼저 확인 |
| 구분 학습 보정 | CatBoost를 전체로 한 번 학습할지, 조건별로 나누어 학습할지에 따라 시작 기준값과 leaf 값이 달라짐 | `PRE-SPLIT-CB`를 추가해 구분 학습이 보정값을 줄이는지 확인 |
| 보정값 산출 방식 | PP-A가 보정 적용 중심이라 모델별/구간별 보정값을 먼저 넓게 뽑아보는 단계가 부족함 | `PRE-CAL`을 추가해 correction map을 먼저 생성 |
| PP-A2 vs PP-C2 | 가격대별 대표 오차 보정 목적이 거의 동일함 | PP-A2를 대표 실험으로 실행하고 PP-C2는 보류 |
| PP-A2 기존 표현 | `실제 가격 구간`은 운영 시 알 수 없어 보정 기준으로 사용할 수 없음 | `예측 가격 구간`만 보정 기준으로 사용하고 실제 가격은 평가 라벨로만 사용 |
| PP-B1~B3 | 검증 데이터 예측 오차만 학습하면 검증 데이터에 맞춘 보정 모델이 될 위험이 있음 | OOF 교차 예측 기반 오차를 먼저 만들고 실행 |
| PP-G1/PP-H4 | 기존 E/F/G/H/I/J에서 이미 사용한 작가 메타/팔로워와 중복 가능 | 기존 컬럼 재사용이 아니라 신규 수집 또는 보강 데이터일 때만 실행 |
| PP-F1~F4 | 가격 범위/신뢰도는 단일 예측 정확도 개선 실험이 아님 | 정확도 개선 후보정과 분리해 서비스 표시 안정화 실험으로 관리 |
| PP-I1~I2 | 후처리라기보다 모델 설정값 튜닝에 가까움 | 후순위로 두고 모델 튜닝/민감도 확인 항목으로 표시 |
| 모델별 커스텀 보정 | Huber, CatBoost, LightGBM의 예측 구조가 달라 같은 보정식을 일괄 적용하면 설명력이 약함 | `Group PP-J`를 추가해 모델 구조별 보정 실험을 분리 관리 |
| 추천 보조 조합 | Huber/CatBoost/LightGBM 외에 MAPE와 p95_APE를 낮출 수 있는 보조 조합이 있으나 목적이 PP-D/E와 일부 겹칠 수 있음 | `Group PP-K`로 분리하고, OOF 기반 조합/가격 범위/유사 작품 fallback처럼 목적이 명확한 후보만 검증 |
| PRE-CAL-WCB | Warm CatBoost가 기준 후보로 남지 않으면 Warm CatBoost 보정값 산출은 불필요함 | `PRE-MODEL-WCB`에서 Warm CatBoost가 유효할 때만 조건부 실행 |
| PP-J1~PP-J6 | PP-A/PRE-CAL과 같은 residual을 쓰므로 바로 실행하면 중복 보정이 될 수 있음 | PRE-CAL과 PP-A 결과에서 남은 문제 구간이 확인된 경우에만 모델별 커스텀 보정 실행 |
| PP-K1~PP-K10 | 추천 조합을 test에서 직접 반복 선택하면 test 맞춤 위험이 있음 | validation 또는 OOF에서 조합 기준을 정하고 test는 최종 후보만 확인 |
| PP-K vs PP-L | 둘 다 Huber/Quantile/CatBoost 조합을 다루므로 실행자가 중복 실험으로 오해할 수 있음 | PP-K는 간단한 추천 보조 조합 탐색, PP-L은 MAPE 최적화를 목표로 한 정식 순차 학습 실험으로 분리 |
| PP-L1~PP-L10 | Huber/Quantile/CatBoost 순차 학습은 단계가 많아 validation 과적합 위험이 있음 | `huber_quantile_catboost_mape_optimization_plan.md`를 기준 문서로 두고, Quantile 구간/가중치/residual 보정 기준은 validation 또는 OOF에서만 확정. PP-L7은 L7-0/L7-H/L7-CB/L7-HCB로 나누어 실행 |
| PP-L7 하위 실험 | PP-L7을 한 줄로만 두면 Quantile 구간 생성, Huber 학습, CatBoost 학습, 결합 실험 중 일부가 생략될 수 있음 | PP-L7-0, PP-L7-H, PP-L7-CB, PP-L7-HCB를 별도 row로 분리해 실행 순서를 명시 |
| PP-L8/PP-L9 residual 학습 | Huber 예측값을 같은 학습 데이터 예측으로 만들면 CatBoost residual 모델이 누수될 수 있음 | Huber `pred_log`는 OOF 예측으로 만들고 residual target은 OOF 기반으로만 생성 |
| PP-L8 vs PP-L9 ratio 해석 | `price_range_ratio`와 `residual_range_ratio`를 혼동하면 Quantile 구간 의미가 달라짐 | PP-L8은 가격 예측 범위 ratio, PP-L9는 Huber residual 범위 ratio로 명확히 구분 |
| PP-D 모델 결합 | 이미 보정된 예측값을 다시 평균하면 보정이 이중 적용될 수 있음 | 1차 비교는 보정 전 `pred_log`로 실행하고, 보정 후 결합은 별도 후보로 분리 |
| test 반복 확인 | 많은 후처리 후보를 test로 반복 비교하면 test에 맞춘 선택이 될 수 있음 | validation에서 후보를 고르고 test는 최종 후보만 1회 확인 |

## 공통 채택/중단 기준

후처리 후보는 아래 기준을 만족할 때만 다음 단계로 넘긴다.

| 기준 | 내용 |
|---|---|
| 데이터 기준 | 보정값, 라우팅 기준, 가중치는 validation에서만 정한다. test는 최종 후보 확인에만 사용한다. |
| 표본 수 기준 | segment 보정은 validation rows `>= 50`을 기본 기준으로 한다. 부족하면 상위 fallback을 사용한다. |
| 성능 기준 | MdAPE가 개선되거나, MdAPE가 유지되는 상태에서 p95_APE가 명확히 줄어야 한다. |
| 악화 방지 | p95_APE가 악화되면 대표 정확도가 좋아도 운영 후보로 바로 채택하지 않는다. |
| 중복 방지 | 같은 목적의 실험은 단순한 방식부터 실행한다. 단순 보정이 충분하면 복잡한 보정은 보류한다. |
| 과보정 방지 | 보정값이 큰 segment는 cap을 적용하고, cap 적용 후에도 불안정하면 낮은 신뢰도 후보로만 사용한다. |

## PP-L 전용 채택/중단 기준

PP-L은 MAPE 최적화가 목표이므로 공통 기준에 아래 기준을 추가로 적용한다.

| 기준 | 내용 |
|---|---|
| 우선순위 | MdAPE 유지 또는 개선을 1순위로 두고, 그 범위 안에서 MAPE 감소를 본다. |
| MAPE 채택 | MAPE가 개선되어도 MdAPE 또는 p95_APE가 악화되면 보류한다. |
| 구간 안정성 | stable 구간 성능이 악화되면 전체 MAPE가 좋아도 운영 후보로 바로 채택하지 않는다. |
| ratio 구분 | PP-L8은 `price_range_ratio`, PP-L9는 `residual_range_ratio` 기준으로 결과를 분리 기록한다. |
| OOF 필수 | Huber/CatBoost residual 학습은 OOF 예측 기반 residual만 사용한다. |
| 복잡도 기준 | 단순 Huber, CatBoost, PP-K 조합보다 개선이 명확하지 않으면 PP-L 순차 구조는 보류한다. |
| 필수 baseline | PP-L 후보는 Huber 단독, CatBoost 단독, Quantile q50 단독, 전체 median 보정, Huber+CatBoost residual, Huber+Quantile residual, 단순 가중 앙상블과 비교한다. |
| 통계 검증 | 최종 후보는 paired bootstrap 95% CI, Wilcoxon signed-rank test, seed 반복 평균/표준편차를 기록한다. |
| 민감도 분석 | Quantile 구간 기준 33/66, 50/80, 70/90, price_range_ratio 1.5/2.5배를 비교한다. |
| 실패 기록 | 개선된 후보만 기록하지 않고 보류/실패한 후보와 실패 사유를 함께 남긴다. |

## 실행 정리

| 분류 | 대상 실험 | 판단 |
|---|---|---|
| 1단계 사전 피처 검증 | PRE-PP-CB, PRE-PP-LGB, PRE-PP-W | 후처리 기준으로 쓸 피처/구간이 실제 성능에 필요한지 확인 |
| 2단계 사전 모델 검증 | PRE-MODEL-WCB, PRE-MODEL-CCB | 보정 전에 Warm/Cold CatBoost를 기준 모델 후보로 볼 가치가 있는지 확인 |
| 3단계 구분 학습 검증 | PRE-SPLIT-WCB, PRE-SPLIT-CCB | CatBoost를 조건별로 따로 학습하면 보정값이 줄어드는지 확인 |
| 4단계 보정값 산출 | PRE-CAL-W, PRE-CAL-WCB, PRE-CAL-CB, PRE-CAL-LGB | 후처리 적용 전에 모델별/구간별 반복 오차 지도를 만든다 |
| 5단계 기본 residual 보정 | PP-A1~PP-A8 | PRE-CAL 결과로 보정 segment를 확정한 뒤 실행 |
| 6단계 모델별 커스텀 보정 | PP-J1~PP-J6 | Huber/CatBoost/LightGBM 구조 차이를 반영한 보정 후보를 확인 |
| 7단계 남은 오차 모델 | PP-B4, PP-B1~PP-B3 | 학습 내부 교차 예측(OOF)으로 남은 오차를 먼저 만들어야 누수 위험이 낮음 |
| 8~13단계 정책/표시/추천 조합 검증 | PP-C, PP-D, PP-E, PP-K, PP-L, PP-F | 재보정, 모델 결합, 조건별 선택, 추천 보조 조합, MAPE 최적화 순차 학습, 가격 범위/신뢰도를 순서대로 확인 |
| 보류 | PP-C2 | PP-A2와 목적과 방식이 거의 같아 별도 실험으로 두면 중복됨 |
| 14단계 조건부 외부 데이터 | PP-G1~PP-G5, PP-H1~PP-H6 | 기존 작가 메타 실험과 중복 가능성이 있어 신규 수집 또는 보강 데이터가 있을 때만 실행 |
| 15단계 최종 조정/통합 | PP-I1~PP-I6 | 설정값, 보정 강도, 라우팅 기준을 최종 조정하고 최신 후보까지 통합 검증 |

## 실험군 요약

아래 요약은 실행 순서가 아니라 실험군 이름 기준으로 정렬한다. 실제 실행 순서는 뒤의 `실험 실행 순서` 섹션을 따른다.

| 실험군 | 피처/보정 구성 | 목적 | 핵심 질문 | 실행 상태 |
|---|---|---|---|---|
| PRE-CAL | 상세 보정값 산출 | 모델별/구간별 correction map 생성 | 어떤 구간에서 얼마나 높게/낮게 예측하는가? | 사전 실행 |

실험은 아래 순서로 진행한다. 앞 단계 결과가 다음 단계의 모델, segment, 보정 기준을 결정하므로 순서를 바꾸지 않는다.

| 1 | `PRE-PP-W`, `PRE-PP-CB`, `PRE-PP-LGB` | Warm `Huber(base_existing_combo)`, Cold `CatBoost(base_medium_shape)`, Cold `LightGBM(base_support_size)` | 후처리 기준으로 쓸 피처/구간이 실제 성능에 필요한지 확인 | 모델별 중요 피처 그룹, 제거 시 악화되는 피처 그룹 |
