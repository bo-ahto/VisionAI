공통 계산 단위

모든 점 예측 후보는 원 가격이 아니라 로그 가격에서 보정한 뒤 다시 원 가격으로 환산한다. 이렇게 해야 보정폭이 고가/저가 구간에서 비율 기준으로 작동한다.

predicted_price = exp(predicted_price_log)

component 용어 사전

아래 표는 이 문서의 공식에서 쓰는 설명형 변수명과 실제 입력 component를 연결한 것이다. 모두 원 가격이 아니라 로그 가격 예측값이다. defensive_model_price_log, warm_feature_price_log, similar_artwork_price_log는 이 후처리 단계에서 새로 학습하지 않고 앞단 가격 예측 파이프라인에서 이미 계산되어 들어오는 입력 component다.

1. 70:30 기준가 + 크기/신뢰도 잔차 Huber 보정

운영 기본 후보 fixed test 0.1388 / 0.2730 / 0.8064 0604 stress 0.2731 / 0.3744 / 0.9835

기존 base_price_log를 크게 바꾸지 않고, 남은 잔차 중 유사 작품 기준가의 신뢰도, fallback 여부, 크기 정보로 설명되는 작은 방향만 보정한다. fixed test, 0604 stress, row/artist OOF 반복 검증을 모두 통과했기 때문에 현재 기본 점 예측 후보로 유지한다.

로직 설명

  1. 운영 component로 base_price_log를 만든다.
  2. 학습 구간에서 actual_price_log - base_price_log를 잔차 목표값으로 둔다.
  3. 유사 작품 prior, fallback, shrink gap, 면적, 표본 수, 가격 분산 폭을 피처로 만든다.
  4. 표준화된 피처로 Huber residual model을 학습한다.
  5. 예측 보정값을 [-0.05, 0.05]로 자르고 절반만 반영한다.
  6. 보정된 로그 가격을 exp로 원 가격으로 환산한다.

2. 기준가 gap 잔차 Huber + 저위험 라우팅

연구 후보 fixed test 0.1383 / 0.2729 / 0.8060 반복 all3 0.4333

기본 후보보다 더 낮은 MdAPE/MAPE를 얻기 위해 train-only 기준가 component를 추가로 만들고, 여러 기준가가 서로 크게 어긋나지 않는 행에만 작은 보정을 적용한다. fixed test는 더 좋지만 반복 all3 안정성이 낮아 운영 기본값으로 승격하지 않는다.

로직 설명

  1. 먼저 1번 방법으로 stable_default_price_log를 만든다.
  2. 학습 데이터만 사용해 작가 전체, 작가+크기, 작가+재료/지지체, 작가+크기+재료/지지체, fallback 기준가를 만든다.
  3. 각 기준가와 stable_default_price_log의 차이를 gap 피처로 변환한다.
  4. gap 피처로 actual_price_log - stable_default_price_log 잔차를 예측한다.
  5. 보정폭은 0.005 이내로 자르고 0.50만 반영한다.
  6. 표본 수, 기준가 spread, 면적 범위 조건을 통과한 행에만 보정 후보를 적용한다.

3 약한 Huber 보정 raw_residual_adjustment_log = HuberResidualModel(reference_gap_feature_set, alpha=0.001) small_p95_adjustment_log = clip(raw_residual_adjustment_log, -0.0075, 0.0075) * 0.20 cap은 0.0075이지만 strength를 0.20으로 낮춰 실제 반영폭을 더 작게 만든다.
4 fallback 일치도 gate fallback_gap_is_safe = abs_fallback_to_stable_gap_log <= 0.6607 fallback 기준가와 안정 후보가 크게 충돌하지 않는 validation 하위 75% 구간만 통과시킨다.
5 최종 분기 if fallback_gap_is_safe: final_price_log = stable_default_price_log + small_p95_adjustment_log else: final_price_log = stable_default_price_log fallback이 불안정한 행에서는 보정을 하지 않아 p95 악화 가능성을 낮춘다.
raw_residual_adjustment_log = HuberResidualModel(reference_gap_feature_set) small_p95_adjustment_log = clip(raw_residual_adjustment_log, -0.0075, 0.0075) * 0.20 if abs_fallback_to_stable_gap_log <= 0.6607: final_price_log = stable_default_price_log + small_p95_adjustment_log else: final_price_log = stable_default_price_log

판단: fixed test MdAPE는 가장 낮은 축에 속하지만 반복 all3 안정성이 약하다. 운영 기본 후보가 아니라 p95 방어형 참고 후보로 관리한다.

4. 방향 일치 segment 초미세 이동

tiny correction 후보 fixed test 0.1388 / 0.2729 / 0.8062 0604 stress 0.2727 / 0.3744 / 0.9834

강한 source 후보를 그대로 쓰지 않고, row OOF와 artist OOF에서 실제 잔차 방향과 source 이동 방향이 같은 segment에만 아주 작은 이동을 허용한다. 개선폭은 작지만 fixed test와 0604에서 p95-neutral하게 확인된 후보이다.

로직 설명

  1. 1번 방법으로 stable_default_price_log를 만든다.
  2. component gap, 가격범위 폭, 위험도 피처를 사용해 direction source 후보의 이동 방향을 만든다.
  3. segment별로 median(actual_price_log - stable_default_price_log)와 median(direction_source_price_log - stable_default_price_log)의 부호를 비교한다.
  4. row OOF와 artist OOF 양쪽에서 방향이 같고 p95가 나빠지지 않는 segment만 남긴다.
  5. 통과 segment에서는 direction source 방향으로 0.001 이내의 초미세 이동만 적용한다.

순서도

stable_default_price_log1번 방법의 출력

direction sourcecomponent gap + 가격범위 폭 기반 이동 제안
→
OOF 방향 검증row + artist consensus
→
segment 선택artist level 또는 low width gap 구간
→
초미세 이동tiny_directional_adjustment_log

순서별 공식/로직

순서단계공식 또는 로직해석
1 기본 후보와 source 준비 stable_default_price_log = default_method_final_price_log direction_source_price_log = DirectionSourceModel(component_gap_features, price_range_width_features, risk_feature_set) direction source 후보는 직접 대체하지 않고 이동 방향을 제안하는 용도로만 사용한다.
2 segment별 실제 잔차 방향 actual_residual_direction(segment) = sign(median(actual_price_log - stable_default_price_log)) 각 segment에서 안정 후보가 실제로 높게 예측했는지 낮게 예측했는지 본다.
3 segment별 source 이동 방향 source_move_direction(segment) = sign(median(direction_source_price_log - stable_default_price_log)) direction source 후보가 해당 segment에서 어느 방향으로 움직이려 하는지 계산한다.
4 OOF 방향 합의 oof_direction_consensus = ( row_oof_direction_match and artist_oof_direction_match and p95_not_worse ) row OOF와 artist OOF 양쪽에서 방향이 맞고 p95가 악화되지 않는 segment만 남긴다.
5 segment gate eligible_direction_segment = ( svc_group_level == "artist" or (price_range_width_band == "price_range_width_low" and gap_band == "gap_005_010") ) 검증에서 방향 일치가 확인된 대표 segment 2개만 사용한다.
6 초미세 이동 source_to_stable_move_log = direction_source_price_log - stable_default_price_log tiny_directional_adjustment_log = clip(0.025 * source_to_stable_move_log, -0.001, 0.001) direction source 방향을 2.5%만 따라가고 로그 기준 최대 0.001까지만 이동한다.
7 최종 분기 if oof_direction_consensus and eligible_direction_segment: final_price_log = stable_default_price_log + tiny_directional_adjustment_log else: final_price_log = stable_default_price_log 방향 합의가 없거나 선택 segment가 아니면 안정 후보를 그대로 사용한다.

사용 segment rule

svc_group_level = artist OR price_range_width_band = price_range_width_low AND gap_band = gap_005_010
source_to_stable_move_log = direction_source_price_log - stable_default_price_log tiny_directional_adjustment_log = clip(0.025 * source_to_stable_move_log, -0.001, 0.001) if row_artist_oof_direction_consensus_segment: final_price_log = stable_default_price_log + tiny_directional_adjustment_log else: final_price_log = stable_default_price_log

판단: fixed test와 0604에서는 거의 모든 지표가 아주 작게 좋아지지만, 개선폭이 너무 작고 반복 all3 안정성이 낮다. 기본값 교체보다 검증 후보로 두는 편이 낫다.

5. q10~q90 가격범위 폭 기반 신뢰도 tier

서비스 표시 정책 점 예측 대체 아님 test high tier MdAPE 약 0.1148

이 방법은 점 예측값을 바꾸는 후보가 아니다. 기본 점 예측은 1번 방법으로 유지하고, q10/q50/q90 기반 가격범위 폭과 component 예측값 분산으로 가격 범위와 신뢰도 badge를 나눈다.

로직 설명

  1. 기본 점 예측은 1번 방법의 final_price를 사용한다.
  2. 별도 quantile model에서 range_low_price_log, range_mid_price_log, range_high_price_log를 만든다.
  3. price_range_width_log = range_high_price_log - range_low_price_log를 계산한다.
  4. 주요 component 간 분산인 component_prediction_spread_log와 함께 validation 고정 경계로 tier를 나눈다.
  5. high 구간은 점 예측을 더 신뢰하고, low/very_low 구간은 가격 범위와 검토 필요 표시를 함께 보여준다.

순서도

점 예측1번 방법 final_price
→
가격범위 예측range_low, range_mid, range_high
→
불확실성 계산price_range_width_log + component_prediction_spread_log
→
tier 분기high / medium / low / very_low
→
서비스 표시가격 범위 + confidence tier badge

순서별 공식/로직

순서단계공식 또는 로직해석
1 점 예측 고정 display_point_price_log = default_method_final_price_log display_point_price = exp(display_point_price_log) 신뢰도 tier는 점 예측을 바꾸지 않고 표시 정책만 결정한다.
2 quantile 범위 생성 range_low_price = exp(range_low_price_log) range_mid_price = exp(range_mid_price_log) range_high_price = exp(range_high_price_log) 로그 quantile을 원 가격 범위로 변환한다.
3 불확실성 폭 계산 price_range_width_log = range_high_price_log - range_low_price_log relative_price_range = (range_high_price - range_low_price) / display_point_price 로그 기준 범위 폭과 원화 기준 상대 범위 폭을 함께 본다.
4 component 예측값 분산 계산 component_prediction_spread_log = spread([similar_artwork_price_log, defensive_blend_price_log, warm_feature_price_log, range_mid_price_log]) 주요 예측 component가 서로 얼마나 다른지 측정해 불확실성 신호로 사용한다.
5 tier 분기 if price_range_width_log <= 1.2116 and component_prediction_spread_log <= 0.2611: confidence_tier = high elif price_range_width_log <= 1.5114: confidence_tier = medium elif price_range_width_log <= 1.7065: confidence_tier = low else: confidence_tier = very_low validation에서 고정한 경계값으로 신뢰도 구간을 나눈다.
6 서비스 표시 display = { "display_point_price": display_point_price, "range": [range_low_price, range_high_price], "confidence_tier": confidence_tier } high는 점 예측 중심, low/very_low는 가격 범위와 검토 필요 신호를 함께 노출한다.

연구 후보

기준가 gap low-risk 라우팅은 fixed test에서 더 좋아 보이지만 all3 안정성이 부족하다. 다음 개선 작업은 이 후보의 반복 안정성 보강이 우선이다.

p95 방어 후보

fallback-gap 라우팅과 방향 일치 초미세 이동은 큰 오차를 방어하거나 아주 작은 개선을 만드는 후보지만 운영 승격 기준에는 아직 부족하다.

서비스 표시

가격범위 폭 기반 tier는 점 예측 대체가 아니라 가격 범위, 신뢰도 badge, 검토 필요 여부를 나누는 정책으로 유지한다.
