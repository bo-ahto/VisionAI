# Warm / Warm-lite / Cold 가격 예측 모델 상세 발표 스크립트

- 대상 슬라이드: `partner_warm_cold_best_model_detailed_presentation.md`
- 기준 리포트: `partner_warm_cold_best_model_report.html`
- 권장 시간: 발표 150~180분 + 질의 30분
- 발표 방식: 각 경로를 `목적 -> 피처 -> 계산 순서 -> 예시 -> 성능 근거` 순서로 설명
- 주의: 현재 운영 라우팅은 `0.1v API` 기준으로 설명한다. 내부 artifact 버전명은 API 버전으로 읽지 않는다.

## 0. 타이틀 슬라이드

- 예상 시간: 2분

오늘 발표에서는 Warm, Warm-lite, Cold 가격 예측 모델을 각각 따로 설명하겠습니다. 발표의 중심은 모델 이름이나 실험 ID가 아니라, 실제 입력 작품이 어떤 조건에서 어떤 경로로 들어가고, 그 경로 안에서 어떤 피처와 산식을 거쳐 최종 가격이 만들어지는지입니다.

발표 시간은 질의까지 포함하면 길게 잡는 것이 맞습니다. Warm만 해도 유사작품 비교군, 보조안정 예측값, 버킷순차보정, Huber 잔차 보정, 위험도 라우터가 있고, Warm-lite와 Cold도 별도의 계산 구조가 있습니다. 그래서 오늘은 전체를 빠르게 훑기보다, 각 단계의 의미를 충분히 설명하는 방식으로 진행하겠습니다.

## 1. 발표 목표와 진행 방식

- 예상 시간: 4분

오늘 발표의 목적은 모델을 이름이나 성능 숫자로만 소개하는 것이 아니라, 실제 가격 예측값이 어떤 순서로 만들어지는지 설명하는 것입니다. 이 모델은 단일 회귀 모델 하나가 모든 작품을 같은 방식으로 처리하는 구조가 아닙니다. 입력 작품의 정보 조건에 따라 Warm, Warm-lite, Cold로 나뉘고, 각 경로가 쓰는 피처와 보정 방식이 다릅니다.

오늘은 다섯 가지 질문에 답하는 방식으로 진행하겠습니다. 첫째, 어떤 작품이 어떤 경로로 가는지입니다. 둘째, 각 경로에서 어떤 피처를 쓰는지입니다. 셋째, 로그가격이 어떤 순서로 계산되는지입니다. 넷째, 왜 그런 보정이나 방어 로직을 넣었는지입니다. 다섯째, 그 구조가 어떤 실험 근거로 검증됐는지입니다.

발표 흐름은 공통 라우팅을 먼저 설명하고, 그 다음 Warm, Warm-lite, Cold를 같은 구조로 반복합니다. 이렇게 해야 듣는 사람이 세 경로를 따로 외우지 않아도 됩니다. "이 작품은 왜 Warm인가", "왜 이 작품은 Warm-lite인가", "Cold는 왜 검색 피처가 필요한가"를 같은 기준으로 이해할 수 있습니다.

## 2. 현재 0.1v API 라우팅 기준

- 예상 시간: 5분

먼저 전체 라우팅입니다. 현재 0.1v API는 작품이 들어오면 바로 가격 모델을 돌리지 않습니다. 먼저 작가 매칭이 얼마나 확실한지 보고, 그 다음 같은 작가의 사용 가능한 가격 이력이 몇 건인지 확인합니다.

작가매칭신뢰도점수가 0.80 이상이고 같은 작가 이력이 5건 이상이면 Warm입니다. 이 경우에는 작가 본인의 가격 이력이 충분하므로, 같은 작가의 유사작품 가격대를 기준으로 삼을 수 있습니다. 작가매칭신뢰도점수가 0.80 이상이지만 이력이 1건에서 4건이면 Warm-lite입니다. 이 구간은 이력이 적지만 0건은 아니기 때문에, Cold로 보내지 않고 저이력 전용 모델을 씁니다.

그 외에는 Cold 또는 검수대기입니다. 같은 작가 이력이 없거나, 작가 매칭이 불확실하거나, 동명이인 위험이 있으면 같은 작가의 과거 가격을 기준으로 삼는 것이 위험합니다. 이때는 작품 피처, 작가 메타, 검색 문맥, 불확실성 방어를 쓰는 Cold 경로로 갑니다.

여기서 중요한 점은 세 경로가 성능 순서로 줄 세운 모델이 아니라는 것입니다. Warm, Warm-lite, Cold는 서로 다른 정보 조건을 처리하기 위한 별도 경로입니다.

## 3. 라우팅 값 1: 작가매칭신뢰도점수

- 예상 시간: 6분

라우팅의 첫 번째 값은 작가매칭신뢰도점수입니다. 이 값은 입력 작가가 학습 데이터의 특정 작가와 같은 사람인지 판단하는 점수입니다. 작가키가 직접 일치하면 점수는 1.00입니다. 이 경우는 이름이 비슷한 수준이 아니라 내부 식별자가 같은 작가를 가리킨다고 보는 경우입니다.

작가키가 없거나 신뢰하기 어렵다면 이름일치점수, 보조정보일치점수, 학습작가등록점수, 동명이인위험점수, 핵심정보충돌점수를 조합합니다. 이름일치점수는 정규화 작가명이나 문자열 유사도로 계산합니다. 여기서 문자열 유사도는 두 작가명 문자열이 글자 단위로 얼마나 비슷한지를 0~100점으로 환산한 값이고, 내부 matcher에서는 fuzzy ratio라고 부르는 계열입니다.

보조정보는 생년, 국적, 외부 작가 식별자처럼 이름 외에 같은 작가인지 확인할 수 있는 근거입니다. 동명이인 위험은 같은 이름의 다른 작가 후보가 있는지 보는 값입니다. 핵심정보충돌은 생년이나 외부 식별자가 서로 맞지 않는 경우입니다.

이름이 같아도 보조정보가 없고 동명이인 후보가 있으면 Warm으로 보내면 안 됩니다. 잘못된 작가 이력으로 Warm 가격을 만들면 Cold보다 더 나쁜 예측이 나올 수 있기 때문입니다. 그래서 작가매칭신뢰도점수는 성능 이전에 계산 안전성을 지키는 값입니다.

## 4. 라우팅 값 2: 같은작가_사용가능가격이력수

- 예상 시간: 5분

두 번째 값은 같은작가_사용가능가격이력수입니다. 이 값은 단순히 학습 데이터에 작가 이름이 몇 번 등장했는지를 뜻하지 않습니다. 가격 예측 기준으로 실제 사용할 수 있는 같은 작가의 가격 이력 수입니다.

포함되는 데이터는 같은 작가로 확정됐고, 실제 가격값이 있으며, 로그가격 계산이 가능하고, 예측 대상 작품과 중복되지 않는 작품입니다. 반대로 가격이 없거나 0 이하인 행, 동일 작품 또는 동일 거래의 중복, 평가 대상의 정답 가격, 작가 매칭이 불확실한 후보는 제외합니다.

현재 0.1v API 기준으로 이력 5건 이상이면 Warm, 1~4건이면 Warm-lite, 0건이면 Cold 또는 검수대기입니다. 여기서 자주 헷갈리는 것이 Warm 내부의 "최소 표본 1"입니다. 최소 표본 1은 Warm 진입 조건을 1건으로 낮췄다는 뜻이 아닙니다. 이미 Warm에 들어온 5건 이상 작가 안에서, 더 좁은 하위 유사작품 비교군을 1건부터 인정한다는 뜻입니다.

즉 작가 전체 이력이 1건이면 Warm이 아니라 Warm-lite입니다. Warm의 최소 표본 1은 라우팅 정책이 아니라, Warm 내부 비교군을 더 정밀하게 잡기 위한 기준입니다.

## 5. 공통 계산 단위

- 예상 시간: 5분

세 경로는 모두 내부에서 로그가격을 계산합니다. 가격은 분포가 매우 넓기 때문에 원화 가격을 그대로 모델링하면 큰 가격대 샘플이 오차와 학습을 과도하게 지배할 수 있습니다. 그래서 내부 계산은 로그가격으로 하고, 마지막에 `exp()`를 적용해 원화 가격으로 되돌립니다.

잔차는 실제 로그가격에서 예측 로그가격을 뺀 값입니다. 학습과 검증 단계에서는 잔차를 이용해 보정 모델을 만들거나 성능을 평가합니다. 하지만 운영 예측 시점에는 실제 가격을 모르기 때문에 실제 가격을 입력으로 쓰지 않습니다.

`clip`은 값을 특정 범위 안으로 제한하는 함수입니다. Warm에서는 잔차 보정이 기준가격을 과하게 뒤집지 못하게 하기 위해 쓰고, Cold에서는 구간별 보정값이 너무 크게 움직이지 않도록 쓰입니다.

Quantile은 가격 분포의 특정 위치입니다. Cold에서는 낮은쪽 40% 지점 가격과 Quantile예측구간폭을 직접 산출합니다. Warm에서는 Quantile 폭이 위험도 피처로 사용됩니다. lookup은 미리 만든 조회표에서 값을 찾는 방식입니다. Cold의 작가 검색 보정이 lookup 방식입니다.

## 6. 경로별 성능 기준 요약

- 예상 시간: 6분

이 슬라이드는 세 경로의 성능 기준을 한눈에 보여줍니다. Warm은 fixed test 607건 기준으로 MdAPE 0.104326, MAPE 0.235814, p95 APE 0.739416입니다. Warm-lite는 실존 저이력 작가 leave-one-out을 3회 반복한 1,947행 기준으로 MdAPE 0.109200, MAPE 0.286600, p95 APE 0.876500입니다. Cold는 fixed test 3,099건 기준으로 MdAPE 0.409820, MAPE 0.849260, p95 APE 2.346465입니다.

여기서 `n`은 학습 작품 수가 아닙니다. 성능 지표를 계산한 평가 행 수입니다. Warm과 Cold는 fixed test 행 수이고, Warm-lite는 실존 저이력 작가 649명에 대해 leave-one-out 평가를 3회 반복한 행 수입니다.

또 하나 주의할 점은 Cold 숫자를 Warm과 단순 비교하면 안 된다는 것입니다. Cold는 같은 작가 가격 이력을 쓰지 못하는 훨씬 어려운 조건입니다. Warm과 Warm-lite는 직접 작가 가격 이력을 사용하지만, Cold는 작품/작가/검색 피처로 간접 추정합니다. 따라서 이 표는 "어떤 모델이 더 우수한가"가 아니라 "각 정보 조건에서 어떤 성능 기준을 확인했는가"로 읽어야 합니다.

RMSE log는 Cold 비교값이 없어 세 경로 비교표에는 넣지 않았습니다. Warm과 Warm-lite의 RMSE log는 각 경로 내부 보조 검증값입니다.

## 7. Warm과 Warm-lite를 분리한 실험 근거

- 예상 시간: 10분

이 장은 Warm과 Warm-lite를 왜 나누는지 설명하는 핵심 근거입니다. 먼저 1~4건 이력을 Cold로 보내는 경우를 봤습니다. PP-WCUT4에서 실존 저이력 작가를 leave-one-out으로 검증했을 때 Warm-lite는 0.1092 / 0.2866 / 0.8765였습니다. 같은 행을 Cold로 보내면 0.5429 / 0.9946 / 2.5358입니다. 중앙값 오차만 봐도 Cold가 약 4.97배 큽니다. 즉 1~4건 이력은 Cold로 보내면 안 됩니다.

그 다음 질문은 "그러면 1~4건도 Warm으로 통일하면 되는가"입니다. 이 부분은 PP-WMIN9C와 PP-WMIN9E에서 확인했습니다. 누수 없이 비교 가능한 WMIN8 svc-core proxy를 저이력 동일 행에 적용했을 때, 1~4건 전체에서 Warm-lite가 0.1092 / 0.2866 / 0.8765이고, WMIN8 svc-core proxy는 0.1291 / 0.2932 / 0.9163입니다. 전체 구간에서는 Warm-lite가 전 지표 우세입니다.

k별로 보면 k=2와 k=3은 Warm-lite가 MdAPE, MAPE, p95 모두 우세합니다. k=1은 MAPE만 proxy가 0.0009p 낮고 Warm-lite는 MdAPE와 p95가 우세합니다. k=4는 p95만 proxy가 낮고 Warm-lite는 MdAPE와 MAPE가 우세합니다. 즉 일부 구간에 trade-off는 있지만 1~4건 전체 정책으로 보면 Warm-lite 유지가 현재 근거에 맞습니다.

마지막으로 5건 이상에 Warm-lite를 강제 적용한 반례도 봤습니다. PP-WMIN9D에서 같은 607개 fixed test 행에 Warm-lite를 강제 적용하면 0.108722 / 0.248054 / 0.837824이고, WMIN8은 0.104326 / 0.235814 / 0.739416입니다. 5건 이상 전체에서는 WMIN8이 전 지표 우세입니다. 그래서 현재 0.1v API의 `5건 이상 Warm`, `1~4건 Warm-lite` 분기는 실험 근거와 맞습니다.

## 8. Warm 모델 목적

- 예상 시간: 4분

이제 Warm을 보겠습니다. Warm은 작가 매칭이 확실하고 같은 작가의 사용 가능한 가격 이력이 5건 이상인 작품에 적용됩니다. 이 조건에서는 작가 본인의 과거 가격대가 가장 강한 가격 신호입니다.

Warm의 핵심은 가격을 처음부터 새로 맞히는 것이 아닙니다. 먼저 같은 작가 유사작품 기준가격을 만듭니다. 여기에 보조 안정 Warm 예측값을 일부 섞어서 비교군 기준가격이 너무 흔들리지 않도록 합니다. 그 다음 Huber 잔차 보정으로 남은 반복 오차를 제한적으로 보정합니다. 마지막으로 작품 위험도가 0.2534 이상이고 대안 후보가 기본 후보보다 0.005 log 이상 낮을 때만 보수 대안으로 교체합니다.

따라서 Warm을 한 문장으로 설명하면, "같은 작가 가격 이력을 중심으로 기준가격을 만들고, 작은 보정과 조건부 방어를 더하는 경로"입니다. 이 구조는 같은 작가 가격 이력이라는 강한 신호를 보호하면서도, 큰 오차가 날 수 있는 작품에는 방어 장치를 켜는 방식입니다.

## 9. Warm 전체 계산 흐름

- 예상 시간: 6분

Warm 계산은 큰 흐름으로 다섯 단계입니다. 첫 번째는 같은 작가 유사작품 비교군 기준가격입니다. 작가키, 매체, 지지체, 크기 구간을 사용해서 같은 작가 안에서 가장 가까운 비교군을 찾습니다.

두 번째는 보조안정 Warm 예측값입니다. 이 값은 큰오차방어 Warm 예측값 75%와 버킷순차보정 Warm 예측값 25%를 섞은 값입니다. 같은 작가 비교군 가격이 중심이지만, 단일 비교군에 과의존하지 않기 위해 보조 축을 일부 섞습니다.

세 번째는 기본 후보와 대안 후보 기준가격을 만드는 단계입니다. 기본 후보는 같은작가 유사작품 기준가격 70%, 보조안정값 30%이고, 대안 후보는 같은작가 유사작품 기준가격 85%, 보조안정값 15%입니다.

네 번째는 Huber 잔차 보정입니다. 기준가격에 남은 반복 오차를 예측하고, 그 보정값을 작은 범위로 제한해서 더합니다. 다섯 번째는 위험도 라우터입니다. 위험도가 0.2534 이상이고 대안 후보가 기본 후보보다 0.005 log 이상 낮을 때만 대안 후보를 선택합니다.

## 10. Warm 피처 지도

- 예상 시간: 7분

Warm 피처는 단계별로 역할이 다릅니다. 라우팅 단계에서는 작가매칭신뢰도점수와 같은작가_사용가능가격이력수가 필요합니다. 이 두 값이 Warm 진입 조건을 결정합니다.

유사작품 비교군 단계에서는 artist_key, medium_category, support_category, size_bucket이 중요합니다. 이 피처들은 같은 작가 안에서 어떤 작품들을 비교군으로 삼을지 결정합니다. 비교군이 정해지면 같은작가_유사작품기준로그가격, 비교군표본수로그, 비교군가격IQR 같은 통계 피처가 만들어집니다.

보조안정 단계에서는 큰오차방어 Warm 예측값과 버킷순차보정 Warm 예측값이 들어갑니다. 이 두 축은 Warm 기준가격이 특정 비교군에 과도하게 흔들리는 것을 완충합니다.

Huber 잔차 단계에서는 보조안정값, 수축 prior, 로그면적, 비교군 표본 수, 후보 간 차이 등이 들어갑니다. 이 피처들은 기준가격의 남은 오차가 어떤 방향으로 발생하는지 설명합니다.

마지막 위험도 라우터에서는 Quantile예측구간폭, 후보예측분산, 기준-안정차이, 신뢰도구간, 가격대가 쓰입니다. 이 값들은 가격 자체를 직접 만드는 피처라기보다, 기본 후보를 유지할지 대안 후보로 바꿀지 판단하는 피처입니다.

## 11. Warm 유사작품 비교군 기준가격

- 예상 시간: 7분

Warm의 기준가격 출발점은 같은 작가 유사작품 비교군입니다. 먼저 가장 좁은 조건부터 봅니다. 1순위는 같은 작가, 같은 재료/지지체, 같은 크기 구간입니다. 이 조건에서 자기 fold를 제외하고 1건 이상 있으면 그 비교군을 씁니다. 2순위는 같은 작가와 같은 크기 구간입니다. 3순위는 작가 전체 이력입니다.

여기서 최소 표본 1의 의미가 중요합니다. 이전에는 하위 비교군에 최소 5건이 필요했다면, 현재 Warm 기준에서는 1건부터 인정합니다. 하지만 이것은 이미 Warm에 들어온 5건 이상 작가 안에서 하위 비교군을 더 정밀하게 쓰는 것입니다. 전체 작가 이력 1건인 작가를 Warm으로 보내는 정책이 아닙니다.

자기 가격 누수도 차단합니다. 평가나 검증에서 자기 fold를 제외한 뒤 비교군이 0건이면 다음 우선순위로 fallback합니다. 이렇게 해야 평가 대상 작품의 실제 가격이 자기 피처로 들어가는 문제가 생기지 않습니다.

이 단계의 목적은 같은 작가의 가격 신호를 최대한 구체적인 조건에서 잡는 것입니다. 같은 작가라도 매체, 지지체, 크기가 다르면 가격대가 달라질 수 있기 때문에, 좁은 비교군부터 확인합니다.

## 12. Warm 보조안정 예측값

- 예상 시간: 7분

보조안정_Warm예측로그가격은 Warm 계산에서 갑자기 생기는 임시값이 아닙니다. 이미 학습되고 동결된 두 예측 축을 로그가격 단위에서 섞은 값입니다. 식은 `0.75 * 큰오차방어_Warm예측로그가격 + 0.25 * 버킷순차보정_Warm예측로그가격`입니다.

큰오차방어 Warm 예측값은 여러 Warm 후보 예측값, 후보 간 평균과 분산, 범위, 불확실성 폭을 입력으로 받아 Huber meta-model이 만든 방어형 예측값입니다. 이 값은 기준가격이 큰 오차로 갈 수 있는 상황에서 안정적인 보조 기준 역할을 합니다.

버킷순차보정 Warm 예측값은 작품 크기, 형태, 매체, 지지체를 bucket으로 나누고, CatBoost Quantile, Huber 중심선, CatBoost 잔차 보정을 순서대로 적용해 만든 예측값입니다. 이 축은 작품 조건에 따른 가격 패턴을 다른 방식으로 반영합니다.

Warm의 기준가격은 같은 작가 유사작품이 중심입니다. 하지만 비교군 표본이 작거나 특정 조건에 치우치면 기준가격이 흔들릴 수 있습니다. 보조안정 값은 그 흔들림을 줄이기 위해 일부 섞는 보조 기준입니다.

---

## 13. 버킷순차보정 Warm 예측값 생성

- 예상 시간: 8분

버킷순차보정 Warm 예측값은 단순 산식 하나가 아닙니다. 먼저 작품 기본 피처를 만듭니다. 가로, 세로, 깊이, 면적, 로그면적, 가로세로비, 매체 범주, 지지체 범주, artist_key 등이 들어갑니다.

그 다음 생성 bucket 피처를 만듭니다. size_bucket, shape_bucket, support_size_bucket, medium_shape_bucket, is_large_2d, is_large_3d 같은 값입니다. 연속적인 크기나 형태 정보를 모델이 쓰기 쉬운 구간 신호로 바꾸는 단계입니다.

이 피처들을 바탕으로 CatBoost Quantile이 q10, q50, q90 로그가격을 예측합니다. q90에서 q10을 빼면 Quantile예측구간폭이 됩니다. 이 폭은 해당 작품 가격에 대한 불확실성 신호입니다.

그 다음 Huber 중심선이 안정적인 중심 로그가격을 계산합니다. Huber는 큰 오차 작품에 덜 끌려가는 손실이기 때문에 중심선을 안정적으로 잡는 데 유리합니다. 마지막으로 CatBoost 잔차 보정 모델이 중심선에 남은 오차를 예측합니다. Huber 중심선과 CatBoost 잔차보정값을 더한 것이 버킷순차보정 Warm 예측값입니다.

이 값은 예측 시점에 새로 학습하지 않습니다. 학습은 과거 데이터에서 끝났고, 운영에서는 동결된 bucket 규칙과 모델을 적용만 합니다.

## 14. 버킷순차보정의 학습 단계와 예측 단계

- 예상 시간: 7분

이 슬라이드는 학습과 예측을 구분하기 위한 장입니다. 버킷순차보정 안에는 실제 가격을 사용하는 단계가 있지만, 그것은 학습과 검증 단계입니다. 운영 예측 단계에서는 실제 가격을 알 수 없기 때문에 실제 가격을 쓰지 않습니다.

학습 단계에서는 실제 로그가격이 있는 데이터로 Quantile 모델, Huber 중심선, CatBoost 잔차 모델을 학습합니다. 특히 CatBoost 잔차 모델의 target은 `실제_로그가격 - Huber_OOF_중심선_로그가격`입니다. 여기서 OOF는 out-of-fold입니다. 학습 행을 직접 본 중심선으로 잔차를 만들면 보정 모델이 과하게 좋은 잔차를 학습할 수 있기 때문에, fold 밖 예측을 사용합니다.

예측 단계에서는 새 작품의 피처만 넣습니다. 동결된 Quantile 모델이 q10/q50/q90을 만들고, 동결된 Huber 중심선이 중심 로그가격을 만들고, 동결된 CatBoost 잔차 모델이 잔차보정값을 예측합니다. 그 둘을 더해 버킷순차보정_Warm예측로그가격을 만듭니다.

따라서 "잔차 보정은 실제 가격을 알아야 가능한 것 아닌가"라는 질문에는 이렇게 답하면 됩니다. 실제 가격은 학습 때 잔차 target을 만들기 위해 사용됩니다. 운영 예측에서는 실제 가격 없이 피처만으로 잔차보정값을 예측합니다.

---

## 15. Warm 기준가격 후보 생성

- 예상 시간: 6분

Warm은 기준가격 후보를 두 개 만듭니다. 기본후보_기준가는 같은작가_유사작품기준로그가격 70%와 보조안정_Warm예측로그가격 30%를 섞습니다. 대안후보_기준가는 같은작가_유사작품기준로그가격 85%와 보조안정_Warm예측로그가격 15%를 섞습니다.

기본 후보는 일반적으로 유지하는 기준가격입니다. 같은 작가 유사작품 신호를 중심으로 하되, 보조안정 값을 30% 섞어 완충합니다. 대안 후보는 같은 작가 유사작품 신호를 더 강하게 반영한 후보입니다.

대안 후보를 항상 쓰지는 않습니다. 뒤에서 설명할 위험도 조건과 후보 차이 조건이 모두 맞을 때만 씁니다. 이 구조는 Warm이 전체 작품을 보수적으로 낮추는 모델이 아니라는 점을 보여줍니다. 기본은 안정적인 기준가격을 유지하고, 위험한 작품에서만 대안 후보를 선택합니다.

이 단계에서 중요한 해석은 "기준가격의 중심은 같은 작가 유사작품이고, 보조안정 값은 기준가격이 특정 비교군에 과하게 흔들리지 않도록 일부 섞는 값"이라는 점입니다.

## 16. Warm Huber 잔차 보정

- 예상 시간: 7분

기준가격 후보 두 개가 만들어지면, 각각에 Huber 잔차 보정을 적용합니다. 식은 `후보_보정로그가격 = 후보_기준가 + clip(0.50 * 잔차예측, -0.05, +0.05)`입니다.

여기서 Huber는 단순 규칙이 아니라 학습된 회귀 예측기입니다. Huber 자체는 큰 오차 영향을 완만하게 처리하는 손실 함수이지만, 여기서는 그 손실을 기준으로 회귀계수와 절편을 적합한 모델을 의미합니다.

잔차 예측값을 그대로 더하지 않고 0.50만 반영합니다. 그리고 최종 보정폭은 -0.05에서 +0.05 log로 제한합니다. 이유는 Warm의 주 가격 신호가 같은 작가 유사작품 기준가격이기 때문입니다. 잔차 모델이 기준가격보다 더 강한 결정권을 가지면 표본이 작거나 비교군이 흔들리는 작품에서 가격을 과도하게 뒤집을 수 있습니다.

따라서 Huber 잔차 보정은 새 가격을 처음부터 만드는 단계가 아닙니다. 기준가격에 남은 반복 오차를 작은 폭으로 줄이는 단계입니다.

---

## 17. Warm 위험도 조건부 라우터

- 예상 시간: 7분

Warm의 마지막 단계는 위험도 조건부 라우터입니다. 이 라우터는 기본 후보와 대안 후보 중 어느 것을 최종 가격으로 쓸지 결정합니다.

작품단위위험도에는 다섯 가지 축이 들어갑니다. Quantile예측구간폭이 넓은지, 후보예측분산이 큰지, 현재값과 안정기준 차이가 큰지, 저신뢰 구간인지, 초고가 구간인지입니다. 각 항목을 0~1 범위로 정규화하고 가중합한 뒤 최종 위험도를 0~1로 clip합니다.

대안 후보를 쓰려면 두 조건이 모두 필요합니다. 첫째, 작품단위위험도가 0.2534 이상이어야 합니다. 이 값은 validation 위험도 중앙값 기준입니다. 둘째, 기본후보_보정로그가격에서 대안후보_보정로그가격을 뺀 차이가 0.005 log 이상이어야 합니다. 위험도가 높아도 두 후보가 거의 같으면 바꿀 이유가 없기 때문입니다.

따라서 라우터의 의미는 정성 표현이 아니라 수치 조건입니다. 정확히는 위험도 0.2534 이상이고, 대안 후보가 기본 후보보다 0.005 log 이상 낮을 때입니다.

## 18. Warm 계산 예시 1: 라우팅과 비교군

- 예상 시간: 6분

이제 Warm 계산 예시를 보겠습니다. 입력 작품은 oil/canvas, 100cm x 80cm이고, 작가 매칭 신뢰도는 0.92, 같은 작가 사용 가능 이력은 12건이라고 하겠습니다. 0.92는 0.80 이상이고 12건은 5건 이상이므로 Warm 경로로 들어옵니다.

그 다음 같은 작가 유사작품 비교군을 찾습니다. 1순위는 같은 작가, 같은 oil/canvas, 비슷한 크기 구간입니다. 자기 fold를 제외하고도 남은 작품이 3건이라고 하겠습니다. 이 3건의 로그가격이 18.100, 18.300, 18.500이면 중앙값은 18.300입니다. 이것이 같은작가_유사작품기준로그가격입니다.

비교군표본수로그는 `log1p(3)`이므로 1.386입니다. 비교군가격IQR은 예시에서 0.200입니다. 이 값들은 이후 Huber 잔차 보정이나 위험도 판단에서 비교군 신뢰도를 설명하는 피처로 쓰입니다.

이 단계에서 핵심은 가장 가까운 같은 작가 비교군이 1건 이상 있으면 그 비교군을 우선 사용한다는 점입니다. 단, Warm 진입은 이미 전체 작가 이력 5건 이상을 만족한 상태입니다.

## 19. Warm 계산 예시 2: 보조안정과 후보

- 예상 시간: 7분

예시에서 큰오차방어_Warm예측로그가격은 18.500이라고 하겠습니다. 버킷순차보정 내부에서는 CatBoost Quantile이 q10 17.700, q50 18.250, q90 18.900을 예측합니다. Quantile예측구간폭은 1.200입니다.

Huber 중심선은 18.260이고, CatBoost 잔차보정은 +0.040입니다. 따라서 버킷순차보정_Warm예측로그가격은 18.300입니다. 이 값은 Huber 중심선 18.260에 잔차보정 0.040을 더한 값입니다.

이제 보조안정_Warm예측로그가격을 계산합니다. 큰오차방어 18.500을 75%, 버킷순차보정 18.300을 25% 섞으면 18.450입니다.

그 다음 기본후보_기준가를 만듭니다. 같은작가 유사작품 기준가격 18.300을 70%, 보조안정값 18.450을 30% 섞으면 18.345입니다. 대안후보_기준가는 같은작가 유사작품 기준가격을 85%로 더 강하게 반영하므로 18.323입니다.

이 예시에서는 대안 후보가 기본 후보보다 낮습니다. 하지만 아직 최종 선택은 아닙니다. 다음 단계의 Huber 잔차 보정과 위험도 조건을 통과해야 합니다.

## 20. Warm 계산 예시 3: 잔차, 위험도, 최종

- 예상 시간: 7분

기본 후보 기준가는 18.345였습니다. 여기에 Huber 잔차예측이 +0.020이라고 하면, 0.50을 곱해 +0.010만 반영합니다. clip 범위 안에 있으므로 최종 보정값은 +0.010이고, 기본후보_보정로그가격은 18.355입니다.

대안 후보 기준가는 18.323이었습니다. 잔차예측이 +0.016이면 0.50을 곱해 +0.008만 반영합니다. 대안후보_보정로그가격은 18.331입니다.

이제 위험도를 봅니다. Quantile예측구간폭 1.65, 후보예측분산 0.08, 현재-안정기준차이 0.03 등의 기여를 합쳐 작품단위위험도가 0.348이라고 하겠습니다. 위험도임계는 0.2534이므로 첫 번째 조건을 통과합니다.

두 번째 조건은 기본 후보와 대안 후보 차이입니다. 18.355에서 18.331을 빼면 0.024입니다. 0.005 이상이므로 두 번째 조건도 통과합니다. 따라서 최종 Warm 로그가격은 대안후보_보정로그가격인 18.331입니다. 여기에 `exp()`를 적용하면 약 9,100만 원입니다.

이 예시의 핵심은 최종 값 18.331이 갑자기 선택된 것이 아니라는 점입니다. 비교군 기준가격, 보조안정값, 후보 생성, 잔차 보정, 위험도 조건을 순서대로 통과한 결과입니다.

## 21. Warm 성능과 해석

- 예상 시간: 5분

Warm fixed test 607건 기준 성능은 MdAPE 0.104326, MAPE 0.235814, p95 APE 0.739416입니다. RMSE log는 0.377190입니다. validation OOF 519건에서도 MdAPE 0.094033, MAPE 0.175114, p95 APE 0.571291로 확인됐습니다.

이전 Warm 기준선과 비교하면 MdAPE는 26%, MAPE는 13%, p95는 8% 개선됐습니다. 여기서 중요한 것은 개선의 원인이 단순히 보정 모델을 크게 넣은 것이 아니라는 점입니다. Warm은 유사작품 비교군을 최소 표본 1로 더 정밀하게 잡고, 그 기준가격을 작은 잔차 보정과 위험도 라우터로 방어했습니다.

API parity도 중요합니다. 동결 번들과 실험 산출물의 예측이 607건 모두 일치했고, 최대 로그가격 차이는 5.33e-15였습니다. 이 값은 사실상 수치 오차 수준입니다. 즉 실험에서 확인한 계산과 API 연결 경로가 같은 결과를 내는지 확인됐다는 뜻입니다.

Warm을 대외적으로 설명할 때는 "정밀 유사작품 비교군 기반 위험도 조건부 Warm 모델"이라고 부르면 이해가 쉽습니다.

## 22. Warm-lite 모델 목적

- 예상 시간: 5분

Warm-lite는 작가 매칭이 확실하지만 같은 작가 가격 이력이 1~4건뿐인 작품을 위한 경로입니다. 이 구간은 Warm처럼 5건 이상 이력이 충분하지는 않지만, Cold처럼 이력이 없는 것도 아닙니다.

핵심은 1건이라도 같은 작가의 실제 가격 이력이 있으면 그것이 매우 강한 가격 신호라는 점입니다. PP-WCUT4에서 확인했듯이 동일 행 Cold보다 Warm-lite가 훨씬 좋았습니다. 그래서 이 이력을 버리고 Cold로 보내는 것은 손해입니다.

하지만 1~4건을 5건 이상 Warm 본체와 동일하게 처리하는 것도 현재 근거로는 적절하지 않습니다. Warm 본체에는 정밀 비교군, 보조안정 축, Huber 잔차, 위험도 라우터가 모두 들어가고, 저이력 hold-out에 frozen full WMIN8을 그대로 적용하면 상류 Warm stack 누수 문제가 생길 수 있습니다.

따라서 Warm-lite는 별도 경량 경로입니다. 같은 작가 1~4건 이력 통계와 작품 크기/매체/지지체 피처를 결합하고, 6개 Huber 회귀 예측값을 평균해 최종 로그가격을 만듭니다.

## 23. Warm-lite 계산 흐름

- 예상 시간: 6분

Warm-lite 계산은 먼저 라우팅 조건을 확인합니다. 작가 매칭 신뢰도가 0.80 이상이고 같은 작가 이력이 1~4건이어야 합니다. 이 조건을 만족하면 작가 이력 통계를 만듭니다.

작가 이력 통계는 가장 가까운 이력부터 찾습니다. 같은 작가, 같은 매체/지지체, 같은 크기 구간을 먼저 찾고, 없으면 같은 작가와 같은 크기 구간으로 넓힙니다. 그래도 없으면 같은 작가 전체 1~4건 이력을 사용합니다.

그 다음 Warm-lite 피처를 구성합니다. 작품 크기와 형태 피처, 매체와 지지체, 크기 구간 같은 범주 피처, 작가 로그가격 통계, 작가 면적단가 통계, 표본 수와 매칭 단계가 들어갑니다.

이 피처를 6개 Huber 회귀 구성에 넣고, 여섯 예측값의 평균을 최종 Warm-lite 로그가격으로 사용합니다. 이력 1건이면 `warm_lite_low` 같은 낮은 등급과 검수 플래그를 붙이고, 이력 2~4건이면 표준 Warm-lite 등급으로 봅니다. 마지막으로 `exp()`를 적용해 원화 가격으로 변환합니다.

## 24. Warm-lite 피처 지도

- 예상 시간: 7분

Warm-lite의 피처는 크게 일곱 묶음입니다. 첫째, 작품 크기와 형태입니다. 가로, 세로, 깊이, 면적, 로그면적, 가로세로비, 깊이 존재 여부, 입체 후보 여부가 들어갑니다. 이 값들은 작품 규모와 형태의 가격 차이를 설명합니다.

둘째, 작품 범주입니다. medium_category, support_category, size_bucket, medium_support_bucket 같은 값입니다. 같은 작가라도 oil/canvas와 acrylic/paper의 가격 패턴은 다를 수 있으므로 필요합니다.

셋째, 작가 이력 수입니다. 1건과 4건은 모두 Warm-lite이지만 신뢰도는 다릅니다. 그래서 artist_history_count와 grp_n_log가 들어갑니다.

넷째, 작가 로그가격 통계입니다. median, q25, q75, IQR이 들어갑니다. 저이력 작가의 직접 가격 수준과 가격 분산을 반영합니다.

다섯째, 작가 면적단가 통계입니다. 이력 작품의 로그가격에서 이력 작품의 log_area를 뺀 값을 이용하고, 대상 작품의 log_area를 다시 더해 면적보정 가격 proxy를 만듭니다. 여섯째, 이력 매칭 단계입니다. 가장 가까운 이력을 썼는지, 작가 전체 이력을 썼는지 구분합니다. 일곱째, fallback 통계입니다. 이것은 정상 1~4건 입력에서는 예외 방어용입니다.

---

## 25. Warm-lite 작가 이력 매칭 사다리

- 예상 시간: 5분

Warm-lite의 이력 매칭 사다리는 Warm과 비슷해 보이지만 목적이 다릅니다. Warm은 5건 이상 작가 안에서 정밀 비교군 기준가격을 만드는 것이고, Warm-lite는 1~4건 이력을 최대한 안전하게 통계화하는 것입니다.

1순위는 같은 작가, 같은 매체/지지체, 같은 크기 구간입니다. 가장 가까운 이력입니다. 2순위는 같은 작가와 같은 크기 구간입니다. 매체나 지지체까지 맞추면 표본이 없을 때 한 단계 넓힙니다. 3순위는 같은 작가 전체 1~4건 이력입니다. 이 경우 세부 조건은 약하지만 작가 개인 가격대는 유지됩니다.

4순위 fallback은 동결된 비작가 비교군 통계입니다. 하지만 이것을 오해하면 안 됩니다. Warm-lite는 같은 작가 이력 1~4건이 있어야 들어오는 경로입니다. fallback은 작가 이력 통계를 만들 수 없는 예외 상황이나 입력 결측에 대비한 방어 장치이지, 작가 이력 없이 Warm-lite를 쓰겠다는 뜻이 아닙니다.

이 구조의 핵심은 저이력에서도 가능한 한 작가 개인 가격대를 유지하되, 표본 부족으로 통계가 비는 상황을 방어한다는 점입니다.

---

## 26. Warm-lite Huber 6구성 ensemble

- 예상 시간: 7분

Warm-lite의 최종 모델은 6개 Huber 회귀 예측값의 평균입니다. 여기서 Huber는 손실 함수이지만, 실제로는 Huber loss 기준으로 회귀계수와 절편을 학습한 예측기입니다.

Huber 1~4는 피처를 넓게 씁니다. 작품 크기와 형태 8개, 작가 로그가격 median/q25/q75/IQR, 작가 면적단가 median/IQR, grp_price_proxy, 표본 수와 매칭 단계, 매체/지지체/크기 범주가 들어갑니다. 이 구성은 작가 가격 분포 정보를 최대한 넓게 사용합니다.

Huber 5~6은 조금 더 축약된 입력을 씁니다. q25/q75와 면적단가 IQR처럼 저표본에서 흔들릴 수 있는 피처를 줄입니다. 대신 로그가격 median/IQR, grp_price_proxy, 표본 수, 매칭 단계와 범주 피처를 사용합니다. 이 구성은 저표본 분위수의 흔들림을 줄이는 보수적 축입니다.

최종 Warm-lite 로그가격은 여섯 예측값의 평균입니다. 여러 구성을 평균하는 이유는 저이력 구간에서 한 가지 설정이나 한 가지 통계에 과하게 의존하지 않기 위해서입니다.

## 27. Warm-lite 계산 예시 1: 입력과 작가 통계

- 예상 시간: 6분

예시를 보겠습니다. 작가 매칭 신뢰도는 0.87이고, 같은 작가 사용 가능 이력은 2건입니다. 0.87은 0.80 이상이고, 이력 2건은 1~4건에 들어가므로 Warm-lite 경로입니다.

입력 작품은 acrylic/paper, 72cm x 60cm입니다. 면적은 4,320이고 log_area는 8.371입니다. 가로세로비는 1.200이고, 크기 구간은 예시상 중형입니다.

작가 이력을 조회합니다. 1순위인 같은 작가, 같은 매체/지지체, 같은 크기 구간은 충분하지 않다고 하겠습니다. 2순위인 같은 작가와 같은 크기 구간에서 2건을 찾습니다. 이력 로그가격이 17.450과 17.600이면 중앙값은 17.525입니다. q25는 17.488, q75는 17.563, IQR은 0.075입니다.

이 통계는 단순 평균이 아니라 Huber ensemble에 들어가는 피처입니다. 즉 Warm-lite는 이력 2건의 중앙값만 최종 가격으로 쓰는 것이 아니라, 그 통계와 작품 크기/매체/지지체 피처를 함께 모델 입력으로 사용합니다.

## 28. Warm-lite 계산 예시 2: 면적보정과 ensemble

- 예상 시간: 6분

이번에는 면적보정을 봅니다. 이력 1의 로그가격이 17.450이고 이력 log_area가 8.200이면 면적단가 로그는 9.250입니다. 이력 2는 17.600에서 8.550을 빼서 9.050입니다. 두 값의 중앙값은 9.150입니다.

대상 작품의 log_area는 8.371이므로 면적보정작가기준로그가격은 9.150 + 8.371 = 17.521입니다. 이 값은 이력 작품과 대상 작품의 크기 차이를 반영한 작가 기준가격 proxy입니다.

이제 6개 Huber 예측값을 봅니다. 예시에서는 17.490, 17.530, 17.510, 17.550, 17.500, 17.520입니다. 여섯 값을 더해 6으로 나누면 최종 Warm-lite 로그가격은 17.517입니다.

k가 2이므로 이 예시는 표준 Warm-lite 등급입니다. 마지막으로 `exp(17.517)`을 적용하면 약 4,050만 원입니다. 이 예시에서 중요한 것은 최종 값이 작가 이력 중앙값 하나가 아니라, 면적보정 가격 proxy와 작품 피처, 범주 피처, Huber ensemble을 거쳐 나온 값이라는 점입니다.

## 29. Warm-lite 성능과 유지 근거

- 예상 시간: 7분

Warm-lite의 대표 검증은 PP-WCUT4입니다. 실존 저이력 작가 649명에 대해 leave-one-out 평가를 3회 반복해 총 1,947행을 만들었습니다. Warm-lite 성능은 0.1092 / 0.2866 / 0.8765입니다. 같은 행을 Cold로 보내면 0.5429 / 0.9946 / 2.5358입니다. MdAPE 기준으로 Cold가 Warm-lite보다 4.97배 큽니다.

이 결과는 이력 1~4건을 Cold로 보내지 말아야 한다는 근거입니다. 반대로 1~4건을 Warm 본체로 통일해도 되는지는 PP-WMIN9C와 PP-WMIN9E로 봤습니다. 전체 1~4건에서 Warm-lite는 0.1092 / 0.2866 / 0.8765이고, WMIN8 svc-core proxy는 0.1291 / 0.2932 / 0.9163입니다. 전체 구간에서는 Warm-lite가 전 지표 우세입니다.

k=1과 k=4에는 일부 혼합 결과가 있습니다. k=1은 Warm-lite가 MdAPE와 p95에서 우세하고 proxy가 MAPE만 0.0009p 낮습니다. k=4는 Warm-lite가 MdAPE와 MAPE에서 우세하고 proxy가 p95만 낮습니다. 하지만 정책은 전체 구간과 안정성을 봐야 합니다. k=2와 k=3은 Warm-lite 전 지표 우세이고, 1~4 전체도 Warm-lite 전 지표 우세입니다.

따라서 현재 근거로는 1~4건을 Warm 하나로 통일하기보다 Warm-lite 전용 경로를 유지하는 것이 타당합니다.

## 30. Cold 모델 목적

- 예상 시간: 5분

이제 Cold입니다. Cold는 같은 작가 가격 이력이 0건이거나 작가 매칭이 불확실한 작품에 적용됩니다. Warm과 Warm-lite는 같은 작가 가격 이력을 직접 쓰지만, Cold는 그 신호를 쓸 수 없거나 쓰면 위험한 조건입니다.

그래서 Cold는 작품 피처, 작가 메타, 검색 문맥을 사용합니다. LightGBM Quantile 회귀로 기준 후보와 낮은쪽 40% 기준, Quantile예측구간폭을 만들고, 그 뒤에 대표 로그가격 안정화, 과대예측 방어, 작가 검색 보정 lookup을 순서대로 적용합니다.

Cold의 주요 리스크는 과대예측입니다. 신규 작가나 무이력 작가에서 가격을 너무 높게 잡으면 운영상 문제가 큽니다. 그래서 Quantile 폭이 넓고 대표가격이 낮은쪽 기준보다 충분히 높을 때만 guard를 켜서 하향 방어합니다.

Cold를 한 문장으로 설명하면, "같은 작가 가격 이력이 없는 조건에서 작품/작가/검색 문맥으로 가격을 추정하고, 불확실성이 큰 경우 과대예측을 방어하는 경로"입니다.

## 31. Cold 계산 흐름

- 예상 시간: 6분

Cold 계산은 먼저 원천 피처를 생성합니다. 작품 크기, 매체, 지지체에서 면적, 로그면적, 가로세로비, 크기/형태 bucket 등을 만듭니다. 작가 메타에서는 생년, 국적, 경력 단계, 총 작품 수, 판매 중 작품 수, 팔로워 수, 결측 여부 등을 만듭니다. 검색 스냅샷에서는 검색 결과 수, 미술 문맥 비율, 갤러리/시장 문맥, 동명이인 위험 등을 만듭니다.

그 다음 LightGBM Quantile 회귀가 세 가지 값을 만듭니다. 검색피처포함_기초Quantile후보_로그가격, 낮은쪽40퍼센트기준_로그가격, Quantile예측구간폭입니다.

이 기초 후보를 바로 최종으로 쓰지 않고, Quantile 폭 구간별 잔차 보정으로 대표 로그가격을 안정화합니다. 이후 과대예측 guard 조건을 확인합니다. 조건이 맞으면 대표 로그가격과 낮은쪽40퍼센트기준 로그가격을 50:50으로 섞습니다.

마지막으로 작가 검색 보정 lookup을 적용합니다. lookup에 작가별 보정값이 있으면 더하고, 없으면 0을 더합니다. 최종 로그가격에 `exp()`를 적용해 원화 가격을 만듭니다.

## 32. Cold 피처 지도

- 예상 시간: 7분

Cold 피처는 Warm이나 Warm-lite보다 넓습니다. 같은 작가 가격 이력이 없기 때문에 간접 신호를 최대한 구조화해야 합니다.

작품 크기와 형태 피처는 기본 가격 수준을 잡습니다. width, height, depth, area, log_area, aspect_ratio가 들어갑니다. 매체와 지지체, 크기/형태 bucket은 재료와 크기 조합에 따른 가격 차이를 반영합니다.

작가 메타는 작가 세대, 활동량, 인지도 신호를 줍니다. birth year, nationality, career stage, total works, for sale works, followers 등이 해당합니다. 결측 여부도 별도 피처입니다. 메타 정보가 없다는 사실 자체가 예측 불확실성과 관련될 수 있기 때문입니다.

검색 피처는 Cold에서 매우 중요합니다. 검색 결과 수, 출처 수, 미술 문맥, 전시 문맥, 갤러리 문맥, 시장 문맥, 동명이인 문맥이 들어갑니다. 검색 상호작션 피처도 있습니다. 예를 들어 검색 품질과 log_area를 곱하거나, 미술 문맥 비율과 팔로워 로그값을 결합합니다.

마지막으로 Quantile 산출값이 있습니다. y18_qwidth_pred_log는 상류 대표 후보, lgb_q40_pred_log는 낮은쪽 40% 방어 후보, quantile_width_log는 불확실성 폭입니다.

## 33. Cold 검색 품질 점수

- 예상 시간: 6분

Cold에서 검색 결과 수 자체보다 중요한 것은 검색 결과의 품질입니다. 검색품질점수는 미술 문맥, 신뢰 도메인, 전시 문맥, 시장/거래 문맥, 최근 결과, 검색 제공자 커버리지, 작가명 일치, 동명이인 위험을 조합합니다.

미술 문맥 비율은 검색 결과가 실제 미술 작가 활동과 관련 있는지 보는 값입니다. 신뢰 도메인은 갤러리, 미술관, 경매사 같은 출처인지 확인합니다. 전시 문맥과 시장/거래 문맥은 작가 활동성과 시장성을 간접적으로 보여줍니다.

반대로 동명이인 위험은 감점입니다. 검색 결과가 많아도 같은 이름의 다른 사람이 섞여 있다면 가격 예측에는 위험한 신호입니다. 그래서 동명이인위험비율에는 -0.30 가중이 들어갑니다.

이 점수는 "검색량이 많으니 비싸다" 같은 단순한 신호가 아닙니다. 검색 결과가 미술 가격 문맥에 맞는지, 신뢰 가능한 출처인지, 입력 작가명과 맞는지를 함께 보는 품질 점수입니다.

---

## 34. Cold LightGBM Quantile 산출값

- 예상 시간: 6분

Cold의 LightGBM Quantile 단계는 평균 가격 하나만 예측하지 않습니다. 가격 분포의 특정 위치를 예측합니다. 기초 Quantile 후보는 검색 피처까지 포함한 기준 후보입니다. 낮은쪽40퍼센트기준_로그가격은 조건이 비슷한 작품을 낮은 가격부터 높은 가격까지 줄 세웠을 때 40% 위치의 로그가격입니다. Quantile예측구간폭은 높은 Quantile과 낮은 Quantile의 차이입니다.

여기서 낮은쪽 40% 기준은 가격을 40% 할인한다는 뜻이 아닙니다. 가격 분포에서 40% 위치를 예측한 값입니다. 이 값은 과대예측 위험이 있을 때 대표가격을 낮추는 방어 기준으로 쓰입니다.

Quantile예측구간폭은 불확실성입니다. 높은쪽과 낮은쪽의 예측 차이가 크면 모델이 해당 작품의 가격 범위를 넓게 보고 있다는 뜻입니다. Cold에서는 이 폭을 대표 로그가격 안정화와 guard 조건에 모두 사용합니다.

정리하면 LightGBM Quantile은 Cold에서 기준가격 후보, 방어가격 후보, 불확실성 폭을 동시에 만드는 상류 예측 단계입니다.

---

## 35. Cold 대표 로그가격 안정화

- 예상 시간: 6분

Cold는 LightGBM Quantile의 기초 후보를 그대로 최종 기준가격으로 쓰지 않습니다. Quantile예측구간폭에 따라 구간을 만들고, 같은 구간 안에서 validation 잔차 중앙값을 계산합니다.

잔차는 실제_로그가격에서 검색피처포함_기초Quantile후보_로그가격을 뺀 값입니다. 불확실성 수준이 비슷한 작품끼리는 반복되는 치우침이 있을 수 있습니다. 예를 들어 Quantile 폭이 넓은 구간에서 기초 후보가 지속적으로 낮거나 높게 나오는 패턴이 있을 수 있습니다. 이 패턴을 구간별 잔차 중앙값으로 보정합니다.

다만 구간별 보정값도 무제한 더하지 않습니다. -0.25에서 +0.25 log 범위로 clip합니다. 이렇게 해야 후처리 보정값이 가격을 과도하게 움직이지 않습니다.

운영 예측에서는 실제 가격을 사용하지 않습니다. 구간별 잔차 중앙값은 학습/검증 단계에서 미리 계산해 동결해 둔 값입니다. 운영에서는 새 작품의 Quantile 폭이 어느 구간에 속하는지만 보고, 해당 구간의 동결 보정값을 조회합니다.

---

## 36. Cold 과대예측 방어 guard

- 예상 시간: 7분

Cold의 과대예측 guard는 세 조건이 모두 맞을 때만 켜집니다. 첫째, Quantile예측구간폭이 1.4612207078910142 이상이어야 합니다. 즉 모델이 가격 범위를 넓게 보고 있는 불확실한 작품이어야 합니다.

둘째, 검색포함_대표로그가격과 낮은쪽40퍼센트기준_로그가격의 차이가 0.07715547281151025 이상이어야 합니다. 대표가격이 낮은쪽 기준보다 충분히 높아야 한다는 뜻입니다. 셋째, 낮은쪽40퍼센트기준_로그가격이 실제로 대표 로그가격보다 낮아야 합니다.

세 조건이 모두 참이면 대표 로그가격과 낮은쪽40퍼센트기준 로그가격을 50:50으로 섞습니다. 조건이 하나라도 거짓이면 대표 로그가격을 그대로 둡니다.

이 guard는 모든 Cold 가격을 낮추는 장치가 아닙니다. 불확실성이 크고 대표가격이 낮은쪽 기준보다 충분히 높을 때만 선택적으로 하향합니다. 목적은 평균 오차를 조금 줄이는 것보다, 큰 과대예측 tail을 방어하는 것입니다.

---

## 37. Cold 작가 검색 보정 lookup

- 예상 시간: 6분

과대예측 방어 이후에는 작가 검색 보정 lookup을 적용합니다. lookup은 실시간 검색이나 즉석 학습이 아니라, 미리 만들어 둔 조회표에서 값을 찾는 방식입니다. 여기서는 `search_delta_lookup[artist_key]`로 작가별 검색 보정 로그값을 조회합니다.

lookup에 작가가 있으면 보정값을 최종 로그가격에 더합니다. 보정값은 ±0.20 log 범위로 제한합니다. lookup에 작가가 없으면 보정값은 0입니다. 이 경우에는 guard only로 처리됩니다.

검수 플래그도 여기서 중요합니다. Quantile 폭이 넓으면 불확실성이 큰 작품이므로 낮은 신뢰도 또는 검수 플래그가 필요합니다. lookup이 없으면 검색 보정 근거가 없다는 뜻이므로 이것도 검수 플래그 사유가 됩니다.

검색 보정의 의미는 작가 검색 문맥에서 반복적으로 설명된 잔차를 최종적으로 보정하는 것입니다. 예를 들어 갤러리/미술관 문맥이 강한 작가군에서 특정 방향의 잔차가 반복되면 그 값을 작가별 조회표로 저장해 적용합니다.

## 38. Cold 계산 예시 1: 입력과 Quantile 후보

- 예상 시간: 6분

Cold 예시를 보겠습니다. 작가 매칭 신뢰도는 0.58이고 같은 작가 사용 가능 이력은 0건입니다. 0.58은 0.80보다 낮고, 이력도 0건이므로 Warm이나 Warm-lite가 아니라 Cold입니다.

입력 작품은 mixed media, 65cm x 53cm입니다. 면적은 3,445이고 log_area는 8.145입니다. 가로세로비는 1.226, 매체 범주는 mixed_media, 지지체는 unknown입니다.

검색 스냅샷을 보면 검색 결과 수가 12개, 미술 문맥 결과가 8개, 갤러리/미술관 문맥이 3개, 시장/판매 문맥이 2개, 동명이인 위험 문맥이 1개입니다. 여기서 search_result_count_log는 `log1p(12)`로 2.565이고, search_art_match_ratio는 8/12인 0.667입니다. gallery ratio는 0.250, market ratio는 0.167입니다. 예시 검색품질점수는 0.620입니다.

이 피처들을 LightGBM Quantile에 넣으면 기초Quantile후보는 17.800, 낮은쪽40퍼센트기준은 17.550, Quantile예측구간폭은 1.700이라고 하겠습니다.

## 39. Cold 계산 예시 2: 안정화, guard, lookup

- 예상 시간: 7분

먼저 대표 로그가격 안정화입니다. Quantile예측구간폭 1.700이 속한 구간의 검증 잔차 중앙값이 +0.040이라고 하겠습니다. 이 값은 학습/검증 단계에서 미리 계산된 동결 보정값입니다. clip 범위 안에 있으므로 구간별_보정값은 +0.040이고, 검색포함_대표로그가격은 17.800 + 0.040 = 17.840입니다.

이제 guard 조건을 봅니다. Quantile예측구간폭 1.700은 임계값 1.4612207078910142 이상입니다. 대표 로그가격과 낮은쪽40퍼센트기준의 차이는 17.840 - 17.550 = 0.290이고, 이것은 0.07715547281151025 이상입니다. 낮은쪽40퍼센트기준 17.550은 대표 로그가격 17.840보다 낮습니다. 세 조건이 모두 참이므로 guard가 켜집니다.

과대예측방어_로그가격은 대표 로그가격 17.840과 낮은쪽40퍼센트기준 17.550의 50:50 혼합입니다. 계산하면 17.695입니다.

마지막으로 작가 검색 보정 lookup을 적용합니다. 예시에서 lookup 보정값이 +0.060이면 최종 Cold 로그가격은 17.695 + 0.060 = 17.755입니다. `exp(17.755)`를 적용하면 약 5,140만 원입니다.

## 40. Cold 성능과 해석

- 예상 시간: 5분

Cold는 단계별로 성능 변화를 확인할 수 있습니다. 검색포함 대표 로그가격만 보면 MdAPE 0.424663, MAPE 0.991042, p95 APE 3.305298입니다.

과대예측 방어만 적용하면 MdAPE 0.417765, MAPE 0.963963, p95 APE 2.537708입니다. p95가 크게 줄어듭니다. 이것은 guard가 큰 오차 상위 구간을 방어한다는 뜻입니다.

검색 보정만 추가하면 MdAPE 0.412921, MAPE 0.875749, p95 APE 2.937449입니다. 평균 오차가 줄어듭니다. 검색 문맥 보정이 평균적인 치우침을 줄이는 데 효과가 있다는 뜻입니다.

과대예측 방어와 검색 보정을 함께 적용하면 MdAPE 0.409820, MAPE 0.849260, p95 APE 2.346465입니다. 이 값이 Cold 성능 기준입니다. 두 장치는 역할이 다릅니다. guard는 tail을 줄이고, 검색 보정은 평균 오차를 줄입니다. 둘을 함께 적용했을 때 평균과 tail이 동시에 가장 낮습니다.

## 41. 세 경로 계산 구조 비교

- 예상 시간: 6분

이제 세 경로를 같은 표로 다시 비교합니다. Warm은 고신뢰 매칭과 이력 5건 이상이 전제입니다. 주 가격 신호는 같은 작가 유사작품 비교군입니다. 모델 구조는 기준가격, Huber 잔차, 위험도 라우터입니다.

Warm-lite는 고신뢰 매칭과 이력 1~4건이 전제입니다. 주 가격 신호는 같은 작가 저이력 통계입니다. 모델은 6구성 Huber ensemble입니다. 이력 1건이면 낮은 등급과 검수 플래그가 붙습니다.

Cold는 이력 0건 또는 매칭 불확실 조건입니다. 주 가격 신호는 작품 피처, 작가 메타, 검색 문맥입니다. 모델 구조는 LightGBM Quantile, guard, search lookup입니다.

검색 피처의 차이도 중요합니다. Warm과 Warm-lite는 최종 가격 계산에서 검색 피처를 직접 쓰지 않습니다. Warm과 Warm-lite는 같은 작가 가격 이력이 가격 판단의 중심입니다. Cold는 그 이력이 없기 때문에 검색 피처가 핵심 입력이자 최종 보정 신호가 됩니다.

세 경로 모두 마지막에는 로그가격에 `exp()`를 적용해 원화 가격을 만듭니다.

## 42. 학습 단계와 운영 예측 단계 구분

- 예상 시간: 7분

모델 설명에서 가장 중요한 안전성 포인트는 학습 단계와 운영 예측 단계를 구분하는 것입니다. 실제 가격은 학습과 검증에서는 사용됩니다. 모델을 학습하고, 잔차 target을 만들고, 성능 지표를 계산해야 하기 때문입니다. 하지만 운영 예측에서는 실제 가격을 사용하지 않습니다.

Warm 유사작품 통계는 학습/검증에서 자기 fold를 제외해 누수를 차단합니다. Warm 버킷순차보정은 학습 때 실제 가격으로 Quantile, Huber, CatBoost 잔차 모델을 학습하지만, 예측 때는 동결된 모델로 예측만 합니다.

Warm-lite는 학습/검증에서 leave-one-out 또는 fold 제외 방식으로 작가 통계를 만듭니다. 운영에서는 확정된 같은 작가 1~4건 이력으로 통계를 만듭니다.

Cold의 구간별 잔차 보정은 validation에서 미리 계산해 동결합니다. 운영에서는 새 작품의 Quantile 폭 구간에 맞는 보정값만 조회합니다. Cold 검색 lookup도 검증된 검색 스냅샷에서 만든 고정 조회표입니다.

따라서 발표 중 "실제 가격을 예측에 쓰는 것 아닌가"라는 질문이 나오면, 실제 가격은 학습과 평가에만 쓰이고 운영 예측 입력에는 들어가지 않는다고 명확히 답하면 됩니다.

## 43. 재현 가능성과 검증 근거

- 예상 시간: 5분

마지막 검증 근거입니다. Warm WMIN8 성능은 `warm_model_policy_wmin8.json`에서 확인된 fixed test 607건 성능입니다. Warm API parity는 PP-WMIN10에서 607건 모두 성공했고, 최대 로그가격 차이는 5.33e-15입니다. Warm 최소 표본 1 매칭률은 PP-WMIN2에서 81.9%로 확인됐습니다.

Warm-lite는 PP-WCUT4에서 실존 저이력 1,947행 성능을 확인했습니다. Warm-lite와 WMIN8 svc-core proxy의 저이력 비교는 PP-WMIN9C와 PP-WMIN9E에서 확인했고, 1~4건 전체는 Warm-lite가 전 지표 우세입니다. 5건 이상에 Warm-lite를 강제 적용한 반례는 PP-WMIN9D에서 확인했고, WMIN8이 전 지표 우세입니다.

Cold는 v0.3 reproduction check에서 `all_passed=true`이고 최대 지표 차이는 1.110e-16입니다. 현재 0.1v 라우팅 상수는 `official_v0_1_service.py`에서 0.80, 5건 이상 Warm, 1~4건 Warm-lite로 확인됐습니다.

이 검증 장표는 발표의 신뢰성을 보강하는 역할입니다. 모델 구조를 설명한 뒤, 마지막에 "이 계산은 실험 산출물과 코드 기준으로 재현 확인됐다"는 것을 보여줍니다.

## 44. 발표 결론

- 예상 시간: 5분

오늘 발표의 결론은 세 가지입니다. 첫째, 현재 0.1v 가격 예측은 작가 매칭 신뢰도와 같은 작가 가격 이력 수로 Warm, Warm-lite, Cold를 나누는 3경로 구조입니다. 둘째, 세 경로는 같은 모델의 단순 옵션이 아니라 서로 다른 정보 조건을 처리하는 별도 계산 구조입니다. 셋째, 각 경로는 가격 근거의 신뢰도에 맞춰 서로 다른 피처와 방어 로직을 사용합니다.

Warm은 같은 작가 이력이 5건 이상일 때 정밀 유사작품 기준가격을 만들고, Huber 잔차 보정과 위험도 라우터로 방어합니다. Warm-lite는 1~4건 이력을 Cold로 버리지 않고, 저이력 작가 통계와 작품 피처를 Huber ensemble로 결합합니다. Cold는 같은 작가 이력이 없거나 매칭이 불확실하기 때문에 작품/작가/검색 피처와 Quantile 기반 과대예측 방어를 사용합니다.

이 모델의 핵심은 "어떤 알고리즘을 썼는가"보다 "입력 작품이 가진 근거의 양과 신뢰도에 맞춰 계산 경로를 다르게 설계했다"는 점입니다. 그래서 발표를 마무리할 때는 성능 숫자보다 이 계산 논리를 강조하는 것이 좋습니다.
