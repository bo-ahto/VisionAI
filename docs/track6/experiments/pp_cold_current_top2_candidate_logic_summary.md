# Cold 모델 후보 1, 2위 정리

- 작성일: 2026-06-18
- 기준 실험: PP-CMETA5, PP-CSIM2, PP-CSIM3, PP-CSIM4, PP-CSIM5, PP-CSIM6, PP-CSIM7, PP-CSIM8
- 공통 조건: `artist_key`, 같은 작가 가격 이력, `artist_key` lookup 후처리, `search_*`, 외부 live 검색 미사용
- 목적: 현재 Cold 모델 후보 1, 2위의 학습/사용 로직과 선택 근거를 문서화한다.

## 1. 현재 후보 순위

| 순위 | 후보 | 성격 | MdAPE | MAPE | p95 APE | RMSE log | APE > 5 |
|---:|---|---|---:|---:|---:|---:|---:|
| 1 | `k160_alpha45` | 균형형 개선 후보 | 0.471031 | 0.999148 | 2.569218 | 0.880774 | 74 |
| 2 | `user_meta_core_bucket` | 보수형 기존 안정 후보 | 0.473483 | 1.100452 | 2.942330 | 0.887405 | 72 |
| 참고 | `k160_alpha50` | 공격적 성능 후보 | 0.467623 | 1.068718 | 2.920315 | 0.876089 | 76 |

해석:

- `k160_alpha45`는 기존 후보보다 MdAPE, MAPE, p95 APE, RMSE log를 모두 개선한다.
- `k160_alpha45`는 `k160_alpha50`보다 중앙 오차는 조금 나쁘지만, p95와 APE > 5가 더 안정적이다.
- `user_meta_core_bucket`은 평균 성능은 밀리지만 APE > 5가 72건으로 가장 낮다.
- 따라서 운영 후보 1위는 `k160_alpha45`, 극단오차 보수 기준의 2위는 `user_meta_core_bucket`으로 본다.

## 2. 후보 1: `k160_alpha45`

### 2.1 역할

`k160_alpha45`는 Cold 입력에서 같은 작가의 가격 이력을 직접 쓰지 못하는 문제를 보완하기 위해, 입력 작품과 비슷한 과거 작품 160건의 가격 분포를 모델 피처로 추가한 후보이다.

여기서 중요한 점은 “같은 작가”를 찾는 모델이 아니라는 점이다. 이 후보는 `artist_key`를 쓰지 않고, 작품의 크기/매체/지지체/형태 정보와 사용자가 입력 가능한 작가 메타를 함께 사용한다.

### 2.2 학습 단계

1. 학습 데이터 준비
   - 실제 가격 라벨이 있는 과거 작품을 사용한다.
   - Cold 조건을 유지하기 위해 `artist_key`, 같은 작가 가격 이력, artist-key 기반 lookup은 제외한다.
   - 사용 피처는 작품 정보와 사용자 입력 가능한 작가 메타만 사용한다.

2. 작품 유사 비교군 생성
   - 각 작품에 대해 작품 피처를 만든다.
   - 사용 피처:
     - 가로 cm, 세로 cm, 깊이 cm
     - 면적, 로그 면적, 종횡비
     - 매체, 지지체, 매체-지지체 조합
     - 크기 bucket
     - 입체 여부, 극단 비율 여부
   - train 내부에서는 KFold out-of-fold 방식으로 비교군을 만든다.
   - 즉 학습 행의 유사작품 통계를 만들 때, 자기 자신의 가격이 비교군 통계에 들어가지 않게 한다.

3. 유사작품 k160 통계 생성
   - 입력 작품과 가장 가까운 유사작품 160건을 찾는다.
   - 그 160건의 가격 분포에서 다음 통계를 만든다.
     - 유사작품 로그가격 중앙값
     - q25, q75, IQR
     - 평균, 표준편차
     - 면적당 로그가격 중앙값
     - 유사도 평균/최대/최소
   - 이 값들은 최종 가격을 직접 대체하지 않고, 모델 입력 피처로 들어간다.

4. LightGBM Quantile 학습
   - 목표값은 실제 로그가격이다.
   - `alpha=0.45` Quantile 모델을 학습한다.
   - q50이 아니라 q45를 쓰는 이유는 q50 직접 예측보다 약간 보수적으로 예측해 과대평가 tail을 줄이기 위해서다.

### 2.3 사용 단계

1. 사용자가 작품 정보를 입력한다.
   - cm 기준 크기
   - 매체, 지지체
   - 입체 여부 또는 깊이 정보

2. 사용자가 작가 메타를 입력한다.
   - 출생연도
   - 작품 수 또는 활동량
   - 팔로워/인지도성 지표
   - 경력 단계
   - 국적/활동권 등 입력 가능한 메타

3. 입력 작품과 비슷한 학습 작품 160건을 찾는다.
   - 이때 `artist_key`로 같은 작가를 찾지 않는다.
   - 작품 조건이 가까운 과거 작품을 기준으로 비교군을 만든다.

4. 유사작품 가격 통계를 계산한다.
   - 유사작품 로그가격 중앙값, q25/q75, IQR 등
   - 유사도 평균/최대/최소
   - 면적당 가격 통계

5. LightGBM Quantile q45 모델에 입력한다.
   - 작품 피처
   - 사용자 입력 작가 메타
   - 유사작품 k160 통계
   - 모델은 q45 로그가격을 출력한다.

6. 최종 가격으로 변환한다.
   - 최종 가격 = `exp(예측 로그가격)`

### 2.4 선택 근거

기존 `user_meta_core_bucket` 대비:

- MdAPE: 0.473483 -> 0.471031
- MAPE: 1.100452 -> 0.999148
- p95 APE: 2.942330 -> 2.569218
- RMSE log: 0.887405 -> 0.880774

paired bootstrap test 기준:

- MAPE 개선 확률: 1.0000
- p95 개선 확률: 1.0000
- RMSE 개선 확률: 0.9875
- MdAPE 개선 확률: 0.7250

주의:

- APE > 5는 기존 72건에서 74건으로 2건 증가한다.
- `followers`, `total works` 계열 메타가 빠질 때 성능이 약해진다.
- 따라서 해당 작가 메타는 운영 입력에서 권장 또는 필수 입력으로 관리하는 것이 좋다.

## 3. 후보 2: `user_meta_core_bucket`

### 3.1 역할

`user_meta_core_bucket`은 현재 가장 보수적인 Cold 후보이다. 유사작품 비교군을 쓰지 않고, 작품 정보와 사용자가 입력 가능한 작가 메타 bucket만 사용한다.

평균 성능은 `k160_alpha45`보다 낮지만 APE > 5가 더 적어, 극단오차 안정성 기준으로는 여전히 중요한 후보이다.

### 3.2 학습 단계

1. 학습 데이터 준비
   - 실제 가격 라벨이 있는 과거 작품을 사용한다.
   - `artist_key`, 같은 작가 가격 이력, artist-key lookup은 제외한다.

2. 작품 피처 생성
   - 가로/세로/깊이 cm
   - 면적, 로그 면적, 종횡비
   - 매체, 지지체, 매체-지지체 조합
   - 크기 bucket, 극단 비율 여부

3. 사용자 입력 작가 메타 피처 생성
   - 출생연도
   - 총 작품 수
   - 팔로워/인지도성 지표
   - 경력 단계
   - P1 여부, 국제 활동 여부
   - 국적/활동권
   - 각 메타의 missing flag

4. 메타 bucket 생성
   - 출생연대 bucket
   - 작품 수 bucket
   - 팔로워 bucket
   - 경력 단계 bucket
   - 메타 완성도 bucket
   - 매체 x 출생연대
   - 지지체 x 메타 완성도
   - 경력 단계 x 크기 bucket

5. LightGBM Quantile q50 학습
   - 목표값은 실제 로그가격이다.
   - q50, 즉 중앙값 예측 모델을 학습한다.

### 3.3 사용 단계

1. 사용자가 작품 정보를 입력한다.
2. 사용자가 작가 메타를 입력한다.
3. 작가 메타 bucket을 생성한다.
4. LightGBM Quantile q50 모델에 작품 피처와 작가 메타 bucket을 넣는다.
5. 모델이 예측 로그가격을 출력한다.
6. 최종 가격 = `exp(예측 로그가격)`으로 변환한다.

### 3.4 선택 근거

`user_meta_core_bucket`은 다음 기준에서 2위 후보로 유지한다.

- APE > 5가 72건으로 현재 후보군 중 가장 낮다.
- `k160_alpha45`보다 평균 성능은 낮지만, 극단오차 최소화 기준에서는 안정적이다.
- 유사작품 통계를 만들지 않기 때문에 구조가 단순하고 운영 구현 난이도가 낮다.

## 4. APE > 5 증가를 더 줄일 수 있는 방법

이미 시도한 방법:

1. 유사작품 기준가격 + residual clip
   - 결과: MdAPE와 p95가 악화되어 운영 후보로 부적합

2. 유사작품 가격 상단 기준 output cap
   - 결과: MdAPE/MAPE는 소폭 개선했지만 APE > 5는 줄이지 못함

3. 저가 가중치 + 낮은 quantile
   - 결과: APE > 5는 줄었지만 MdAPE 손실이 커짐

아직 시도할 만한 방법:

### 4.1 과대평가 전용 asymmetric loss

현재 quantile을 낮추는 방식은 전체 예측을 낮추는 효과가 있다. 그래서 tail은 줄지만 고가/중가 구간의 중앙 오차가 손상된다.

다음 실험에서는 전체를 낮추지 말고, 학습 중 과대평가 오차에만 더 큰 패널티를 주는 방식이 필요하다.

예상 실험:

- q45 또는 q50 기반
- 예측값이 실제값보다 높게 틀린 행에 더 큰 가중치
- 특히 실제 가격 100만원 미만 구간의 과대평가에 더 큰 가중치

목표:

- APE > 5를 72건 이하로 줄이기
- MdAPE는 0.48 이하 유지
- MAPE/p95는 기존 후보보다 개선 유지

### 4.2 저가구간 전용 별도 모델

저가 구간은 전체 Cold에서 가장 어렵다. 단일 모델이 전체 가격대를 모두 맞히면 저가 tail이 계속 생긴다.

다음 실험:

- 저가 후보 판별 모델을 먼저 학습
- 저가 가능성이 높은 입력은 별도 저가 특화 모델 사용
- 다만 이 방식은 라우터 성격이 있으므로, 사용자가 라우터를 보류한다면 나중 단계로 미룬다.

### 4.3 APE > 5 위험 예측용 보조 검수 모델

최종 가격을 바꾸지 않고, 위험 표시만 붙이는 방식이다.

입력:

- 예측 가격
- q45/q50 차이
- 유사작품 가격 IQR
- 유사도 평균/최소
- 작가 메타 missing 개수
- 저가 가능성

출력:

- `검수 필요`
- `저신뢰`
- `가격 범위 표시 권장`

이 방식은 가격 정확도 자체를 바꾸지는 않지만 운영 리스크를 줄인다.

### 4.4 q45 + 약한 저가 가중치 추가 탐색

PP-CSIM7에서는 저가 가중치를 2배, 3배로 비교했다. 중간값을 더 세밀하게 볼 수 있다.

후속 grid:

- low_weight = 1.2, 1.4, 1.6, 1.8
- mid_weight = 1.05, 1.10, 1.20
- alpha = 0.43, 0.45, 0.47

목표는 `k160_alpha45`의 장점을 유지하면서 APE > 5 증가분 2건을 없애는 것이다.

## 5. 현재 권장안

현재 운영 후보를 정리하면 다음과 같다.

1. 기본 개선 후보: `k160_alpha45`
   - 성능 균형이 가장 좋다.
   - MAPE/p95 개선이 명확하다.
   - APE > 5가 2건 증가하는 점은 남은 리스크다.

2. 보수 후보: `user_meta_core_bucket`
   - 극단오차가 가장 낮다.
   - 구조가 단순하고 운영 리스크가 낮다.
   - 평균 성능과 p95는 `k160_alpha45`보다 떨어진다.

최종 선택 전에 필요한 추가 확인:

- q45 + 약한 저가 가중치 세밀 grid
- APE > 5 발생 행의 실제 공통 원인 분석
- 저가 구간 별도 검수 표시 기준
- 작가 메타 필수/권장 입력 정책
