2.1 Warm/Cold 라우팅 기준

  • 핵심 답변: 작가 이력이 1건이라도 있으면 무조건 Warm으로 보내는 구조가 아님
  • 실험 split 기준: Warm validation/test 작가는 학습 데이터에 같은 작가가 존재하고, 최소 학습 이력 5건을 만족하도록 구성
  • 실험 split 기준: Cold validation/test 작가는 학습 데이터의 artist_key, 정규화 작가명과 겹치지 않도록 구성
  • 운영 고정 기준(재검증 반영): 작가매칭신뢰도점수 >= 0.80 통과 시 이력 5건 이상 → Warm, 1~4건 → Warm-lite, 그 외(매칭 실패/이력 0건) → Cold
  • 이력 1~4건 처리: 기존 Warm 파이프라인이 아니라 전용 경량 경로(Warm-lite)로 처리 — 기존 Warm으로 보내지 않는 구조 제약은 유지
  • 1~4건을 Cold로 처리하는 이유: 현행 Warm 파이프라인의 작가 단위 유사작품 매칭이 최소 표본 5건을 요구하는 구조라서, 5건 미만은 작가 가격 신호가 발동하지 않음 (성능 실험으로 정한 임계값이 아니라 현행 구조의 적용 가능 최소선)
  • Warm-lite 경로 동결 완료: 이력 1~4건 고신뢰 매칭 작가 전용 경량 Warm 경로가 검증을 통과해 별도 모델 번들로 동결됨 (warm_lite_v0.1, PP-WCUT1/PP-WCUT2/PP-WLITE-ARTIFACT1). 기존 Warm/Cold 경로는 변경 없음
  • Warm-lite 적용 시 라우팅: 매칭신뢰도 >= 0.90 AND 이력 5건 이상 → Warm / 매칭신뢰도 >= 0.90 AND 이력 1~4건 → Warm-lite / 그 외 → Cold. 이력 1건은 차등 등급(넓은 범위 표시 + 검수 플래그)으로 처리
  • Warm-lite 운영 연동 전제: 매칭 점수 캘리브레이션(운영 매칭 로그 수집·검수)과 신규 트래픽 모니터링 — 준비 완료 전까지는 현행 라우팅(1~4건 → Cold) 유지
  • 유사작품 정보의 역할: Warm/Cold 라우팅을 단독으로 결정하는 기준이 아니라, Warm 내부 기준가격과 신뢰도 계산을 안정화하는 보조 근거

2.1.1.1 이력 5건 기준의 성격과 실험 근거

  • 기준의 성격: 5건 이상은 성능 비교로 찾은 임계값이 아니라, 현행 Warm 파이프라인의 작가 매칭(1~3순위)이 최소 표본 5를 요구하는 구조 제약에 따른 적용 가능 최소선
  • 실측 근거 1 (이력 절단 실험, warm test 607행): 작가 이력을 k건으로 인위 절단하면 현행 구조에서는 k=1~4에서 작가 매칭이 발동하지 않아 Warm이 Cold와 동등~열위, k=5에서 MdAPE 0.49 → 0.18로 단절 개선 — 즉 5건 미만 작품을 현행 Warm으로 보내면 안 되는 것은 실측으로 확인됨
  • 실측 근거 2 (이력 수별 성능, warm test 실측): 이력 5~7건 작가 MdAPE 0.2256 vs 50건 이상 작가 0.1072 — 이력이 많을수록 오차가 단조 감소
  • Warm-lite 동결 완료: 저표본 매칭(최소 1건)을 허용한 경량 Warm 경로가 반복 검증(절단 seed 3개 × k=1~4 전 조합, 개선확률 0.995 이상)을 통과해 warm_lite_v0.1로 동결됨
  • Warm-lite 동결 모델 성능(warm test 실측, MdAPE 기준): 이력 1건 0.199, 2건 0.174, 3건 0.176, 4건 0.152 — 같은 행 Cold 0.47~0.49 대비 2.3~3.1배 개선, 4건이면 기존 Warm(0.141) 수준에 근접
  • 운영 연동 전제: 매칭 점수 캘리브레이션 + 신규 트래픽 모니터링(절단 시뮬레이션 한계 보완) — 준비 완료 전까지 현행 운영 기준은 위 표(5건)를 유지

  • 같은 한글명이 여러 작가에게 연결되면 보조 정보 확인 전까지 Warm으로 보내지 않음
  • 학습 작가 사전에 한글 alias가 없고 영문명만 있는 경우, 자동 번역/로마자 변환만으로는 고신뢰 매칭으로 보지 않음
  • 검색 결과만으로 같은 작가라고 추정되는 경우는 작가매칭신뢰도점수를 낮게 보고 Cold로 처리

작가매칭신뢰도점수 =

    0.95
  )
변수 값 산정 기준 의미
이름일치점수 정규화 이름이 완전 일치하면 1.00; 문자열 유사도 85점 이상이면 문자열유사도 / 100; 85점 미만이면 0.00 작가명이 얼마나 비슷한지. 문자열 유사도는 기존 작가 matcher의 fuzzy ratio 기준
보조정보일치점수 생년 또는 외부 작가 식별자가 일치하면 1.00; 생년은 없지만 국적/프로필이 충돌하지 않고 후보가 1명뿐이면 0.70; 확인 근거가 부족하면 0.00 이름 외에 같은 작가라고 볼 근거
학습작가등록점수 학습 데이터에 해당 후보 작가가 존재하면 1.00, 없으면 0.00 Warm 기준가격을 만들 수 있는 후보인지
동명이인위험점수 같은 이름 후보가 여러 명이면 1.00; 일부 혼동 가능성이 있으면 0.50; 위험 근거가 없으면 0.00 이름은 같지만 다른 사람일 위험
핵심정보충돌점수 생년/국적/외부 식별자 중 하나라도 충돌하면 1.00; 충돌이 없으면 0.00 같은 작가로 보면 안 되는 명확한 반대 근거

clip(x, 0.00, 0.95)의 의미:

  • 계산값이 0.00보다 작으면 0.00으로 제한
  • 계산값이 0.95보다 크면 0.95로 제한
  • 작가키 직접 일치가 아닌 이름 기반 매칭은 최대 0.95까지만 허용
  • 이유: 이름 기반 매칭은 항상 동명이인/표기 변형 위험이 있으므로, artist_key 직접 일치 1.00과 구분

임계값 0.90의 정량 근거 (오매칭 비용 실측, PP-WMATCH1):

  • 오매칭 비용: 잘못된 작가의 이력으로 Warm 가격을 만들면 MdAPE 0.66~0.70, p95 APE 9.3~9.7로 Cold(0.41 / 2.17)보다 훨씬 나쁨 — 장르가 비슷한 작가로 잘못 매칭되어도 거의 동일하게 파괴적
  • 기대손실 계산: 매칭 실제 정확도가 약 85% 이상일 때만 Warm 라우팅이 Cold 대비 기대 우위 (MAPE 기준 0.83, p95 기준 0.85) → 임계 0.90은 이 최소선 위에 마진을 둔 보수 설정
  • 동명이인 실태(학습 데이터 실측): 작가 1,773명 중 정규화 한글명 충돌 117 artist_key(6.6%), 충돌 작가의 생년 보유율 41% — "보조 정보 확인 전 Warm 금지" 원칙의 근거
  • 운영 과제: 매칭 점수와 실제 정확도의 대응(캘리브레이션)은 운영 매칭 로그·검수 데이터로 보정 필요 — 위 가중치 산식은 이 보정 전까지의 보수 설계안
  • 재검증 결과(PP-E2E1, 2026-06-12): 임계 0.90은 자격 작가의 64~73%를 보조정보 부재만으로 Cold로 보내 기대 오차가 all-Cold 수준 — 임계 0.80 하향(이름 완전일치+사전 등록, 보조정보 무 구간은 검수 플래그 동반) 권고. Cold 오유입은 0~0.5%로 허용 한계(~30%) 대비 마진 큼. 최종 적용은 운영 매칭 로그로 사전 밖 동명이인율 확인 후 결정

MAPE 계산식:

최종예측가격_KRW = exp(최종_로그가격)

작품별_APE =
  abs(최종예측가격_KRW - 실제가격_KRW)
  / 실제가격_KRW

MAPE = mean(작품별_APE)
MdAPE = median(작품별_APE)
p95 APE = quantile(작품별_APE, 0.95)

RMSE log 계산식:

RMSE log =
  sqrt(mean((최종_로그가격 - 실제_로그가격)^2))
  • MAPE, MdAPE, p95 APE: 원화 가격으로 변환한 뒤 실제 원화 가격과 비교한 비율 오차
  • RMSE log: 로그가격 공간에서 계산한 오차
  • 두 지표를 함께 표기하는 이유: MAPE는 사업 관점에서 실제 가격 대비 몇 퍼센트 틀렸는지 보기 쉽고, RMSE log는 모델이 학습/보정하는 로그가격 공간의 오차를 확인하기 좋음

후보분산순위 작품 단위 위험도 후보예측분산을 0~1 순위값으로 변환 선행 후보 간 예측 차이가 큰 작품의 보정 상한 축소
기준-안정가격차이순위 작품 단위 위험도 abs(안정성우선_기준로그가격 - 미세보정전_기준로그가격)를 0~1 순위값으로 변환 기준가격과 안정성 기준가격이 다르면 보정 상한 축소

표본부족점수 작품 단위 위험도 유사작품표본수가 적을수록 1에 가까워짐 유사작품 수가 적은 작품의 보정 상한 축소
작품단위위험도 최종 보정 상한 불확실성, 가격 범위, 후보 분산, 신뢰도, 표본 수를 가중합 위험도가 높을수록 최종 보정 폭을 작게 제한
방향확신도 보정 강도 abs(상향확률 - 0.5) * 2 상향/하향 판단이 애매하면 보정 약화
적용확신도 보정 강도 방향확신도에서 최소 기준 0.12를 뺀 뒤 0~1로 제한 방향 판단이 충분할 때만 보정값 반영
예상방향 보정 gate 상향확률이 0.5 이상이면 +1, 미만이면 -1 Huber 잔차 방향과 비교하는 기준
잔차방향일치 보정 gate sign(Huber잔차예측값) == 예상방향이면 1 두 모델이 같은 방향을 말할 때만 보정 허용
원시보정값 clip 전 보정값 0.025 * Huber잔차예측값 * 잔차방향일치 * 적용확신도 최종보정값의 후보값
방향별기본상한 보정 상한 상향은 0.00005, 하향은 0.000035 방향별 최대 이동 폭 지정
적용상한 최종 보정 상한 기본상한에 불확실성순위와 작품단위위험도 축소율 적용 위험한 작품은 원시보정값이 커도 작게만 반영
최종보정값 최종 로그가격 clip(원시보정값, -적용상한, +적용상한) 기준 로그가격에 더해지는 최종 미세 보정
안정기준가격대 검수/해석 가격대별 결과 해석과 보고용 구간 최종 보정 산식에는 직접 가산하지 않음
이전_안정기준로그가격, 기존70대30기준로그가격 추적/검수 이전 기준 후보와 최종 후보 비교 최종 보정 산식에는 직접 가산하지 않음
실제_로그가격, 실제_가격 평가 전용 MdAPE, MAPE, p95 APE, RMSE log 계산 예측 시 입력으로 사용하지 않음
작품추적ID, 작가키, 작가명 재현/검수 작품 및 작가 추적 최종 보정 산식에는 직접 가산하지 않음

4.4 Warm 모델과 산식

  • Warm 최종 모델의 순차 사용 모델:
모델 또는 방법 역할 사용 위치
방향 분류 모델 기준가격보다 실제 가격이 높을 확률 계산 보정 방향 판단
Huber 잔차 모델 기준 로그가격 대비 남은 잔차 예측 보정 크기 제안
Quantile 예측 폭 가격을 직접 만들지 않고 예측 불확실성으로 사용 보정 상한 축소
작품 단위 위험도 후보 간 차이와 불확실성을 요약 보정 상한 축소
  • Warm 최종 계산식:
실제_로그가격 = log(실제_가격)

잔차 = 실제_로그가격 - 미세보정전_기준로그가격

방향라벨 = 1  if 잔차 > 0
방향라벨 = 0  if 잔차 <= 0
  • 방향 분류 모델의 역할: 상향확률 계산
  • 재현 패키지 기준: 상류 방향 분류 모델의 산출값인 상향확률을 입력으로 사용
방향확신도 = abs(상향확률 - 0.5) * 2

적용확신도
  = clip((방향확신도 - 0.12) / (1 - 0.12), 0, 1)
  • Huber 모델의 역할: 잔차 예측
  • 재현 패키지 기준: 상류 Huber 잔차 모델의 산출값인 Huber잔차예측값을 입력으로 사용
잔차예측 = Huber잔차예측값
  • 보정 적용 조건: 방향 분류 모델과 Huber 잔차 모델의 방향이 같은 경우만 적용
예상방향 = +1  if 상향확률 >= 0.5
예상방향 = -1  if 상향확률 < 0.5

잔차방향일치 = 1  if sign(잔차예측) == 예상방향
잔차방향일치 = 0  otherwise
  • 원시 보정값 계산:
원시보정값
  = 0.025
    * 잔차예측
    * 잔차방향일치
    * 적용확신도
  • 작품별 보정 상한: 불확실성과 위험도가 높을수록 축소
방향별기본상한
  = 0.00005   if 원시보정값 >= 0
  = 0.000035  if 원시보정값 < 0

적용상한
  = clip(
      방향별기본상한
      * (1 - 0.55 * 불확실성순위)
      * (1 - 0.80 * 작품단위위험도),
      0.000006,
      방향별기본상한
    )

최종보정값 = clip(원시보정값, -적용상한, +적용상한)

최종_Warm_로그가격 = 미세보정전_기준로그가격 + 최종보정값

최종_Warm_가격_KRW = exp(최종_Warm_로그가격)

5.3.3 LightGBM Quantile 회귀 후보의 의미

  • Quantile 회귀 의미: 평균 가격 하나를 맞추는 회귀가 아니라, 조건이 비슷한 작품들의 가격 분포에서 특정 위치의 로그가격을 예측하는 방식
  • 50% Quantile 의미: 같은 조건의 작품 가격을 낮은 순서로 세웠을 때 중앙에 가까운 가격
  • 40% Quantile 의미: 같은 조건의 작품 가격을 낮은 순서에서 높은 순서로 세웠을 때 40% 지점에 있는 가격
  • 문서 표현: 낮은쪽 40% 지점 가격
  • 주의: 낮은쪽 40% 지점 가격은 40% 할인 또는 가격을 40% 낮춘다는 뜻이 아님
  • 10%와 90% Quantile 의미: 낮은 쪽과 높은 쪽의 예측 범위를 잡기 위한 경계값
  • Quantile예측구간폭 의미: 높은 Quantile 예측값과 낮은 Quantile 예측값의 차이이며, 값이 클수록 모델이 해당 작품 가격을 불확실하게 보고 있다는 뜻
문서용 이름 내부 의미 계산 또는 생성 방식 최종 모델에서의 역할
검색피처포함_기초Quantile후보_로그가격 검색 피처까지 포함한 LightGBM Quantile 회귀 기반 기준 후보 작품 피처, 작가 메타, 검색 피처, 검색 상호작용 피처를 입력으로 LightGBM Quantile 회귀 모델이 예측 Cold 대표 로그가격을 만들기 전의 기준값
낮은쪽40퍼센트기준_로그가격 LightGBM 40% Quantile 로그가격 같은 입력 조건에서 낮은 가격부터 높은 가격까지 줄 세웠을 때 40% 지점을 예측 과대예측 위험이 있을 때 대표 로그가격을 낮추는 방어 기준
Quantile예측구간폭 높은 Quantile 예측값과 낮은 Quantile 예측값의 차이 예: 90%Quantile_로그가격 - 10%Quantile_로그가격 불확실성 측정, 구간별 잔차 안정화, 과대예측 방어 조건에 사용
검색포함_대표로그가격 기초 Quantile 후보를 검증 잔차로 안정화한 값 검색피처포함_기초Quantile후보_로그가격 + 구간별_보정값 과대예측 방어 전 Cold 기준가격
  • LightGBM Quantile 회귀 후보 생성 흐름:
작품 피처 + 작가 메타 피처 + 검색 피처
        |
        v
LightGBM Quantile 회귀 모델
        |
        +--> 기준 Quantile 로그가격
        +--> 낮은쪽 40% 지점 로그가격
        +--> 90% Quantile과 10% Quantile 차이 기반 Quantile예측구간폭
  • 일반 LightGBM 회귀와의 차이:
구분 일반 LightGBM 회귀 LightGBM Quantile 회귀
목표 평균적인 정답 가격에 가까운 값 예측 가격 분포의 특정 Quantile 위치 예측

구간별_보정값 대표 로그가격 안정화 clip(구간별_잔차중앙값, -0.25, +0.25) 대표 로그가격이 과도하게 움직이지 않도록 제한
검색포함_대표로그가격 과대예측 방어 전 기준가격 기초 Quantile 후보에 구간별 보정값을 더함 Cold 후처리의 기준가격
낮은쪽40퍼센트기준_로그가격 과대예측 방어 방어조건이 켜지면 대표 로그가격과 50:50 혼합 큰 과대예측 가능성을 낮춤
방어조건 과대예측 방어 Quantile예측구간폭이 넓고 대표 로그가격이 낮은쪽40퍼센트기준보다 충분히 높을 때 활성화 과대예측 위험 작품만 선택적으로 하향
과대예측방어_로그가격 검색 보정 전 최종 후보 방어조건이 켜지면 대표 로그가격과 낮은쪽40퍼센트기준 로그가격을 50:50 혼합, 아니면 대표 로그가격 유지 큰 오차 상위 구간 완화
artist_key 작가 검색 보정 고정 검색 보정 lookup의 key로 사용 작가별 검색 문맥 보정값 적용
search_delta_lookup[artist_key] 최종 검색 보정 최종_Cold_로그가격 = 과대예측방어_로그가격 + 작가검색보정_로그값 작가별 검색 문맥에 따른 최종 로그가격 이동
작가검색보정_로그값 최종 검색 보정 lookup에 있으면 작가별 보정값, 없으면 0 작가 검색 문맥을 최종 가격에 추가 반영
최종_Cold_로그가격 최종 가격 변환 과대예측방어_로그가격 + 작가검색보정_로그값 exp() 변환 전 최종 예측값

5.4 Cold 모델과 산식

  • 작가 검색 보정값 사용 방식: 실시간 검색 호출이 아니라 검증된 검색 스냅샷에서 만든 고정 lookup 사용
  • 검색 피처 포함 대표 예측의 역할: LightGBM Quantile 회귀 후보와 Quantile예측구간폭 구간별 검증 잔차를 결합해 기준이 되는 대표 로그가격 생성
검색피처포함_기초Quantile후보_로그가격
  = LightGBM_Quantile회귀후보(
      작품피처
      + 작가메타피처
      + 검색피처
      + 검색상호작용피처
    )

Quantile예측구간폭 = 저장된_Quantile예측폭

낮은쪽40퍼센트기준_로그가격 = LightGBM_40퍼센트_Quantile로그가격
  • 대표 로그가격 안정화 방식: Quantile예측구간폭 구간별 검증 잔차 중앙값을 더해 보정
Quantile예측구간폭_구간 = bucket(Quantile예측구간폭)

구간별_잔차중앙값
  = median(실제_로그가격 - 검색피처포함_기초Quantile후보_로그가격)
    within same Quantile예측구간폭_구간

구간별_보정값
  = clip(구간별_잔차중앙값, -0.25, +0.25)

검색포함_대표로그가격
  = 검색피처포함_기초Quantile후보_로그가격 + 구간별_보정값
  • 과대예측 방어 조건:
방어조건 =
  (Quantile예측구간폭 >= 1.4612207078910142)
  AND (검색포함_대표로그가격 - 낮은쪽40퍼센트기준_로그가격 >= 0.07715547281151025)
  AND (낮은쪽40퍼센트기준_로그가격 < 검색포함_대표로그가격)
  • 방어조건 활성화 시 처리: 대표 로그가격을 낮은쪽 40% 지점 가격 쪽으로 낮춤
과대예측방어_로그가격
  = 0.50 * 검색포함_대표로그가격
  + 0.50 * 낮은쪽40퍼센트기준_로그가격
  • 방어조건 비활성화 시 처리: 대표 로그가격 유지
과대예측방어_로그가격 = 검색포함_대표로그가격
  • 최종 처리: 작가 검색 보정값 추가
작가검색보정_로그값 =
  search_delta_lookup[artist_key]
  if artist_key exists in lookup

작가검색보정_로그값 = 0
  if artist_key does not exist in lookup

최종_Cold_로그가격
  = 과대예측방어_로그가격 + 작가검색보정_로그값

최종_Cold_가격_KRW = exp(최종_Cold_로그가격)

6. Warm/Cold 비교 요약

항목 Warm Cold
적용 대상 작가 매칭이 확실하고 같은 작가의 학습 가격 이력이 충분한 작품 같은 작가 이력이 없거나 부족하거나 작가 매칭이 불확실한 작품
기준가격 생성 선행 Warm 예측가격과 유사작품 기반 통계 검색 피처 포함 LightGBM Quantile 회귀 후보 + Quantile예측구간폭 구간 안정화
핵심 보정 방향 분류 + Huber 잔차 미세 보정 Quantile예측구간폭/낮은쪽40퍼센트기준 차이 기반 과대예측 방어 + 작가 검색 보정

검색 피처 사용 최종 미세 보정층에는 직접 사용하지 않음 핵심 피처로 사용

운영상 설명 안정 기준가격을 거의 유지하는 미세 보정형 모델 검색 문맥과 불확실성 방어를 결합한 신규/저이력 작가용 모델

7. 추가 성능 개선 방향

7.1 핵심 판단

  • 현재까지의 실험 결과 기준: 추가 성능 개선의 가장 큰 병목은 모델 구조 자체보다 데이터 품질과 데이터 커버리지
  • Warm 개선 방향: 이미 안정화된 기준가격을 크게 바꾸지 않는 구조로 수렴했으므로, 저신뢰 구간의 유사작품 데이터 보강이 우선
  • Cold 개선 방향: 작가 이력과 비교가격이 부족한 상황을 다루는 모델이므로, 작가/작품/검색 문맥 데이터 수집이 성능 개선에 직접적인 영향을 줌
  • 모델 보정의 역할: 현재 보유 데이터 안에서 오차가 반복되는 구간을 줄이는 작업
  • 데이터 수집의 역할: 모델이 기준가격을 더 정확하게 잡을 수 있도록 가격 판단에 필요한 근거 자체를 늘리는 작업

7.2 실험 결과 기반 근거

관찰 내용 실험에서 확인된 현상 해석

Warm 저신뢰 구간은 보정 상한이 자동으로 줄어듦 유사작품표본수, 유사작품가격범위비율, Quantile예측구간폭이 위험도 계산에 사용됨 유사작품 표본이 부족하거나 가격 분산이 큰 구간은 모델이 의도적으로 조심스럽게 움직임

Cold 구간별 보정은 추가 개선 여지를 보임 지지체/크기 구간, tail-risk 구간, 예측구간폭 구간 보정에서 validation p95 APE가 낮아짐 구간별 표본이 더 충분해지면 보정값을 더 안정적으로 추정할 수 있음

10. 모델 적용 방식 요약

  • 전체 구조: 가격 예측 모델은 Warm과 Cold 두 경로로 구성
  • Warm 적용 조건: 작가 매칭이 확실하고 같은 작가의 사용 가능한 학습 가격 이력이 충분한 작품
  • Warm 계산 방식: 기존 Warm 기준가격을 만든 뒤 방향 분류 모델과 Huber 잔차 모델이 같은 방향을 가리킬 때만 미세 보정
  • Warm-lite 적용 조건: 작가 매칭이 확실하고 같은 작가의 사용 가능 가격 이력이 1~4건인 작품
  • Warm-lite 계산 방식: 매칭 작가의 이력 1~4건으로 작가 가격 통계를 즉시 계산해 경량 Huber 앙상블로 예측 (이력 1건은 차등 등급)
  • Warm-lite 성능: 실존 저이력 작가 1,947행 기준 MdAPE 0.1092, p95 APE 0.8765 (동일 행 Cold 대비 MdAPE 5배 개선)
  • 라우팅 운영: 매칭 임계 0.80(경계 비교 tolerance 필수), 모니터링 하니스(monitor_warm_lite_routing.py)로 규칙 위반·트래픽 분포·성능 경보 상시 점검
  • Cold 적용 조건: 같은 작가 이력이 없거나 부족하거나 작가 매칭이 불확실한 작품
  • Cold 계산 방식: 작품 피처, 작가 메타, 작가명 검색 피처를 함께 사용한 LightGBM Quantile 회귀 후보를 Quantile예측구간폭 구간별 검증 잔차로 안정화해 대표 예측가격 계산
  • Cold 방어 방식: Quantile예측구간폭이 넓고 대표 예측가격이 낮은쪽 40% 지점 가격보다 높은 작품은 낮은쪽 가격 기준으로 낮춤
  • Cold 최종 보정: 갤러리/미술관 검색 문맥 기반 작가별 보정값 추가
  • Warm 성능: fixed test 607건 기준 MAPE 0.269888, p95 APE 0.807325
  • Cold 성능: fixed test 3,099건 기준 MAPE 0.849260, p95 APE 2.346465
  • 최종 가격 산출: 두 모델 모두 로그가격 기준으로 계산한 뒤 exp()를 적용해 원화 예측가격으로 변환
  • 재현 가능성: 재현 스크립트와 결과 파일을 통해 동일 지표 확인 가능
