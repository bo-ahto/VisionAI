# PP-WCUT1 Warm 이력 절단 실험 요약 — "5건" 라우팅 기준의 실증 검증

- 실행일: 2026-06-12 / 스크립트: `scripts/track6/run_pp_wcut1_warm_history_truncation.py` (+min1 변형) / 폴더: `experiments/track6/PP-WCUT1_warm_history_truncation/`
- 질문: 작가 train 이력 1~4건에서 Warm 경로가 Cold 경로보다 나은가? (기존 근거는 split 설계·사다리 구조·5+ 외삽뿐 — 직접 측정 부재)
- 설계: warm test 607행 고정, 각 작가 train 이력을 k건만 무작위 잔류(seed 고정) → Warm proxy(7단 사다리+선형 Huber 6구성) vs Cold proxy(작가 미사용 LGB+guard+미커버 상수) 재학습 비교. 0604 미사용.

## 결과 1 — 현행 구조(사다리 min 5): k=5에서 단절적 개선

| k | 작가 매칭률 | Warm proxy (MdAPE/MAPE/p95) | Cold serving |
|---|---:|---|---|
| 1~4 | **0%** | 0.484~0.500 / 0.80~0.82 / 2.99~3.18 | 0.465~0.498 / 0.74~0.78 / **2.62~2.77** |
| **5** | **100%** | **0.1798 / 0.3169 / 1.0433** | 0.4607 / 0.7435 / 2.4338 |
| 8 / full | 100% | 0.186 / 0.153 | 0.46 / 0.41 |

- 현행 구조에서는 k<5면 작가 매칭이 불발되어 Warm이 Cold 대비 동등~열위(p95는 명확히 열위). k=5에서 MdAPE -63% 단절 개선.

## 결론 (파트너 문서 수정 필요)

1. **"5건"은 성능 임계값이 아니라 현행 파이프라인의 구조 제약**(매칭 사다리 min_n=5)이다. k=5 단절 개선은 그 지점에서 작가 신호가 "허용되기 시작"하기 때문이지, 데이터가 5부터 유의미해서가 아니다.
2. **이력 1건이라도 고신뢰 매칭이면 작가 가격 prior가 Cold 대비 압도적**(MdAPE 0.20 vs 0.50). 2건+이면 k=5 수준(0.17)에 근접.
3. 라우팅 함의: 1~4건 고신뢰 작가의 Cold행은 보수적이지만 큰 성능 손실 — **"Warm-lite"(저표본 사다리) 경로 신설이 유망한 후속 후보**.
4. 한계(정직): ① warm test 작가는 실제 5+ 보유 작가라 진짜 1~4건 작가(더 무명/고변동)와 분포 차이 가능 ② 선형 proxy(운영 blend 아님) ③ 단일 seed 절단 — 운영 반영 전 반복 seed + artist holdout 게이트 재검증 필요(후속: PP-WCUT2).

## 파트너 문서 기술 권고

- "5건 = 실험으로 검증된 성능 임계값" 표현 금지.
- 정확한 기술: "현행 Warm 파이프라인은 작가 매칭에 최소 5건을 요구하는 구조라 5건 미만은 적용 불가 → Cold로 보수 처리. 단 절단 실험상 1~4건 고신뢰 작가용 경량 Warm 경로가 유망해 후속 검증 예정."
