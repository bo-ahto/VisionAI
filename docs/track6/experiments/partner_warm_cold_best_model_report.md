# Warm/Cold 가격 예측 모델 종합 리포트

- 작성일: 2026-06-10
- 보고 목적: 협력 업체 공유용 기술 설명 및 성능 요약
- 대상 범위: Warm 최종 운영 후보 + Cold 최고 성능 연구 기준 모델

## 1. 결론 요약

- 가격 예측 모델 적용 기준: 작가 매칭 신뢰도와 학습 데이터 내 사용 가능한 작가 가격 이력 수에 따라 Warm 경로와 Cold 경로로 구분

- Warm 경로 적용 대상: 작가가 신뢰도 높게 매칭되고, 학습 데이터 안에 같은 작가의 사용 가능한 가격 이력이 충분한 작품
- Cold 경로 적용 대상: 같은 작가의 학습 이력이 없거나, 작가 매칭이 불확실하거나, 같은 작가 이력이 충분하지 않은 작품
- 성능 관리 방식: Warm과 Cold의 입력 조건과 난이도가 다르므로 별도 지표로 관리

- 최종 보고 기준 성능:

| 구분 | 채택 모델 | 평가 기준 | n | MdAPE | MAPE | p95 APE | RMSE log | 해석 |
|---|---|---|---:|---:|---:|---:|---:|---|
| Warm | 기준가격 기반 미세 보정 모델 | fixed test | 607 | 0.140976 | 0.269888 | 0.807325 | 0.397454 | 기존 Warm 기준가격을 거의 유지하면서 방향이 확인된 작품만 미세 보정 |
| Cold | 검색 피처 포함 Quantile 예측 + 과대예측 방어 + 작가 검색 보정 | fixed test | 3,099 | 0.409820 | 0.849260 | 2.346465 | - | 신규/저이력 작가 상황에서 검색 피처와 불확실성 방어를 함께 사용 |

- 핵심 판단:

- Warm 모델 구조: `기준가격 + 미세 보정값`
- Warm 보정 방식: 기준가격을 크게 바꾸지 않고, 방향 분류 모델과 Huber 잔차 모델이 같은 방향을 가리킬 때만 아주 작게 보정
- Warm 적용 범위: 같은 작가로 고신뢰 매칭되고 같은 작가 가격 이력이 5건 이상인 작품만 Warm으로 처리
- Warm 보조 정보: 유사작품 정보는 Warm 내부 기준가격과 신뢰도 계산을 돕는 보조 피처이며, 유사작가나 유사작품만으로 Warm 적용 범위를 넓히지 않음
- Cold 모델 구조: `검색 피처 포함 대표 예측가격 + 과대예측 방어 + 작가 검색 보정값`
- Cold 보정 방식: 검색 피처로 작가 문맥을 보강하고, 예측 불확실성이 큰 경우 낮은쪽 40% 지점 가격 기준으로 하향
- 최종 가격 변환: 두 모델 모두 로그가격에서 계산 후 `exp()`를 적용해 원화 예측가격으로 변환
- MAPE 계산 기준: `최종예측가격_KRW = exp(최종_로그가격)`으로 원화 예측가격을 만든 뒤 실제 원화 가격과 비교해 계산
- RMSE log 계산 기준: `최종_로그가격`과 `실제_로그가격`의 차이로 계산

### 2.1 Warm/Cold 라우팅 기준

- 핵심 답변: 작가 이력이 1건이라도 있으면 무조건 Warm으로 보내는 구조가 아님
- 실험 split 기준: Warm validation/test 작가는 학습 데이터에 같은 작가가 존재하고, 최소 학습 이력 5건을 만족하도록 구성
- 실험 split 기준: Cold validation/test 작가는 학습 데이터의 `artist_key`, 정규화 작가명과 겹치지 않도록 구성
- 운영 고정 기준: `작가매칭신뢰도점수 >= 0.90`이고 `같은작가_사용가능가격이력수 >= 5`이면 Warm, 그 외에는 Cold
- 운영 고정 기준: 같은 작가 이력이 1~4건이면 자동 Warm으로 보내지 않고 Cold로 처리
- 1~4건을 Cold로 처리하는 이유: 현행 Warm 파이프라인의 작가 단위 유사작품 매칭이 최소 표본 5건을 요구하는 구조라서, 5건 미만은 작가 가격 신호가 발동하지 않음 (성능 실험으로 정한 임계값이 아니라 현행 구조의 적용 가능 최소선)
- Warm-lite 경로 동결 완료: 이력 1~4건 고신뢰 매칭 작가 전용 경량 Warm 경로가 검증을 통과해 별도 모델 번들로 동결됨 (`warm_lite_v0.1`, PP-WCUT1/PP-WCUT2/PP-WLITE-ARTIFACT1). 기존 Warm/Cold 경로는 변경 없음
- Warm-lite 적용 시 라우팅: `매칭신뢰도 >= 0.90 AND 이력 5건 이상 → Warm` / `매칭신뢰도 >= 0.90 AND 이력 1~4건 → Warm-lite` / `그 외 → Cold`. 이력 1건은 차등 등급(넓은 범위 표시 + 검수 플래그)으로 처리
- Warm-lite 운영 연동 전제: 매칭 점수 캘리브레이션(운영 매칭 로그 수집·검수)과 신규 트래픽 모니터링 — 준비 완료 전까지는 현행 라우팅(1~4건 → Cold) 유지
- 유사작품 정보의 역할: Warm/Cold 라우팅을 단독으로 결정하는 기준이 아니라, Warm 내부 기준가격과 신뢰도 계산을 안정화하는 보조 근거

#### 2.1.1 운영 라우팅 수치 기준

| 운영 변수 | Warm 기준 | Cold 기준 | 산정 방식 |
|---|---:|---:|---|
| `작가매칭신뢰도점수` | `0.90 이상` | `0.90 미만` | 입력 작가와 학습 데이터 작가가 같은 사람인지 판단한 0~1 점수 |
| `같은작가_사용가능가격이력수` | `5건 이상` | `0~4건` | 동일 작가로 확정된 학습 데이터 중 가격 예측 기준으로 사용할 수 있는 작품 가격 이력 수 |

```text
운영 라우팅 공식

Warm 적용 여부 =
  (작가매칭신뢰도점수 >= 0.90)
  AND
  (같은작가_사용가능가격이력수 >= 5)

위 조건을 하나라도 만족하지 못하면 Cold 적용
```

#### 2.1.1.1 이력 5건 기준의 성격과 실험 근거

- 기준의 성격: `5건 이상`은 성능 비교로 찾은 임계값이 아니라, 현행 Warm 파이프라인의 작가 매칭(1~3순위)이 최소 표본 5를 요구하는 구조 제약에 따른 적용 가능 최소선
- 실측 근거 1 (이력 절단 실험, warm test 607행): 작가 이력을 k건으로 인위 절단하면 현행 구조에서는 k=1~4에서 작가 매칭이 발동하지 않아 Warm이 Cold와 동등~열위, k=5에서 MdAPE `0.49 → 0.18`로 단절 개선 — 즉 5건 미만 작품을 현행 Warm으로 보내면 안 되는 것은 실측으로 확인됨
- 실측 근거 2 (이력 수별 성능, warm test 실측): 이력 5~7건 작가 MdAPE `0.2256` vs 50건 이상 작가 `0.1072` — 이력이 많을수록 오차가 단조 감소
- Warm-lite 동결 완료: 저표본 매칭(최소 1건)을 허용한 경량 Warm 경로가 반복 검증(절단 seed 3개 × k=1~4 전 조합, 개선확률 0.995 이상)을 통과해 `warm_lite_v0.1`로 동결됨
- Warm-lite 동결 모델 성능(warm test 실측, MdAPE 기준): 이력 1건 `0.199`, 2건 `0.174`, 3건 `0.176`, 4건 `0.152` — 같은 행 Cold `0.47~0.49` 대비 2.3~3.1배 개선, 4건이면 기존 Warm(`0.141`) 수준에 근접
- 운영 연동 전제: 매칭 점수 캘리브레이션 + 신규 트래픽 모니터링(절단 시뮬레이션 한계 보완) — 준비 완료 전까지 현행 운영 기준은 위 표(5건)를 유지

#### 2.1.2 작가매칭신뢰도점수 계산 방식

- 목적: 입력 작가가 학습 데이터의 특정 작가와 같은 사람인지 0~1 사이 점수로 환산
- 점수 해석: `1.00`에 가까울수록 같은 작가일 가능성이 높고, `0.00`에 가까울수록 같은 작가로 볼 근거가 약함
- Warm 라우팅 기준: `작가매칭신뢰도점수 >= 0.90`
- 보수 원칙: 작가명이 같아도 생년/국적/동명이인 위험을 확인할 수 없으면 Warm으로 보내지 않음

작가명 정규화 방식:

```text
정규화작가명 =
  소문자 변환
  + 앞뒤 공백 제거
  + 연속 공백 1칸으로 축소
  + 한글명은 공백 제거 버전도 후보에 포함
  + 영문명은 "First Last", "Last First" 순서 후보를 모두 포함
```

한글 이름 입력을 artist_key로 연결하는 방식:

```text
[입력 작가명: 한글명 중심]
        |
        v
[작가명 정규화]
  - 공백 정리
  - 한글명 공백 제거 후보 생성
  - 영문명이 있으면 순서 변형 후보 생성
        |
        v
[학습 작가 사전에서 후보 검색]
  - artist_name_ko 정규화값 일치
  - artist_name_ko 공백 제거값 일치
  - artist_name_en 정규화값 일치
  - 위 조건이 없으면 문자열 유사도 85점 이상 후보 확인
        |
        v
[후보 검증]
  - 후보가 1명인가?
  - 생년/국적/외부 작가 식별자가 충돌하지 않는가?
  - 동명이인 후보가 섞이지 않는가?
        |
        v
[확정된 후보의 artist_key 사용]
```

| 단계 | 운영 처리 | Warm 라우팅 영향 |
|---|---|---|
| 한글명 완전 일치 | `김환기`와 학습 작가 사전의 `김환기`가 정규화 후 일치 | 후보가 1명이고 보조 정보가 맞으면 `작가매칭신뢰도점수` 상승 |
| 한글명 공백 차이 | `김 환 기`, `김환기`처럼 공백만 다른 경우 같은 후보로 처리 | 공백 차이만으로 Cold로 떨어지지 않음 |
| 영문명 병기 | `Kim Whanki`, `Whanki Kim` 순서 변형까지 후보화 | 한글명과 영문명이 함께 있으면 보조 검증에 사용 |
| 문자열 유사도 후보 | 오탈자나 표기 차이가 있을 때 fuzzy ratio 85점 이상만 후보로 인정 | 85점 미만이면 같은 작가로 보지 않음 |
| 동명이인 후보 | 같은 한글명이 여러 artist_key에 연결되는 경우 | 생년/외부 식별자 확인 전에는 Warm 금지 |
| 한글명만 있고 보조 정보 없음 | 이름은 같지만 생년/국적/외부 식별자를 확인할 수 없음 | `작가매칭신뢰도점수`가 보통 `0.80` 수준이라 Cold |

운영에서 필요한 작가 사전 필드:

| 필드 | 용도 |
|---|---|
| `artist_key` | 모델 내부에서 사용하는 작가 고유 식별자 |
| `artist_name_ko` | 한글명 직접 매칭 |
| `artist_name_ko_normalized` | 공백/대소문자/기호 차이를 줄인 한글명 |
| `artist_name_ko_no_space` | 한글명 공백 제거 매칭 |
| `artist_name_en` | 영문명 보조 매칭 |
| `artist_name_en_reversed` | 영문 성/이름 순서가 바뀐 경우 보조 매칭 |
| `birth_year` | 동명이인 분리와 보조 검증 |
| `nationality` | 동명이인 분리와 보조 검증 |
| `external_artist_id` | Artsy, Saatchi 등 외부 작가 식별자 검증 |
| `usable_training_price_count` | Warm 라우팅의 가격 이력 수 기준 |

주의할 점:

- 한글 이름 문자열 자체가 `artist_key`가 되는 것은 아님
- 한글 이름은 학습 작가 사전에서 기존 `artist_key` 후보를 찾기 위한 입력값
- 같은 한글명이 여러 작가에게 연결되면 보조 정보 확인 전까지 Warm으로 보내지 않음
- 학습 작가 사전에 한글 alias가 없고 영문명만 있는 경우, 자동 번역/로마자 변환만으로는 고신뢰 매칭으로 보지 않음
- 검색 결과만으로 같은 작가라고 추정되는 경우는 `작가매칭신뢰도점수`를 낮게 보고 Cold로 처리

작가키가 있는 경우:

```text
if 입력_artist_key == 학습_artist_key:
    작가매칭신뢰도점수 = 1.00
```

작가키가 없거나 신뢰할 수 없는 경우:

```text
작가매칭신뢰도점수 =
  clip(
      0.70 * 이름일치점수
    + 0.20 * 보조정보일치점수
    + 0.10 * 학습작가등록점수
    - 0.15 * 동명이인위험점수
    - 0.20 * 핵심정보충돌점수,
    0.00,
    0.95
  )
```

| 변수 | 값 산정 기준 | 의미 |
|---|---|---|
| `이름일치점수` | 정규화 이름이 완전 일치하면 `1.00`; 문자열 유사도 85점 이상이면 `문자열유사도 / 100`; 85점 미만이면 `0.00` | 작가명이 얼마나 비슷한지. 문자열 유사도는 기존 작가 matcher의 fuzzy ratio 기준 |
| `보조정보일치점수` | 생년 또는 외부 작가 식별자가 일치하면 `1.00`; 생년은 없지만 국적/프로필이 충돌하지 않고 후보가 1명뿐이면 `0.70`; 확인 근거가 부족하면 `0.00` | 이름 외에 같은 작가라고 볼 근거 |
| `학습작가등록점수` | 학습 데이터에 해당 후보 작가가 존재하면 `1.00`, 없으면 `0.00` | Warm 기준가격을 만들 수 있는 후보인지 |
| `동명이인위험점수` | 같은 이름 후보가 여러 명이면 `1.00`; 일부 혼동 가능성이 있으면 `0.50`; 위험 근거가 없으면 `0.00` | 이름은 같지만 다른 사람일 위험 |
| `핵심정보충돌점수` | 생년/국적/외부 식별자 중 하나라도 충돌하면 `1.00`; 충돌이 없으면 `0.00` | 같은 작가로 보면 안 되는 명확한 반대 근거 |

`clip(x, 0.00, 0.95)`의 의미:

- 계산값이 `0.00`보다 작으면 `0.00`으로 제한
- 계산값이 `0.95`보다 크면 `0.95`로 제한
- 작가키 직접 일치가 아닌 이름 기반 매칭은 최대 `0.95`까지만 허용
- 이유: 이름 기반 매칭은 항상 동명이인/표기 변형 위험이 있으므로, `artist_key` 직접 일치 `1.00`과 구분

임계값 `0.90`의 정량 근거 (오매칭 비용 실측, PP-WMATCH1):

- 오매칭 비용: 잘못된 작가의 이력으로 Warm 가격을 만들면 MdAPE `0.66~0.70`, p95 APE `9.3~9.7`로 Cold(`0.41 / 2.17`)보다 훨씬 나쁨 — **장르가 비슷한 작가로 잘못 매칭되어도 거의 동일하게 파괴적**
- 기대손실 계산: 매칭 실제 정확도가 약 `85%` 이상일 때만 Warm 라우팅이 Cold 대비 기대 우위 (MAPE 기준 0.83, p95 기준 0.85) → 임계 `0.90`은 이 최소선 위에 마진을 둔 보수 설정
- 동명이인 실태(학습 데이터 실측): 작가 1,773명 중 정규화 한글명 충돌 117 `artist_key`(6.6%), 충돌 작가의 생년 보유율 41% — "보조 정보 확인 전 Warm 금지" 원칙의 근거
- 운영 과제: 매칭 점수와 실제 정확도의 대응(캘리브레이션)은 운영 매칭 로그·검수 데이터로 보정 필요 — 위 가중치 산식은 이 보정 전까지의 보수 설계안
- 재검증 결과(PP-E2E1, 2026-06-12): 임계 `0.90`은 자격 작가의 64~73%를 보조정보 부재만으로 Cold로 보내 기대 오차가 all-Cold 수준 — **임계 `0.80` 하향(이름 완전일치+사전 등록, 보조정보 무 구간은 검수 플래그 동반) 권고**. Cold 오유입은 0~0.5%로 허용 한계(~30%) 대비 마진 큼. 최종 적용은 운영 매칭 로그로 사전 밖 동명이인율 확인 후 결정

계산 예시:

| 상황 | 계산 | 작가매칭신뢰도점수 | Warm 가능 여부 |
|---|---|---:|---|
| `artist_key`가 학습 데이터와 동일 | 직접 일치 | `1.00` | 가격 이력 5건 이상이면 Warm |
| 정규화 이름 완전 일치, 생년 일치, 학습 작가 존재, 동명이인 위험 없음 | `0.70*1.00 + 0.20*1.00 + 0.10*1.00 = 1.00`, 최대값 제한 | `0.95` | 가격 이력 5건 이상이면 Warm |
| 정규화 이름 완전 일치, 생년/국적 확인 불가, 학습 작가 존재 | `0.70*1.00 + 0.20*0.00 + 0.10*1.00 = 0.80` | `0.80` | Cold |
| 문자열 유사도 92점, 생년 일치, 학습 작가 존재 | `0.70*0.92 + 0.20*1.00 + 0.10*1.00 = 0.944` | `0.944` | 가격 이력 5건 이상이면 Warm |
| 정규화 이름 완전 일치, 동명이인 후보 여러 명, 보조 정보 없음 | `0.70*1.00 + 0.10*1.00 - 0.15*1.00 = 0.65` | `0.65` | Cold |
| 생년 또는 외부 식별자가 충돌 | 충돌 감점 적용 | `0.90 미만으로 하락` | Cold |

| 작가 매칭 상태 | `작가매칭신뢰도점수` | 운영 판단 |
|---|---:|---|
| `artist_key`가 동일하게 매칭됨 | `1.00` | 가격 이력 수 조건을 추가 확인 |
| `artist_key`는 없지만 정규화 한글명/영문명이 일치하고 생년 또는 외부 작가 식별자도 일치함 | `0.95` | 가격 이력 수 조건을 추가 확인 |
| 작가명은 일치하지만 생년/국적/동명이인 여부를 확인할 수 없음 | `0.80` | Cold |
| 검색 결과나 유사 텍스트만으로 같은 작가로 추정됨 | `0.60` | Cold |
| 같은 작가로 볼 근거가 없음 | `0.00` | Cold |

`같은작가_사용가능가격이력수`에 포함하는 데이터 기준:

- 같은 작가로 확정된 학습 데이터 작품
- 실제 가격값이 존재하고 `가격 > 0`인 작품
- 로그가격 계산이 가능한 작품
- 현재 예측 대상 작품과 중복되지 않는 작품
- 동일 거래/동일 작품 중복 입력이 제거된 작품
- 테스트 데이터 또는 운영 평가 대상의 정답 가격을 포함하지 않은 작품

| 조건 | 권장 경로 | 판단 이유 |
|---|---|---|
| 작가매칭신뢰도점수 `0.90 이상`이고 같은 작가의 사용 가능한 학습 가격 이력이 `5건 이상` | Warm | 작가별 과거 가격대를 기준가격에 반영할 수 있음 |
| 작가매칭신뢰도점수 `0.90 이상`이지만 같은 작가의 사용 가능한 학습 가격 이력이 `1~4건` | Cold | 표본이 너무 적어 작가별 기준가격을 안정적으로 만들기 어려움 |
| 작가 매칭이 불확실하거나 동명이인 위험이 있음 | Cold | 잘못된 작가 이력을 Warm 기준가격에 쓰는 위험이 큼 |
| 학습 데이터에 같은 작가 이력이 없음 | Cold | 작품/작가 메타/검색 피처와 비작가 비교군으로 추정해야 함 |
| 같은 작가는 아니지만 매체/크기/지지체가 비슷한 유사작품만 있음 | Cold 보조 근거 또는 낮은 신뢰도 참고 | 작가별 가격 기준은 없으므로 Warm으로 보지 않음 |

```text
Warm/Cold 운영 라우팅 판단

작가매칭신뢰도점수 >= 0.90?
        |
        +-- 아니오 --> Cold
        |
        v
같은작가_사용가능가격이력수 >= 5건?
        |
        +-- 예 ----> Warm
        |
        +-- 아니오 --> Cold
```

- 문서에서 `작가 이력이 충분하다`의 의미: 단순히 작가명이 한 번 등장했다는 뜻이 아니라, 가격 예측 기준으로 사용할 수 있는 같은 작가의 학습 가격 이력이 충분하다는 뜻
- 문서에서 `신규/저이력 작가`의 의미: 학습 데이터에 같은 작가 이력이 없거나, 있더라도 Warm 기준가격을 만들기에는 표본 수와 매칭 신뢰도가 부족한 작가

## 3. 평가 기준

- 성능 수치 기준: 기존 Warm/Cold fixed test 기준

| 구분 | 평가 데이터 | 목적 |
|---|---|---|
| Warm fixed test | 607건 | 기존 Warm 실험들과 동일 기준에서 최종 운영 후보 성능 확인 |
| Warm validation out-of-fold | 519건 | 미세 보정 학습 및 과적합 방지 검증 |
| Cold fixed test | 3,099건 | Cold 최고 성능 연구 기준 모델 성능 확인 |
| Cold validation | 2,753건 | guard 임계값과 검색 보정 재현 확인 |

- 주요 지표 해석:

| 지표 | 의미 | 낮을수록 좋은가 |
|---|---|---|
| MdAPE | 작품별 절대 퍼센트 오차의 중앙값 | 예 |
| MAPE | 작품별 절대 퍼센트 오차의 평균 | 예 |
| p95 APE | 큰 오차 상위 5% 구간을 보는 95퍼센타일 오차 | 예 |
| RMSE log | 로그가격 기준 평균제곱근 오차 | 예 |

MAPE 계산식:

```text
최종예측가격_KRW = exp(최종_로그가격)

작품별_APE =
  abs(최종예측가격_KRW - 실제가격_KRW)
  / 실제가격_KRW

MAPE = mean(작품별_APE)
MdAPE = median(작품별_APE)
p95 APE = quantile(작품별_APE, 0.95)
```

RMSE log 계산식:

```text
RMSE log =
  sqrt(mean((최종_로그가격 - 실제_로그가격)^2))
```

- MAPE, MdAPE, p95 APE: 원화 가격으로 변환한 뒤 실제 원화 가격과 비교한 비율 오차
- RMSE log: 로그가격 공간에서 계산한 오차
- 두 지표를 함께 표기하는 이유: MAPE는 사업 관점에서 실제 가격 대비 몇 퍼센트 틀렸는지 보기 쉽고, RMSE log는 모델이 학습/보정하는 로그가격 공간의 오차를 확인하기 좋음

### 3.1 모델/학습법/통계 방식 표기 점검

- 점검 목적: 모델명, 학습법, 통계 처리, 후처리 로직이 서로 섞여 보이지 않도록 문서용 표기와 실제 역할을 구분
- 표기 원칙: 최종 계산 경로에 영향을 주는 항목은 본문에서 기능 중심 이름과 계산 역할을 함께 표기
- 제외 원칙: 최종 계산 경로에 포함되지 않는 실험 후보명이나 내부 추적 ID는 본문 설명이 아니라 내부 추적 표에서만 관리

| 구분 | 문서용 표기 | 실제 의미 | 이 보고서에서의 사용 위치 |
|---|---|---|---|
| 모델 학습법 | `Huber 잔차 모델` | 큰 오차 샘플의 영향을 줄이면서 기준 로그가격에 남은 잔차를 예측하는 강건 회귀 방식 | Warm 미세 보정값의 원천 후보 계산 |
| 모델 학습법 | `방향 분류 모델` | 기준가격보다 실제 가격이 높을지 낮을지를 확률로 판단하는 분류 모델 | Warm 보정 방향과 보정 적용 여부 판단 |
| 모델 학습법 | `LightGBM Quantile 회귀` | LightGBM 트리 모델을 평균 예측이 아니라 특정 Quantile 위치의 가격을 예측하도록 학습한 방식 | Cold 기준 후보, 낮은쪽 방어가격, 불확실성 폭 생성 |
| 통계 방식 | `Quantile예측구간폭` | 높은 Quantile 예측값과 낮은 Quantile 예측값의 차이 | Warm 보정 상한 축소, Cold 불확실성 판단 |
| 통계 방식 | `잔차` | `실제_로그가격 - 예측_로그가격` | Warm Huber 보정 학습, Cold 구간별 보정값 계산 |
| 통계 방식 | `중앙값` 또는 `median()` | 값을 순서대로 정렬했을 때 가운데에 있는 값 | MdAPE 지표, Cold 구간별 잔차 안정화 |
| 통계 방식 | `rank01()` | 값의 상대적 순위를 0~1 범위로 변환하는 처리 | Warm 작품단위위험도 계산 |
| 후처리 방식 | `clip()` | 값이 정해진 하한/상한을 넘지 않도록 제한하는 처리 | Warm 보정 상한, Cold 구간별 보정값 제한 |
| 후처리 방식 | `bucket()` 또는 구간화 | 연속값을 의미 있는 구간으로 나누는 처리 | 가격대, 신뢰도, Quantile예측구간폭 구간 생성 |
| 후처리 방식 | `lookup` | 학습 중 실시간으로 계산하는 모델이 아니라 미리 검증해 저장한 표에서 값을 조회하는 방식 | Cold 작가 검색 보정값 적용 |
| 계산 표현 | `로그가격` | 가격에 자연로그를 적용한 값 | 두 모델 모두 로그가격에서 계산 후 원화 가격으로 변환 |
| 계산 표현 | `exp()` | 로그가격을 다시 원화 가격으로 되돌리는 지수 함수 | 최종 Warm/Cold 원화 예측가격 산출 |
| 평가 표현 | `fixed test` | 실험 간 비교를 위해 고정한 테스트 데이터 | Warm/Cold 최종 성능 비교 기준 |
| 평가 표현 | `validation out-of-fold` | 학습에 직접 쓰지 않은 fold 예측으로 검증하는 방식 | Warm 미세 보정의 과적합 여부 확인 |

- 표기 보완 결과:

- `Quantile`은 Warm과 Cold에서 모두 사용되지만 역할이 다르므로 별도 표기
- Warm의 `Quantile` 역할: 기준가격 생성이 아니라 보정 위험도와 보정 상한 계산에 사용
- Cold의 `LightGBM Quantile 회귀` 역할: 기준 후보, 보수 후보, 예측 불확실성 폭을 직접 생성
- `Huber`는 약어가 아니라 강건 회귀 방식 이름이므로 `Huber 잔차 모델`로 표기
- `lookup`, `rank01`, `clip`, `bucket`, `median`은 모델명이 아니라 통계/후처리 방식으로 표기

Quantile 역할 차이:

| 구분 | Warm에서의 Quantile | Cold에서의 Quantile |
|---|---|---|
| 핵심 역할 | 최종 예측가격을 직접 만들지 않음 | 최종 예측가격의 출발점이 되는 기준 후보를 직접 만듦 |
| 사용 위치 | 기준가격 생성 이후의 위험도 판단 단계 | 기준가격 후보 생성 단계와 과대예측 방어 단계 |
| 주요 산출값 | `Quantile예측구간폭` | `검색피처포함_기초Quantile후보_로그가격`, `낮은쪽40퍼센트기준_로그가격`, `Quantile예측구간폭` |
| 가격 이동 방식 | 예측 폭이 넓으면 보정 상한을 줄여 가격을 덜 움직임 | 예측 폭이 넓고 과대예측 위험이 있으면 낮은쪽 40% 지점 가격 쪽으로 낮춤 |
| 해석 | “이 작품은 불확실하니 Warm 보정을 약하게 하자” | “이 작품의 기준가격과 낮은쪽 방어가격을 Quantile 모델로 만들자” |

Warm에서의 Quantile 사용 흐름:

```text
[미세보정전 기준로그가격]
        |
        v
[Quantile예측구간폭 확인]
        |
        v
[불확실성순위 = rank01(Quantile예측구간폭)]
        |
        v
[적용상한 축소]
        |
        v
[최종보정값을 작게 제한]
        |
        v
[최종 Warm 로그가격]
```

Cold에서의 Quantile 사용 흐름:

```text
[작품 피처 + 작가 메타 피처 + 검색 피처]
        |
        v
[LightGBM Quantile 회귀]
        |
        +--> 검색피처포함_기초Quantile후보_로그가격
        +--> 낮은쪽40퍼센트기준_로그가격
        +--> Quantile예측구간폭
        |
        v
[Quantile예측구간폭 구간별 잔차 보정]
        |
        v
[과대예측 위험이면 낮은쪽 40% 지점 가격 쪽으로 하향]
        |
        v
[최종 Cold 로그가격]
```

## 4. Warm 모델 상세

### 4.1 모델 목적

- 적용 대상: 작가가 신뢰도 높게 매칭되고, 학습 데이터 안에 같은 작가의 사용 가능한 가격 이력이 충분한 작품
- 모델 구조: 가격을 처음부터 새로 예측하는 단일 모델이 아니라, 선행 Warm 예측가격으로 만든 기준 로그가격 위에 매우 작은 보정값을 더하는 구조
- 계산 관점: `기준가격 + 미세 보정값`

- 핵심 처리:

- 1차 판단: 기준가격이 실제보다 낮은지 높은지 방향 판단
- 보정 조건: Huber 잔차 모델이 제안한 보정 방향과 방향 분류 모델의 방향이 일치할 때만 보정

### 4.2 Warm 계산 순서도

```text

  - 유사작품 기반 선행 예측값
  - 작품 크기/매체/지지체
  - 유사작품 수와 가격 범위
  - 예측 불확실성
        |
        v
[미세 보정 전 기준 로그가격 준비]
  - 선행 균형 기준 로그가격
  - p95 방어형/개선형 보조 예측가격
  - 안정 기준 로그가격
        |
        v
[파생 피처 생성]
  - 가격대 구간
  - 신뢰도 구간
  - Quantile예측구간폭 구간
  - 매체/지지체 조합

        |
        v

        |
        v

  - 기준 로그가격에 남아 있는 잔차 예측
        |
        v
[방향 일치 여부 확인]
  - 방향 분류 모델과 잔차 모델의 방향이 같은가?
        |
        v
[보정 상한 적용]
  - 예측 불확실성과 작품 단위 위험도가 높으면 보정 폭 축소
        |
        v

        |
        v

```

### 4.3 Warm 사용 피처

- Warm 최종 미세 보정층의 입력 범위: 선행 Warm 모델들이 만든 기준 로그가격, 유사작품 기반 통계, 불확실성 지표, 파생 구간 피처
- 원천 작가 메타 사용 방식: 최종 미세 보정층에서 직접 다시 학습하지 않음
- 작가 정보 반영 방식: 선행 Warm 기준가격 생성 단계에는 작가키와 유사작품 정보가 이미 반영되어 있으며, 최종 미세 보정층은 그 결과값을 받아 추가 보정만 수행
- 피처 설명 기준: 최종 재현 패키지가 직접 읽는 컬럼과, 재현 스크립트 내부에서 계산하는 파생 피처를 구분
- 변수명 표기 기준: 본문 계산식에는 의미를 바로 알 수 있는 문서용 이름을 사용하고, 내부 컬럼명은 재현 확인용 별도 열에만 병기

#### 4.3.2 Warm 선행 기준가격 계열 보충 설명

- 선행 기준가격 계열의 역할: 최종 미세 보정층이 새로 가격을 처음부터 만들기 전에, 이전 Warm 실험에서 이미 계산된 여러 기준 로그가격을 입력으로 받음
- 최종 산식 기준: `미세보정전_기준로그가격`만 최종 예측가격의 직접 출발점으로 사용
- 참고값 기준: `기존70대30기준로그가격`, `이전_안정기준로그가격`은 최종 가격에 직접 더하거나 섞지 않고, 후보 비교와 검수에 사용

| 문서용 이름 | 어떤 값인가 | 계산 또는 생성 방식 | 현재 최종 모델에서의 역할 |
|---|---|---|---|
| `미세보정전_기준로그가격` | 최종 미세 보정을 적용하기 직전의 기준 로그가격 | 선행 Warm 후보들을 비교한 뒤 운영 후보로 선택한 기준 로그가격 | 최종 Warm 로그가격의 직접 출발점 |
| `기존70대30기준로그가격` | 이전 운영 후보에서 사용하던 70:30 혼합 기준 로그가격 | `0.70 * 비교군통계_Huber후보로그가격 + 0.30 * 방어형블렌드후보로그가격` | 현재 최종 산식에는 직접 사용하지 않고, 이전 기준과의 비교/검수에 사용 |
| `비교군통계_Huber후보로그가격` | 같은 작가로 확정된 Warm 대상에서 작가 가격 이력과 작품 특성이 비슷한 비교군 통계를 중심으로 만든 Warm Huber 후보 | 유사작품 통계 피처와 Huber 계열 예측을 결합한 선행 후보 | `기존70대30기준로그가격`의 70% 구성요소 |
| `방어형블렌드후보로그가격` | 평균오차와 큰 오차 방어를 함께 고려한 선행 방어형 후보 | 과거 구성 기준: `0.75 * 방어형후보로그가격 + 0.25 * 생성버킷순차보정후보로그가격` | `기존70대30기준로그가격`의 30% 구성요소 |
| `이전_안정기준로그가격` | Huber 계수 보정 계열에서 안정성이 좋았던 과거 기준 로그가격 | 특정 구간에서만 약하게 보정하고, 조건을 만족하지 않으면 기준값을 유지하는 방식으로 관리된 선행 후보 | 가격대 구간 생성과 후보 비교용 참고값 |
| `안정성우선_기준로그가격` | 큰 오차 상위 구간을 더 방어하도록 선택한 안정성 우선 로그가격 | p95 APE 방어를 더 중시한 선행 Warm 기준 후보 | 최종 가격에 직접 섞기보다 `미세보정전_기준로그가격`과의 차이를 위험도로 사용 |

- 70:30의 의미:

```text
기존70대30기준로그가격
  = 0.70 * 비교군통계_Huber후보로그가격
  + 0.30 * 방어형블렌드후보로그가격
```

- 70% 구성요소: 같은 작가로 확정된 Warm 대상에서 작가 가격 이력과 유사작품 비교군 통계를 더 신뢰한 가격 후보
- 30% 구성요소: 큰 오차를 줄이기 위해 방어적으로 만든 후보
- 현재 최종 모델과의 차이: 최종 모델은 이 70:30 값을 다시 섞지 않고, 더 안정적인 `미세보정전_기준로그가격`에 아주 작은 `최종보정값`만 더함

#### 4.3.3 Warm 파생 피처 계산

```text
[Warm 직접 입력 피처]
  - 미세보정전_기준로그가격
  - 안정성우선_기준로그가격
  - 상향확률
  - Huber잔차예측값
  - Quantile예측구간폭
  - 유사작품가격범위비율
  - 유사작품표본수
  - 후보예측분산
  - 현재-안정기준차이
        |
        v
[순위형 파생 피처]
  - 불확실성순위
  - 가격범위순위
  - 후보분산순위
  - 기준-안정가격차이순위
        |
        v
[작품 단위 위험도]
        |
        v
[방향확신도와 적용확신도]
        |
        v
[최종 보정 상한과 최종 Warm 가격]
```

| 파생 피처 | 계산식 또는 생성 방식 | 역할 |
|---|---|---|
| `불확실성순위` | `rank01(Quantile예측구간폭)` | 예측 폭이 큰 작품의 보정 상한 축소 |
| `가격범위순위` | `rank01(유사작품가격범위비율)` | 유사작품 가격 범위가 넓은 작품의 위험 반영 |
| `후보분산순위` | `rank01(후보예측분산)` | 선행 모델들이 서로 다르게 예측한 정도 반영 |
| `기준-안정가격차이순위` | `rank01(abs(안정성우선_기준로그가격 - 미세보정전_기준로그가격))` | 기준가격과 안정성 기준가격의 괴리 반영 |
| `저신뢰표시값` | `1 if 신뢰도구간 contains low else 0` | 저신뢰 구간 위험 가산 |
| `표본부족점수` | `clip((10 - 유사작품표본수) / 10, 0, 1)` | 유사작품 표본이 적을수록 위험 증가 |
| `작품단위위험도` | `clip(0.25*불확실성순위 + 0.20*가격범위순위 + 0.20*후보분산순위 + 0.18*기준-안정가격차이순위 + 0.09*저신뢰표시값 + 0.08*표본부족점수, 0, 1)` | 최종 보정 상한을 줄이는 핵심 위험 점수 |
| `방향확신도` | `abs(상향확률 - 0.5) * 2` | 방향 분류 모델의 확신도 |
| `적용확신도` | `clip((방향확신도 - 0.12) / (1 - 0.12), 0, 1)` | 방향이 애매한 작품의 보정 약화 |

#### 4.3.4 Warm Quantile 사용 방식

- Warm에서도 Quantile 정보를 사용함
- Warm에서의 Quantile 역할: 기준가격을 직접 만드는 모델이 아니라, 기준가격을 얼마나 조심스럽게 보정할지 정하는 불확실성 신호
- 핵심 입력값: `Quantile예측구간폭`
- 해석 기준: Quantile 예측 폭이 넓을수록 같은 작품에 대해 가능한 가격 범위가 넓다는 뜻이므로, 최종 보정값을 더 작게 제한

| 항목 | Warm에서의 사용 | Cold에서의 사용 |
|---|---|---|
| Quantile 모델 역할 | 보정 위험도와 보정 상한 계산에 사용 | 기준가격 후보, 낮은쪽 방어가격, 예측 불확실성 폭 생성에 사용 |
| 기준가격 생성 여부 | Quantile이 최종 기준가격을 직접 만들지는 않음 | LightGBM Quantile 회귀 후보가 Cold 기준가격 생성에 직접 참여 |
| 주요 산출값 | `Quantile예측구간폭` | `검색피처포함_기초Quantile후보_로그가격`, `낮은쪽40퍼센트기준_로그가격`, `Quantile예측구간폭` |
| 최종 영향 | 보정값을 줄이는 방향으로 작동 | 기준가격 생성과 과대예측 방어 양쪽에 작동 |

```text
Warm에서의 Quantile 사용 흐름

Quantile예측구간폭
        |
        v
불확실성순위 = rank01(Quantile예측구간폭)
        |
        v
적용상한 축소
        |
        v
최종보정값 제한
```

| 문서용 이름 | 내부 컬럼명 | 계산 기준 | 해석 |
|---|---|---|---|
| `신뢰도구간` | `confidence_tier` | 예측 폭, 후보 간 분산, 유사작품 가격 범위, 유사작품 수, 기준-안정가격 차이를 조합 | 고신뢰/중신뢰/저신뢰 작품 구분 |
| `안정기준가격대` | `stable_price_band` | `이전_안정기준로그가격`을 `(-∞, 13.0]`, `(13.0, 14.5]`, `(14.5, 16.0]`, `(16.0, ∞)`로 구간화 | 안정 기준 가격대 구분 |

- 신뢰도 구간 해석 조건:

```text
고신뢰조건 =
  Quantile예측구간폭 <= 1.20
  and 후보예측분산 <= 0.10
  and 유사작품가격범위비율 <= 2.00
  and 유사작품표본수 >= 5
  and 현재-안정기준차이 <= 0.025

저신뢰조건 =
  Quantile예측구간폭 > 1.60
  or 후보예측분산 > 0.18
  or 유사작품가격범위비율 > 2.50
  or 유사작품표본수 < 5
  or 현재-안정기준차이 > 0.050

신뢰도구간 =
  고신뢰  if 고신뢰조건
  저신뢰  if 저신뢰조건
  중신뢰  otherwise
```

#### 4.3.6 Warm 전체 피처 사용처

```text
[직접 입력/상류 산출 피처]
        |
        +--> [기준 로그가격 선택]
        |      - 미세보정전_기준로그가격
        |
        +--> [방향 판단]
        |      - 상향확률
        |      - 방향확신도
        |      - 적용확신도
        |
        +--> [잔차 보정 후보]
        |      - Huber잔차예측값
        |      - 잔차방향일치
        |      - 원시보정값
        |
        +--> [위험도/상한 계산]
        |      - Quantile예측구간폭
        |      - 유사작품가격범위비율
        |      - 후보예측분산
        |      - 안정성우선_기준로그가격 - 미세보정전_기준로그가격
        |      - 신뢰도구간
        |      - 유사작품표본수
        |
        +--> [평가/검수]
               - 평가구분
               - 작품추적ID
               - 작가키
               - 작가명
               - 실제_로그가격
               - 실제_가격
               - 이전_안정기준로그가격
               - 기존70대30기준로그가격
               - 안정기준가격대
```

| 피처 또는 파생값 | 실제 사용 단계 | 사용 방식 | 예측가격에 미치는 영향 |
|---|---|---|---|
| `미세보정전_기준로그가격` | 기준 로그가격 | `최종_Warm_로그가격 = 미세보정전_기준로그가격 + 최종보정값`의 출발점 | 최종 가격의 대부분을 결정 |
| `상향확률` | 방향 판단 | 방향확신도, 적용확신도 계산 | 방향이 불확실하면 보정값이 0에 가까워짐 |
| `Huber잔차예측값` | 잔차 보정 후보 | Huber 잔차 예측값으로 원시보정값 계산 | 방향이 맞고 확신도가 있을 때만 미세 보정 |
| `안정성우선_기준로그가격` | 위험도 계산 | `abs(안정성우선_기준로그가격 - 미세보정전_기준로그가격)`를 후보 간 괴리로 사용 | 기준가격과 안정성 기준가격이 많이 다르면 보정 상한 축소 |
| `Quantile예측구간폭` | 불확실성 순위와 상한 계산 | `불확실성순위 = rank01(Quantile예측구간폭)` | Quantile 예측 폭이 넓을수록 보정 상한 축소 |
| `유사작품가격범위비율` | 작품 단위 위험도 | 가격범위순위 계산 | 유사작품 가격 범위가 넓을수록 보정 상한 축소 |
| `후보예측분산` | 작품 단위 위험도 | 후보분산순위 계산 | 선행 모델 간 의견 차이가 클수록 보정 상한 축소 |
| `현재-안정기준차이` | 신뢰도 구간 | high/low confidence 조건에 사용 | 신뢰도 구간을 통해 위험도에 간접 반영 |
| `유사작품표본수` | 표본 부족 점수 | `clip((10 - 유사작품표본수) / 10, 0, 1)` | 유사작품 수가 적을수록 보정 상한 축소 |
| `신뢰도구간` | 작품 단위 위험도 | low confidence 여부를 위험 점수에 가산 | 저신뢰 작품의 보정 폭 축소 |
| `불확실성순위` | 작품 단위 위험도 | `Quantile예측구간폭`을 0~1 순위값으로 변환 | 예측 폭이 큰 작품의 보정 상한 축소 |
| `가격범위순위` | 작품 단위 위험도 | `유사작품가격범위비율`을 0~1 순위값으로 변환 | 유사작품 가격 분포가 넓은 작품의 보정 상한 축소 |
| `후보분산순위` | 작품 단위 위험도 | `후보예측분산`을 0~1 순위값으로 변환 | 선행 후보 간 예측 차이가 큰 작품의 보정 상한 축소 |
| `기준-안정가격차이순위` | 작품 단위 위험도 | `abs(안정성우선_기준로그가격 - 미세보정전_기준로그가격)`를 0~1 순위값으로 변환 | 기준가격과 안정성 기준가격이 다르면 보정 상한 축소 |
| `저신뢰표시값` | 작품 단위 위험도 | `신뢰도구간`이 low이면 1, 아니면 0 | 저신뢰 구간을 위험 점수에 직접 반영 |
| `표본부족점수` | 작품 단위 위험도 | `유사작품표본수`가 적을수록 1에 가까워짐 | 유사작품 수가 적은 작품의 보정 상한 축소 |
| `작품단위위험도` | 최종 보정 상한 | 불확실성, 가격 범위, 후보 분산, 신뢰도, 표본 수를 가중합 | 위험도가 높을수록 최종 보정 폭을 작게 제한 |
| `방향확신도` | 보정 강도 | `abs(상향확률 - 0.5) * 2` | 상향/하향 판단이 애매하면 보정 약화 |
| `적용확신도` | 보정 강도 | 방향확신도에서 최소 기준 0.12를 뺀 뒤 0~1로 제한 | 방향 판단이 충분할 때만 보정값 반영 |
| `예상방향` | 보정 gate | 상향확률이 0.5 이상이면 +1, 미만이면 -1 | Huber 잔차 방향과 비교하는 기준 |
| `잔차방향일치` | 보정 gate | `sign(Huber잔차예측값) == 예상방향`이면 1 | 두 모델이 같은 방향을 말할 때만 보정 허용 |
| `원시보정값` | clip 전 보정값 | `0.025 * Huber잔차예측값 * 잔차방향일치 * 적용확신도` | 최종보정값의 후보값 |
| `방향별기본상한` | 보정 상한 | 상향은 0.00005, 하향은 0.000035 | 방향별 최대 이동 폭 지정 |
| `적용상한` | 최종 보정 상한 | 기본상한에 불확실성순위와 작품단위위험도 축소율 적용 | 위험한 작품은 원시보정값이 커도 작게만 반영 |
| `최종보정값` | 최종 로그가격 | `clip(원시보정값, -적용상한, +적용상한)` | 기준 로그가격에 더해지는 최종 미세 보정 |
| `안정기준가격대` | 검수/해석 | 가격대별 결과 해석과 보고용 구간 | 최종 보정 산식에는 직접 가산하지 않음 |
| `이전_안정기준로그가격`, `기존70대30기준로그가격` | 추적/검수 | 이전 기준 후보와 최종 후보 비교 | 최종 보정 산식에는 직접 가산하지 않음 |
| `실제_로그가격`, `실제_가격` | 평가 전용 | MdAPE, MAPE, p95 APE, RMSE log 계산 | 예측 시 입력으로 사용하지 않음 |
| `작품추적ID`, `작가키`, `작가명` | 재현/검수 | 작품 및 작가 추적 | 최종 보정 산식에는 직접 가산하지 않음 |

### 4.4 Warm 모델과 산식

- Warm 최종 모델의 순차 사용 모델:

| 모델 또는 방법 | 역할 | 사용 위치 |
|---|---|---|
| 방향 분류 모델 | 기준가격보다 실제 가격이 높을 확률 계산 | 보정 방향 판단 |
| Huber 잔차 모델 | 기준 로그가격 대비 남은 잔차 예측 | 보정 크기 제안 |
| Quantile 예측 폭 | 가격을 직접 만들지 않고 예측 불확실성으로 사용 | 보정 상한 축소 |
| 작품 단위 위험도 | 후보 간 차이와 불확실성을 요약 | 보정 상한 축소 |

- Warm 최종 계산식:

```text
실제_로그가격 = log(실제_가격)

잔차 = 실제_로그가격 - 미세보정전_기준로그가격

방향라벨 = 1  if 잔차 > 0
방향라벨 = 0  if 잔차 <= 0
```

- 방향 분류 모델의 역할: 상향확률 계산
- 재현 패키지 기준: 상류 방향 분류 모델의 산출값인 `상향확률`을 입력으로 사용

```text
방향확신도 = abs(상향확률 - 0.5) * 2

적용확신도
  = clip((방향확신도 - 0.12) / (1 - 0.12), 0, 1)
```

- Huber 모델의 역할: 잔차 예측
- 재현 패키지 기준: 상류 Huber 잔차 모델의 산출값인 `Huber잔차예측값`을 입력으로 사용

```text
잔차예측 = Huber잔차예측값
```

- 보정 적용 조건: 방향 분류 모델과 Huber 잔차 모델의 방향이 같은 경우만 적용

```text
예상방향 = +1  if 상향확률 >= 0.5
예상방향 = -1  if 상향확률 < 0.5

잔차방향일치 = 1  if sign(잔차예측) == 예상방향
잔차방향일치 = 0  otherwise
```

- 원시 보정값 계산:

```text
원시보정값
  = 0.025
    * 잔차예측
    * 잔차방향일치
    * 적용확신도
```

- 작품별 보정 상한: 불확실성과 위험도가 높을수록 축소

```text
방향별기본상한
  = 0.00005   if 원시보정값 >= 0
  = 0.000035  if 원시보정값 < 0

적용상한
  = clip(
      방향별기본상한
      * (1 - 0.55 * 불확실성순위)
      * (1 - 0.80 * 작품단위위험도),
      0.000006,
      방향별기본상한
    )

최종보정값 = clip(원시보정값, -적용상한, +적용상한)

최종_Warm_로그가격 = 미세보정전_기준로그가격 + 최종보정값

최종_Warm_가격_KRW = exp(최종_Warm_로그가격)
```

### 4.5 Warm 성능 해석

- Warm fixed test 607건 기준 최종 성능:

| 지표 | 값 |
|---|---:|
| MdAPE | 0.140976 |
| MAPE | 0.269888 |
| p95 APE | 0.807325 |
| RMSE log | 0.397454 |
| within 30% | 0.780890 |
| within 50% | 0.883031 |

- Warm 모델 해석: 큰 폭으로 가격을 바꾸는 모델이 아니라, 이미 안정화된 기준가격을 거의 유지하면서 일부 작품의 방향만 확인해 미세 보정
- 대외 설명 권장 표현: `안정성 중심의 미세 보정형 Warm 모델`

## 5. Cold 모델 상세

### 5.1 모델 목적

- 적용 대상: 같은 작가의 충분한 학습 가격 이력이 없거나, 작가 매칭이 불확실하거나, 신규 작가에 가까운 작품
- 모델 구조: Warm처럼 유사작품 기준가격을 강하게 쓰기 어려운 상황에서 작품 피처, 작가 메타, 작가명 검색 피처를 함께 사용
- 계산 관점: `검색 피처 포함 대표 예측가격 + 과대예측 방어 + 작가 검색 보정값`

- Cold 최고 성능 모델의 구성 단계:

- 대표 로그가격 생성: 검색 피처 포함 LightGBM Quantile 회귀 후보를 Quantile예측구간폭 구간별 검증 잔차로 안정화
- 과대예측 방어: Quantile예측구간폭이 넓고 대표 로그가격이 낮은쪽 40% 지점 가격보다 높은 작품을 낮은쪽 가격 기준으로 하향
- 최종 검색 보정: 작가 검색 결과의 갤러리/미술관 문맥 기반 보정값 추가

### 5.2 Cold 계산 순서도

```text
[작품 입력 정보 + 작가 정보]
  - 작품 크기
  - 매체/지지체
  - 작가 메타
  - 작가명
        |
        v
[작가명 기반 검색 피처 조회]
  - 저장된 검색 피처 캐시 사용
  - 검색 결과 제목, 요약, URL, 도메인을 작가 단위로 집계
  - 최종 보정에는 고정된 작가별 검색 보정 lookup 사용
        |
        v
[검색 피처 포함 대표 예측 준비]
  - 작품 피처, 작가 메타, 검색 피처를 포함한 LightGBM Quantile 회귀 후보 사용
  - Quantile예측구간폭 구간별 검증 잔차 중앙값으로 대표 로그가격 안정화
        |
        v
[Quantile예측구간폭과 낮은쪽 40% 지점 로그가격 확인]
  - Quantile예측구간폭 = 저장된 Quantile 예측 폭
  - 낮은쪽40퍼센트기준_로그가격 = LightGBM 40% Quantile 로그가격
        |
        v
[과대예측 방어]
  - Quantile예측구간폭이 넓고 대표 로그가격이 낮은쪽40퍼센트기준 로그가격보다 높으면
    대표 로그가격과 낮은쪽40퍼센트기준 로그가격을 50:50으로 혼합
        |
        v
[작가 검색 보정값 추가]
  - 갤러리/미술관 검색 문맥 기반 작가별 보정값
        |
        v
[최종 Cold 로그가격]
        |
        v
[최종 Cold 가격 = exp(최종 Cold 로그가격)]
```

### 5.3 Cold 사용 피처

| `search_source_ratio` | `search_source_count / max(search_result_count, 1)` | 검색 출처 다양성 반영 |
| `search_quality_x_log_area` | `search_quality_score * log_area` | 검색 신뢰도와 작품 크기의 결합 효과 반영 |
| `search_art_match_x_followers_log` | `search_art_match_ratio * artist_meta_followers_log` | 작가 검색 문맥과 인기도 결합 |
| `search_exhibition_x_career_stage` | `search_exhibition_ratio * artist_meta_career_stage` | 전시 문맥과 작가 경력 단계 결합 |

- 검색 품질 점수 구성:

검색품질점수 =
  0.30 * 미술문맥비율
+ 0.20 * 신뢰도메인비율
+ 0.15 * 전시문맥비율
+ 0.15 * 시장/거래문맥비율
+ 0.10 * 최근결과비율

#### 5.3.3 LightGBM Quantile 회귀 후보의 의미

- Quantile 회귀 의미: 평균 가격 하나를 맞추는 회귀가 아니라, 조건이 비슷한 작품들의 가격 분포에서 특정 위치의 로그가격을 예측하는 방식
- 50% Quantile 의미: 같은 조건의 작품 가격을 낮은 순서로 세웠을 때 중앙에 가까운 가격
- 40% Quantile 의미: 같은 조건의 작품 가격을 낮은 순서에서 높은 순서로 세웠을 때 40% 지점에 있는 가격
- 문서 표현: `낮은쪽 40% 지점 가격`
- 주의: `낮은쪽 40% 지점 가격`은 40% 할인 또는 가격을 40% 낮춘다는 뜻이 아님
- 10%와 90% Quantile 의미: 낮은 쪽과 높은 쪽의 예측 범위를 잡기 위한 경계값
- Quantile예측구간폭 의미: 높은 Quantile 예측값과 낮은 Quantile 예측값의 차이이며, 값이 클수록 모델이 해당 작품 가격을 불확실하게 보고 있다는 뜻

| 문서용 이름 | 내부 의미 | 계산 또는 생성 방식 | 최종 모델에서의 역할 |
|---|---|---|---|
| `검색피처포함_기초Quantile후보_로그가격` | 검색 피처까지 포함한 LightGBM Quantile 회귀 기반 기준 후보 | 작품 피처, 작가 메타, 검색 피처, 검색 상호작용 피처를 입력으로 LightGBM Quantile 회귀 모델이 예측 | Cold 대표 로그가격을 만들기 전의 기준값 |
| `낮은쪽40퍼센트기준_로그가격` | LightGBM 40% Quantile 로그가격 | 같은 입력 조건에서 낮은 가격부터 높은 가격까지 줄 세웠을 때 40% 지점을 예측 | 과대예측 위험이 있을 때 대표 로그가격을 낮추는 방어 기준 |
| `Quantile예측구간폭` | 높은 Quantile 예측값과 낮은 Quantile 예측값의 차이 | 예: `90%Quantile_로그가격 - 10%Quantile_로그가격` | 불확실성 측정, 구간별 잔차 안정화, 과대예측 방어 조건에 사용 |
| `검색포함_대표로그가격` | 기초 Quantile 후보를 검증 잔차로 안정화한 값 | `검색피처포함_기초Quantile후보_로그가격 + 구간별_보정값` | 과대예측 방어 전 Cold 기준가격 |

- LightGBM Quantile 회귀 후보 생성 흐름:

```text
작품 피처 + 작가 메타 피처 + 검색 피처
        |
        v
LightGBM Quantile 회귀 모델
        |
        +--> 기준 Quantile 로그가격
        +--> 낮은쪽 40% 지점 로그가격
        +--> 90% Quantile과 10% Quantile 차이 기반 Quantile예측구간폭
```

- 일반 LightGBM 회귀와의 차이:

| 구분 | 일반 LightGBM 회귀 | LightGBM Quantile 회귀 |
|---|---|---|
| 목표 | 평균적인 정답 가격에 가까운 값 예측 | 가격 분포의 특정 Quantile 위치 예측 |
| 출력 해석 | 하나의 평균형 예측값 | 중앙값, 낮은쪽 방어가격, 높은/낮은 Quantile 경계 등으로 해석 가능 |
| 이 문서에서의 사용 | Cold 최종 경로의 핵심 방식은 아님 | Cold 최종 경로의 기준가격, 낮은쪽 방어가격, 불확실성 폭 생성에 사용 |

| `구간별_잔차중앙값` | 대표 로그가격 안정화 | 같은 Quantile예측구간폭 구간의 `실제_로그가격 - 검색피처포함_기초Quantile후보_로그가격` 중앙값 | 구간별로 반복되는 치우침 보정 |
| `구간별_보정값` | 대표 로그가격 안정화 | `clip(구간별_잔차중앙값, -0.25, +0.25)` | 대표 로그가격이 과도하게 움직이지 않도록 제한 |
| `검색포함_대표로그가격` | 과대예측 방어 전 기준가격 | 기초 Quantile 후보에 구간별 보정값을 더함 | Cold 후처리의 기준가격 |
| `낮은쪽40퍼센트기준_로그가격` | 과대예측 방어 | 방어조건이 켜지면 대표 로그가격과 50:50 혼합 | 큰 과대예측 가능성을 낮춤 |
| `방어조건` | 과대예측 방어 | Quantile예측구간폭이 넓고 대표 로그가격이 낮은쪽40퍼센트기준보다 충분히 높을 때 활성화 | 과대예측 위험 작품만 선택적으로 하향 |
| `과대예측방어_로그가격` | 검색 보정 전 최종 후보 | 방어조건이 켜지면 대표 로그가격과 낮은쪽40퍼센트기준 로그가격을 50:50 혼합, 아니면 대표 로그가격 유지 | 큰 오차 상위 구간 완화 |
| `artist_key` | 작가 검색 보정 | 고정 검색 보정 lookup의 key로 사용 | 작가별 검색 문맥 보정값 적용 |
| `search_delta_lookup[artist_key]` | 최종 검색 보정 | `최종_Cold_로그가격 = 과대예측방어_로그가격 + 작가검색보정_로그값` | 작가별 검색 문맥에 따른 최종 로그가격 이동 |
| `작가검색보정_로그값` | 최종 검색 보정 | lookup에 있으면 작가별 보정값, 없으면 0 | 작가 검색 문맥을 최종 가격에 추가 반영 |
| `최종_Cold_로그가격` | 최종 가격 변환 | `과대예측방어_로그가격 + 작가검색보정_로그값` | `exp()` 변환 전 최종 예측값 |
| `actual_log`, `actual_price` | 평가 전용 | MdAPE, MAPE, p95 APE 계산 | 예측 시 입력으로 사용하지 않음 |
| `_track6_row_id`, `split` | 재현/검수 | 데이터 병합, split 구분, 결과 추적 | 최종 예측 산식에는 직접 사용하지 않음 |

### 5.4 Cold 모델과 산식

- 작가 검색 보정값 사용 방식: 실시간 검색 호출이 아니라 검증된 검색 스냅샷에서 만든 고정 lookup 사용

- 검색 피처 포함 대표 예측의 역할: LightGBM Quantile 회귀 후보와 Quantile예측구간폭 구간별 검증 잔차를 결합해 기준이 되는 대표 로그가격 생성

```text
검색피처포함_기초Quantile후보_로그가격
  = LightGBM_Quantile회귀후보(
      작품피처
      + 작가메타피처
      + 검색피처
      + 검색상호작용피처
    )

Quantile예측구간폭 = 저장된_Quantile예측폭

낮은쪽40퍼센트기준_로그가격 = LightGBM_40퍼센트_Quantile로그가격
```

- 대표 로그가격 안정화 방식: Quantile예측구간폭 구간별 검증 잔차 중앙값을 더해 보정

```text
Quantile예측구간폭_구간 = bucket(Quantile예측구간폭)

구간별_잔차중앙값
  = median(실제_로그가격 - 검색피처포함_기초Quantile후보_로그가격)
    within same Quantile예측구간폭_구간

구간별_보정값
  = clip(구간별_잔차중앙값, -0.25, +0.25)

검색포함_대표로그가격
  = 검색피처포함_기초Quantile후보_로그가격 + 구간별_보정값
```

- 과대예측 방어 조건:

```text
방어조건 =
  (Quantile예측구간폭 >= 1.4612207078910142)
  AND (검색포함_대표로그가격 - 낮은쪽40퍼센트기준_로그가격 >= 0.07715547281151025)
  AND (낮은쪽40퍼센트기준_로그가격 < 검색포함_대표로그가격)
```

- 방어조건 활성화 시 처리: 대표 로그가격을 낮은쪽 40% 지점 가격 쪽으로 낮춤

```text
과대예측방어_로그가격
  = 0.50 * 검색포함_대표로그가격
  + 0.50 * 낮은쪽40퍼센트기준_로그가격
```

- 방어조건 비활성화 시 처리: 대표 로그가격 유지

```text
과대예측방어_로그가격 = 검색포함_대표로그가격
```

- 최종 처리: 작가 검색 보정값 추가

```text
작가검색보정_로그값 =
  search_delta_lookup[artist_key]
  if artist_key exists in lookup

작가검색보정_로그값 = 0
  if artist_key does not exist in lookup

최종_Cold_로그가격
  = 과대예측방어_로그가격 + 작가검색보정_로그값

최종_Cold_가격_KRW = exp(최종_Cold_로그가격)
```

### 5.5 Cold 성능 해석

- Cold fixed test 3,099건 기준 성능:

|---|---:|---:|---:|---|
| 검색포함 대표 로그가격 | 0.424663 | 0.991042 | 3.305298 | 검색 피처 포함 기준 예측 |

## 6. Warm/Cold 비교 요약

| 항목 | Warm | Cold |
|---|---|---|
| 적용 대상 | 작가 매칭이 확실하고 같은 작가의 학습 가격 이력이 충분한 작품 | 같은 작가 이력이 없거나 부족하거나 작가 매칭이 불확실한 작품 |
| 기준가격 생성 | 선행 Warm 예측가격과 유사작품 기반 통계 | 검색 피처 포함 LightGBM Quantile 회귀 후보 + Quantile예측구간폭 구간 안정화 |
| 핵심 보정 | 방향 분류 + Huber 잔차 미세 보정 | Quantile예측구간폭/낮은쪽40퍼센트기준 차이 기반 과대예측 방어 + 작가 검색 보정 |
| 불확실성 처리 | Quantile width와 작품 단위 위험도로 보정 상한 축소 | Quantile예측구간폭이 넓으면 낮은쪽 40% 지점 가격 기준으로 이동 |
| 검색 피처 사용 | 최종 미세 보정층에는 직접 사용하지 않음 | 핵심 피처로 사용 |
| 최종 가격 변환 | `exp(최종_Warm_로그가격)` | `exp(최종_Cold_로그가격)` |
| 운영상 설명 | 안정 기준가격을 거의 유지하는 미세 보정형 모델 | 검색 문맥과 불확실성 방어를 결합한 신규/저이력 작가용 모델 |

## 7. 추가 성능 개선 방향

### 7.1 핵심 판단

- 현재까지의 실험 결과 기준: 추가 성능 개선의 가장 큰 병목은 모델 구조 자체보다 데이터 품질과 데이터 커버리지
- Warm 개선 방향: 이미 안정화된 기준가격을 크게 바꾸지 않는 구조로 수렴했으므로, 저신뢰 구간의 유사작품 데이터 보강이 우선
- Cold 개선 방향: 작가 이력과 비교가격이 부족한 상황을 다루는 모델이므로, 작가/작품/검색 문맥 데이터 수집이 성능 개선에 직접적인 영향을 줌
- 모델 보정의 역할: 현재 보유 데이터 안에서 오차가 반복되는 구간을 줄이는 작업
- 데이터 수집의 역할: 모델이 기준가격을 더 정확하게 잡을 수 있도록 가격 판단에 필요한 근거 자체를 늘리는 작업

### 7.2 실험 결과 기반 근거

| 관찰 내용 | 실험에서 확인된 현상 | 해석 |
|---|---|---|
| Warm은 기준가격 의존도가 높음 | 최종 Warm은 `미세보정전_기준로그가격`에 매우 작은 `최종보정값`만 더하는 구조 | 기준가격이 잘못 잡힌 작품은 큰 보정보다 기준가격 생성 근거를 보강하는 편이 안정적 |
| Warm에서 작품 크기 피처 영향이 큼 | 크기 피처를 제거한 검증 실험에서 MdAPE가 `0.2126 → 0.5671`, p95 APE가 `1.3194 → 4.9148`로 악화 | 크기, 면적, 형태, 매체/지지체 정보의 정규화 품질이 성능에 중요 |
| Warm 저신뢰 구간은 보정 상한이 자동으로 줄어듦 | `유사작품표본수`, `유사작품가격범위비율`, `Quantile예측구간폭`이 위험도 계산에 사용됨 | 유사작품 표본이 부족하거나 가격 분산이 큰 구간은 모델이 의도적으로 조심스럽게 움직임 |
| Cold는 검색 피처와 보수 방어로 개선됨 | Cold에서 검색 보정과 과대예측 방어를 결합하면 MAPE가 `0.991042 → 0.849260`, p95 APE가 `3.305298 → 2.346465`로 개선 | 신규/저이력 작가에서는 작가 검색 문맥과 불확실성 판단이 핵심 개선 요인 |
| Cold 구간별 보정은 추가 개선 여지를 보임 | 지지체/크기 구간, tail-risk 구간, 예측구간폭 구간 보정에서 validation p95 APE가 낮아짐 | 구간별 표본이 더 충분해지면 보정값을 더 안정적으로 추정할 수 있음 |
| CatBoost 등 대체 모델만으로는 우위가 확인되지 않음 | 같은 split 비교에서 Cold LightGBM 기준 모델이 CatBoost 기준 모델보다 안정적 | 현재 단계에서는 모델 교체보다 데이터 보강과 구간별 검증 데이터 축적이 우선 |

### 7.5 운영 관점의 결론

- 단기 개선: 현재 데이터 기준으로 구간별 보정값, 과대예측 방어 조건, 검색 보정값을 정교화
- 중기 개선: Warm 저신뢰 구간과 Cold 신규/저이력 작가 구간의 비교가격과 작가 메타를 집중 보강
- 장기 개선: 작가명 검색 결과를 자동 수집하되, 동명이인/무관 결과를 검증하는 라벨링 체계 구축
- 우선순위 판단: 모델 튜닝만 반복하기보다, 오차가 큰 구간의 데이터가 실제로 부족한지 먼저 확인하고 해당 구간부터 수집
- 예상 효과: 데이터가 보강되면 기준가격 자체가 안정화되고, 보정 모델은 더 작은 폭으로도 같은 성능 개선을 낼 수 있음

## 9. 테스트 방식 검증

- 검증 목적: 같은 입력에 대한 결과 변동, 재현 실패, row 순서 영향, label 누수, split 중복, 반복 OOF/holdout 안정성 의심 항목 점검
- 별도 감사 문서: `docs/track6/experiments/warm_cold_test_method_validity_audit.md`
- 별도 감사 HTML: `docs/track6/experiments/warm_cold_test_method_validity_audit.html`

| 구분 | 검증 결과 | 핵심 확인 내용 |
|---|---|---|
| Warm | 통과 | fixed test와 validation OOF 지표가 저장 지표와 동일하게 재현됨 |
| Cold | 통과 | 기존 Cold 재현 검증 `all_passed=true`, 기록 지표와 재계산 지표 최대 차이 `1.110e-16` |
| 같은 입력 반복 실행 | 통과 | Warm/Cold 모두 row 순서를 랜덤으로 바꿔도 최종 예측 로그가격 차이 `0.000e+00` |
| label 누수 의심 | 통과 | `actual_price`, `actual_log`를 임의 값으로 바꿔도 최종 예측 로그가격 변화 없음 |
| split 중복 의심 | 통과 | validation/test row id 중복과 split 간 overlap 없음 |
| OOF/holdout 안정성 | 통과 | Warm은 반복 holdout/bootstrap 근거 확인, Cold guard는 row/artist holdout에서 MAPE와 p95 개선확률 유지 |

- Warm 테스트 방식 판단:

```text
fixed test 지표 최대 재현 차이       = 0.000e+00
validation OOF 지표 최대 재현 차이  = 0.000e+00
row 순서 셔플 예측 차이             = 0.000e+00
label 변경 후 예측 차이             = 0.000e+00
```

- Cold 테스트 방식 판단:

```text
기록 지표와 재계산 지표 최대 차이     = 1.110e-16
guard 임계값 재계산 차이              = 0.000e+00
후처리기와 독립 계산식 예측 차이       = 0.000e+00
row 순서 셔플 예측 차이                = 0.000e+00
label 변경 후 예측 차이                = 0.000e+00
```

- 해석:

- 현재 고정 artifact 기준에서는 같은 입력을 넣었을 때 결과가 달라지는 현상은 확인되지 않음
- 실제 가격 label은 예측값 계산에 사용되지 않고, 평가 지표 산출에만 사용됨
- validation과 test는 row id 기준으로 분리되어 있어 같은 작품이 양쪽에 동시에 들어간 흔적은 확인되지 않음
- 반복 OOF/holdout 결과는 fixed test 지표를 대체하는 값이 아니라, 후보가 특정 split에만 우연히 맞은 것이 아닌지 확인하는 안정성 근거로 사용
- 새 데이터 수집, split 변경, 재학습, 검색 피처 재생성 시 동일 감사 스크립트를 다시 실행해야 함

## 10. 모델 적용 방식 요약

- 전체 구조: 가격 예측 모델은 Warm과 Cold 두 경로로 구성
- Warm 적용 조건: 작가 매칭이 확실하고 같은 작가의 사용 가능한 학습 가격 이력이 충분한 작품
- Warm 계산 방식: 기존 Warm 기준가격을 만든 뒤 방향 분류 모델과 Huber 잔차 모델이 같은 방향을 가리킬 때만 미세 보정
- Cold 적용 조건: 같은 작가 이력이 없거나 부족하거나 작가 매칭이 불확실한 작품
- Cold 계산 방식: 작품 피처, 작가 메타, 작가명 검색 피처를 함께 사용한 LightGBM Quantile 회귀 후보를 Quantile예측구간폭 구간별 검증 잔차로 안정화해 대표 예측가격 계산
- Cold 방어 방식: Quantile예측구간폭이 넓고 대표 예측가격이 낮은쪽 40% 지점 가격보다 높은 작품은 낮은쪽 가격 기준으로 낮춤
- Cold 최종 보정: 갤러리/미술관 검색 문맥 기반 작가별 보정값 추가
- Warm 성능: fixed test 607건 기준 MAPE 0.269888, p95 APE 0.807325
- Cold 성능: fixed test 3,099건 기준 MAPE 0.849260, p95 APE 2.346465
- 최종 가격 산출: 두 모델 모두 로그가격 기준으로 계산한 뒤 `exp()`를 적용해 원화 예측가격으로 변환
- 재현 가능성: 재현 스크립트와 결과 파일을 통해 동일 지표 확인 가능
