# Warm/Cold 가격 예측 모델 핵심 설명

이 문서는 상세 리포트 `partner_warm_cold_official_v0_1_unified_model_report.html`의 운영 설명용 축약본이다.
 목표는 모델을 처음 보는 사람도 “어떤 입력이 어떤 경로로 가고, 어떤 피처를 쓰며, 가격이 어떤 계산으로 나오고, 검증 근거가 무엇인지”를 5장 안에서 이해하게 하는 것이다.

### 1. 운영 라우팅

| 입력 조건 | 사용 경로 | 의미 |
|---|---|---|
| 작가 매칭이 신뢰 가능하고, 같은 작가 가격 이력이 1건 이상 있음 | `Warm-lite current` | 작가의 실제 과거 거래/판매 가격 정보를 기준가격으로 직접 활용한다. |
| 같은 작가 가격 이력이 없거나, 작가 매칭 신뢰가 부족함 | `Cold 보수 후보 적용 + 검색 보정` | 같은 작가 가격 이력을 직접 쓰지 못하므로 작품 정보, 작가 메타, 검색 기반 피처로 예측한다. |

> 현재 기본 운영은 `1건 이상 같은 작가 가격 이력`을 하나의 Warm-lite current 계산 흐름으로 처리한다.
 예전처럼 `1~4건`과 `5건 이상`을 서로 다른 Warm 모델로 나누지 않는다.

### 3. 성능 기준

| 경로 | 평가 기준 | n | MdAPE | MAPE | p95 APE | RMSE log | 해석 |
|---|---|---|---|---|---|---|---|
| Warm current | fixed test | 607 | 0.084485 | 0.225214 | 0.803203 | 0.382171 | 기본 Warm 후보 |
| Warm 기존 WMIN8 | fixed test | 607 | 0.104326 | 0.235814 | 0.739416 | 0.377190 | 이전 Warm 운영 후보 |
| Cold | fixed test | 3,099 | 0.409820 | 0.849260 | 2.346465 | 비교값 없음 | 같은 작가 이력 미사용 경로 |

- `n`은 학습 작품 수가 아니라 평가 행 수다.
- 같은 607개 fixed test 기준으로 Warm current는 기존 WMIN8 대비 MdAPE가 0.104326 → 0.084485로 19.0% 개선됐고, MAPE는 0.235814 → 0.225214로 4.5% 개선됐다.
- 다만 p95 APE는 0.739416 → 0.803203, RMSE log는 0.377190 → 0.382171로 악화되어 큰 오차 방어는 별도 운영 모니터링 대상이다.
- Warm과 Cold는 입력 조건과 난이도가 다르므로 숫자를 단순 순위로 비교하지 않는다.
- 주 지표는 `MdAPE`, `MAPE`, `p95 APE`이고, `RMSE log`는 로그 가격 기준 보조 검증값이다.

## Warm: 같은 작가 가격 이력을 쓰는 예측

Warm은 작가가 신뢰도 높게 매칭되고 같은 작가 가격 이력이 1건 이상 있을 때 사용한다.
 핵심은 “같은 작가의 유사 작품 가격 통계로 기준가격을 만들고, 작품 조건과 모델 보정으로 과도한 오차를 줄이는 것”이다.

### 1. 학습 단계

```text
[학습 데이터 구성]
실제 로그가격이 있는 과거 작품
  → fold/hold-out으로 평가 대상 가격이 자기 통계에 들어가지 않게 차단

[피처 생성]
같은 작가 가격 통계 + 작품 크기/면적/비율 + 매체/지지체 + 크기/형태 bucket
  → q10/q50/q90 Quantile 예측
  → q90 - q10으로 예측의 불확실성 폭 계산

[보정 모델 학습]
Huber residual 모델이 Quantile 기준가격에서 남은 오차를 학습
  → clip으로 보정 폭을 제한해 극단 보정을 방지

[동결/검증]
Warm-lite current 후보를 fixed test와 API 재현성 기준으로 검증
```

### 2. 사용 단계

```text
[입력 작품]
작가 매칭 신뢰 통과 + 같은 작가 가격 이력 1건 이상
        |
        v
[같은 작가 이력 통계 생성]
작가 로그가격 중앙값, q25/q75, IQR, 면적단가, 표본 수, 매칭 단계
        |
        v
[Quantile 예측]
전체 피처 기반 q50과 흔들림을 줄인 q50을 각각 계산
두 q50 평균을 기준 로그가격으로 사용
        |
        v
[Huber residual 보정]
기준 로그가격에서 남은 오차를 예측하고 clip으로 보정 폭 제한
        |
        v
최종 Warm 로그가격 → exp(로그가격) = 최종 Warm 가격
```

### 3. 핵심 산식

```text
기준로그가격 = 평균(전체피처_q50, 안정피처_q50)

기본후보 =
    기준로그가격
  + clip(0.50 * Huber잔차예측, -0.10, +0.10)

최종 Warm 로그가격 =
    기본후보
```

`clip`은 보정값이 정해진 하한보다 작으면 하한으로, 상한보다 크면 상한으로 잘라내는 함수다.
 즉 모델이 큰 보정값을 예측해도 운영 가격이 한 번에 과도하게 움직이지 않게 막는다.

### 4. 검증 근거

| 검증 | 결과 | 해석 |
|---|---|---|
| Warm-lite current fixed test | 607행, MdAPE 0.084485, MAPE 0.225214, p95 0.803203 | 기본 Warm 후보 |
| 기존 Warm WMIN8 대비 | 같은 607행에서 MdAPE -0.019841, MAPE -0.010600 | 대표 오차와 평균 오차가 개선됐다. p95는 +0.063787로 악화되어 큰 오차 모니터링이 필요하다. |
| 학습 데이터 증가 실험 | 25% → 100% fixed cohort에서 MdAPE 평균 -0.064615 | 품질 관리된 학습 데이터가 늘면 Warm 개선 가능성이 큼 |

## 가격 예측에 사용하는 피처

피처는 모델에 넣는 입력 정보다. Warm과 Cold는 같은 작품 기본 정보를 쓰지만, Warm은 같은 작가의 과거 가격 이력을 직접 쓰고,
 Cold는 같은 작가 가격 이력을 쓰지 못해 작가 메타와 검색 기반 정보를 더 많이 사용한다.

### 1. Warm 사용 피처

| 피처 묶음 | 구체 항목 | 가격 계산에서 하는 역할 |
|---|---|---|
| 작품 크기 | 가로, 세로, 깊이, 면적, 로그 면적, 가로세로 비율, 입체 여부 | 같은 작가라도 크기와 형태가 다르면 가격 수준이 달라지므로 기준가격과 보정값에 반영한다. |
| 재료/지지체 | 매체 분류, 지지체 분류, 매체+지지체 조합 | 캔버스, 종이, 혼합재료 등 제작 조건 차이를 반영한다. |
| 크기/형태 구간 | 크기 구간, 형태 구간, 매체+형태 조합, 지지체+크기 조합 | 연속 숫자인 크기 정보를 모델이 더 안정적으로 해석하도록 구간화한다. |
| 같은 작가 가격 이력 | 로그가격 중앙값, q25, q75, IQR, 면적단가 중앙값, 면적단가 IQR, 표본 수, 매칭 단계 | Warm의 핵심 근거다. 같은 작가의 과거 가격 분포를 기준가격 생성에 직접 사용한다. |
| Quantile 예측값 | 낮은값 q10, 중앙값 q50, 높은값 q90, 전체 피처 q50, 안정 피처 q50 | 가격의 중심과 예측 불확실성을 만든다. 기본 Warm 가격은 두 q50의 평균을 중심으로 삼는다. |
| 잔차 보정 입력 | 작품 피처, 작가 이력 피처, Quantile 예측값, 예측 불확실성 폭 | 기준가격에서 남은 오차를 LightGBM Huber residual 모델이 작게 보정한다. |

### 2. Cold 사용 피처

| 피처 묶음 | 구체 항목 | 가격 계산에서 하는 역할 |
|---|---|---|
| 작품 조건 | 가로, 세로, 깊이, 면적, 비율, 매체, 지지체, 크기/형태 구간 | 같은 작가 이력이 없을 때 작품 자체 조건으로 기본 가격대를 추정한다. |
| 작가 메타 | 작가 등록 여부, 작가 식별 상태, 작가 관련 외부/내부 메타 가용성 | 작가 정보가 충분한지, 신뢰 가능한 예측인지 판단하는 데 사용한다. |
| 검색 기반 피처 | 작가명 검색 커버 여부, 검색 기반 가격 신호, 검색 결과 품질 상태 | 같은 작가 가격 이력을 직접 쓰지 못할 때 시장 기준가격을 보완한다. |
| Cold Quantile 예측값 | q10, q40, q50, q90, q90 - q10 | 대표 가격과 보수 가격 후보, 예측 불확실성 폭을 만든다. |
| 검수/신뢰도 피처 | 예측 불확실성 폭, 모델 간 차이, 검색 커버 여부 | high/low/review 표시와 보수 후보 적용 여부를 결정한다. |

### 3. 피처 해석에서 주의할 점

- Warm의 같은 작가 가격 이력은 입력 작품 자기 가격을 직접 참조하지 않도록 fold/hold-out으로 누수를 차단해 만든다.
- Cold는 같은 작가 가격 이력을 직접 쓰지 않으므로 Warm보다 불확실성이 크고, 검색/메타/검수 피처의 역할이 커진다.
- Quantile의 `q90 - q10`은 모델이 보는 가격 범위의 폭이며, 폭이 클수록 예측이 더 불확실하다는 뜻이다.

## Cold: 같은 작가 가격 이력이 없을 때의 예측

Cold는 같은 작가 가격 이력을 직접 기준가격으로 쓸 수 없는 입력을 처리한다.
 Warm보다 불확실성이 크기 때문에 점예측만 만들지 않고, 검색 기반 기준가격, Quantile 불확실성, 보수 후보 적용 조건, 신뢰도 표시를 함께 사용한다.

### 1. Cold 학습 단계

```text
[Cold 학습 데이터 구성]
같은 작가 가격 이력을 직접 쓰지 않는 조건으로 학습/검증 데이터 구성
        |
        v
[피처 생성]
작품 크기/면적/형태, 매체, 지지체, 작가 메타, 작가명 검색 결과,
검색 커버 여부, 검색 기반 가격 신호
        |
        v
[LightGBM Quantile 학습]
q10/q40/q50/q90 등 가격 분포 후보를 학습
q90 - q10으로 예측의 불확실성 폭 계산
        |
        v
[검색 기반 기준가격 보정]
검색 q50을 기준으로 qwidth bucket별 OOF median residual 보정값을 학습
        |
        v
[보수 후보 적용 조건 검증]
불확실성이 크고, 보수 후보가 충분히 낮은 경우에만 보수 후보를 섞도록 임계값 동결
```

### 2. Cold 사용 단계

```text
[Cold 입력]
같은 작가 가격 이력 없음 또는 작가 매칭 신뢰 부족
        |
        v
[작품/작가/검색 피처 생성]
작품 조건 + 작가 메타 + 검색 결과 기반 가격 신호
        |
        v
[대표 기준 로그가격]
검색 q50 + clip(qwidth bucket별 보정값, -0.25, +0.25)
        |
        v
[보수 후보 적용 여부 판단]
불확실성 폭이 크고, q40 보수 후보가 대표 기준보다 충분히 낮으면
대표 기준과 q40을 50:50으로 섞음
        |
        v
[검색 delta lookup 보정]
검색 커버/미커버 조건에 따른 최종 보정값 적용
        |
        v
최종 Cold 로그가격 → exp(로그가격) = 최종 Cold 가격
```

### 3. 핵심 산식

```text
Quantile 예측의 불확실성 폭 = q90 - q10

대표로그가격 =
    검색_q50
  + clip(qwidth_bucket별_OOF_median_residual, -0.25, +0.25)

보수 후보 적용 조건 =
    불확실성폭 >= 1.4612207078910142
    AND 대표로그가격 - LGBM_q40 >= 0.07715547281151025
    AND LGBM_q40 < 대표로그가격

보수후보적용_로그가격 =
    0.50 * 대표로그가격 + 0.50 * LGBM_q40, if 보수 후보 적용 조건 통과
    대표로그가격, otherwise

최종 Cold 로그가격 =
    보수후보적용_로그가격 + 검색delta_lookup
```

### 4. 보수 후보 적용 조건의 성능 효과

이 조건은 Cold가 만든 대표 가격을 항상 낮추는 규칙이 아니다.
 예측 불확실성이 크고, q40 보수 후보가 대표 가격보다 충분히 낮은 경우에만 대표 가격과 q40을 섞는다.
 조건을 쓰지 않으면 검색 보정은 유지하되 대표 가격을 그대로 사용한다.

| 비교 기준 | MdAPE | MAPE | p95 APE | 해석 |
|---|---|---|---|---|
| 보수 후보 적용 없음 + 검색 보정 | 0.412921 | 0.875749 | 2.937449 | 검색 보정만 적용한 기준 |
| 보수 후보 적용 + 검색 보정 | 0.409820 | 0.849260 | 2.346465 | 현재 Cold 최종 기준 |

- 보수 후보 적용 조건을 쓰면 MdAPE는 0.003101, MAPE는 0.026489, p95 APE는 0.590984 낮아진다.
- 개선 폭은 특히 p95 APE에서 크다. 즉 이 조건은 일반적인 중앙 오차보다 큰 오차 방어에 더 큰 역할을 한다.

### 5. 신뢰도와 검수 표시

| 구분 | 조건 | 의미 |
|---|---|---|
| high | 불확실성폭 ≤ 0.7349424254094605, 모델 차이 ≤ 0.15320873993739603, 검색 커버 있음 | Cold 안에서 상대적으로 안정적인 예측 |
| low | 불확실성폭 ≥ 2.1572852836013667 또는 모델 차이 ≥ 0.42534619182266353 | 예측 분산이 큰 입력 |
| review | 불확실성폭 ≥ 1.4612207078910142 또는 검색 미커버 | 운영 검수가 필요한 입력 |

> Cold 내부 artifact의 `v0.3`, `v0.4`는 모델 산출물 버전명이다.
 외부 API 기준 표기는 계속 `0.1v API`로 통일한다.

## 검증, 재현성, 운영 시 해석 기준

### 1. 재현성 체크

| 항목 | 검증 내용 | 결과 |
|---|---|---|
| Warm bundle manifest | 동결된 Warm bundle 파일 해시 검증 | 전체 OK |
| Warm bundle replay parity | Warm current가 동결된 모델 산출물에서 재현되는지 확인 | 동결된 Warm-lite 산출물의 current 후보 사용 |
| Warm HTTP API parity | 운영 반영 전 기본 정책별 API 출력 비교 | current 기본값 확인 완료 |
| Cold v0.3 reproducibility | Cold 최고 성능 점예측 재현 | 재현 통과 |
| Cold v0.4 confidence policy | 신뢰도 등급, 검수 필요 표시, 검색 미커버 보정 표시 정책 검증 | tier mismatch 0행, review flag mismatch 0행 |

### 2. 학습 데이터가 늘면 Warm이 좋아지는가

별도 learning curve 실험에서 fixed test split은 고정하고 Warm train split만 25%, 50%, 75%, 100%로 늘렸다.
 모든 비율에서 Warm 처리가 가능한 동일 test cohort 기준으로 비교했기 때문에, 단순히 평가 대상이 바뀌어서 좋아진 것이 아니라 학습 데이터 증가 효과를 본 실험이다.

| train 비율 | n 평균 | MdAPE 평균 | MAPE 평균 | p95 APE 평균 | RMSE log 평균 |
|---|---|---|---|---|---|
| 25% | 550 | 0.153252 | 0.363610 | 0.990130 | 0.487094 |
| 50% | 550 | 0.114222 | 0.256292 | 0.908345 | 0.425109 |
| 75% | 550 | 0.102419 | 0.234519 | 0.815625 | 0.404022 |
| 100% | 550 | 0.088637 | 0.229596 | 0.806068 | 0.379168 |

> 25%에서 100%로 늘렸을 때 fixed cohort 평균 변화는 MdAPE -0.064615, MAPE -0.134014, p95 APE -0.184062, RMSE log -0.107926이다.
 따라서 품질 관리된 학습 데이터가 늘면 Warm 정확도가 좋아질 근거는 있다. 다만 신규 운영 데이터도 가격 라벨, 작가 매칭, 작품 피처 품질 검수를 통과해야 같은 개선을 기대할 수 있다.
 주의: 이 학습곡선 100% 행(MdAPE 0.088637 / p95 0.806068)은 학습곡선 전용으로 재학습한 별도 실험이라, Page 2의 배포 Warm-lite current(0.084485 / 0.803203)와 셋업이 달라 정확히 같지 않다. 핵심은 절대 수치가 아니라 데이터가 늘수록 좋아지는 추세다.

### 3. 운영 설명 문장

```text
현재 official 0.1v 가격 예측은 먼저 같은 작가 가격 이력을 쓸 수 있는지 판단한다.
작가 매칭이 신뢰 가능하고 같은 작가 가격 이력이 1건 이상이면 Warm-lite current 모델을 사용한다.
Warm은 같은 작가 가격 통계와 작품 피처로 Quantile 기준가격을 만들고, Huber residual 보정을 더해 최종 가격을 정한다.

같은 작가 가격 이력을 직접 쓰기 어렵거나 작가 매칭이 불확실하면 Cold 경로를 사용한다.
Cold는 작품 조건, 작가 메타, 검색 피처로 가격 분포를 예측하고, 불확실성이 큰 경우 보수 후보를 조건부로 섞으며, 신뢰도와 검수 필요 여부를 함께 표시한다.

두 경로 모두 운영 반영 전 동결 산출물 재현성 검증과 official 0.1v API parity 검증을 통과해야 한다.
```

### 4. 주의할 해석

- Warm 성능과 Cold 성능은 같은 문제를 푼 결과가 아니므로 직접 우열 비교하지 않는다.
- Cold는 같은 작가 가격 이력을 직접 쓰지 못해 본질적으로 불확실성이 더 크다.
- 임계값과 보정 폭은 운영 중 매 요청마다 다시 최적화하지 않고, 검증 실험에서 선택한 값을 동결해 재현성을 확보한다.
- 새 학습 데이터 추가는 자동 승격이 아니라 재학습, hold-out 검증, parity 검증을 통과한 뒤 운영 반영한다.
