# Track 3 실험 가설 문서

- 목적: 작품 가격 예측 모델 실험에서 검증할 가설을 정리하고, 각 가설에 따른 연구방법과 진행 상태를 관리하기 위한 보고용 문서
- 핵심 방향:
- 실험을 바로 늘리기보다, 먼저 가설을 정의함
- 각 가설별로 연구방법을 정한 뒤 실험함
- 실험 결과는 Warm / Cold로 나누어 해석함
- 실패한 실험도 어떤 가설에서 실패했는지 추적 가능하게 남김

## 1. 가설 문서를 따로 두는 이유

- 모델 실험을 무작정 늘리면 결과 해석이 어려워짐
- 어떤 실험이 어떤 질문을 검증한 것인지 불분명해질 수 있음
- 같은 아이디어를 이름만 바꿔 반복할 위험이 있음
- 따라서 Track 3에서는 가설을 먼저 정리한 뒤 실험을 진행함
- 목표
- 실험 목적을 명확히 함
- 실험 실패 원인을 가설 단위로 추적함
- 후속 실험 우선순위를 정하기 쉽게 만듦
- 최종 모델 선택 이유를 설명 가능하게 만듦

## 2. 가설 ID 표기 방식

- 각 가설은 `H1`, `H2`, `H3`처럼 관리함
- `H`는 `Hypothesis`의 약자임
- 의미
- `H`: 검증하려는 질문 또는 가설
- `PR`: 실제 실행한 실험 또는 스크립트 단위
- 예시
- `H7`: 2D / 3D 분기가 특정 약점 구간 보완에 적합한가
- `PR17`, `PR18`, `PR19`: H7을 검증한 실제 실험들

## 3. 각 가설에 대해 정리하는 내용

- 배경
- 왜 이 가설이 필요한지
- 질문
- 정확히 무엇을 확인하려는지
- 연구방법
- 어떤 데이터, 변수, 모델, 지표로 확인할지
- 현재 판단
- 현재까지 실험 결과를 어떻게 해석하는지
- 다음 확인 포인트
- 앞으로 무엇을 더 검증해야 하는지

## 4. 가설별 연구방법 정리 방식

- 가설이 생기면 바로 실험하지 않음
- 먼저 연구방법을 정리함
- 연구방법 단계에서 정리하는 내용
- 사용할 데이터
- 사용할 split 기준
- 사용할 입력 변수
- baseline 모델
- 비교할 모델 또는 비교군
- 성공 기준
- Warm / Cold 각각의 평가 방식
- 주요 지표
- `median APE`
- `Within-30%`
- `RMSE(log)`
- 원칙
- 한 번에 여러 요소를 바꾸지 않음
- 실험 결과는 반드시 Warm / Cold로 나누어 기록함
- 최종 채택 전에는 release split confirm을 확인함

## 5. 실험 진행 순서

- 1단계
- 가설 정리
- 2단계
- 연구방법 결정
- 3단계
- 실험 실행
- 4단계
- 결과 검증
- 5단계
- 결론 정리
- 이 순서를 고정한 이유
- 같은 실험을 반복하는 문제를 줄이기 위함
- 실패한 아이디어를 근거 없이 다시 시도하지 않기 위함
- 어떤 부분이 실패했는지 가설 단위로 추적하기 위함
- 전체 방향이 아니라 해당 가설만 보류하거나 중단할 수 있게 하기 위함

## 6. 현재 가설 목록

| 가설 ID | 가설 요약 | 연구 방법 | 현재 상태 | 현재 판단 |
|---|---|---|---|---|
| H1 | 크기 정보는 대표 표현으로 정리하는 것이 더 안정적일 것이다 | `width/height`, `log_area`, `estimated_ho` 조합별 Warm / Cold 성능 비교 | 검증 완료 | 대표 표현 전면 단순화 기각, `V0_all` 유지 |
| H2 | 작가 정보 없이도 작품 구조 정보만으로 Cold 예측이 가능할 것이다 | 작가 정보 제외 후 작품 구조 변수만으로 Cold baseline 성능 확인 | 검증 완료 | Cold 구조 변수 baseline 성립, 약점 slice는 후속 가설로 이관 |
| H3 | Warm에서는 작가 정보를 포함할 때 성능이 좋아질 것이다 | 작가 정보 제외 모델과 `artist_name_ko`, `artist_works_log` 포함 모델 비교 | 검증 완료 | 작가명과 작가 작품 수 피처 모두 Warm 개선 확인 |
| H4 | 운영 가능한 파생 피처가 추가 성능 개선을 줄 것이다 | 파생 피처를 하나씩 추가하며 Warm / Cold `median APE` 변화 확인 | 검증 완료 | `artist_works_log`는 유지, 나머지 파생 피처 확장은 제한 |
| H5 | Warm에서는 비선형 트리 모델이 선형보다 우세할 것이다 | 동일 피처셋에서 선형 계열과 LightGBM / XGBoost / CatBoost 비교 | 검증 완료 | `tuned LightGBM` 우세 |
| H6 | Cold에서는 robust 선형 계열이 더 안정적일 것이다 | Cold에서 LAD / Quantile / Huber와 트리 계열 모델 비교 | 검증 완료 | `LAD / Quantile / Huber` 계열 우세 |
| H7 | 2D / 3D 분기는 특정 약점 구간 보완용으로 적합할 것이다 | `2D / 3D` 분기 모델과 기존 모델을 slice별로 비교 | 부분 검증 | `Cold 2D` 개선 신호 있음 |
| H8 | Cold 2D 한정 fallback이 전체 모델 교체보다 효율적일 것이다 | `Cold 2D`에만 fallback 적용 후 전체 Cold와 tail risk 확인 | 예정 | 아직 미실행 |
| H9 | 일부 정보를 의도적으로 가리고 학습하면 결측 상황에서 더 잘 버틸 것이다 | 작가명 / 재료 / 제작연도 등을 masking한 학습 모델과 일반 모델 비교 | 예정 | 결측 대응 신규 가설 |
| H10 | 작가명보다 거래 이력 기반 구조화 피처가 Warm에서 더 안정적일 것이다 | 작가명 단독, 거래 이력 피처 단독, 병행 모델을 Warm에서 비교 | 예정 | Warm 작가 피처 확장 가설 |
| H11 | 정보량에 따라 가격 범위와 신뢰도를 함께 주는 방식이 더 실용적일 것이다 | 정보량 구간별 prediction interval coverage와 interval width 확인 | 예정 | 출력 정책 후속 가설 |
| H12 | 작가 기본 가격대와 작품별 편차를 분리한 2단계 구조가 일부 Warm에서 설명력 있을 것이다 | 작가 기본 가격대 추정 후 residual 예측 모델을 기존 Warm 모델과 비교 | 예정 | residual 구조 신규 가설 |
| H13 | 재료를 더 세분화한 피처가 Cold 정확도를 개선할 것이다 | 재료 flag 추가 후 Cold 중심으로 보되 Warm도 함께 ablation | 예정 | H2 후속 가설, `mixed / other` 약점 보완 후보 |
| H14 | 크기와 재료의 조합 효과가 단독 피처보다 가격을 더 잘 설명할 것이다 | `medium_size_bucket`, `is_large_oil` 등 조합 피처를 추가해 Warm / Cold 비교 | 예정 | H2 후속 가설, 공통 피처 후보라 Warm / Cold 모두 평가 |
| H15 | 결측 패턴 자체가 신뢰도와 가격 오차를 설명할 것이다 | `missing_count`, `info_completeness_score` 등 정보량 피처 추가 후 Warm / Cold 오차 변화 확인 | 예정 | H2 후속 가설, 정보량별 신뢰도 확인 |

### 가설 연결 방식

- H2는 Cold 예측 가능성을 보는 상위 가설임
- H13, H14, H15는 H2에서 남은 Cold 약점 구간을 보완하기 위한 후속 가설임
- 단, H13~H15의 피처는 Warm / Cold 모두에서 만들 수 있는 경우가 많음
- 따라서 Cold 개선 목적이어도 Warm 성능을 함께 확인함
- Warm 전용 피처와 Cold에서 사용할 수 없는 피처는 별도로 분리해서 해석함

## 7. 가설 그룹 구분

### A. 이미 방향이 비교적 정리된 가설

- H1
- 대표 크기 표현 전면 단순화는 기각, `V0_all` 유지
- H2
- Cold 구조 변수 baseline 성립
- H3
- Warm에서는 작가 정보 포함이 유효
- H4
- 파생 피처는 `artist_works_log` 중심으로 제한 유지
- H5
- Warm에서는 `tuned LightGBM` 우세
- H6
- Cold에서는 robust 선형 계열 우세

### B. 기존 실험선에서 마무리해야 할 가설

- H7
- `Cold 2D` 개선 신호가 있으나 전면 채택 근거 부족
- H8
- `Cold 2D` 한정 fallback을 실제로 검증할 필요 있음

### C. 후속 확장 가설

- H9
- 결측 대응 강건성
- H10
- 거래 이력 기반 Warm 피처
- H11
- 가격 범위 / 신뢰도
- H12
- 작가 기본 가격대 + 작품별 편차
- H13
- 재료 세분화 피처
- H14
- 크기와 재료 조합 피처
- H15
- 결측 패턴 피처화

## 8. 현재 우선순위

### 1순위

- H7
- H8
- 이유
- 기존 실험선과 직접 연결됨
- 이미 일부 신호가 있음
- `Cold 2D` 약점 보완 여부를 먼저 닫는 것이 자연스러움

### 2순위

- H13
- H14
- H15
- 이유
- 현재 데이터만으로도 실험 가능성이 높음
- Cold 약점 구간과 직접 연결됨
- 새 모델보다 피처 개선 중심이라 실험 비용이 상대적으로 낮음

### 3순위

- H9
- 이유
- 운영 결측 상황과 직접 연결됨
- 다만 masking 실험 설계가 필요함

### 4순위

- H10
- H11
- H12
- 이유
- 가치가 있지만 누수 관리, 출력 정책, 모델 구조 설계가 더 복잡함

## 9. 문서 관리 방식

- 가설 설명 문서
- 각 가설의 배경, 질문, 현재 판단, 다음 확인 포인트 관리
- 가설 요약표
- 가설 상태를 한눈에 관리
- 가설 결과 종합표
- 각 가설에 연결된 실험과 결과를 관리
- 실험 결과 요약표
- 날짜 / 실험 ID 기준으로 실행 결과 관리
- 개별 실험 기록
- 사용 변수, Warm 결과, Cold 결과, 해석, 결론을 상세 기록

## 10. 한 줄 정리

- Track 3의 가설 관리는 `가설 정의 -> 연구방법 결정 -> 실험 -> 검증 -> 결론` 순서로 진행하며, 각 가설과 실제 실험을 문서로 연결해 모델 선택 이유와 후속 실험 우선순위를 설명 가능하게 만드는 것이 목적임
