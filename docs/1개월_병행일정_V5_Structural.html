1개월 가격예측 모델 실험 + 운영 도입 계획

작성일: 2026-05-05 · 대상 기간: 2026-05-06 (수) ~ 2026-06-02 (4주) · 구조: Champion-Challenger (두 트랙 동시 검증, 단일 운영 엔드포인트 배포)

1. 핵심 요약 (TL;DR)

본 문서는 콜론30 (client) 의뢰에 대한 4주 실행 계획
  • 우선 목표 = 모델 고도화 + 예측 정확도 개선 → 콜론30 의뢰 결과물 품질 극대화
  • 콜론30 관련 사항 = 외부 의존이 아닌 Week 1-2 내 능동 조율로 반영 — 회신 없어도 내부 기준안 선행 진행, 회신 반영은 범위 내 보정
두 가지 모델 트랙을 동시 검증 후, 운영 엔드포인트에는 최종 선정 모델 1개 배포
  • 트랙 1 (예측력 우선, Predictive Challenger): 매주 수요일 갱신 데이터 + V5 후보 (mixed-effects / retrieval) 도입 검증
  • 트랙 2 (해석력 우선, Interpretable Challenger): Core 5 / Main 7 후보 검증 후 freeze, hedonic mixed-effects 모델
운영 원칙
  • Week 1: 후보군 + 평가 기준 freeze (트랙 2: Core 5 / Main 7 후보군 정의)
  • Week 2: 동일 protocol 로 두 트랙 offline 검증 + 트랙 2 feature set freeze (Core 5 / Main 7 비교 후)
  • Week 3 초: shadow 검증 — 이중 트랙 모드 (2-track mode) (두 트랙 모두 통과) 또는 단일 트랙 모드 (single-track mode) (1개 트랙만 GATE 2 통과 시 자격 검증)
  • Week 3 말: 최종 선정 모델 (champion) 결정 — 이중 트랙 모드는 복합 scorecard 비교, 단일 트랙 모드는 최소 자격 충족 여부
  • Week 4: 최종 선정 모델만 canary → full rollout + 안정화
  • 비선정 모델은 원칙적으로 보고서·설명용 보조 모델로 전환 / 모니터링 목적이 있을 때에만 한시적 shadow challenger 로 유지
4주 후 산출물
  • 운영 엔드포인트에 최종 선정 모델 배포 완료 + 4-5일 초기 안정화
  • 최종 선정 모델 결정 근거 + 비선정 모델 활용 방안 메모
  • Week 2 freeze 된 feature set (Core 5 또는 Main 7) 기반 해석 가능 모델 보고서 (10-15페이지) — 콜론30 의뢰 결과물
  • 두 트랙 비교 표 (정확도 + 안정성 + 운영성 + 해석성)
결정/관리 사항: 마이그레이션 데이터 사용 가능일 / 최종 선정 모델 결정 / 배포 방식 / rollback owner → §10 타임라인 참조
콜론30 조율 사항: 미매칭 갤러리 검수 / 요구사항 반영 / 중간 산출물 리뷰 → §8 참조

2. 배경 — 현재 운영 모델 상태

측정 조건 오차 (MdAPE) 의미 활용 가능성
기존 작가 (학습에 작품이 있는 작가) 12-18% 예측이 실제값의 12-18% 범위 (median) ✅ 운영 활용 가능
신규 작가 (학습에 등장하지 않은 작가) 28-48% 예측 변동성 큼 ⚠️ 보조 도구로만 사용 권장
격차 23%p 기존/신규 작가 본질적 difficulty 차이 핵심 개선 영역
주요 용어 풀이
  • MdAPE: 예측 오차의 대표값 (중앙값 기준 % 오차)
  • holdout: 학습에 사용하지 않은 별도 검증 셋
  • 3 seeds: 랜덤 분할을 3회 반복한 재현성 점검
  • Champion-Challenger: 동일 protocol 검증, 최종 선정 모델 (champion) 만 운영 배포 / 비선정 모델은 원칙적으로 보고서·설명용 보조 모델로 전환 / 모니터링 목적이 있을 때에만 한시적 shadow challenger 로 유지
  • shadow → canary → full rollout: 신모델 단계적 배포 (트래픽 0% → 1% → 5% → 25% → 50% → 100%)

3. 트랙 정의

트랙 1 — 예측력 우선 (Predictive Challenger)

항목내용
목표 운영 엔드포인트의 예측력 (특히 신규 작가 예측) 직접 개선
모델 형태
  • 현 운영 모델 (V3, 32 features, GBM ensemble) baseline
  • 도입 후보:
    • 작가별 차이 보정 (mixed-effects 잔차 모델)
    • 매체 + 크기 기반 가격 anchor (유사 작품 NN retrieval)
    • 매체 + 크기만 사용 (image 효과 부족 시 fallback)
피처 설계
  • Week 1 에 V3 32 features 의 기여/누수/운영 리스크 검증 + 후보군 정의 (GATE 1)
  • 새 candidate features 도입 후 검증
  • source 유지 (예측력 + calibration 검증됨)
강점 예측 정확도 / cold-start 일반화 / 운영 안정성

트랙 2 — 해석력 우선 (Interpretable Challenger)

항목내용
목표 변수별 가격 영향이 설명 가능한 간결 모델 — 동일 protocol 검증 후 최종 선정 모델 후보
모델 형태
  • Hedonic mixed-effects 회귀
  • 변수별 가격 기여 분해
  • 작가/갤러리별 차이 분리 (random effects)
  • "왜 이 가격이 나왔는가" 를 Week 2 freeze 된 feature set (Core 5 또는 Main 7) 으로 설명
Feature set 원칙
  • Core 5 후보 (검증 후 freeze): structural 변수 중심 + 시장 포지셔닝 proxy 1개
  • Main 7 후보 (비교 후 freeze): Core 5 + productivity proxy + missingness control
  • Sensitivity set (한계 검증용): Main 7 + control / predictive only 변수

※ Week 1 후보 정의 → Week 2 비교 검증 → Week 2 후반 freeze. 상세 변수 spec 은 아래 접힘 섹션 참조.
Freeze 기준
  • 해석성 (변수별 elasticity 일관성)
  • 안정성 (3-seed 변동성)
  • Holdout 성능 (운영 모델 비교)
강점 변수 해석성 / 인과 framing / 운영 의사결정 설명력
최종 미선정 시 가치
  • 설명 가능한 benchmark
  • Feature discipline (Core 5 / Main 7 의미성 검증)
  • Fallback 후보 모델
  • 사업 설명 frame (변수별 가격 기여 표)
📎 트랙 2 상세 변수 spec (접기/펼치기)
set변수 목록
Core 5 후보
  • log_area — structural / 인과 가능
  • medium_family (oil/acrylic/paper/other) — structural / 인과 가능
  • year_made_centered — structural / vintage 효과
  • career_stage — structural / Galenson curve
  • gallery_tier — associational / 시장 포지셔닝 proxy (caveat)
Main 7 후보 Core 5 + log_artist_total_works (productivity proxy) + missingness control 1개
Sensitivity Main 7 + source [control only] + log_followers [predictive only] + is_krw 또는 has_seoul

※ 상세 변수 정의 / 처리 spec / VIF 검증은 별도 internal doc (data_requirements) 관리

4. 최종 선정 모델 결정 기준 (복합 Scorecard)

축 (Dimension) 측정 지표 가중치 (총 100)
정확도 Holdout MdAPE (전체 + 신규 작가) / W30 / W50 40
안정성 3-seed 재현성 / cold-start 변동성 / 분포 drift 30
운영성 Latency / Fallback 빈도 / 입력 누락 robustness / 모델 수렴 안정성 20
해석성 변수별 가격 기여 설명 가능 여부 / 인과 신뢰도 등급 10
📌 최종 선정 모델 (champion) 결정 규칙 (단계별)
  1. 1단계 — 자격 통과 (필수, mode 공통)
    • 정확도 ≥ baseline
    • 안정성 pass (3-seed 변동성 ≤ 임계 / cold-start 재현성 일관 / drift 정상)
    • 운영성 pass (latency p99 ≤ 임계 / fallback 빈도 ≤ 임계 / 입력 누락 robust)
    ※ 안정성 / 운영성 fail 시 자동 탈락 (정확도 우수해도 X)
  2. 2단계 — 모드별 결정
    • 이중 트랙 모드 (2-track mode): 자격 충족 후보 비교 → 점수제 (정확도 40 / 안정성 30 / 운영성 20 / 해석성 10) → 총점 우위 후보 = 최종 선정 모델
    • 단일 트랙 모드 (single-track mode): 단일 후보가 자격 조건 충족 → 최종 선정 확정 / 미충족 → V3 baseline 유지
  3. 3단계 — 동점 처리 (이중 트랙 모드 만)
    • 총점 차이 ≤ 5점: 운영성 → 해석성 순 우선

※ 비선정 모델은 원칙적으로 보고서·설명용 보조 모델로 전환 / 모니터링 목적이 있을 때에만 한시적 shadow challenger 로 유지

※ latency / drift / fallback / sample size / rollback threshold 의 수치 기준은 별도 모니터링 runbook 에서 고정 관리
