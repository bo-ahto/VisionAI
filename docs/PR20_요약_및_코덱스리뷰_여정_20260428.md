## 2. 코덱스 리뷰 1차 — 평가 메트릭 정렬

### 발견 사항

**P1 #1 — 평가가 서빙 라우팅과 안 맞음**
- 표/대시보드에 ensemble MdAPE만 보고
- 실제 서빙 (`primary_predictor.py`):
  - cold (training_count<5) → **CatBoost only**
  - warm (training_count>=5) → **XGBoost only**
- ensemble 평균으로 의사결정하면 잘못된 목표 최적화

**P1 #2 — career_stage 죽은 피처**
- Artsy 학습 데이터 분포: Stage 1=75% / Stage 2=25% / Stage 3=**0건** / Stage 4=0.2%
- 4단계 분류 조건 (`career_age >= 15 AND solo >= 3`)이 실제 데이터에 없어 Stage 3 발생 불가
- 사실상 binary로 압축된 죽은 피처

### 1차 수정

1. `_warm_mask(groups)` 헬퍼 추가
2. `cv_kfold` / `_final_cv_kfold_5`에 by-source + warm_slice 메트릭 추가
3. `career_stage v2`: 4단계 int → 0~10 연속 multi-factor 점수
   ```
   age_score (0~3)         + activity_score (0~3) +
   career_duration (0~2)   + market_presence (0~2)
   ```
4. `career_stage_int`를 별도 컬럼에 보존 (vintage_premium/freshness_discount 파생용)

## 3. 코덱스 리뷰 2차 — followers 버그 + train/tune 정렬

- "평가 정렬"을 말했다면 학습도 정렬해야 함

**P3 cleanup**:
- `CAREER_STAGE_V2_OVERRIDE` env (train만 있음, tune 없음) — 비대칭
- prepare 출력이 float v2를 "Stage n" 라벨로 출력 (오해 야기)

### 2차 수정

1. `row.get("ln_followers", 0.0)` 직접 사용
2. train script도 warm slice로 최종 XGBoost 학습 (tune와 정렬)
3. `CAREER_STAGE_V2_OVERRIDE` env 제거
4. prepare 출력을 quartile로 변경

## 4. 코덱스 리뷰 3차 — career_age 학습/서빙 드리프트

### 발견 사항

**P1 — career_age 학습/서빙 드리프트**
- 학습 데이터: Artsy 76% non-NaN (range 0~16), v2 score에 평균 0.51 기여, max 2.0
- 서빙: `artist_matcher.py:83`에서 `career_age: 0` 하드코딩, DB 스키마에 컬럼 없음
- 결과: matched Artsy 작가의 career_duration 항이 추론 시 통째로 사라짐
- 이전 38.9 cold 메트릭은 학습/서빙 불일치로 인한 **과대평가**

### 3차 수정

1. `career_stage_v2_score` 시그니처 변경: `career_age` 파라미터 제거
2. v2 스케일 0~10 → **0~8**
3. prepare/feature_builder/Saatchi 모두 새 시그니처 사용
4. `cv_kfold` (full data, CB) + `cv_kfold_warm` (warm slice 전용 XGB CV) 분리
   - 기존: XGB trained on full → evaluated on warm subset (post-hoc)
   - 수정: XGB trained on warm-only → evaluated on warm (서빙 일치)

## 5. 코덱스 리뷰 4차 — 잔존 드리프트 (현재 상태)

- `CB_FEATURES`에는 여전히 `career_age` 직접 피처로 존재

## 7. 결정 사항

### 머지 전 결론

코덱스 NO-GO를 받아들이고 다음 중 선택:

#### 옵션 A: 이 PR 안에서 모든 drift 해소
- `career_age`, `work_age`, `vintage_premium`, `freshness_discount`를 `CB_FEATURES`에서 제거
- 재학습 + 재튜닝
- importance 합쳐서 약 4.5 (XGB gain) 잃음 → metric 후퇴 가능성 큼
- 작업량: ~1시간

#### 옵션 B: PR 톤 다운 + 후속 PR 분리
- 이 PR은 "career_stage v2 도입 + 평가 도구 정정"으로 명확히 정의
- "production metric aligned" 주장 철회
- 후속 PR로:
  - drift 해소 (DB 스키마 + 수집기 + builder 일관성)
  - warm 라우팅 기준 통일
  - bootstrap CI

#### 옵션 C: 부분 drift 해소 + 나머지 후속
- career_age는 v2 직접 관련 → 이 PR에서 `CB_FEATURES`에서도 제거
- work_age/vintage/freshness는 사전 존재 → 후속 PR
- 균형점

### 권장: 옵션 C

**근거**:
- career_age는 이 PR의 v2 도입과 직접 연관 → 같이 처리하는 게 일관성
- work_age/vintage/freshness는 진짜 사전 존재 이슈, 별도 검토 필요 (DB 스키마 변경 등)
- 이 PR이 너무 비대해지지 않게
