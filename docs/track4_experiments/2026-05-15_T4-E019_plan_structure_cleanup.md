# T4-E019 실험 계획서 구조 정리

- 날짜: 2026-05-15
- 상태: 완료
- 연결 가설: 없음
- 목적: Track 4 계획서에서 데이터 준비 단계와 모델 실험 가설을 분리

## 1. 배경

- 기존 계획서에서는 데이터 통합/클렌징 항목이 `우선 가설 후보` 표에 포함되어 있었음
- 데이터셋 구성은 모델 성능을 검증하는 가설이 아니라 실험 준비 단계임
- 따라서 데이터 준비 체크포인트와 모델 실험 가설을 분리하는 것이 더 명확함

## 2. 변경 내용

- `T4-H0`, `T4-C1~T4-C7` 성격의 항목을 가설 후보에서 분리함
- 데이터 준비 항목을 `T4-D0~T4-D9` 체크포인트로 재정리함
- 모델 실험 가설 후보는 `T4-H1~T4-H5`만 남김
- 데이터셋 구성 방식과 추가 데이터 반영 방법은 별도 파이프라인 문서에서 관리하도록 명시함
- 파이프라인 문서에 데이터셋 구성 방식 섹션을 추가함

## 3. 현재 문서 구조

- 전체 실험 계획
- `docs/track4_experiment_plan_v1.md`
- 데이터셋 구성/클렌징/추가 수집 파이프라인
- `docs/track4_cleaning_pipeline.md`
- Warm / Cold 모델 실험 프로세스
- `docs/track4_warm_cold_process.md`

## 4. 판단

- 데이터 준비 체크포인트는 실험 품질을 보장하기 위한 선행 조건으로 관리함
- 모델 가설은 준비된 데이터셋을 사용해 성능, 안정성, 운영 가능성을 검증하는 항목으로 관리함
- 데이터셋 구성 방법은 계획서에 모두 넣지 않고 별도 문서로 관리하는 것이 적절함
- 이유는 추가 데이터 수집 시 실행 스크립트, 입력 파일, 산출물이 계속 바뀔 수 있기 때문임

## 5. 다음 작업

- 모델 실험을 시작할 때는 `T4-H1`부터 별도 실험 기록으로 진행
- 추가 데이터가 들어오면 `docs/track4_cleaning_pipeline.md` 기준으로 파이프라인 재실행
- 데이터 준비 체크포인트 숫자가 바뀌면 계획서가 아니라 파이프라인 리포트와 실험 기록에 반영
