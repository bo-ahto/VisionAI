# Track 4 모델 완성 흐름

- 목적: 순서도 기준으로 Track 4 모델을 완성하기 위한 남은 작업과 닫기 기준을 정리
- 기준일: 2026-05-17
- 작성 방식: 개조식

## 1. 순서도 기준 현재 위치

- 완료된 단계
- 모델 목표 정의
- 관련 데이터 수집
- 수집 데이터 정제
- 기본 피처 정의
- 기본 피처 기반 후보 모델 비교
- 기준 모델 선정 및 고정
- 피처 실험 일부 진행
- 피처 조합별 성능 평가 일부 진행

- 현재 위치
- `후보 피처 조합 선정`
- `후보 피처 기반 최종 모델 비교`
- 이 두 단계 사이에 있음

- 아직 필요한 단계
- validation에서 고른 후보를 test에서 확인
- 성능만 좋은 후보와 운영 가능한 후보를 분리
- Warm / Cold 최종 후보를 각각 정함
- 가격 범위와 신뢰도 정책을 붙임
- 재현 가능한 학습/예측 패키지로 묶음

## 2. 검증 완료로 닫는 기준

- 가설을 `검증 완료`로 바꾸려면 아래 조건 중 해당 가설에 필요한 조건을 만족해야 함
- validation 결과가 있음
- test 결과가 있음
- Warm / Cold를 분리해서 판단함
- median APE와 p95 APE를 함께 봄
- source slice에서 특정 출처만 과도하게 좋은 결과가 아닌지 확인함
- 모델 입력 피처가 manifest 검사를 통과함
- 운영에서 만들 수 없는 피처는 최종 후보에서 제외하거나 별도 조건부 후보로 표시함

## 3. 최종 후보 판단 방식

- Warm
- 성능 최고 후보와 운영 보수 후보를 분리함
- 성능 최고 후보: 작가 key + train 기준 작가 가격 통계
- 운영 보수 후보: 작가 key + 작가 작품 수
- 작가별 과거 가격 DB를 운영에서 만들 수 있으면 성능 최고 후보를 사용 가능
- 만들 수 없으면 운영 보수 후보를 사용함

- Cold
- median APE 기준 후보와 tail risk 기준 후보를 분리함
- median 기준 후보: full size 피처
- tail risk 기준 후보: area only 또는 위험 구간별 범위 정책
- Cold는 단일 가격만 제공하기보다 가격 범위와 신뢰도 경고가 필요함

## 5. 세부 가설로 분리해야 하는 경우

- test에서 validation 결과가 유지되지 않으면 세부 가설로 분리함
- 예시
- `T4-H4-a`: Cold full size 후보는 test median APE 기준으로도 우세한가
- `T4-H4-b`: Cold full size 후보는 p95 APE 악화를 허용 가능한 수준으로 줄일 수 있는가
- `T4-H11-a`: Warm 가격 범위는 80% coverage를 유지하면서 폭이 실용적인가
- `T4-H11-b`: Cold 가격 범위는 저위험 구간에 한정하면 실용적인가
- `T4-H17-a`: Cold high risk 그룹은 단일 가격 대신 범위/경고로만 제공해야 하는가

## 6. 다음 실행 순서

- 1단계: 최종 후보 validation/test 동시 평가
- 실행: `python3 scripts/track4/run_t4_e038_candidate_closure.py`
- 산출물: `data/track4/results/t4_e038_candidate_closure_metrics.json`

- 2단계: 완료 가능한 가설 상태 업데이트

- Cold 단일 가격 사용 가능 범위를 정함
- 저위험/고위험 구간별 가격 범위 폭을 다시 계산함

- 4단계: 최종 운영 패키지 dry-run
- 학습 명령
- 입력 schema

- manifest 검사
- 예측 결과 샘플
- 대시보드/문서 링크를 묶음
