## 2. Track 3의 목표

- 작품 1건의 정보를 보고 가격을 예측하는 모델 구축
- 처음 보는 작가와 이미 본 작가를 나누어 평가
- 실제 운영에서 다시 만들 수 있는 변수만 사용
- 실험 결과를 문서로 남겨 최종 모델 선택 이유를 설명 가능하게 만듦

### 2.1 세부 연구 목표

- 궁극적인 목표는 `작품 1건의 정보를 보고 가격을 예측하는 모델 구축`임
- 각 가설은 아래 세부 목표 중 하나 이상을 검증하기 위해 둠
- 가설 요약표에는 `세부 목표` 컬럼을 두어 어떤 목표를 위한 가설인지 함께 표시함

| 세부 목표 ID | 세부 목표 | 설명 |
|---|---|---|
| G1 | 기본 예측 가능성 확인 | 작품 구조 정보만으로 가격 예측 baseline이 성립하는지 확인 |
| G2 | Warm 성능 개선 | 이미 학습 데이터에 등장한 작가의 새 작품 가격을 더 잘 예측 |
| G3 | Cold 성능 개선 | 처음 보는 작가의 작품 가격을 더 안정적으로 예측 |
| G4 | 운영 가능 피처 선정 | 실제 서비스 입력에서 다시 만들 수 있는 변수만 남김 |
| G5 | 약점 구간 보완 | 2D/3D, 대형 작품, 특정 재료 등 오차가 큰 구간 개선 |
| G6 | 모델 안정성 확인 | 반복 학습, split 차이, 기준 변경에도 성능이 유지되는지 확인 |
| G7 | 결측/정보량/신뢰도 대응 | 정보 부족 상황, 예측 범위, 신뢰도 표시 가능성 확인 |
| G8 | 최종 후보 정책 결정 | Warm / Cold / Cold 3D 모델을 어떻게 나눠 쓸지 결정 |

### 2.2 세부 목표와 가설 연결 원칙

- 새 가설을 만들 때 먼저 `어떤 세부 목표를 검증하는가`를 적음
- 하나의 가설이 여러 세부 목표에 연결될 수 있음
- 예시
- H31은 `G2 Warm 성능 개선`과 `G8 최종 후보 정책 결정`을 위한 가설임
- H32는 `G3 Cold 성능 개선`, `G5 약점 구간 보완`, `G8 최종 후보 정책 결정`을 위한 가설임
- 세부 목표가 불분명한 가설은 실험 전에 질문을 다시 좁힘

## 3. 문제 정의

### 3.1 예측 대상

- 입력 단위: 작품 1건
- 예측 대상: 작품 가격
- 학습 목표값: `ln_price_krw_unified`
- 해석용 가격: `price_krw_unified`
- 로그 가격을 쓰는 이유
- 가격 분포가 한쪽으로 치우쳐 있음
- 로그값이 학습을 더 안정적으로 만듦

### 3.2 예측 상황 구분

- `Warm`
- 학습 데이터에 이미 나온 작가의 새 작품 가격 예측
- `Cold`
- 학습 데이터에 한 번도 나오지 않은 작가의 작품 가격 예측
- 원칙
- Warm과 Cold는 난이도가 다름
- 성능을 합쳐서 한 숫자로만 판단하지 않음

### 3.3 운영 입력 정보 수준 구분

- Warm / Cold 구분과 별도로, 실제 운영에서는 입력 정보의 충분도도 다를 수 있음
- 운영 시나리오 예시
- `정보 충분`
- 작가명, 크기, 재료, 제작연도 등 핵심 정보가 대부분 있음
- `정보 일부 부족`
- 작가명은 있으나 재료나 제작연도 일부가 비어 있음
- `정보 매우 부족`
- 작가명 없음
- 재료 없음
- 제작연도 없음
- 사이즈만 있거나, 일부 기본 정보만 있음
- 의미
- Warm / Cold는 학습과 평가 구조를 나누는 기준
- 정보 충분도는 실제 입력 상태를 나누는 기준
- 원칙
- 같은 Warm이라도 정보가 적으면 예측 신뢰도는 낮아질 수 있음
- 후속 실험에서는 정보 수준별 성능 저하와 대응 방식을 함께 검토함

## 4. 실험 진행 원칙

- 데이터를 먼저 고정하고 모델 실험을 시작함
- 입력 변수는 한 번에 많이 바꾸지 않음
- 변수는 하나씩 추가하며 효과 확인
- Warm 성능과 Cold 성능을 항상 따로 기록
- 최고 점수 하나보다 반복 실험 시 안정성을 더 중요하게 봄
- 최종 확인용 데이터는 실험 중간에 참고하지 않음

### 4.0-1 후속 재검증 원칙

- 성능이 좋아진 가설은 바로 운영 채택하지 않음
- 아래 순서로 한 번 더 확인함
- 재현 가능성
- seed나 내부 분할이 바뀌어도 비슷한 결과가 나오는지 확인
- 운영 가능성
- 실제 운영 시점에 만들 수 있는 피처인지 확인
- 누수 가능성
- 예측 시점 이후 정보가 들어가지 않는지 확인
- 보조 출력 가능성
- 가격 범위, 신뢰도 같은 출력은 point prediction과 별도로 calibration을 확인
- 현재 후속 재검증 가설
- H16: 작가 이력 피처 temporal-safe 가능 여부 감사
- H17: 작가 이력 피처 반복 안정성 검증
- H18: 가격 범위 calibration 보완

### 4.1 상위 가설과 하위 가설 관리 원칙

- 일부 가설은 하나의 큰 목표를 설명하는 상위 가설로 관리함
- 예시
- H2는 `작가 정보 없이도 Cold 예측이 가능한가`를 보는 상위 가설임
- H13, H14, H15는 H2 이후 Cold 성능을 개선하기 위한 후속 또는 하위 가설로 연결함
- 단, 하위 가설이라고 해서 Cold만 보는 것은 아님
- 재료, 크기, 결측처럼 Warm / Cold 공통으로 만들 수 있는 변수는 Warm과 Cold 모두에서 평가함
- 이유
- Cold만 좋아지고 Warm이 크게 나빠지면 공통 운영 피처로 쓰기 어려움
- Warm / Cold가 같은 입력 변수를 공유하는 경우가 많기 때문에 한쪽 성능만 보고 채택하면 위험함
- 정리
- H2: Cold baseline 가능성 확인
- H13~H15: Cold 약점 보완 중심 후속 가설
- 공통 피처: Warm / Cold 모두 평가
- Warm 전용 피처: Warm에서만 평가
- Cold에서 사용할 수 없는 피처: Cold 피처셋에서 제외

## 7. 데이터 새어 나감 방지 원칙

- 의미
- 원래 학습할 때 알면 안 되는 정보가 모델에 들어가는 문제
- 잘못된 예
- 테스트 데이터까지 합쳐서 작가별 작품 수를 셈
- 전체 데이터를 보고 범주 목록을 만듦
- 테스트 데이터 분포를 본 뒤 변수를 수정함
- 지켜야 할 규칙
- 모델 학습은 항상 `train`만 사용
- 어떤 작품의 가격을 예측할 때는 그 작품의 `예측 시점` 또는 `거래일` 이전 정보만 사용
- 범주형 값 목록도 `train`만 보고 정함
- 크기 조정, 구간 나누기, 집계 변수 계산도 `train`만 보고 수행
- `artist_works_log` 같은 파생 변수는 split 이후 다시 계산
- `test_warm`, `test_cold`는 학습에 쓰지 않고 성능 확인에만 사용
- 특히 아래 정보는 모두 `예측 시점 이전` 기준으로 집계해야 함
- 작가 과거 거래 이력
- 전시 이력
- 갤러리 정보
- 소장 / 수상 / 언론 이력
- 이후 시점의 최고가, 이후 전시, 이후 거래 정보는 사용 금지

## 8. 입력 변수 설계 원칙

### 8.1 기본 원칙

- 최종 입력 변수는 아래 조건을 만족해야 함
- 실제 운영에서 다시 만들 수 있어야 함
- 가격 정보가 뒤에서 새어 들어가면 안 됨
- 특정 데이터 출처에만 과하게 기대면 안 됨
- 의미 설명이 가능해야 함
- 반복 실험에서도 비슷한 개선 효과가 나와야 함

### 8.1-1 결측 자체를 정보로 보는 원칙

- 값이 없다는 사실 자체가 의미 있는 신호일 수 있음
- 따라서 단순히 빈칸으로 두는 것보다, `결측 여부`를 별도 변수로 두는 방식을 함께 검토함
- 예시
- `artist_missing`
- `material_missing`
- `year_missing`
- `size_missing`
- `image_missing`
- 원칙
- 결측은 무조건 보간하지 않음
- 결측 자체가 가격 예측과 신뢰도에 어떤 영향을 주는지 확인함
- 후속 실험에서는 `결측 표시 변수`와 `정보 가리기 학습`을 함께 검토함

### 8.2 현재 핵심 변수 후보

- `medium_category`
- `support_category`
- `depth_cm`
- `width_cm`
- `height_cm`
- `log_area`
- `estimated_ho`
- `orientation`
- 의미
- 작품의 재료, 바탕, 크기, 비율, 호수 같은 구조적 정보

### 8.2-1 크기 관련 변수 묶음 검토

- `width_cm`
- `height_cm`
- `log_area`
- `estimated_ho`
- `depth_cm`
- 해석 원칙
- 이 5개는 모두 완전히 다른 역할의 변수는 아님
- `width_cm`, `height_cm`, `log_area`, `estimated_ho`는 같은 크기 축을 다른 방식으로 표현한 후보군으로 봄
- `depth_cm`는 입체성, 깊이, 3D 특성을 설명하는 별도 축으로 봄
- 검토 원칙
- 크기 관련 변수를 모두 동시에 유지하는 것이 목표가 아님
- 같은 정보를 여러 방식으로 중복 입력하고 있을 가능성을 함께 검토함
- 최종 모델에서는 일부만 남기거나 대표 조합으로 축소하는 방향도 포함함
- 예시
- `width_cm + height_cm`
- `log_area`
- `estimated_ho`
- `log_area + estimated_ho`
- `log_area + depth_cm`
- 목적
- 어떤 크기 표현 방식이 가장 단순하고 안정적으로 작동하는지 비교하기 위함

### 8.3 추가로 시험할 변수

- `aspect_ratio`
- 가로와 세로 비율
- `medium_ho_bucket`
- 재료와 호수 구간을 합친 변수
- `artist_works_log`
- 학습 데이터에서 해당 작가가 몇 번 등장했는지를 반영한 변수

### 8.3-1 추가 파생 변수 확대 계획

- 현재 후보 외에도 운영 입력값에서 다시 계산 가능한 의미 있는 파생 변수를 추가 검토함

## 10. 실험 순서

### 10.1 1단계: 데이터 기준 고정

### 10.2 2단계: 기본 모델 만들기

- Warm baseline 이후 LightGBM 계열이 강함

### 10.3 3단계: 기본 변수 성능 확인

- Warm baseline `med_APE 0.739`
- Cold 크기 표현 비교에서는 `log_area + estimated_ho` 조합이 가장 안정적

### 10.4 4단계: 변수 추가 실험

- 변수를 한 번에 많이 넣지 않음

## 11. 평가 방법

### 11.1 기본 평가 지표

- Track 3에서는 하나의 지표만으로 모델을 판단하지 않음
- 각 지표는 `뜻`, `계산식`, `높고 낮음의 의미`, `활용 목적`이 다름

#### `APE`

- 뜻
- 작품 1건의 비율 오차
- 계산식
- `APE = |예측가격 - 실제가격| / 실제가격`
- 해석
- 값이 낮을수록 좋음
- `0`이면 완전히 정확함

#### `median APE`

- 뜻
- 작품별 `APE`의 중앙값
- 계산식
- `median APE = 작품별 APE 값들의 중앙값`
- 또는
- `median APE = median(|예측가격 - 실제가격| / 실제가격)`
- 해석
- 값이 낮을수록 좋음
- 극단적으로 큰 오차에 덜 흔들림
- 활용
- Track 3의 최우선 판단 지표

#### `MAPE`

- 뜻
- 작품별 `APE`의 평균값
- 계산식
- `MAPE = 작품별 APE 값들의 평균`
- 또는
- `MAPE = 평균(|예측가격 - 실제가격| / 실제가격)`
- 해석
- 값이 낮을수록 좋음
- 일부 큰 오차에 쉽게 끌려갈 수 있음
- 활용
- 보조 지표

#### `RMSE(log)`

- 뜻
- 로그 가격 기준 오차의 제곱평균제곱근
- 계산식
- `RMSE(log) = sqrt(평균((로그예측가격 - 로그실제가격)^2))`
- 또는
- `RMSE(log) = sqrt(평균((ln(예측가격) - ln(실제가격))^2))`
- 해석
- 값이 낮을수록 좋음
- `0`에 가까울수록 로그 가격 기준 예측이 안정적임
- 활용
- 학습 안정성 확인용 보조 지표

#### `Within-30%`

- 뜻
- 예측 가격이 실제 가격의 30% 이내로 들어온 비율
- 계산식
- `Within-30% = APE가 0.30 이하인 작품 비율`
- 또는
- `Within-30% = |예측가격 - 실제가격| / 실제가격 <= 0.30 인 비율`
- 해석
- 값이 높을수록 좋음
- 실무적으로 “꽤 근사하게 맞춘 비율”을 보여줌
- 활용
- 실무 해석용 보조 지표

#### `Within-50%`

- 뜻
- 예측 가격이 실제 가격의 50% 이내로 들어온 비율
- 계산식
- `Within-50% = APE가 0.50 이하인 작품 비율`
- 또는
- `Within-50% = |예측가격 - 실제가격| / 실제가격 <= 0.50 인 비율`
- 해석
- 값이 높을수록 좋음
- 완화된 기준에서의 적중 비율을 보여줌
- 활용
- 참고용 보조 지표

## 13. 최종 모델 선택 기준

- Warm과 Cold 모두에서 일정 수준 이상의 성능을 보여야 함
- 반복 실험에서 결과가 크게 흔들리지 않아야 함
- 실제 운영에서도 같은 변수를 다시 만들 수 있어야 함
- 데이터 새어 나감 문제가 없어야 함
- 모델 구조와 변수 계산 방식이 설명 가능해야 함
- 모델 파일과 관련 결과물을 다시 저장하고 불러올 수 있어야 함
- 현재 재현 기준 운영안
- Cold: `LAD / Quantile / Huber` 계열 우선
- Warm: `LightGBM tuned` 우선

## 14. 현재 한계와 주의사항

- 실제 운영 입력에서는 출처를 안정적으로 알기 어려워 `source_platform`을 모델 입력에 넣기 어려움
- 시간 순서대로 나눈 데이터가 아니므로, 시간이 지나도 잘 맞는지는 아직 확인되지 않음
- Cold 평가 데이터는 학습 데이터보다 가격 분포가 조금 낮을 수 있음
- Warm 평가는 작가당 1건이라 개별 작가 해석보다 전체 평균 해석에 더 적합함
- 가격대 역시 운영 입력 변수로는 사용할 수 없으므로, 필요 시 결과 해석용 보조 분석으로만 제한함
- 이미지 스타일 / 이미지 피처는 현재 Track 3 본선 실험선에는 아직 포함되지 않음
- 작가 거래 이력 피처는 유용할 수 있으나, 거래일 이전 정보만 사용하도록 누수 관리가 반드시 필요함
