5. 해석 (코덱스 framing 톤 — exploratory diagnostic)

5.1 Drift features 의 실제 informative 정도 (가설 강하게 시사)

  • Stage 1 가설: "drift features 가 학습 시 informative 가능성"
  • Audit 4 결과: 9 features 제거 시 Overall +0.70%p / Saatchi +1.80%p 악화 → drift features 가 학습 분포 OOF 에서 noise 가 아닌 informative signal 임을 강하게 시사
  • 특히 Saatchi 큰 악화 = has_seoul / has_international / has_depth 등이 Saatchi 분포에 strongly informative 추정 (별도 ablation 필요 — 본 cycle 비목표)

5.2 학습-서빙 gap 의 의미

  • 학습 시 informative features 가 서빙 시 hardcoded 0 = production model 의 학습된 weight 가 inference 시 무효화 가능
  • Reported offline metric (calibrated 38.3% cold) 이 production reality 보다 낙관적일 가능성을 강하게 시사 (단정 X — Stage 4 holdout / 서빙 log 비교 후만 정량)
  • 단 production reality gap 의 정량 측정 = Stage 4 confirmatory holdout + 서빙 log 비교 영역 (본 audit 비목표)

6. Honesty Caveats (코덱스 P1)

  • OOF metric 손실 ≠ production reality 더 나쁨 단정: drift features 가 학습 분포 OOF 에서 informative 였음을 강하게 시사 (단정 X). Production-time actual gap = Stage 4 holdout + 서빙 log 비교 후만 정량 가능
  • 본 audit 단독 = 운영 spec 변경 trigger X: Phase 0 §1.8 decision-binding 분리 그대로
  • Saatchi 큰 악화 (+1.80%p) 의 attribution 미수행: 9 features 중 어느 것이 main driver 인지 별도 ablation 필요 (본 cycle 비목표)
  • 3-split caveat: 본 audit 의 baseline 32f 3-split 결과 (40.20% Ensemble) ≠ 운영 metrics.json 의 38.7% Ensemble. 차이 = (a) 본 audit 3-split rerun vs prior 5-fold offline ensemble + (b) production-path calibrated 38.3% (CatBoost) vs offline ensemble 38.7% 차이 (기술보고서 v2 §1 / docs/model_technical_report_v2.md:53). 본 audit = 두 variant 정합 비교 only / 운영 reported metric 직접 비교 부적합
  • 코드 inspection 기반 audit 한계: Stage 1 의 "no serving-side red flag found" (23 features) 단정 X — 학습-서빙 actual distribution 비교 별도 audit 영역

8. 사전등록 governance 도입의 가치 (본 cycle 의 의의)

사용자 명시 요청 ("트랙 1 도 제대로된 실험 방법론 도입") 의 첫 cycle. 결과 자체는 FAIL 이지만 사전등록 method 도입 자체의 가치:
  • HARK 위험을 실질적으로 낮춘 cycle: drift fix → OOF 개선 가설을 사전 freeze 후 평가 → 결과 반증 (악화). 사전등록 없이 결과 본 후 합리화 시 "23f 가 더 나쁨" 사실 가릴 risk → 본 cycle 은 정직 보고 + 후속 운영 inquiry 로 연결
  • Operational anchor baseline 확정: historical 37f vs 현재 서빙 32f ambiguity 해소 (코덱스 P0)
  • Train-serve gap 의 정량적 시사: 9 features (28%) drift / 7 severe + 2 dead 재분류 / Saatchi-specific informative 가설 강하게 시사 — 단순 코드 inspection 보다 구체적 evidence
  • 운영 영향 분리: decision-binding ≠ exploratory 분리 / 본 결과 = production trigger X 명시 / Stage 4 confirmatory holdout 후만 운영 변경
  • 코덱스 사전 + 사후 검수 cycle 정상 작동 — 외부 governance signal (누적 통계 §9 부록 참조)
