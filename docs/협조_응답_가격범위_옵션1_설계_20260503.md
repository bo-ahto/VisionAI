## 1. Schema 계약 — additive only (코덱스 P1 fix)

**원칙**: `prediction.price_range` 는 required 유지 (기존 client backward compat). 신규 필드만 추가.

```python
# src/visionai/price_engine/api/primary_schemas.py

class Prediction(BaseModel):
    # 기존 — required 유지
    price_krw: int
    price_usd: float
    price_range: PriceRange  # 모든 등급에 값 채움 (D 도 일단 채움 — 호환)
    confidence_grade: str
    margin: float

    # v3.7 신규 (additive — 기존 client 무시 가능)
    range_display_mode: Literal["range", "single", "hidden"] = "range"
    range_visible: bool = True       # frontend hint (D 면 false)
    disclaimer: str | None = None    # C 면 "정확도 낮음" 문구
    margin_policy_version: str = "v1"  # 'v1' = 옛 m, 'v2' = 새 m
```

**Backward compat 분석**:

| Client | 기존 동작 | 옵션 1 적용 후 |
|---|---|---|
| 외부 strict DTO parser | `price_range` required → 정상 | 정상 (값 채워짐) |
| 신규 첫 party frontend | `price_range` 사용 | `range_visible=false` 면 hide / `disclaimer` 표시 |
| ETL (predict_logs) | `predicted_range_low/high_krw` 그대로 | 정상 (D 도 값 채움) |
| Grafana / monitoring | mdape / coverage | 새 `margin_policy_version` 으로 cohort split 가능 |

→ **외부 client 계약 깨짐 X**. v2 응답에서 `price_range` deprecate 는 별도 trk.

## 2. Server 변경

```python
# src/visionai/price_engine/api/primary_predictor.py

# 등급별 m table (artifact: model_test_results/grade_margin_calibration.json 참조)
GRADE_MARGIN_V1 = {"A": 0.20, "B": 0.30, "C": 0.50, "D": 0.70}  # legacy
GRADE_MARGIN_V2 = {"A": 0.286, "B": 0.609, "C": 0.50, "D": 0.70}  # 옵션 1
# C/D 는 m 변경 X (range_display_mode 로 frontend 처리)

def _get_margin(grade: str, policy_version: str) -> float:
    table = GRADE_MARGIN_V2 if policy_version == "v2" else GRADE_MARGIN_V1
    return table.get(grade, 0.7)
```

**등급별 분기 (server 응답 build)**:

```python
# src/visionai/price_engine/api/primary_server.py

def _build_prediction(result: dict, grade: str, policy: str) -> Prediction:
    margin = _get_margin(grade, policy)
    pr = PriceRange(
        low=int(result["price_krw"] * (1 - margin)),
        high=int(result["price_krw"] * (1 + margin)),
    )
    if grade in ("A", "B"):
        return Prediction(
            ...,
            price_range=pr,
            range_display_mode="range",
            range_visible=True,
            disclaimer=None,
            margin_policy_version=policy,
        )
    if grade == "C":
        return Prediction(
            ...,
            price_range=pr,  # 호환 — 값 채움
            range_display_mode="single",
            range_visible=False,
            disclaimer="정확도 낮음 — 단일 참고가만 사용 권장",
            margin_policy_version=policy,
        )
    # D
    return Prediction(
        ...,
        price_range=pr,  # 호환 — 값 채움
        range_display_mode="hidden",
        range_visible=False,
        disclaimer=None,
        margin_policy_version=policy,
    )
```

## 3. Logging schema 확장 (DDL + ETL + SQL 한 세트, 코덱스 P1 fix)

⚠️ **코덱스 review 지적**: `margin_policy_version` 한 column 만 추가하면 v1/v2 dual coverage 비교 불가능. ETL (`scripts/etl_predict_logs.py`) 가 DDL 외 모든 필드를 drop 하기 때문. shadow logging 을 의미있게 하려면 **DDL + ETL + monitoring SQL + test 한 세트 변경**.

### 3.1 predict_logs DDL alter (3 column 추가)

```sql
-- monitoring/sql/004_alter_predict_logs_v3_7_margin_v2.sql
ALTER TABLE predict_logs
    ADD COLUMN margin_policy_version VARCHAR(8),       -- 'v1' | 'v2'
    ADD COLUMN predicted_range_low_krw_v2 INT,         -- shadow: v2 m 기반
    ADD COLUMN predicted_range_high_krw_v2 INT;        -- shadow: v2 m 기반
```

기존 `predicted_range_low_krw / high_krw` 는 그대로 — 응답에 표시된 m 의 기록 (v1 rollout 중에는 v1 m). 신규 `_v2` 두 column 은 shadow 측정.

### 3.4 monitoring SQL — shadow coverage 비교 query

`monitoring/sql/015_metrics_grade_margin.sql` 신규:

```sql
-- v1/v2 동시 80% coverage 비교 (등급 별)
WITH shadow_pairs AS (
    SELECT v.confidence_grade,
           v.predicted_price_krw,
           v.predicted_range_low_krw      AS lo_v1,
           v.predicted_range_high_krw     AS hi_v1,
           v.predicted_range_low_krw_v2   AS lo_v2,
           v.predicted_range_high_krw_v2  AS hi_v2,
           s.sold_price_krw
    FROM v_d7_predict_sold_pairs v
    JOIN sold_actuals s
        ON v.request_id IS NOT NULL
        AND s.sold_at > NOW() - INTERVAL '7 days'
    WHERE v.predicted_range_low_krw_v2 IS NOT NULL
)
SELECT
    confidence_grade,
    COUNT(*) AS n,
    AVG(CASE WHEN sold_price_krw BETWEEN lo_v1 AND hi_v1 THEN 1 ELSE 0 END)
        AS coverage_v1,
    AVG(CASE WHEN sold_price_krw BETWEEN lo_v2 AND hi_v2 THEN 1 ELSE 0 END)
        AS coverage_v2
FROM shadow_pairs
GROUP BY confidence_grade
ORDER BY confidence_grade;
```

## 6. Frontend 협조 사항

신규 3 field 처리:
- `range_display_mode == "range"` → 기존 그대로 표시
- `range_display_mode == "single"` → `price_krw` 만 표시 + `disclaimer` 작은 글씨
- `range_display_mode == "hidden"` → `price_krw` 만 + 범위 hide
- `range_visible` boolean 도 동일 — display mode 의 빠른 hint

frontend 변경 PR 별도 (협력자 측). backend 는 신규 field 만 노출 — frontend 가 무시해도 backward compat.
