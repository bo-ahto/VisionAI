# Warm 최종 70:30 모델: 기준가 생성 + 보정값 적용 로직

- 작성일: 2026-06-08
- 대상: Warm 가격 예측 최종 채택 모델
- 최종 후보: `유사작품통계 Huber seed 평균 70% + PPV8 안정 블렌드 30%`
- 목적: 다른 실험 문서를 보지 않아도 최종 모델의 기준가 생성, 보정값 생성, 최종 가격 산출 과정을 이해할 수 있게 정리한다.

## 1. 최종 모델을 한 문장으로 설명

최종 Warm 모델은 먼저 `작가/유사작품 통계 기반 Huber 모델`로 기준 로그가격을 만들고, 이 기준 로그가격 70%와 `PPV8 안정 블렌드` 로그가격 30%를 섞어 최종 로그가격을 만든다.

```text
최종_Warm_로그가격
  = 0.70 * 기준_로그가격
  + 0.30 * PPV8_안정블렌드_로그가격
```

이 식을 `기준가 + 보정값` 관점으로 다시 쓰면 아래와 같다. 이 표현은 해석용 동치식이다.

```text
최종_Warm_로그가격
  = 기준_로그가격 + 적용_보정_로그값

적용_보정_로그값
  = 0.30 * (PPV8_안정블렌드_로그가격 - 기준_로그가격)
```

즉 기준 로그가격에 1.0을 곱하고 보정값에만 0.3을 곱한다는 뜻이 아니다. `적용_보정_로그값` 안에 `-0.30 * 기준_로그가격`이 포함되어 있어, 전체를 전개하면 기준 로그가격은 최종적으로 0.70만 남는다.

가격으로 바꾸면 아래와 같다.

```text
최종_Warm_KRW가격 = exp(최종_Warm_로그가격)
```

주의할 점은 보정 해석을 사용할 때도 보정이 KRW 가격에서 단순 덧셈으로 들어가는 것이 아니라, 로그가격에서 들어간다는 것이다. KRW 가격 기준으로 보면 아래처럼 보정계수를 곱하는 구조다.

```text
기준_KRW가격 = exp(기준_로그가격)
보정계수 = exp(적용_보정_로그값)
최종_Warm_KRW가격 = 기준_KRW가격 * 보정계수
```

## 2. 전체 순서

```text
1. Warm 라우팅
   학습 데이터에 작가 키가 있는 작품만 이 모델을 사용한다.

2. 기준가 생성
   작가/유사작품 통계와 작품 피쳐를 Huber 모델에 넣어 기준_로그가격을 만든다.

3. PPV8 안정 블렌드 생성
   V2 방어형 후보와 L10 생성버킷 순차보정 후보를 75:25로 섞어 PPV8_안정블렌드_로그가격을 만든다.

4. 보정값 계산
   PPV8_안정블렌드_로그가격과 기준_로그가격의 차이 중 30%만 적용한다.

5. 최종 가격 변환
   최종 로그가격에 exp()를 적용해 KRW 가격으로 변환한다.
```

## 3. 변수명 정의

| 문서 변수명 | 코드/후보명 | 의미 |
|---|---|---|
| `기준_로그가격` | `svc_numeric_seed_mean` | 유사작품 숫자 통계를 넣은 Huber seed 평균 예측 로그가격 |
| `기준_KRW가격` | `exp(svc_numeric_seed_mean)` | 기준 로그가격을 KRW 가격으로 변환한 값 |
| `PPV8_안정블렌드_로그가격` | `pp_v8_compact_blend_mape_guarded` | V2 방어형 후보와 L10 생성버킷 후보를 75:25로 섞은 로그가격 |
| `보정전_차이_로그값` | `PPV8_안정블렌드_로그가격 - 기준_로그가격` | PPV8이 기준가보다 높게 보는지 낮게 보는지의 차이 |
| `적용_보정_로그값` | `0.30 * 보정전_차이_로그값` | 최종 모델이 실제 적용하는 보정량 |
| `보정계수` | `exp(적용_보정_로그값)` | KRW 가격 기준으로 기준가에 곱해지는 배율 |
| `최종_Warm_로그가격` | `blend_svcnum_ppv8_wsvc_0.70` | 최종 Warm 예측 로그가격 |
| `최종_Warm_KRW가격` | `exp(최종_Warm_로그가격)` | 최종 Warm 예측 가격 |

## 4. 1단계: 기준가 생성 로직

기준가는 `유사작품통계 Huber seed 평균`으로 만든다. 이 값은 최종식의 70% 축이다.

### 4.1 기준가에 들어가는 입력 피쳐

| 피쳐 묶음 | 사용 피쳐 |
|---|---|
| 작품 크기/형태 | `width_cm`, `height_cm`, `depth_cm`, `area_cm2`, `log_area`, `aspect_ratio`, `has_depth`, `is_3d_candidate`, `is_extreme_aspect_ratio` |
| 재료/지지체 | `medium_category`, `support_category`, `medium_support_bucket` |
| 작가 식별 | `artist_key` |
| 유사작품 숫자 통계 | `svc_group_log_price_median`, `svc_group_log_price_q25`, `svc_group_log_price_q75`, `svc_group_log_price_iqr`, `svc_group_log_unit_area_median`, `svc_group_log_unit_area_iqr`, `svc_group_n_log` |

여기서 작가 정보는 단순히 `artist_key` 하나로 끝나지 않는다. `artist_key`를 이용해 같은 작가 또는 비슷한 조건의 과거 작품 가격 분포를 찾고, 그 결과를 유사작품 숫자 통계로 모델에 넣는다.

### 4.2 유사작품그룹을 찾는 순서

새 작품마다 학습 데이터에서 아래 순서로 유사작품그룹을 찾는다. 조건을 만족하는 첫 그룹을 사용한다.

| 우선순위 | 그룹 키 | 최소 표본 수 | 의미 |
|---:|---|---:|---|
| 1 | `artist_key + medium_support_bucket + size_bucket` | 5 | 같은 작가, 비슷한 재료/지지체, 비슷한 크기 |
| 2 | `artist_key + size_bucket` | 5 | 같은 작가, 비슷한 크기 |
| 3 | `artist_key` | 5 | 같은 작가 전체 이력 |
| 4 | `medium_support_bucket + size_bucket` | 30 | 비슷한 재료/지지체와 크기 |
| 5 | `medium_category + support_category + size_bucket` | 30 | 재료, 지지체, 크기 |
| 6 | `medium_category + size_bucket` | 50 | 재료와 크기 |
| 7 | 전체 train | 제한 없음 | 위 조건이 모두 실패할 때의 fallback |

각 그룹에서 아래 값을 만든다.

```text
유사작품그룹_중앙값_로그가격 = median(log(price_krw))
유사작품그룹_Q25_로그가격 = quantile(log(price_krw), 0.25)
유사작품그룹_Q75_로그가격 = quantile(log(price_krw), 0.75)
유사작품그룹_가격범위폭 = 유사작품그룹_Q75_로그가격 - 유사작품그룹_Q25_로그가격

작품_로그면적단가 = log(price_krw) - log(max(area_cm2, 1))
유사작품그룹_면적단가_중앙값 = median(작품_로그면적단가)
유사작품그룹_면적단가_범위폭 = Q75(작품_로그면적단가) - Q25(작품_로그면적단가)
유사작품그룹_표본수_로그 = log(1 + 유사작품그룹_표본수)
```

### 4.3 기준가 Huber 모델 학습 순서

```text
1. Train을 5개 fold로 나눈다.
2. train 내부 유사작품 통계는 자기 fold를 제외하고 계산한다.
   즉 자기 가격이 자기 피쳐에 새지 않게 한다.
3. validation/test의 유사작품 통계는 전체 train 기준으로 계산한다.
4. 숫자 피쳐는 median imputation 후 표준화한다.
5. 범주 피쳐는 결측을 "__MISSING__"으로 채우고 one-hot encoding한다.
6. HuberRegressor를 target log(price_krw)에 맞춰 학습한다.
7. seed 10개를 반복하고 예측 로그가격을 평균한다.
```

수식으로는 아래처럼 볼 수 있다.

```text
각 seed s에 대해:
  기준_Huber_s = HuberRegressor(
      epsilon = 1.35,
      alpha = 0.0001,
      max_iter = 4000
  )

  seed별_기준_로그가격_s
    = 기준_Huber_s(작품피쳐, 유사작품숫자통계)

기준_로그가격
  = average(seed별_기준_로그가격_202606030 ... seed별_기준_로그가격_202606039)
```

Huber 모델은 선형 회귀 계열이므로 내부적으로는 아래 구조다.

```text
기준_로그가격
  = 절편
  + Σ(피쳐별_계수 * 전처리된_피쳐값)
```

일반 선형회귀와 다른 점은 큰 오차 샘플의 영향력을 줄이는 Huber loss를 사용한다는 점이다.

```text
minimize_beta sum_i HuberLoss(실제로그가격_i - 예측로그가격_i)
              + alpha * ||beta||^2
```

## 5. 2단계: PPV8 안정 블렌드 생성 로직

PPV8 안정 블렌드는 최종식의 30% 축이다. 이 값은 단일 모델 하나가 만든 값이 아니라, 두 하위 예측값을 로그가격에서 75:25로 섞은 값이다.

```text
PPV8_안정블렌드_로그가격
  = 0.75 * V2_방어형후보_로그가격
  + 0.25 * L10_생성버킷_순차보정_로그가격
```

PPV8 실험에서는 네 후보를 비교했지만 최종 weight는 아래처럼 선택됐다.

| 하위 후보 | 역할 | 최종 weight |
|---|---|---:|
| `V1_대표후보_로그가격` | 대표 단일 후보 | 0.00 |
| `V2_방어형후보_로그가격` | Huber meta-stacking 기반 방어형 후보 | 0.75 |
| `L10_생성버킷_순차보정_로그가격` | Quantile-Huber-CatBoost 순차보정 후보 | 0.25 |
| `L10_작가메타_외부검색_순차보정_로그가격` | 작가 메타/외부 검색 피쳐 포함 순차보정 후보 | 0.00 |

### 5.1 V2 방어형 후보 생성

`V2_방어형후보_로그가격`은 여러 기존 Warm 후보의 예측값을 다시 입력으로 넣고, Huber meta-model로 안정화한 값이다.

#### V2 입력값

| 입력 | 의미 |
|---|---|
| 기존 Warm 후보 예측 로그가격들 | 기본 Huber, L8/L9 순차 후보, D4 블렌드, R5 p95/MAPE 방어 후보, 작가이력 라우팅, 유사작품 fallback, U1 확장 후보 등 |
| 예측값 평균 | 여러 후보가 평균적으로 보는 가격대 |
| 예측값 표준편차 | 후보들끼리 얼마나 의견이 다른지 |
| 예측값 범위 | 가장 높은 후보와 낮은 후보의 차이 |
| 기준후보와의 차이 | 각 후보가 기준 후보보다 얼마나 높거나 낮은지 |
| `routing_width` | 가격 범위/불확실성 폭 |

#### V2 수식

```text
V2_raw_로그가격
  = HuberMetaModel(
      하위후보_예측로그가격들,
      예측값_평균,
      예측값_표준편차,
      예측값_범위,
      기준후보와의_차이들,
      routing_width
    )
```

V2는 예측값이 하위 후보들의 범위를 과도하게 벗어나지 않도록 clipping한다.

```text
하위후보_최소값 = min(하위후보_예측로그가격들)
하위후보_최대값 = max(하위후보_예측로그가격들)

V2_방어형후보_로그가격
  = clip(V2_raw_로그가격, 하위후보_최소값 - 0.03, 하위후보_최대값 + 0.03)
```

V2는 쉽게 말해 “여러 후보의 의견을 보고 Huber 방식으로 다시 조합하되, 너무 튀는 예측을 방지한 방어형 예측값”이다.

### 5.2 L10 생성버킷 순차보정 후보 생성

`L10_생성버킷_순차보정_로그가격`은 `Quantile -> Huber -> CatBoost residual` 순서로 만든다.

#### L10 입력 피쳐

| 묶음 | 피쳐 |
|---|---|
| Warm 기본 피쳐 | `width_cm`, `height_cm`, `depth_cm`, `area_cm2`, `log_area`, `aspect_ratio`, `has_depth`, `is_3d_candidate`, `medium_category`, `support_category`, `medium_support_bucket`, `is_extreme_aspect_ratio`, `artist_key` |
| 작가 학습량 | `artist_works_log`, `artist_works_count_train` |
| 생성 bucket | `size_bucket`, `shape_bucket`, `support_size_bucket`, `medium_shape_bucket`, `is_large_2d`, `is_large_3d` |

#### L10 처리 순서

```text
1. CatBoost Quantile 모델 3개로 q10, q50, q90 로그가격을 예측한다.
2. q90 - q10으로 불확실성 폭인 quantile_width를 만든다.
3. price_range_ratio = exp(quantile_width)를 만든다.
4. 원래 피쳐에 q10, q50, q90, quantile_width, price_range_ratio를 추가한다.
5. Huber 모델이 중심 로그가격을 예측한다.
6. train에서 Huber OOF 예측을 만들고 실제 로그가격과의 차이를 residual target으로 둔다.
7. CatBoost가 residual target을 학습한다.
8. Huber 중심선 + CatBoost 잔차보정으로 최종 L10 로그가격을 만든다.
```

#### L10 수식

```text
q10_log, q50_log, q90_log
  = CatBoostQuantile(작품피쳐, 생성bucket피쳐)

quantile_width = q90_log - q10_log
price_range_ratio = exp(clip(quantile_width, -10, 10))

L10_Huber_중심선_로그가격
  = Huber(작품피쳐, 생성bucket피쳐, q10_log, q50_log, q90_log, quantile_width, price_range_ratio)

잔차_target
  = 실제_로그가격 - L10_Huber_OOF_중심선_로그가격

CatBoost_잔차보정
  = CatBoostRegressor(작품피쳐, 생성bucket피쳐, quantile피쳐들)

L10_생성버킷_순차보정_로그가격
  = L10_Huber_중심선_로그가격 + CatBoost_잔차보정
```

L10은 쉽게 말해 “가격대의 불확실성 폭을 먼저 보고, Huber로 중심 가격을 잡고, 남은 잔차를 CatBoost로 보정한 예측값”이다.

### 5.3 PPV8 75:25 블렌드 선택 방식

PPV8은 아래 방식으로 75:25 weight를 선택했다.

```text
1. 네 하위 후보의 validation 예측 로그가격을 같은 row 기준으로 병합한다.
2. 0.25 단위 weight grid를 탐색한다.
3. MdAPE가 validation 최저 단일 후보의 1.08배 이내인 조합만 허용한다.
4. 허용된 조합 중 MAPE가 가장 낮은 조합을 선택한다.
5. 선택된 weight를 test에 그대로 적용한다.
```

선택 결과가 아래 식이다.

```text
PPV8_안정블렌드_로그가격
  = 0.75 * V2_방어형후보_로그가격
  + 0.25 * L10_생성버킷_순차보정_로그가격
```

## 6. 3단계: 기준가에 보정값 적용

기준_로그가격과 PPV8_안정블렌드_로그가격이 만들어지면, 최종 모델은 두 값을 70:30으로 섞는다.

```text
최종_Warm_로그가격
  = 0.70 * 기준_로그가격
  + 0.30 * PPV8_안정블렌드_로그가격
```

이 값을 `기준가에서 PPV8 방향으로 30% 이동한다`는 관점으로 다시 쓰면 아래와 같다.

```text
보정전_차이_로그값
  = PPV8_안정블렌드_로그가격 - 기준_로그가격

적용_보정_로그값
  = 0.30 * 보정전_차이_로그값

최종_Warm_로그가격
  = 기준_로그가격 + 적용_보정_로그값
```

위 식을 전개하면 다시 원래 70:30 식이 된다.

```text
최종_Warm_로그가격
  = 0.70 * 기준_로그가격
  + 0.30 * PPV8_안정블렌드_로그가격
```

### 6.1 보정값의 방향

PPV8이 기준가보다 높게 예측하면 보정값은 양수다.

```text
PPV8_안정블렌드_로그가격 > 기준_로그가격
=> 적용_보정_로그값 > 0
=> 최종 가격은 기준가보다 올라간다.
```

PPV8이 기준가보다 낮게 예측하면 보정값은 음수다.

```text
PPV8_안정블렌드_로그가격 < 기준_로그가격
=> 적용_보정_로그값 < 0
=> 최종 가격은 기준가보다 내려간다.
```

### 6.2 KRW 가격에서 보는 보정계수

보정형 해석에서 로그가격은 `기준 + 보정`이지만, KRW 가격에서는 `기준가 * 보정계수`다.

```text
기준_KRW가격 = exp(기준_로그가격)

보정계수
  = exp(적용_보정_로그값)
  = exp(0.30 * (PPV8_안정블렌드_로그가격 - 기준_로그가격))

최종_Warm_KRW가격
  = 기준_KRW가격 * 보정계수
```

예를 들어 PPV8이 기준가보다 로그가격 기준으로 `0.20` 높게 본다면 실제 적용 보정은 `0.30 * 0.20 = 0.06`이다.

```text
보정계수 = exp(0.06) = 약 1.062
```

즉 최종 가격은 기준가보다 약 6.2% 높아진다.

## 7. 최종 모델의 성능과 역할

| 항목 | MdAPE | MAPE | p95_APE | RMSE_log |
|---|---:|---:|---:|---:|
| 기준가 단독: 유사작품통계 Huber seed 평균 | 0.1520 | 0.2942 | 0.9381 | 0.4179 |
| 보정축 단독: PPV8 안정 블렌드 | 0.1632 | 0.2816 | 0.9311 | 0.4028 |
| 최종 Warm 70:30 | 0.1405 | 0.2748 | 0.8331 | 0.3996 |

해석:

- 기준가 단독은 중앙 오차인 MdAPE가 강하다.
- PPV8 안정 블렌드는 평균오차인 MAPE와 큰 오차 방어에 도움이 된다.
- 최종 70:30은 기준가의 중앙 성능을 유지하면서 PPV8 방향으로 30%만 이동해 MAPE와 p95를 낮춘다.
