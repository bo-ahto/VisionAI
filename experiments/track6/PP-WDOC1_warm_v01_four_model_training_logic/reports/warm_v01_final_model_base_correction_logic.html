Warm 최종 70:30 모델: 기준가 생성 + 보정값 적용 로직

작성일 2026-06-08 최종 Warm 모델 전용 문서 기준가 + 보정값 구조 단위 로그 KRW
핵심 설명

최종 Warm 모델은 먼저 작가/유사작품 통계 기반 Huber 모델로 기준_로그가격을 만든다. 그 다음 기준 로그가격 70%와 PPV8 안정 블렌드 로그가격 30%를 섞어 최종 로그가격을 만든다.

최종_Warm_로그가격 = 0.70 * 기준_로그가격 + 0.30 * PPV8_안정블렌드_로그가격

같은 식을 기준가 보정 관점으로 다시 쓰면 아래와 같다. 이 표현은 해석용 동치식이다.

최종_Warm_로그가격 = 기준_로그가격 + 적용_보정_로그값 적용_보정_로그값 = 0.30 * (PPV8_안정블렌드_로그가격 - 기준_로그가격)

즉 기준 로그가격에 1.0을 곱하고 보정값에만 0.3을 곱한다는 뜻이 아니다. 보정값 안에 -0.30 * 기준_로그가격이 포함되어 있어 전체 전개 결과는 기준 70%, PPV8 30%다.

전체 순서

1. Warm 라우팅
학습 데이터에 작가 키가 있는 작품만 Warm 최종 모델을 사용한다.
2. 기준가 생성
작가/유사작품 통계와 작품 피쳐로 Huber 기준 로그가격을 만든다.
3. 안정 블렌드 생성
V2 방어형 후보와 L10 생성버킷 후보를 75:25로 섞는다.
4. 보정값 계산
PPV8과 기준가 차이의 30%만 적용한다.
5. 가격 변환
최종 로그가격에 exp()를 적용해 KRW 가격으로 변환한다.

기준가는 유사작품통계 Huber seed 평균으로 만든다. 이 값이 최종식의 70% 축이다.

Huber 기준가 수식

각 seed s에 대해: seed별_기준_로그가격_s = Huber_s(작품피쳐, 유사작품숫자통계) 기준_로그가격 = average(seed별_기준_로그가격_202606030 ... seed별_기준_로그가격_202606039)

2단계: PPV8 안정 블렌드 생성

PPV8 안정 블렌드는 단일 모델 하나가 아니라, 두 하위 후보 예측값을 로그가격에서 75:25로 섞은 값이다.

PPV8_안정블렌드_로그가격 = 0.75 * V2_방어형후보_로그가격 + 0.25 * L10_생성버킷_순차보정_로그가격
하위 후보역할최종 weight
V1 대표후보대표 단일 후보0.00
V2 방어형 후보Huber meta-stacking 기반 방어형 후보0.75
L10 생성버킷 순차보정Quantile-Huber-CatBoost 순차보정 후보0.25
L10 작가메타/외부검색 순차보정작가 메타/외부 검색 피쳐 포함 후보0.00

V2 방어형 후보

V2는 여러 기존 Warm 후보의 예측 로그가격을 입력으로 받아 Huber meta-model로 다시 안정화하고, 하위 후보 범위를 크게 벗어나지 않게 clipping한 값이다.

V2_raw_로그가격 = HuberMetaModel(하위후보_예측로그가격들, 예측값_평균, 예측값_표준편차, 예측값_범위, 기준후보와의_차이들, routing_width) V2_방어형후보_로그가격 = clip(V2_raw_로그가격, 하위후보_최소값 - 0.03, 하위후보_최대값 + 0.03)

L10 생성버킷 순차보정 후보

L10은 가격대 불확실성을 먼저 보고, Huber로 중심 가격을 잡고, 남은 잔차를 CatBoost로 보정한다.

q10_log, q50_log, q90_log = CatBoostQuantile(작품피쳐, 생성bucket피쳐) quantile_width = q90_log - q10_log price_range_ratio = exp(clip(quantile_width, -10, 10)) L10_Huber_중심선_로그가격 = Huber(작품피쳐, 생성bucket피쳐, q10_log, q50_log, q90_log, quantile_width, price_range_ratio) CatBoost_잔차보정 = CatBoostRegressor(실제_로그가격 - L10_Huber_OOF_중심선_로그가격) L10_생성버킷_순차보정_로그가격 = L10_Huber_중심선_로그가격 + CatBoost_잔차보정

3단계: 기준가에 보정값 적용

기준_로그가격과 PPV8_안정블렌드_로그가격이 만들어지면, 최종 모델은 두 값을 70:30으로 섞는다.

최종_Warm_로그가격 = 0.70 * 기준_로그가격 + 0.30 * PPV8_안정블렌드_로그가격

이 값을 기준가에서 PPV8 방향으로 30% 이동한다는 관점으로 다시 쓰면 아래와 같다.

보정전_차이_로그값 = PPV8_안정블렌드_로그가격 - 기준_로그가격 적용_보정_로그값 = 0.30 * 보정전_차이_로그값 최종_Warm_로그가격 = 기준_로그가격 + 적용_보정_로그값
보정형 해석에서 로그가격은 기준가에 보정값을 더하는 구조지만, KRW 가격에서는 기준가에 보정계수를 곱하는 구조다.
기준_KRW가격 = exp(기준_로그가격) 보정계수 = exp(적용_보정_로그값) 최종_Warm_KRW가격 = 기준_KRW가격 * 보정계수
