1. 실험 목적

  • 기본 피처를 먼저 고정한 상태에서 가능한 후보 모델을 넓게 비교합니다.
  • 모든 후보 모델은 기본 설정으로 1차 실행합니다.
  • 1차 결과를 보고 Warm 상위 2~3개, Cold 상위 2~3개 모델로 압축합니다.
  • 압축된 후보만 다음 단계에서 반복 실행, 세부 설정값 조정, slice별 안정성 검증을 진행합니다.

2. 가설

  • 같은 후보 모델군을 Warm과 Cold에 모두 적용하면 모델별 강점과 약점을 공정하게 비교할 수 있다.
  • Warm과 Cold의 차이는 먼저 피처셋과 평가 데이터에서 발생하게 두고, 모델 후보군은 동일하게 유지한다.
  • 처음부터 모든 모델을 튜닝하지 않고, 1차 비교로 가능성이 낮은 모델을 제외한다.
  • 비교 결과를 본 뒤 Warm 상위 후보와 Cold 상위 후보를 따로 선정한다.

3. 기본 피처 정의

  • 기본 피처는 “성능이 좋아 보이는 피처를 모두 넣는 것”이 아니라, 운영에서 안정적으로 입력 가능하고 누수 위험이 낮은 최소 피처부터 시작합니다.
  • Warm과 Cold를 공정하게 비교하기 위해 작품 자체 피처는 최대한 공통으로 두고, Warm에서만 작가명 피처를 추가합니다.
  • 크기 피처는 중복이 많기 때문에 1차 기본 피처에서는 ln_estimated_ho를 대표 크기값으로 사용합니다.
  • width_cm, height_cm, log_area, aspect_ratio는 바로 기본 피처에 넣지 않고 후속 크기 파생 실험에서 추가 효과를 확인합니다.
  • 재료와 지지체는 운영 입력 가능성이 높고 작품 자체 정보라 기본 후보에 포함합니다.
  • 3D/depth 피처는 모든 작품에 항상 있는 정보가 아니므로 기본 피처가 아니라 약점 구간 보완 후보로 둡니다.

4. 실험 방법

  • 같은 데이터 split을 사용합니다.
  • 같은 피처셋 안에서 모델만 바꿔 비교합니다.
  • Warm 모델은 Warm test 성능을 기준으로 우선 판단합니다.
  • Cold 모델은 Cold test 성능을 기준으로 우선 판단합니다.
  • Warm과 Cold 성능을 합쳐 한 숫자로 판단하지 않습니다.
  • 후보 모델은 성능뿐 아니라 재현 가능성, 해석 가능성, 운영 가능성도 같이 봅니다.

5. 비교할 후보 모델군

  • Hedonic은 별도 알고리즘 이름이 아니라, 작가명/호수/재료 같은 설명 변수로 가격을 설명하는 회귀 실험 방식입니다.
  • 같은 estimator, 같은 전처리, 같은 피처를 쓰는 중복 후보는 제거했습니다.
  • 따라서 실제 실행 후보는 아래 8개 모델입니다.

트리 계열 CatBoost 범주형 피처 처리에 강한 트리 기반 모델입니다. 작가명, 재료, 지지체처럼 문자형 피처가 많은 상황에서 강점이 있는지 확인합니다.
트리 계열 XGBoost 성능이 강한 트리 기반 모델로 복잡한 피처 조합을 잘 학습할 수 있습니다. LightGBM/CatBoost와 비교해 성능 개선이 있는지 확인합니다.
트리 계열 HistGradientBoosting scikit-learn 기반 트리 모델로 빠르게 비선형 기준 성능을 확인하기 좋은 모델입니다. 외부 라이브러리 의존도가 낮은 트리 기준 모델로 쓸 수 있는지 확인합니다.
  • 위 후보 모델은 Warm과 Cold에 모두 적용합니다.
  • Warm에서는 Warm 기본 피처셋을 사용하고, Cold에서는 Cold 기본 피처셋을 사용합니다.
  • 모델 후보를 미리 Warm용/Cold용으로 나누지 않고, 결과를 본 뒤 각각 상위 2~3개를 고릅니다.
  • 1차 비교에서는 모든 후보 모델을 기본 설정으로만 실행합니다.
  • 튜닝은 상위 후보가 압축된 뒤 별도 실험에서 진행합니다.

7. 실행 전략

  • 1차 비교: 모든 후보 모델을 기본 설정으로 1회 실행합니다.
  • 1차 목적: 가능성이 낮은 모델을 빠르게 제외합니다.
  • 2차 압축: Warm 상위 2~3개, Cold 상위 2~3개를 선정합니다.
  • 3차 검증: 압축된 후보만 반복 실행, 세부 설정값 조정, slice별 안정성 확인을 진행합니다.
  • 주의: 처음부터 모든 후보 모델을 튜닝하지 않습니다.

8. 유의미함 기준

  • 1순위: median APE가 낮은 모델을 우선합니다.
  • 2순위: p95 APE가 과도하게 높지 않은 모델을 우선합니다.
  • 3순위: Within-30과 Within-50이 높은 모델을 우선합니다.
  • 4순위: 같은 성능이면 단순하고 재현 가능한 모델을 우선합니다.
  • 5순위: Warm에서 좋은 모델이 Cold에서 나빠지면 Warm/Cold 모델을 분리합니다.
  • 6순위: 실행 시간이 과도하게 길면 1차 후보에서는 보류할 수 있습니다.
