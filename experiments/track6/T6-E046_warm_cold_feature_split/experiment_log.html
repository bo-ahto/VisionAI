T6-E046 Warm/Cold 작품 피처 분리 실험

  • 상위 일지: T6-E038 작품 변수 선정 실험 일지
  • 목적: 작품 관련 피처의 채택 여부를 가설 단위로 검증
  • 상태: 실험 계획 작성 완료, 실행 전

1. 실험 일지

  • 가설: Warm과 Cold는 동일한 작품 피처 조합보다 각각 다른 피처 조합을 사용할 때 성능이 좋아질 수 있다.
  • 유의미함 기준: 분리 피처 모델의 각 성능이 더 좋으면 채택
  • 테스트 모델: Warm: Huber / Linear Regression / Ridge, Cold: Huber / Quantile-LAD / LightGBM
  • 확인할 작품 피처: Warm/Cold 후보 피처 조합

2. 초기 실험 데이터

  • 기준 원천 파일: data/track6/track6_feature_candidates_name_corrected.csv
  • 학습 입력과 정답 가격은 분리해서 생성한다.
  • 정답 가격은 train_labels.csv, test_warm_labels.csv, test_cold_labels.csv에만 둔다.
  • Warm 학습 피처에는 artist_name_ko를 둘 수 있지만, 이 실험의 판단 대상은 작품 피처다.
  • Cold 테스트에는 작가명을 사용하지 않는다.

3. 초기 실험 테스트: Warm

  • Warm 목적: Warm에는 작가명과 실제 크기 중심 피처가 필요한지, 공통 피처셋보다 Warm 전용 피처셋이 나은지 확인한다.
  • 공통 피처셋: ln_estimated_ho + nant_material_idx + nant_tool + nant_support + width_cm + height_cm + log_area + aspect_ratio
  • Warm 전용 피처셋: artist_name_ko + ln_estimated_ho + nant_material_idx + nant_tool + nant_support + width_cm + height_cm + log_area + aspect_ratio
  • Warm 테스트 데이터: data/test_warm_features.csv + data/test_warm_labels.csv
  • 비교 방식: 같은 Warm split에서 공통 피처 모델과 Warm 전용 피처 모델을 비교한다.
  • 추가 확인: 작가명 추가 효과와 크기 피처 추가 효과가 따로 보이는지 기록한다.
  • 판단 기준: Warm 전용 피처셋이 개선되면 Warm과 Cold 피처를 분리 관리한다.

4. 초기 실험 테스트: Cold

  • Cold 목적: Cold에는 Warm과 같은 피처셋보다 depth/3D 중심 Cold 전용 피처셋이 더 안정적인지 확인한다.
  • 공통 피처셋: ln_estimated_ho + nant_material_idx + nant_tool + nant_support + width_cm + height_cm + log_area + aspect_ratio
  • Cold 전용 피처셋: ln_estimated_ho + nant_material_idx + nant_tool + nant_support + depth_cm + has_depth + is_3d_candidate
  • Cold 테스트 데이터: data/test_cold_features.csv + data/test_cold_labels.csv
  • 제외 피처: artist_name_ko
  • 비교 방식: 같은 Cold split에서 공통 피처 모델과 Cold 전용 피처 모델을 비교한다.
  • 추가 확인: Cold 2D/3D slice에서 전용 피처셋이 어느 구간을 개선하는지 확인한다.
  • 판단 기준: Cold 전용 피처셋이 전체 또는 약점 slice를 개선하면 Warm/Cold 피처 분리 정책을 유지한다.

6. 판단 기준

  • Warm과 Cold의 median APE를 각각 확인한다.
  • p95 APE가 줄어드는지 확인해 큰 오차가 줄었는지 본다.
  • Warm에서만 개선되면 Warm 전용 후보로 둔다.
  • Cold에서만 개선되면 Cold 전용 후보로 둔다.
  • 운영에서 입력하기 어려운 변수는 성능이 좋아도 최종 후보에서 제외하거나 보류한다.
