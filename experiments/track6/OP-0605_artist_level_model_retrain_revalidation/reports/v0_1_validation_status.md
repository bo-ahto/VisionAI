# v0.1 최종 채택 전 검증 상태

## 1. 확인 목적

- v0.1 후보를 서비스 적용 전 바로 확정해도 되는지 확인
- 반복 split, artist-level split, 모델 재학습 포함 검증이 어디까지 되었는지 구분
- 추가 보정 후보가 실제로 기본 정책에 들어갈 만큼 안정적인지 판단

## 2. Warm v0.1 후보 검증 상태

- 현재 후보: `PP-SVC3 70:30 결합`
- 의미: 유사 작품 기반 가격 피처 후보 70% + 오차 안정화 후보 30% 결합
- 기존 검증:
  - validation에서 결합 비율 선택
  - test에서 MdAPE `0.1405`, MAPE `0.2748`, p95_APE `0.8331`
  - bootstrap 기준 개선 확률 확인
- 검증 해석:
  - 기존 Warm 후보보다 test와 bootstrap에서 개선 신호가 강함
  - 다만 현재 `PP-SVC3` 검증은 기존 예측값을 활용한 결합/부트스트랩 검증
  - 모델을 seed마다 다시 학습하는 완전한 반복 재학습 검증은 아직 별도 보강 대상

## 3. Cold v0.1 후보 검증 상태

- 현재 후보: `PP-Y18 LightGBM Quantile + qwidth 구간 보정`
- 의미: LightGBM Quantile로 가격 중앙값과 불확실성 폭을 예측하고, 불확실성 구간별 잔차 보정 적용
- 기존 검증:
  - test에서 MdAPE `0.4247`, MAPE `0.9910`, p95_APE `3.3053`
  - `PP-Y21`에서 row holdout과 artist holdout을 80회 반복해 예측값 재사용 기준 안정성 확인
- 검증 해석:
  - 기존 Cold 기준선보다 개선 신호는 있음
  - artist holdout에서도 개선 확률은 유지됨
  - 다만 `PP-Y21`은 모델을 다시 학습한 검증이 아니라, 이미 생성된 예측값의 평가 구성을 바꾼 안정성 검증

## 4. 이번에 추가로 진행한 재학습 포함 검증

- 실험 폴더: `OP-0605_artist_level_model_retrain_revalidation`
- 목적: 원인별 보정/라우팅 후보가 모델을 다시 학습해도 안정적으로 작동하는지 확인
- 방식:
  - seed 5개 사용
  - Warm은 학습 작가를 유지하되 평가 행은 제외
  - Cold는 작가를 통째로 제외한 artist-level holdout 사용
  - 각 seed마다 Warm Huber와 Cold LightGBM Quantile을 다시 학습
- 결과:
  - Warm 기준선 평균 MdAPE `0.1716` → 보정 후 `0.1727`
  - Warm 기준선 평균 MAPE `0.3582` → 보정 후 `0.3602`
  - Cold 기준선 평균 MdAPE `0.3276` → 보정 후 `0.3290`
  - Cold 기준선 평균 MAPE `0.6301` → 보정 후 `0.6316`
  - Cold p95_APE는 `2.0126` → `2.0025`로 소폭 개선
- 판단:
  - 원인별 보정/라우팅 후보는 재학습 포함 검증에서 안정적 개선으로 보기 어려움
  - v0.1 기본 정책에 추가하지 않는 것이 적절함

## 5. 현재 채택 판단

- v0.1은 “중간 정책 고정 / 운영 테스트 기준”으로 유지 가능
- Warm은 `PP-SVC3 70:30 결합`을 현재 1순위로 유지
- Cold는 `PP-Y18 LightGBM Quantile + qwidth 구간 보정`을 현재 기준 후보로 유지하되, 서비스에서는 낮은 신뢰도와 넓은 가격 범위로 표시
- 이번 원인별 보정/라우팅 후보는 기본 정책이 아니라 후속 실험 후보로 분리

## 6. 최종 서비스 확정 전 남은 보강

- Warm `PP-SVC3` component chain을 완전한 운영 artifact로 고정
- Warm `PP-SVC3`를 seed별 재학습 또는 추가 holdout으로 재검증
- Cold `PP-Y18`을 모델 재학습 포함 artist-level split으로 추가 재검증
- 신규 0604 데이터는 정합성 검증 후 별도 운영 시뮬레이션 지표로 사용
- 최종 문서에는 “고정 test 성능”, “반복 holdout 성능”, “재학습 포함 검증 성능”을 분리해 표기
