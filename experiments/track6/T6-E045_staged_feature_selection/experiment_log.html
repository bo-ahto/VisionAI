T6-E045 단계적 피처 선택 절차 실험

  • 상위 일지: T6-E038 작품 변수 선정 실험 일지
  • 목적: 작품 관련 피처의 채택 여부를 가설 단위로 검증
  • 상태: 실험 계획 작성 완료, 실행 전

1. 실험 일지

  • 가설: 단계적 피처 선택 방식은 전체 조합 탐색 없이도 기준 모델보다 좋은 피처 조합을 찾을 수 있다.
  • 유의미함 기준: 최종 선택 조합이 기준 모델보다 성능 개선되면 절차 채택
  • 테스트 모델: Warm: Huber / Linear Regression / Ridge, Cold: Huber / Quantile-LAD / LightGBM
  • 확인할 작품 피처: 전체 작품 피처 후보

2. 초기 실험 데이터

  • 기준 원천 파일: data/track6/track6_feature_candidates_name_corrected.csv
  • 학습 입력과 정답 가격은 분리해서 생성한다.
  • 정답 가격은 train_labels.csv, test_warm_labels.csv, test_cold_labels.csv에만 둔다.
  • Warm 학습 피처에는 artist_name_ko를 둘 수 있지만, 이 실험의 판단 대상은 작품 피처다.
  • Cold 테스트에는 작가명을 사용하지 않는다.

3. 초기 실험 테스트: Warm

  • Warm 목적: 전체 조합을 무작정 탐색하지 않고, Warm에서 유효한 작품 피처를 단계적으로 줄여 최종 후보를 찾는다.
  • Warm 시작 기준 피처: artist_name_ko + ln_estimated_ho
  • 1단계: width_cm, height_cm, log_area, aspect_ratio, nant_material_idx, nant_tool, support_category, nant_support, depth_cm, has_depth, is_3d_candidate를 하나씩 추가한다.
  • 2단계: 1단계에서 유효한 피처를 size/material/support/depth 그룹으로 묶어 비교한다.
  • 3단계: 채택 후보 조합에서 피처를 하나씩 제거해 성능 하락 여부를 확인한다.
  • Warm 테스트 데이터: data/test_warm_features.csv + data/test_warm_labels.csv
  • 판단 기준: Warm에서 개선된 피처만 Warm 후보 조합에 남긴다. Cold 결과를 근거로 Warm 피처를 선택하지 않는다.

4. 초기 실험 테스트: Cold

  • Cold 목적: 신규 작가 예측에서 작가명 없이 유효한 작품 피처 조합을 Warm과 별도로 찾는다.
  • Cold 시작 기준 피처: ln_estimated_ho
  • 1단계: Warm과 같은 단일 후보 피처를 하나씩 추가하되 artist_name_ko는 사용하지 않는다.
  • 2단계: Cold에서 개선된 피처만 size/material/support/depth 그룹으로 묶어 비교한다.
  • 3단계: Cold 후보 조합에서 피처를 하나씩 제거해 p95 APE가 악화되는지 확인한다.
  • Cold 테스트 데이터: data/test_cold_features.csv + data/test_cold_labels.csv
  • 제외 피처: artist_name_ko
  • 판단 기준: Cold는 median APE뿐 아니라 p95 APE와 약점 slice 개선을 함께 보고 후보를 남긴다. Warm에서 좋았다는 이유만으로 Cold 피처를 채택하지 않는다.

5. 결과에 대한 기록

  • 결과 파일: outputs/metrics.csv
  • 예측 비교 파일: outputs/predictions.csv
  • 구간별 오차 파일: outputs/slice_metrics.csv
  • 요약 파일: outputs/summary.md
  • 실행 로그: logs/run.log
  • 결론 표기: 채택 / 보류 / 중단

6. 판단 기준

  • Warm과 Cold의 median APE를 각각 확인한다.
  • p95 APE가 줄어드는지 확인해 큰 오차가 줄었는지 본다.
  • Warm에서만 개선되면 Warm 전용 후보로 둔다.
  • Cold에서만 개선되면 Cold 전용 후보로 둔다.
  • 운영에서 입력하기 어려운 변수는 성능이 좋아도 최종 후보에서 제외하거나 보류한다.
