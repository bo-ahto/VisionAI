# Warm 가격 예측 최종 운영 모델 상세 리포트

작성일: 2026-06-10  
대상 모델: 최종 운영 예측가격  
재현 파일 위치: 14장 참고

## 1. 결론 요약

현재 선택된 Warm 운영 예측가격은 독립적으로 처음부터 가격을 예측하는 단일 회귀 모델이 아니라, 미세 보정 전 기준 로그가격 위에 잔차 방향을 한 번 더 확인한 뒤 아주 작은 보정값을 더하는 미세 보정 모델이다.

전체 순서도는 아래와 같다.

```text
[작품 입력 정보]
        |
        v
[기존 Warm 예측가격들의 로그가격 준비]
        |
        v
[미세 보정 전 기준 로그가격 생성]
  - 선행 균형 기준 로그가격
  - 방향 조건부 잔차 보정
  - p95 방어형/개선형 보조 예측가격 이동분
        |
        v
[최종 보정 신호 계산]
  - 미세 보정 전 기준 대비 상향확률
  - Huber 잔차 예측값
  - 예측 불확실성 및 row 위험도
        |
        v
[보정 적용 여부 판단]
  - 방향이 일치하는가?
  - 방향 확신도가 충분한가?
  - row별 보정 상한 안에 있는가?
        |
        v
[최종 Warm 로그가격]
        |
        v
[최종 Warm 가격 = exp(최종 Warm 로그가격)]
```

최종 운영 예측가격의 성능은 기존 고정 테스트셋 607건 기준으로 다음과 같다.

| 예측가격 | MdAPE | MAPE | p95 APE | RMSE log |
|---|---:|---:|---:|---:|
| Huber 계수 기반 안정 기준 예측가격 | 0.138803 | 0.272989 | 0.806366 | 0.398822 |
| 기존 Warm 최고 기준 예측가격 | 0.137878 | 0.270564 | 0.807499 | 0.397991 |
| 미세 보정 전 기준 예측가격 | 0.140975 | 0.269889 | 0.807324 | 0.397454 |
| 최종 운영 예측가격 | 0.140976 | 0.269888 | 0.807325 | 0.397454 |

최종 운영 예측가격은 미세 보정 전 기준 예측가격 대비 MAPE를 `0.0000005351` 낮췄고, repeated p95 win rate는 `0.788782`로 유지했다. p95 APE는 미세 보정 전 기준 예측가격보다 `0.0000002207` 높지만, 전체 MAPE와 replacement score가 개선되어 운영 1순위로 둔다.

## 1.1 용어 정리

| 용어 | 뜻 |
|---|---|
| 로그가격 | 가격에 자연로그 `log()`를 적용한 값. 모델 내부 계산은 대부분 로그가격에서 수행한다 |
| 최종 가격 | 최종 로그가격에 지수함수 `exp()`를 적용해 원 가격 단위로 되돌린 값 |
| p95 APE | absolute percentage error의 95퍼센타일 값. 상위 5% 큰 오차를 보는 지표 |
| RMSE log | 로그가격 기준 root mean squared error. 로그가격 오차의 평균제곱근 |
| repeated win rate | 반복 validation split에서 기준 예측가격보다 더 좋은 결과가 나온 비율 |
| replacement score | 기존 운영 예측가격을 새 예측가격으로 대체할 때 MAPE, p95 APE, 반복 안정성을 함께 반영한 내부 종합 점수 |
| row | 작품 1건에 해당하는 데이터 행 |
| out-of-fold | 학습에 쓰지 않은 fold에서 만든 검증 예측값 |

## 2. 모델 성격

이 모델은 가격을 크게 새로 산출하는 모델이 아니라 보수적인 로그가격 보정층이다.

- 가격을 원 단위에서 직접 보정하지 않고 로그가격에서 보정한다.
- 보정값은 잔차 방향이 맞는 경우에만 적용한다.
- 보정값은 Huber robust regression으로 예측한 잔차를 기반으로 한다.
- 최종 운영 예측가격의 마지막 미세 보정 단계에서 사용하는 양수 방향 기본 상한은 로그가격 기준 `0.00005`다.
- 이 `0.00005`는 전체 Warm 기준 예측가격을 처음 만들 때의 상한이 아니라, 이미 만들어진 `미세보정전_기준로그가격` 위에 마지막으로 한 번 더 적용하는 추가 보정 상한이다.
- 앞단의 `미세 보정 전 기준 로그가격 생성` 단계는 별도 상한을 사용한다. 가격을 올리는 방향은 `0.00010`, 가격을 내리는 방향은 `0.00007`이다.
- 최종 추가 보정 상한 `0.00005`는 가격 비율로 약 `exp(0.00005) - 1`, 즉 약 `0.005%` 수준이다.
- 확인 위치: `미세 보정 전 기준 로그가격 생성` 단계에서 `0.00010`/`0.00007`, `최종 운영 예측가격 산출` 및 `보정 상한 계산` 단계에서 `0.00005`를 확인할 수 있다.

따라서 최종 운영 예측가격은 “큰 성능 변화를 노리는 새 모델”이 아니라, 이미 안정화된 미세 보정 전 기준 예측가격을 거의 유지하면서 일부 row의 잔차 방향만 미세 조정하는 모델이다.

### 2.1 단계별 사용 모델과 적용 위치

이 Warm 운영 예측가격은 여러 모델을 한 번에 섞어 직접 예측하는 구조가 아니다. 선행 예측가격을 만든 뒤, 그 예측가격 위에 방향 확인, 잔차 보정, 불확실성 기반 상한 제한을 순차적으로 적용한다.

| 순서 | 단계 | 사용 모델 또는 방법 | 적용 방식 | 최종 운영 예측가격에서의 역할 |
|---:|---|---|---|---|
| 1 | 안정 기준 로그가격 생성 | Huber 계수 기반 안정 기준 모델 | 작품/유사작품 기반 피처로 안정적인 기준 로그가격 `hcoef_stable` 생성 | 가격대 구간, 구성 예측 분산, 신뢰도 판단의 출발점 |
| 2 | 예측 불확실성 생성 | 선행 quantile 예측 | 상위 분위 로그가격과 하위 분위 로그가격의 차이로 `quantile_width` 생성 | 최종 가격을 직접 만들지는 않고, 보정 강도와 상한을 줄이는 위험 신호로 사용 |
| 3 | 미세 보정 전 기준 예측가격 생성 | 히스토그램 기반 그래디언트 부스팅 방향 분류기 + Huber 잔차 회귀 + p95 보조 예측가격 이동 | 선행 균형 기준 예측가격 위에 방향이 맞는 잔차 보정과 p95 방어/개선 이동분을 아주 작게 더함 | 최종 운영 예측가격의 직접 기준값 생성 |
| 4 | 최종 운영 예측가격 생성 | 히스토그램 기반 그래디언트 부스팅 방향 분류기 + Huber 잔차 회귀 | 미세 보정 전 기준 예측가격 대비 상향확률과 잔차를 다시 계산하고, 방향이 일치할 때만 `0.025 * 잔차` 수준으로 추가 보정 | 최종 선택된 운영 예측가격 산출 |
| 5 | 보정 상한 제한 | quantile width 순위 + row 위험도 | `quantile_width`가 크거나 row 위험도가 높으면 보정 상한을 줄임 | p95 악화 방지 및 불안정 row 방어 |
| 6 | 비교 실험 후보 | CatBoost, LightGBM, XGBoost, Ridge, 추가 Huber 계열 | 이전 실험군에서 방향 분류 또는 잔차 보정 후보로 테스트 | 최종 선택 경로에는 CatBoost/LightGBM/XGBoost가 직접 들어가지 않음 |

정리하면, 현재 선택된 최종 운영 예측가격의 직접 산식에 들어간 핵심 모델은 `히스토그램 기반 그래디언트 부스팅 방향 분류기`와 `Huber 잔차 회귀`다. `quantile`은 가격을 직접 예측하는 마지막 모델이 아니라, 예측 구간 폭을 통해 보정 상한을 줄이는 불확실성 제어 장치로 쓰인다. `CatBoost`는 이전 후보군에서 테스트됐지만 아래 이유로 최종 선택된 계산 경로에는 포함하지 않았다.

#### CatBoost를 최종 경로에서 제외한 이유

CatBoost는 시도하지 않은 모델이 아니다. 이전 후보군에서 다음 두 방식으로 테스트했다.

| 테스트 방식 | 설명 |
|---|---|
| 방향 분류 후보 | CatBoost 분류기로 기준 예측가격이 실제보다 낮게 잡혔는지, 높게 잡혔는지의 방향 확률을 계산한 뒤 방향이 맞을 때만 보정 |
| 잔차 보정 후보 | CatBoost 회귀기로 기준 로그가격 대비 잔차를 예측한 뒤 불확실성 상한 안에서 보정 |

최종 선택에서 CatBoost를 제외한 이유는 성능이 전혀 나빠서가 아니라, 최종 운영 조건인 `MAPE`, `p95 APE`, 반복 안정성, replacement score를 동시에 가장 잘 만족하지 못했기 때문이다. 아래 비교에서 replacement score는 낮을수록 기존 최고 기준 예측가격을 대체하기에 유리한 내부 점수다.

| 비교 후보 | fixed test MAPE | fixed test p95 APE | replacement/recommendation score | 판단 |
|---|---:|---:|---:|---|
| 선택된 히스토그램 기반 방향 분류 + Huber 잔차 경로 | 0.269889 | 0.807324 | -0.001396 | MAPE와 p95 방어, 대체 점수의 균형이 가장 좋음 |
| CatBoost 방향 분류 후보 중 MAPE 우수 후보 | 0.269889 | 0.807326 | -0.001387 | MAPE는 거의 같지만 p95 APE와 대체 점수가 약함 |
| CatBoost 잔차 보정 후보 중 p95 우수 후보 | 0.269901 | 0.807320 | -0.001384 | p95 APE는 소폭 좋지만 MAPE와 대체 점수가 악화됨 |

따라서 CatBoost는 특정 지표나 특정 구간에서는 장점이 있었지만, 최종 운영 후보가 요구한 “평균 오차를 유지하면서 큰 오차 구간도 방어하는 보수적 미세 보정층”에는 선택된 `히스토그램 기반 방향 분류 + Huber 잔차` 조합보다 적합하지 않았다. 최종 경로는 성능이 가장 크게 튀는 후보가 아니라, 기존 Warm 최고 기준 예측가격을 안정적으로 대체할 수 있는 후보를 선택한 결과다.

## 3. 사용 데이터와 재현 기준

이 모델은 제출용 고신뢰 100건 실험을 사용하지 않았다. 기존 Warm 실험과 같은 기준으로 비교했다.

| 구분 | 내용 |
|---|---|
| 학습 및 검증 기준 | 기존 Warm validation out-of-fold 519건 |
| 최종 비교 기준 | 기존 Warm fixed test 607건 |
| 제출용 데이터 사용 여부 | 사용하지 않음 |
| 실험 산출값 수 | 1,610개 |
| 선택 기준 | MAPE, p95 APE, repeated validation 안정성, replacement score |

여기서 `out-of-fold`는 validation 데이터를 여러 fold로 나눠, 각 fold의 예측값은 해당 fold를 학습에 쓰지 않은 모델로 만든다는 뜻이다. 이 방식은 validation 내부에서 발생할 수 있는 과적합을 줄이기 위한 장치다.

## 4. 직접 입력 피처

최종 미세 보정층이 직접 사용하는 피처는 “작품 원본 메타데이터 전체”가 아니다. 실제 입력은 아래 네 계층으로 구성된다.

```text
원천 row 값
  -> 기존 Warm 예측가격 로그가격과 불확실성 요약값 생성
  -> 가격대/신뢰도/구간 파생 피처 생성
  -> 미세 보정 전 기준 예측가격과 보조 예측가격 간 차이 및 row 위험도 생성
  -> 방향 분류 모델과 Huber 잔차 모델의 입력 피처로 사용
```

중요한 점은 최종 미세 보정층에는 `artist_key`, 작가 생년, 갤러리명 같은 원본 작가 메타 컬럼이 직접 들어가지 않는다는 것이다. 다만 이 정보들은 상위의 기존 Warm 예측가격 생성 과정에서 이미 반영되었을 수 있다. 최종 미세 보정층은 그 결과로 만들어진 기준 로그가격과 불확실성 요약값을 받아 미세 보정한다.

### 4.1 입력 피처 전체 lineage

| 최종 입력 피처 | 원천 row 데이터 또는 선행 예측값 | 생성 방식 | 최종 미세 보정층 안에서의 역할 |
|---|---|---|---|
| `stable_price_band` | `hcoef_stable` | `hcoef_stable` 로그가격을 4개 가격대로 구간화 | 가격대별로 잔차 방향과 보조 예측가격 이동 신뢰도를 다르게 학습 |
| `confidence_tier` | `quantile_width`, `component_prediction_spread`, `l10_price_range_ratio`, `svc_group_n`, `current_vs_stable_gap_abs` | 고신뢰/저신뢰 조건을 적용해 high/medium/low로 분류 | 신뢰도 구간별 보정 적용 여부와 방향 확률 학습 |
| `qwidth_band` | `quantile_width` | 예측 구간 폭 순위를 4분위로 나눔 | 예측 불확실성 폭 구간을 범주형 피처로 제공 |
| `medium_support_bucket` | `medium_category`, `support_category` | 두 값을 `medium__support` 형태로 결합 | 매체/지지체 조합별 잔차 패턴 학습 |
| `svc_group_n_band` | `svc_group_n` | 유사작품 수를 5개 표본 수 구간으로 구간화 | 유사작품 표본 수별 안정성 차이를 학습 |
| `area_bin` | `area_cm2` 또는 `log_area` | 작품 면적 로그값을 validation 분위 기준으로 4구간화 | 작품 크기 구간별 잔차 패턴 학습 |
| `quantile_width` | 선행 quantile 예측 | 상위/하위 예측 분위의 로그 폭 | 불확실성 크기를 수치형으로 제공하고 보정 상한 축소에 사용 |
| `l10_price_range_ratio` | 유사작품 10개 기반 가격 통계 | 유사작품 가격 범위 / 중심 가격 계열 비율 | 유사작품 가격 분산이 큰 row의 위험도 반영 |
| `svc_group_n` | 유사작품 그룹 산출 결과 | 같은 유사작품 그룹에 포함된 표본 수 | 표본 수가 적은 row의 불확실성 반영 |
| `component_prediction_spread` | `hcoef_stable`, `current_70_30`, `ppv8_service_proxy`, `svc_numeric_seed_mean`, `l10_seq_pred_log` | 다섯 예측 로그가격의 표준편차 | 내부 예측가격 간 불일치 정도 반영 |
| `current_vs_stable_gap_abs` | `current_70_30`, `hcoef_stable` | `abs(current_70_30 - hcoef_stable)` | 기존 운영 예측가격과 안정 기준 예측가격의 괴리 반영 |
| `gap_operational_abs` | 안정성 우선 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(안정성우선_보조로그가격 - 미세보정전_기준로그가격)` | 안정성 우선 보조 예측가격이 기준 예측가격과 얼마나 다른지 |
| `gap_mape_abs` | 안정성 우선 보조 예측가격, 미세 보정 전 기준 예측가격 | 현재 구현에서는 `gap_operational_abs`와 동일하게 들어감 | 선행 feature builder 호환용. 운영 기준과의 차이 신호로 쓰임 |
| `gap_guarded_abs` | p95 방어형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95방어형_보조로그가격 - 미세보정전_기준로그가격)` | p95 방어형 보조 예측가격과 기준 예측가격의 차이 |
| `gap_recovery_abs` | p95 개선형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95개선형_보조로그가격 - 미세보정전_기준로그가격)` | p95 개선형 보조 예측가격과 기준 예측가격의 차이 |
| `row_risk_operational` | 미세 보정 전 기준 예측가격, 안정성 우선 보조 예측가격, 불확실성 피처 | 두 예측가격 간 이동이 위험한 정도를 0~1로 요약 | 보정 상한 축소 및 방향 모델 학습 |
| `row_risk_guarded` | 미세 보정 전 기준 예측가격, p95 방어형 보조 예측가격, 불확실성 피처 | p95 방어형 보조 예측가격 쪽으로 이동할 때의 위험도 | p95 방어 이동이 불안정한 row 식별 |
| `row_risk_recovery` | 미세 보정 전 기준 예측가격, p95 개선형 보조 예측가격, 불확실성 피처 | p95 개선형 보조 예측가격 쪽으로 이동할 때의 위험도 | p95 개선 이동이 불안정한 row 식별 |
| `pp246_minus_pp234_abs` | 미세 보정 전 기준 예측가격, 선행 균형 기준 예측가격 | 현재 최종 미세 보정 단계에서는 `abs(미세보정전_기준로그가격 - 선행_균형기준로그가격)` | 선행 기준 대비 미세 보정 전 기준이 얼마나 움직였는지 |
| `p95_recovery_delta_abs` | p95 개선형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95개선형_보조로그가격 - 미세보정전_기준로그가격)` | p95 개선형 보조 예측가격의 이동 폭 |
| `operational_delta_abs` | 안정성 우선 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(안정성우선_보조로그가격 - 미세보정전_기준로그가격)` | 안정성 우선 보조 예측가격의 이동 폭 |
| `p95_guarded_delta_abs` | p95 방어형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95방어형_보조로그가격 - 미세보정전_기준로그가격)` | p95 방어형 보조 예측가격의 이동 폭 |
| `p95_extreme_delta_abs` | p95 강화 방어형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95강화방어형_보조로그가격 - 미세보정전_기준로그가격)` | p95 강화 방어형 보조 예측가격의 이동 폭 |
| `pp246_log_centered` | 미세 보정 전 기준 예측가격 | `미세보정전_기준로그가격 - median(미세보정전_기준로그가격)` | 기준 가격 수준을 중앙값 대비 상대값으로 제공 |
| `qwidth_rank` | `quantile_width` | 0~1 순위값 | 불확실성 폭을 연속 순위로 제공 |
| `component_spread_rank` | `component_prediction_spread` | 0~1 순위값 | 내부 예측가격 간 불일치 수준을 연속 순위로 제공 |
| `model_gap_rank` | p95 개선형 보조 예측가격, 미세 보정 전 기준 예측가격 | `abs(p95개선형_보조로그가격 - 미세보정전_기준로그가격)`의 0~1 순위값 | 보조 예측가격과 기준 예측가격의 차이가 큰 row 식별 |

주의할 점은 `pp246_minus_pp234_abs`, `pp246_log_centered` 같은 실제 컬럼명이 과거 실험의 이름을 유지하고 있다는 점이다. 이 문서에서는 해당 컬럼을 내부 ID가 아니라 현재 기능 기준으로 설명한다.

### 4.2 원천값과 선행 예측 로그가격

최종 미세 보정층에 들어가는 파생 피처는 아래 원천값에서 출발한다.

| 원천값 | 설명 |
|---|---|
| `hcoef_stable` | Huber 계수 기반 안정 기준 로그가격 |
| `current_70_30` | 기존 Warm 70:30 조합 로그가격 |
| `ppv8_service_proxy` | 안정 블렌드 계열 보조 로그가격. 내부 추적명은 PPV8 계열이다 |
| `svc_numeric_seed_mean` | 유사작품 통계 기반 로그가격 |
| `l10_seq_pred_log` | 유사작품 10개 기반 순차 보정 계열 로그가격 |
| `quantile_width` | 예측 상하위 분위 로그가격 폭 |
| `l10_price_range_ratio` | 유사작품 10개 기준 가격 범위 비율 |
| `svc_group_n` | 유사작품 그룹 표본 수 |
| `medium_category` | 작품 매체 분류 |
| `support_category` | 작품 지지체 분류 |
| `area_cm2`, `log_area` | 작품 면적 및 로그 면적 |

다섯 개 선행 로그가격은 구성 모델 간 불일치 피처를 만든다.

```text
구성예측로그가격들 =
  [
    hcoef_stable,
    current_70_30,
    ppv8_service_proxy,
    svc_numeric_seed_mean,
    l10_seq_pred_log
  ]

component_prediction_spread = std(구성예측로그가격들)
component_prediction_range  = max(구성예측로그가격들) - min(구성예측로그가격들)
current_vs_stable_gap_abs   = abs(current_70_30 - hcoef_stable)
```

### 4.3 범주형 파생 피처

#### 안정 기준 가격대

`stable_price_band`는 실제 낙찰가나 실제 판매가를 보지 않고, Huber 계수 기반 안정 기준 모델의 로그가격인 `hcoef_stable`만 사용해 만든다.

```text
안정기준로그가격 = hcoef_stable

stable_price_band =
  "low_price"        if 안정기준로그가격 <= 13.0
  "mid_price"        if 13.0 < 안정기준로그가격 <= 14.5
  "high_price"       if 14.5 < 안정기준로그가격 <= 16.0
  "very_high_price"  if 16.0 < 안정기준로그가격
```

즉, 이 컬럼은 “실제 가격대”가 아니라 “안정 기준 모델이 예측한 로그가격대”다. 운영 시 실제 정답 가격 없이도 계산 가능하다.

#### 예측 신뢰 구간

`confidence_tier`는 다섯 개 row 단위 위험 신호로 만든다.

| 위험 신호 | 원천 컬럼 | 의미 |
|---|---|---|
| 예측 구간 폭 | `quantile_width` | 예측 가격 구간이 넓을수록 불확실성이 높음 |
| 구성 모델 예측 분산 | `component_prediction_spread` | 내부 예측가격들의 로그가격이 서로 많이 다르면 불확실성이 높음 |
| 유사작품 10개 기준 가격 범위 비율 | `l10_price_range_ratio` | 유사작품 가격 분포가 넓으면 불확실성이 높음 |
| 유사작품 그룹 수 | `svc_group_n` | 유사작품 수가 적으면 불확실성이 높음 |
| 현재 예측과 안정 기준 예측의 차이 | `current_vs_stable_gap_abs` | `abs(current_70_30 - hcoef_stable)` 값. 두 기준 예측이 크게 다르면 불확실성이 높음 |

고신뢰 조건은 다섯 조건을 모두 만족해야 한다.

```text
high_confidence =
  quantile_width <= 1.20
  and component_prediction_spread <= 0.10
  and l10_price_range_ratio <= 2.00
  and svc_group_n >= 5
  and current_vs_stable_gap_abs <= 0.025
```

저신뢰 조건은 다섯 조건 중 하나라도 걸리면 해당한다.

```text
low_confidence =
  quantile_width > 1.60
  or component_prediction_spread > 0.18
  or l10_price_range_ratio > 2.50
  or svc_group_n < 5
  or current_vs_stable_gap_abs > 0.050
```

둘 다 아니면 중신뢰로 둔다.

```text
confidence_tier =
  "high_confidence"    if high_confidence
  "low_confidence"     if low_confidence
  "medium_confidence"  otherwise
```

같은 위험 신호를 연속형 점수로도 계산한다. 이 값은 row 위험도 계산과 보정 상한 축소의 기반 신호로 쓰인다.

```text
confidence_risk_score
  = (
      clip(quantile_width, 0, 3.0) / 3.0
      + clip(component_prediction_spread, 0, 0.4) / 0.4
      + clip(l10_price_range_ratio, 0, 5.0) / 5.0
      + clip(current_vs_stable_gap_abs, 0, 0.12) / 0.12
      + clip(1 / (svc_group_n + 1), 0, 1)
    ) / 5
```

#### 예측 구간 폭 구간

`qwidth_band`는 `quantile_width`를 validation 기준 순위로 나눠 만든 4분위 구간이다.

```text
qwidth_rank_order = rank(quantile_width)
qwidth_band = q1, q2, q3, q4
```

`q1`은 상대적으로 예측 구간 폭이 작은 구간이고, `q4`는 예측 구간 폭이 큰 구간이다.

#### 유사작품 그룹 수 구간

`svc_group_n_band`는 `svc_group_n`을 아래 기준으로 나눈다.

```text
svc_group_n_band =
  "n_0_4"     if 0 <= svc_group_n <= 4
  "n_5_9"     if 5 <= svc_group_n <= 9
  "n_10_19"   if 10 <= svc_group_n <= 19
  "n_20_49"   if 20 <= svc_group_n <= 49
  "n_50_plus" if 50 <= svc_group_n
```

#### 작품 면적 구간

`area_bin`은 `log_area`를 validation 데이터의 25%, 50%, 75% 분위 기준으로 나눈 구간이다.

```text
log_area = log(area_cm2)

area_bin =
  0  if log_area <= validation_25_percentile
  1  if validation_25_percentile < log_area <= validation_50_percentile
  2  if validation_50_percentile < log_area <= validation_75_percentile
  3  if validation_75_percentile < log_area
```

분위값을 안정적으로 만들 수 없는 경우에는 fallback으로 `[-inf, 3.5, 4.5, 5.5, inf]` 기준을 사용한다.

#### 매체와 지지체 그룹

`medium_support_bucket`은 작품의 매체 분류와 지지체 분류를 결합한 문자열이다.

```text
medium_support_bucket = medium_category + "__" + support_category
```

예시는 다음과 같다.

```text
oil__canvas
other__paper
acrylic__canvas
```

원천 데이터에 이미 `medium_support_bucket`이 있으면 그 값을 사용하고, 없을 때는 `medium_category`와 `support_category`를 결합해 생성한다. 결측은 `__MISSING__` 또는 `missing`으로 처리한다.

### 4.4 미세 보정 전 기준 예측가격과 보조 예측가격의 차이 피처

최종 미세 보정층은 미세 보정 전 기준 예측가격 위에서 보정한다. 따라서 최종 보정층의 핵심 피처는 “미세 보정 전 기준 예측가격이 안정성 우선 보조 예측가격, p95 방어형 보조 예측가격, p95 개선형 보조 예측가격과 얼마나 다른가”다.

```text
미세보정전_기준로그가격 = 미세 보정 전 기준 예측가격의 로그가격

안정성우선_이동폭 = abs(안정성 우선 보조 예측가격의 로그가격 - 미세보정전_기준로그가격)
p95방어형_이동폭 = abs(p95 방어형 보조 예측가격의 로그가격 - 미세보정전_기준로그가격)
p95개선형_이동폭 = abs(p95 개선형 보조 예측가격의 로그가격 - 미세보정전_기준로그가격)
p95강화방어형_이동폭 = abs(p95 강화 방어형 보조 예측가격의 로그가격 - 미세보정전_기준로그가격)
선행기준대비_이동폭 = abs(미세 보정 전 기준 예측가격의 로그가격 - 선행 균형 기준 예측가격의 로그가격)
```

이 값들이 큰 row는 내부 예측가격들이 서로 다른 판단을 내린 row다. 이런 row는 보정이 도움이 될 수도 있지만, 잘못 움직이면 p95 오차를 키울 위험도 있다. 그래서 방향 분류 모델에는 이 차이값을 넣고, 최종 보정 상한 계산에는 row 위험도를 함께 사용한다.

### 4.5 row 위험도 피처

row 위험도는 특정 예측가격 쪽으로 이동할 때 불안정할 가능성을 0~1 범위로 요약한 값이다. 내부 함수는 아래 성격의 신호를 함께 본다.

| 위험도 구성 신호 | 의미 |
|---|---|
| `quantile_width` 순위 | 예측 구간 폭이 클수록 위험 |
| `l10_price_range_ratio` 순위 | 유사작품 가격 분포가 넓을수록 위험 |
| `component_prediction_spread` 순위 | 구성 모델 예측이 갈라질수록 위험 |
| `current_vs_stable_gap_abs` 순위 | 기존 조합과 안정 기준 차이가 클수록 위험 |
| 예측가격 간 로그가격 차이 | 기준 예측가격과 이동 대상 예측가격의 차이가 클수록 위험 |
| `svc_group_n` 부족도 | 유사작품 수가 적을수록 위험 |
| `confidence_tier` | `low_confidence`이면 위험 가산 |

개념식은 다음과 같다.

```text
row위험도
  = weighted_sum(
      quantile_width_rank,
      l10_price_range_ratio_rank,
      component_prediction_spread_rank,
      current_vs_stable_gap_rank,
      candidate_gap_rank,
      low_sample_score,
      low_confidence_flag
    )

row위험도 = clip(row위험도, 0, 1)
```

최종 미세 보정에서는 이 row 위험도가 클수록 적용 가능한 보정 상한이 줄어든다.

### 4.6 실제 모델 입력 행 예시

실제 feature detail 파일에는 각 작품 row별로 아래와 같은 형태가 저장된다.

```text
eval_split, _track6_row_id,
stable_price_band, confidence_tier, qwidth_band,
medium_support_bucket, svc_group_n_band, area_bin,
pp246_log, pp252_log, pp252_stability_log,

```

이 중 `prob_hist35_pp252`는 “미세 보정 전 기준 예측가격보다 실제 가격이 더 높을 확률”이고, `resid_huber_pp252`는 “미세 보정 전 기준 예측가격 대비 잔차 예측값”이다. 실제 컬럼명에는 내부 ID가 남아 있지만, 최종 미세 보정층은 이 둘을 사용해 최종 적용 보정값을 계산한다.

## 5. 학습 대상

모델은 두 가지를 학습한다.

1. 기준 로그가격이 실제 가격보다 낮은지 높은지의 방향
2. 기준 로그가격에 아직 남아 있는 잔차의 크기

기준 로그가격을 `기준_로그가격`이라고 하면 validation 데이터에서 잔차는 다음과 같이 정의한다.

```text
실제_로그가격 = log(실제_가격)

잔차 = 실제_로그가격 - 기준_로그가격
```

잔차가 양수이면 기준 예측이 실제보다 낮았다는 뜻이다. 이 경우 가격을 올리는 방향이 맞다. 잔차가 음수이면 기준 예측이 실제보다 높았다는 뜻이고, 가격을 낮추는 방향이 맞다.

방향 분류 라벨은 다음과 같다.

```text
방향라벨 = 1  if 잔차 > 0
방향라벨 = 0  if 잔차 <= 0
```

## 6. 미세 보정 전 기준 로그가격 생성

최종 미세 보정의 직접 기준값은 미세 보정 전 기준 예측가격의 로그가격이다. 이 기준 예측가격은 선행 균형 기준 예측가격 위에 방향 조건부 잔차 보정과 p95 방어형/개선형 보조 예측가격의 이동분을 결합해 만든다.

문서용 변수명은 아래와 같이 둔다.

| 변수 | 의미 |
|---|---|
| `선행_균형기준로그가격` | 선행 균형 기준 예측가격의 로그가격 |
| `선행기준_상향확률` | 선행 균형 기준 예측가격보다 실제 가격이 더 높을 확률 |
| `선행기준_잔차예측` | Huber robust regression이 예측한 선행 균형 기준 예측가격 대비 잔차 |
| `선행기준_p95방어형이동` | p95 방어형 보조 예측가격의 로그가격 - 선행 균형 기준 예측가격의 로그가격 |
| `선행기준_p95개선형이동` | p95 개선형 보조 예측가격의 로그가격 - 선행 균형 기준 예측가격의 로그가격 |

미세 보정 전 기준 예측가격을 만들 때의 방향 확신도는 다음과 같이 계산한다.

```text
선행기준_방향확신도 = abs(선행기준_상향확률 - 0.5) * 2

선행기준_적용확신도
  = clip((선행기준_방향확신도 - 0.14) / (1 - 0.14), 0, 1)
```

상향확률이 0.5에 가까우면 방향을 잘 모르는 상태다. 이때 적용확신도는 0에 가까워져 보정이 거의 적용되지 않는다.

방향 일치 여부는 다음과 같이 계산한다.

```text
선행기준_예상방향 = +1  if 선행기준_상향확률 >= 0.5
선행기준_예상방향 = -1  if 선행기준_상향확률 < 0.5

선행기준_잔차방향일치 = 1  if sign(선행기준_잔차예측) == 선행기준_예상방향
선행기준_잔차방향일치 = 0  otherwise

선행기준_p95방어형방향일치 = 1  if sign(선행기준_p95방어형이동) == 선행기준_예상방향
선행기준_p95방어형방향일치 = 0  otherwise

선행기준_p95개선형방향일치 = 1  if sign(선행기준_p95개선형이동) == 선행기준_예상방향
선행기준_p95개선형방향일치 = 0  otherwise
```

미세 보정 전 기준 예측가격의 원시 보정값은 다음이다.

```text
미세보정전_원시보정
  = 0.05 * 선행기준_잔차예측 * 선행기준_잔차방향일치 * 선행기준_적용확신도
  + 0.04 * 선행기준_p95방어형이동 * 선행기준_p95방어형방향일치 * 선행기준_적용확신도
  + 0.02 * 선행기준_p95개선형이동 * 선행기준_p95개선형방향일치 * 선행기준_적용확신도
```

미세 보정 전 기준 예측가격은 보정값을 그대로 더하지 않고 row별 상한을 적용한다.

```text
미세보정전_방향별기본상한
  = 0.00010   if 미세보정전_원시보정 >= 0
  = 0.00007   if 미세보정전_원시보정 < 0

미세보정전_적용상한
  = clip(
      미세보정전_방향별기본상한
      * (1 - 0.50 * 불확실성순위)
      * (1 - 0.75 * row위험도),
      0.000006,
      미세보정전_방향별기본상한
    )

미세보정전_적용보정 = clip(미세보정전_원시보정, -미세보정전_적용상한, +미세보정전_적용상한)

미세보정전_기준로그가격 = 선행_균형기준로그가격 + 미세보정전_적용보정
```

미세 보정 전 기준 예측가격의 역할은 선행 균형 기준 예측가격보다 MAPE와 p95 안정성을 동시에 높인 기준 로그가격을 만드는 것이다.

## 7. 최종 운영 예측가격 산출

최종 운영 예측가격은 미세 보정 전 기준 로그가격에서 다시 시작한다.

최종 운영 예측가격의 계산 순서도는 다음과 같다.

```text
[미세보정전_기준로그가격]
        |
        +--> [방향 분류 모델]
        |       |
        |       v
        |   미세보정전_상향확률
        |       |
        |       v
        |   최종보정_적용확신도
        |
        +--> [Huber 잔차 모델]
        |       |
        |       v
        |   미세보정전_잔차예측
        |
        v
[방향 일치 여부 확인]
        |
        v
[최종보정_원시값 계산]
        |
        v
[불확실성순위와 row위험도로 보정 상한 축소]
        |
        v
[최종보정_적용값]
        |
        v
[최종로그가격 = 미세보정전_기준로그가격 + 최종보정_적용값]
        |
        v
[최종가격 = exp(최종로그가격)]
```

문서용 변수명은 아래와 같다.

| 변수 | 의미 |
|---|---|
| `미세보정전_기준로그가격` | 미세 보정 전 기준 예측가격의 로그가격 |
| `미세보정전_상향확률` | 미세 보정 전 기준 예측가격보다 실제 가격이 더 높을 확률 |
| `미세보정전_잔차예측` | Huber robust regression이 예측한 미세 보정 전 기준 예측가격 대비 잔차 |
| `안정성우선_보조이동` | 안정성 우선 보조 예측가격의 로그가격 - 미세 보정 전 기준 예측가격의 로그가격 |
| `최종로그가격` | 선택된 Warm 모델의 최종 로그가격 |
| `최종가격` | `exp(최종로그가격)`으로 환산한 가격 |

최종 운영 예측가격 산출에 쓰는 파라미터는 다음이다.

| 항목 | 값 |
|---|---:|
| 방향 확신도 임계값 | 0.12 |
| Huber 잔차 보정 강도 | 0.025 |
| 안정성 우선 보조 예측가격 이동 강도 | 0.000 |
| 양수 방향 기본 상한 | 0.00005 |
| 음수 방향 기본 상한 | 0.000035 |
| 불확실성 축소 강도 | 0.55 |
| row 위험도 축소 강도 | 0.80 |
| 최소 적용 상한 | 0.000006 |

선택된 설정에서는 안정성 우선 보조 예측가격으로 이동하는 강도가 `0.000`이다. 즉, 최종 운영 예측가격은 안정성 우선 보조 예측가격 쪽으로 이동하지 않고, 미세 보정 전 기준 예측가격 대비 Huber 잔차 보정만 사용한다.

### 7.1 방향 확률

방향 분류 모델은 히스토그램 기반 그래디언트 부스팅 분류기다.

```text
입력 피처 = 가격대, 신뢰도, 예측 구간 폭, 매체/지지체, 유사작품 수,
          작품 면적, 예측가격 간 로그가격 차이, row 위험도 등

학습 라벨 = 1 if 실제_로그가격 - 미세보정전_기준로그가격 > 0 else 0

미세보정전_상향확률 = 방향 분류 모델이 예측한 class 1 확률
```

확신도는 다음과 같이 계산한다.

```text
최종보정_방향확신도 = abs(미세보정전_상향확률 - 0.5) * 2

최종보정_적용확신도
  = clip((최종보정_방향확신도 - 0.12) / (1 - 0.12), 0, 1)
```

예를 들어 상향확률이 `0.5`에 가까우면 가격을 올릴지 내릴지 불명확하므로 적용확신도는 0이 된다. 상향확률이 0이나 1에 가까울수록 적용확신도는 커진다.

### 7.2 잔차 예측

잔차 예측 모델은 Huber robust regression이다. Huber 방식은 일반적인 선형 회귀보다 큰 이상치의 영향을 덜 받는다. Warm 가격 데이터는 일부 고가 작품이나 특이 작품이 오차를 크게 만들 수 있으므로, 잔차 보정에는 Huber 방식이 적합했다.

```text
미세보정전_잔차예측 = Huber robust regression(
  target = 실제_로그가격 - 미세보정전_기준로그가격,
  features = 미세 보정 전 기준 예측가격에서 파생한 feature set
)
```

### 7.3 방향 일치 조건

잔차 예측값이 방향 분류 모델이 예상한 방향과 같을 때만 보정을 적용한다.

```text
최종보정_예상방향 = +1  if 미세보정전_상향확률 >= 0.5
최종보정_예상방향 = -1  if 미세보정전_상향확률 < 0.5

최종보정_잔차방향일치 = 1  if sign(미세보정전_잔차예측) == 최종보정_예상방향
최종보정_잔차방향일치 = 0  otherwise
```

이 조건 때문에 잔차 회귀 모델이 가격을 올리라고 하더라도 방향 분류 모델이 가격을 내려야 한다고 판단하면 해당 row는 보정되지 않는다.

### 7.4 원시 보정값

최종 운영 예측가격을 만들기 위한 원시 보정값은 다음이다.

```text
최종보정_원시값
  = 0.025
    * 미세보정전_잔차예측
    * 최종보정_잔차방향일치
    * 최종보정_적용확신도
```

실험 산출값 생성 단계에는 안정성 우선 보조 예측가격 이동분도 있었지만, 선택된 설정에서는 안정성 우선 보조 예측가격 이동 강도가 0이다.

```text
안정성우선_이동보정
  = 0.000
    * 안정성우선_보조이동
    * 안정성우선_보조방향일치
    * 최종보정_적용확신도
  = 0
```

따라서 최종 운영 예측가격의 실질 보정은 Huber 잔차 기반 연속 미세 보정 하나다.

## 8. 보정 상한 계산

최종 운영 예측가격은 원시 보정값을 그대로 쓰지 않고 row별 상한을 적용한다. 상한은 보정 방향, 예측 불확실성, row 위험도에 따라 달라진다.

```text
최종보정_방향별기본상한
  = 0.00005   if 최종보정_원시값 >= 0
  = 0.000035  if 최종보정_원시값 < 0
```

불확실성순위는 `quantile_width`를 0~1 범위의 순위값으로 바꾼 값이다. 예측 구간 폭이 클수록 불확실성순위가 크다.

```text
불확실성순위 = rank01(quantile_width)
```

row 위험도는 기준 예측가격과 이동 대상 예측가격 사이의 불안정 가능성을 0~1 범위로 계산한 값이다. 위험도가 높을수록 보정 상한을 더 줄인다.

```text
최종보정_적용상한
  = clip(
      최종보정_방향별기본상한
      * (1 - 0.55 * 불확실성순위)
      * (1 - 0.80 * row위험도),
      0.000006,
      최종보정_방향별기본상한
    )
```

최종 적용 보정값은 다음이다.

```text
최종보정_적용값 = clip(최종보정_원시값, -최종보정_적용상한, +최종보정_적용상한)
```

최종 로그가격과 최종 가격은 다음과 같이 산출한다.

```text
최종 Warm 로그가격 = 미세보정전_기준로그가격 + 최종보정_적용값

최종 Warm 가격 = exp(최종 Warm 로그가격)
```

## 9. 최종 미세 보정층 계산 흐름

흐름 정리 범위:

- 입력: `미세 보정 전 기준 로그가격 생성` 단계에서 이미 생성된 미세 보정 전 기준 예측가격
- 대상: 최종 운영 예측가격 생성 단계
- 제외: 미세 보정 전 기준 예측가격보다 앞선 기준 예측가격 생성 과정

```text
1. 기존 Warm 예측값 준비
   - Huber 계수 기반 안정 기준 예측가격
   - 선행 균형 기준 예측가격
   - 미세 보정 전 기준 예측가격
   - p95 개선형 보조 예측가격
   - p95 방어형 보조 예측가격
   - 안정성 우선 보조 예측가격

2. 미세 보정 전 기준 예측가격 기반 feature set 생성
   - 가격대, 신뢰도, 예측 구간 폭, 매체/지지체, 유사작품 수, 면적 구간
   - 예측가격 간 로그가격 차이
   - row 위험도
   - 불확실성 순위와 예측가격 간 차이 순위

3. validation out-of-fold 519건 기반 방향 분류 모델 학습
   - target: 실제 로그가격이 미세 보정 전 기준 로그가격보다 높은지 여부

4. validation out-of-fold 519건 기반 Huber 잔차 모델 학습
   - target: 실제 로그가격 - 미세 보정 전 기준 로그가격

5. row별 상향확률과 잔차예측 계산

6. 상향확률 기반 방향확신도 생성

7. 잔차예측 방향과 방향 분류 모델의 예상 방향 일치 여부 확인

8. 방향 일치 및 확신도 충족 row에 한해 원시 보정값 생성

9. quantile width와 row 위험도 기반 보정 상한 축소

10. 보정값 상한 제한 후 미세 보정 전 기준 로그가격에 가산

11. 최종 로그가격을 exp()로 원 가격 단위 환산
```

## 10. 최종 운영 예측가격 계산 절차

절차 표기 기준:

- 실제 실행 코드 원문: 아님
- 표기 방식: 문서용 변수명 사용
- 목적: 최종 운영 예측가격의 계산 순서와 산식 설명

```text
1. 기준 로그가격 준비

   기준로그가격 = 미세보정전_기준로그가격

2. 방향 분류 모델 기반 상향확률 계산

   미세보정전_상향확률
     = 방향분류모델(미세보정전_기준가격_파생피처)

3. 상향확률을 방향확신도로 변환

   최종보정_방향확신도 = abs(미세보정전_상향확률 - 0.5) * 2

   최종보정_적용확신도
     = clip((최종보정_방향확신도 - 0.12) / (1 - 0.12), 0, 1)

4. Huber 잔차 모델 기반 잔여 오차 예측

   미세보정전_잔차예측
     = Huber잔차모델(미세보정전_기준가격_파생피처)

5. 방향 분류 모델과 잔차 모델의 방향 일치 여부 확인

   최종보정_예상방향 = +1  if 미세보정전_상향확률 >= 0.5
   최종보정_예상방향 = -1  if 미세보정전_상향확률 < 0.5

   최종보정_잔차방향일치 = 1  if sign(미세보정전_잔차예측) == 최종보정_예상방향
   최종보정_잔차방향일치 = 0  otherwise

6. 방향 일치 및 확신도 존재 시 원시 보정값 생성

   최종보정_원시값
     = 0.025
       * 미세보정전_잔차예측
       * 최종보정_잔차방향일치
       * 최종보정_적용확신도

7. 보정 방향별 기본 상한 설정

   최종보정_방향별기본상한
     = 0.00005   if 최종보정_원시값 >= 0
     = 0.000035  if 최종보정_원시값 < 0

8. 예측 불확실성과 row 위험도 기반 상한 축소

   최종보정_적용상한
     = clip(
         최종보정_방향별기본상한
         * (1 - 0.55 * 불확실성순위)
         * (1 - 0.80 * row위험도),
         0.000006,
         최종보정_방향별기본상한
       )

9. 원시 보정값 상한 제한

   최종보정_적용값
     = clip(최종보정_원시값, -최종보정_적용상한, +최종보정_적용상한)

10. 기준 로그가격에 최종 보정값 가산

    최종로그가격 = 미세보정전_기준로그가격 + 최종보정_적용값

11. 로그가격을 원 가격 단위로 환산

    최종가격 = exp(최종로그가격)
```

## 11. 모델 선택 기준

최종 운영 예측가격은 아래 조건을 기준으로 선택했다. 여기서 비교 기준은 “미세 보정 전 기준 예측가격”이다.

```text
MAPE <= 미세보정전_기준예측가격_MAPE + 0.000001
p95 APE <= 미세보정전_기준예측가격_p95_APE + 0.000002
repeated p95 win rate >= 미세보정전_기준예측가격_repeated_p95_win_rate
replacement score <= 미세보정전_기준예측가격_replacement_score + 0.000002
```

최종 운영 예측가격은 이 조건을 만족하면서 MAPE와 replacement score를 가장 잘 개선했다.

| 항목 | 미세 보정 전 기준 예측가격 | 최종 운영 예측가격 | 변화 |
|---|---:|---:|---:|
| MAPE | 0.2698887309 | 0.2698881958 | -0.0000005351 |
| p95 APE | 0.8073244865 | 0.8073247073 | +0.0000002207 |
| repeated MAPE win rate | 0.953846 | 0.953846 | 0.000000 |
| repeated p95 win rate | 0.788782 | 0.788782 | 0.000000 |
| replacement score | -0.0188291572 | -0.0188296923 | -0.0000005351 |

## 12. 운영 해석

최종 운영 예측가격을 운영 1순위로 둘 수 있는 이유는 다음이다.

- 미세 보정 전 기준 예측가격 대비 fixed test MAPE가 낮아졌다.
- repeated p95 win rate가 유지됐다.
- replacement score가 개선됐다.
- 보정 상한이 매우 작아서 기존 Warm 예측을 크게 흔들지 않는다.
- Huber robust regression과 방향 분류를 함께 사용해, 잔차 크기와 잔차 방향이 모두 확인되는 경우에만 움직인다.

다만 개선 폭은 매우 작다. 따라서 이 모델은 “확정적으로 큰 성능 개선을 만든 새 구조”라기보다 “현재까지의 Warm 예측가격 중 가장 앞선 운영 1순위”로 표현하는 것이 정확하다.

## 15. 다음 검증 필요 사항

최종 운영 예측가격의 개선 폭은 작기 때문에 다음 단계는 추가 튜닝보다 검증이 먼저다.

권장 후속 검증은 다음이다.

1. bootstrap으로 최종 운영 예측가격이 미세 보정 전 기준 예측가격보다 안정적으로 이기는지 확인한다.
2. row별 APE 개선분을 분해해 특정 몇 개 row가 개선을 대부분 만들었는지 확인한다.
3. 가격대, 신뢰도, 예측 구간 폭, 매체/지지체, 유사작품 수 구간별로 개선 방향이 일관적인지 확인한다.
4. 특정 row 의존성이 크면 최종 운영 예측가격을 보류하고 미세 보정 전 기준 예측가격을 운영 fallback으로 둔다.
